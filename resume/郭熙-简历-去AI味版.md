### XEYO - 自研桌面 Agent 引擎　2026.05 - 2026.07

用 Python 从零实现的桌面 AI Agent 引擎，包含 Agent 主循环、工具系统、上下文工程、记忆与权限安全，支持多会话并行、任务后台执行与小时级长任务稳定运行。

**实测**（deepseek-v4-flash 执行）：Terminal-Bench 2.1 全量 89 题通过 63 题，70.8%，高于官方参考实现 10.1pp。

公开基准实战：全量 89 题单次运行出分，89 份完整轨迹留存可复盘；26 道失败题逐题归因，归为三类，机制修复后直接多通过 2 题。

- **Agent 主循环**：主循环以 Goal 状态机管理目标修订、轮次与唤醒预算，并加入停滞检测与计划提醒。A/B 对比下，契约建立率由 0% 提升至 100%，单题成本下降 65%。支持快照 + 逆操作日志的断点续跑与崩溃恢复。
- **工具系统**：工具调用默认拒绝，单次授权，撤回即失效，权限裁决 p95 在 20ms 以内。Bash 通过 JobObject 隔离，可整树终止，只读命令走白名单。输出侧：Bash 输出精简 93.1%，按符号定位节省 99.2% token（快 18 倍），超过 30k 的截断内容全量落盘，可随时找回。
- **上下文工程**：上下文分为三区，易变内容通过单独通道注入；压缩不留经验常数——是否压缩、保留多少，全部按真实会话统计量化权衡「省下的开销」与「信息损失」，计划与用户原话永不压缩。压缩策略离线 A/B 实测：36 个场景下单任务成本由 ¥0.0487 降至 ¥0.0069，节省 85.7%；生产环境缓存命中率中位数 93.9%（累计 1.02 亿 token）。
- **回滚与检查点**：20 轮会话的存储增量约等于真正改动的文件体积，而不是「轮次 × 仓库体积」——检查点在模型动手前冻结，底层是内容寻址存储，只有被改过的文件才新增一份。回滚按消息锚定，文件与对话历史一起回退。
- **权限与安全**：deny-first 先拒后授，撤回即失效，DENY 不可被授权穿越；指纹只绑定工具、不绑定参数，注入无法伪造身份；直连、网关、子代理、worker 共用同一道权限门，写范围声明即排他，冲突在派发层消除（500 进程压测零冲突），碰撞重试的 token 消耗归零。
- **扩展系统**：通过标准 MCP 协议接入外部工具，网关统一负责发现、鉴权与调用；会话内启停即时生效，不触碰上下文缓存；配置损坏时自动回退至上次可用状态，扩展故障不影响主链路。

### RXY-Agent - Java 企业级 RAG 系统　2026.04 - 2026.05

用 Java 从零实现的企业级 RAG 系统，覆盖 ETL 管道、多通道召回、评估与万级并发，每个环节均有多层降级，整条链路可追踪。

**实测**　检索：公开基准 CRAG（Meta KDD 2024）60 题、5 个领域，Evidence Hit@8 0.967 / MRR 0.958，多跳 comparison 1.000，评测脚本可复现；并发：10,000 连接、10,325 请求零错误，聚合约 5k RPS（单机 16 核）。

- **检索质量**：重排阶段将文档名与章节路径一并注入重排输入（借鉴 Anthropic Contextual Retrieval）；增加跨文档置信度门控，剔除弱来源文档候选，解决同主题双文档在文件级的混淆；再叠加元数据加权（BM25F 思路）。多轮迭代后检索 Precision 提升 24%，同主题混淆用例由 6 个降至 2 个，中英文语料交叉验证证据命中均在 95% 以上。
- **证据门控（Agentic 决策）**：库外问题硬答会产生幻觉，一刀切拒答又会误伤，为此设计四步决策链：证据充分性评分 → 改写重检索 → 长期记忆个性化分支 → 明示拒答。实测三类问题各走各的分支：知识问答正常通过、记忆问题个性化回答、库外问题如实告知。
- **分层记忆**：多级缓存覆盖进程内 embedding、Redis 检索、语义与答案四层，均带 userId 权限维度；跨会话长期记忆采用规则抽取 + 多因子加权召回，全程不依赖 LLM，结果可复现；会话级以 Redis ZSet 滑窗配合摘要压缩。
- **并发与性能**：Java 21 虚拟线程，Tomcat 与全部 IO 执行器均替换；Kafka producer 分级确认，ETL 走强一致，观测事件批量压缩。压测中定位并修复连接池排队与外部 rerank 限速两处瓶颈，检索 p95 从 2.2s 降至 404ms。
- **评估闭环**：建立中英两套评测集，作为检索侧每次改动合入前必须通过的检验；借此把检索准确率由 81.5% 提升至 95.4%，20 道用例的通过数由 13 提升至 18。用户点踩的失败案例自动回流进评测集，下次回归即可拦截同类问题。英文长文档评测还暴露出中文短文档评测无法触发的问题——单批提交文本超出服务端上限，导致长文档未能入库。评测不依赖付费模型，可一键复跑。
- **文档 ETL 与权限**：Tika 解析 → 清洗 → 标题感知语义分块（512 token 父子切片）→ Contextual Retrieval 前缀 + 假设问题双向量入库，Kafka 异步解耦、同步确认防丢；权限侧以 ACL 位图在 Milvus 查询层下推，未授权 chunk 不进候选集。

## 子代理运行时 · 素材出处

`docs/面试知识书/07-第六册-扩展与多智能体.md` §15.2.1，原文：

> 我们让子代理**共享 abort、不共享 store**。因为这两件事的语义相反：**取消是「全局的意志」**（用户不想再跑了），而**历史是「局部的记录」**（工人的中间过程不该进主会话）。如果反过来（各 store 独立但 abort 独立），用户按停止就停不干净；如果 store 共享，主会话上下文会被工人的细节污染。
