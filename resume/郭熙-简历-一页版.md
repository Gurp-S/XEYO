## 项目经历

**XEYO — 自研桌面 Agent 引擎**　2026.05–2026.07　**独立完成**

用 Python 从零实现的桌面 AI Agent 引擎，包含 Agent 主循环、工具系统、上下文工程、记忆与权限安全，支持多会话并行、任务后台执行与小时级长任务稳定运行。

**实测**（deepseek-v4-flash 同模型）Terminal-Bench 2.1 官方 89 题：引擎实跑 182 次 trial 覆盖 57 题，在官方中立 scaffold 单次全量**打不下的 32 道硬题上攻下 13 道（40.6%，官方 0%）**。

- **公开基准实战**：把"失败"从笼统的"模型不行"变成可执行清单 —— 逐题留存轨迹与 verifier 原始输出，把**判分基建假阴性**与**真实能力缺口**分开归类 —— 34 道失败题完成取证分类（7 道基建 + 27 道能力）。
- **长任务稳定性**：解决"轮次硬切只留半句话"与"Agent 自我续跑烧钱"两个相反问题 —— 预算只开回合 256 / 工具调用 64 两根轴，触顶不开杀而是开 **3 轮收尾窗**（窗内仍放行 3 次工具，长命令自动转后台）；目标是 **5 态白名单状态机** + `revision` CAS，**轮次只在合成轮被引擎接受后才计数**，唤醒预算与后台任务共享且**只有人类输入能回满**；回滚走 **SHA-256 内容寻址快照 + 条件写**（hash 不符即抛冲突、绝不 force，`plan_hash` 授权、幂等重试）。
- **停滞检测**：真实事故是模型在同一个失败命令上**连续重试 166 次**把预算烧光 —— 执行层逐字节判四档：同签名连续 ≥6 / 尾部窗口周期 k∈{2,3} / 结果 `sha256` 连续 ≥3 次相同 / 同工具连续 ≥4 次无新内容；命中即**不执行该次调用**，**被拒时不更新签名故同签名再来仍拒**，连拒 3 次才放行一次半开探针。
- **工具系统与权限**：解决"一个 4 万字输出吃满上下文""bash 卡死杀不掉孙进程""提示注入伪造身份" —— 执行收口在固定链（只读门禁 → 钩子 → 权限三态 → 路由 → 执行 → 输出预算 → 审计），Bash 挂 **Windows 作业对象**（内存上限 2048MB）；整树终止**故意不用 `TerminateJobObject`**（嵌套作业下会阻塞）而走 `taskkill /T /F`；超 16000 字符先落盘再回"头 6000 + 尾 2000 + 路径"；权限侧是 **11 个判定点的顺序链**、**未知工具兜底 ASK**，授权指纹的输入里**没有任何模型可控字段**（参数永不参与）、**组合命令不吃授权**（堵 `git status && curl|sh`）—— **裁决 p95 1.36ms / p99 1.66ms（n=2 万次混合工具形态实测）**。
- **符号定位**：读一个小函数原本要先 Read 全文再看，两轮烧 2 万 token，正则 grep 又抓不全 —— 用 **Python `ast` / tree-sitter 建符号表**（缓存键取 `(size, blake2b16)`，**不依赖 mtime**，checkout 后不会整仓失效），`Read(symbol=…)` 精确切片、`Grep(output_mode="symbols")` **完全不调 ripgrep** —— **读一个符号 20,523 → 206 token；仓库符号召回 100%（480/480）对比正则 grep 51%（244/480）**。
- **上下文工程与工具面冻结**：system 里只要放日期或模型名，换一天就整段 KV 前缀失效、全量重算 —— 按**写入权**把上下文切成三区（左段字节稳定 / 历史只允许追加 / 易变内容只改投影），易变块的物理实现就是**在投影末尾新增一条原生 system 消息**，**只有纯追加能让既有字节原地不动**；同一原因下，会话内新增工具也不动 tools 数组，唯一通道是起点就注册的**一个网关工具**（约 150 token 固定 schema）；压缩分三级，C2 须同时过**压力门 0.80** 与**收益门**，切点强制落在 `tool_use ↔ tool_result` 成对边界 —— **真实用量账本 28 天 9,144 次调用 / 5.31 亿 prompt token：≥50k token 请求缓存命中中位 98.54%、P90 99.58%（n=2,902），单请求峰值 49.6 万 token 命中 99.8%**。

**RXY-Agent — Java 企业级 RAG 系统**　2026.04–2026.05　**独立完成**

用 Java 从零实现的企业级 RAG 系统，覆盖 ETL 管道、多通道召回、评估闭环与万级并发，每个环节多层降级、全链路可追踪。

**实测**　检索：公开基准 CRAG（Meta KDD 2024）60 题 5 域 Evidence Hit@8 **0.967（58/60）** / MRR **0.958**，逐题原始记录在库、可独立复核 ｜ 并发：10,000 连接 / 10,325 请求 0 错误、聚合 ~5k RPS（单机 16 核）

- **检索质量工程**：解决同主题双文档的文件级混淆与召回不准 —— 重排阶段把**文档名与章节路径一并注入重排输入**（借鉴 Anthropic Contextual Retrieval），叠加**跨文档置信度门控**剔除弱来源候选，再加**元数据加权**（BM25F 思路）—— 黄金集 20 例上检索平均精度由 **0.769 提升到 0.954（相对 +24.1%，绝对 +18.5pp）**，同主题混淆残余降至 **2 例**。
- **证据门控（Agentic 决策）**：解决"库外问题硬答幻觉"与"拒答一刀切误伤"的两难 —— 四步决策链：证据充分性评分 → 改写重检索 → 长期记忆个性化分支 → 明示拒答 —— 三类问题各归其位：知识问答过闸、记忆问题个性化作答、库外问题如实告知。
- **并发与性能**：解决高并发连接排队与外部依赖限速 —— Java 21 虚拟线程替换 Tomcat 与全部 IO 执行器，Kafka producer 分级确认（ETL 走强一致 / 观测事件批量压缩）；压测定位并修复连接池排队与外部 rerank 限速两处瓶颈 —— **检索 p95 由 2,222ms 降至 404ms**。
- **分层记忆**：解决多轮会话身份串号与长期记忆不可控 —— 多级缓存（进程内 embedding / Redis 检索 / 语义 / 答案）**全部带 userId 权限维度**；跨会话长期记忆用规则抽取 + 多因子加权召回，**全程不依赖 LLM、结果可复现**；会话级用 Redis ZSet 滑窗 + 摘要压缩。
- **文档 ETL 与评估闭环**：解决非结构化文档入库质量、越权检索与改动无法回归 —— Tika 解析 → 清洗 → 标题感知语义分块（512 token 父子切片）→ Contextual Retrieval 前缀 + 假设问题双向量入库，Kafka 异步解耦、同步确认防丢；权限侧以 **ACL 位图在 Milvus 查询层下推**，未授权 chunk 不进候选集；中英双评测集作为合入前必过门、点踩 badcase 自动回流，不依赖付费模型、可一键复跑。
