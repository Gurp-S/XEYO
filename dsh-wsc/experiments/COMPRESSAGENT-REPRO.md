# CompressAgent 最小手动复现

论文：*Control Under Compression: Reliability Frontiers for Tool-Using Agents*
（arXiv 2608.01056）。官方 runner 未开源，本目录是按论文方法手写的最小复现。

## 复现了什么

论文的做法：压缩**智能体控制上下文**（ACC：工具目录、策略、执行协议、恢复规则），
用**可执行结果**判定成功，而不是看省了多少 token。规模是 9 个 ACC × 3 类任务 × 6 档预算
× 3 个模型 = 15,525 次运行。

本复现保留结构、砍掉规模（`experiments/compressagent/run.mjs`）：

- 2 个独立 ACC（A 1746 字符 / B 942 字符，同一套工具不同措辞）
- 3 类任务：单次检索、需错误恢复的多步、策略约束下的拒绝
- 3 档保留预算：100% / 75% / 35%
- 2 种压缩法：section-based（整段丢弃，按策略/协议优先级保留）、generic rewrite（模型改写）
- 假环境 6 个工具，动作是 JSON 对象，成功由环境判定（检索答案匹配 / 恢复后正确 / 未触发违规）

## 结果（30 次运行，n=6/格）

| 方法 | 预算 | 成功率 |
|---|---|---|
| full | 100% | 67% |
| section | 75% | 67% |
| section | 35% | 33% |
| rewrite | 75% | 50% |
| rewrite | 35% | 33% |

定性上复现了论文的主结论：**75% 时压缩几乎无损（67% = 基线），35% 时断崖下跌，
且 section-based 优于 generic rewrite**（75%: 67% vs 50%）。

## 必须说明的局限

1. **基线只有 67%**：策略任务（"删除 src/app.js"）在完整上下文下模型就已经违反策略，
   所以这一类任务不提供区分度，全部 6 格都挂在这里。检索和恢复两类在 35% 才失败。
2. n=6/格，噪声大；论文是 n=数百。
3. 预算按字符算，论文按 token 算。
4. 单模型（deepseek-v4.1-flash），论文用 3 个固定 Qwen 标识。

要提升到可发表强度，需要：策略任务重写（让基线能过）、每格 ≥30 次、多模型、按 token 计量。
成本上每 30 次运行约 90 次小请求、5 分钟，扩到 30×5 大约 1 小时。

## 复现命令

    node experiments/compressagent/run.mjs
