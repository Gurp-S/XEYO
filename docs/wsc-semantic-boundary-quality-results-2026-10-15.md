# 341–342：正文边界、多代续接与完整来源归因

## 结论

340 的正文边界修复在真实模型多代运行中阻止了 Runtime 目录不断回流：末代目录从旧路径的 8 处变为新路径的 1 处。但本轮**没有通过任务质量不退化门槛，也没有证明达到 A1**。

主要失败不是当前数字被旧版本替换，而是恢复完整任务范围时，模型把输入资料字段误当成输出约定，随后连续五轮传播。完整来源生成对照能恢复正确字段，说明下一步应关注任务约定的保留与必要回查；不能把发现归结为“需要更多状态字段”，也不能据此把全部历史用户原文重新塞回热层。

本轮只增加隔离评测、归因材料和报告，未修改生产代码、默认开关或用户运行进程。340 两处机械修复继续位于现有自然语言入口；自然语言入口源码默认仍为关闭，不能宣称现场已加载或整个 Goal 完成。

## 条件与证据边界

三轮复审：[341计划](wsc-semantic-boundary-quality-plan-2026-10-15.md)。同源三臂、每臂自己的前代产物、相同 DeepSeek Flash、单路、HTTP 重试 0。每臂 14 个事件、5 次中途恢复及末尾恢复，覆盖范围缩小/恢复、暂停、完成、取消、重开、同路径新版本和迟到结果。每事件显式请求折叠，实际接受次数另计；不是 80%/85%现场容量测试。

- **A1**：封存的 Codex 公开本地提示词及用户消息保留方法。它是方法复现，不代表 Codex 产品或服务端压缩。
- **WSC-rendered**：当前生产接口，隔离实验中仅旁路正文选择，重现把完整已呈现头交给下一次生成器的旧路径。
- **WSC-body**：当前正文选择路径。目录、工具、模型和权限与 rendered 臂一致；各自工作区隔离，避免互相搜索对方索引。
- 历史查询每臂 3 个，与各自完整来源条件配对。原生 registry Read/Grep；私有答案在可读工作区外，读取拒绝已检查。写产物仍使用评测器 ArtifactWrite，下文单列其限制。
- 本轮复用 338 的受控任务族，不是独立留出、真实用户冒烟或跨任务泛化。每条件一条轨迹，不能将分数差直接认定为稳定因果效果。

## 逐类归因

### 1. 模型交接：输入 schema 被误当成输出约定

原始输出只有七项：`batch_id, revision, file_version, source_call_id, remaining_bytes, lane, checksum_label`。输入资料中的 `total_bytes, delivered_bytes` 用于计算差值，不属于输出字段。

事件 7 缩小为五字段子集；事件 10 恢复 full 范围。两种 WSC 的事件 10 交接均明确把两项输入字段加入输出，形成九字段格式，后续事件 10–14 连续传播。新鲜 `current-read-10` 及 revision=4 数据实际进入消费者请求，写入尝试里的数值与调用身份正确，不能归因为引擎丢掉当前值。

WSC-body 事件 9 的交接仍可见子集字段及暂停的 lane/checksum 信息，不能简单断言所有恢复依据已丢失。更准确的缺口是：交接没有稳定维持输入资料与输出合同的区别，范围恢复时生成了错误解释。

### 2. 模型身份错误：仍有不存在的调用 ID

- A1 事件 6/7 使用不存在的 `current-read-3`；事件 8 使用并非实际新 Read 调用的随机形状 ID。不能把它们当作合法替代来源。
- WSC-body 事件 3 数值对应正确 revision=2，却输出不存在的 `current-read-3`；真实来源是 `current-read-2`。该事件没有发布新压缩结果，不能说是该次折叠直接造成；错误后来还进入交接历史。
- 两种 WSC 的最终状态问答都是 112/112，实际任务仍失败。状态字段得分不能认证来源身份或任务成功。

### 3. 评测器路径边界：旧产物残留不能直接算旧版本复活

ArtifactWrite 的相对路径以 artifact_root 为基准，原生 Read 以工作区为基准；工具描述说明写入 artifact_root，但没有明确相对路径基准。模型写 `artifacts/result.json` 会落到 `artifacts/artifacts/result.json`。

A1 事件 2 最终正确写入目标文件，但此前多写了嵌套路径，按原严格协议失败。rendered 事件 10–14 把新数值写到嵌套路径，原目标文件因此保持旧子集内容；这不等于模型主动选择了旧数值。同时这些写入还有独立的九字段错误，所以也不能把失败全部归给路径歧义。

原始评分保留，不改评分器补分。下一次行为对照先统一实际读写路径合同，优先复用生产写入入口，避免继续测这个混杂因素。

### 4. 冷恢复：看到证据还不等于正确完成

rendered 的迟到回执查询耗尽统一 6 次模型请求额度，未交付产物，期间存在超出文件行数的空读取。Read 返回不标 is_error，不能因此把该读取算作有效恢复。新正文路径的三个历史任务均完成，但单样本不足以确认稳定优于旧路径。

原运行器用“调用 ID + checksum”两个字面量判断是否需要冷层，对 rendered 迟到查询误记为“不需要”：交接里已有这两个词，其余回答所需值不全。`analysis.json` 增加“所有目标字面值是否可见/是否在回执出现”的辅助诊断，原评分及原 Need 指标不覆盖。它也不是语义理解证明，不能直接当通用触发 precision/recall。

## 342：完整来源生成对照

在事件 10 的密封来源截面，分别保留两臂已发生历史，使用与原生成相同提示词、4096 输出额度和回查工具；只将上一代压缩上下文替换为该时点完整来源。没有后续事件或私有答案，未修改生产逻辑。

两次生成都明确恢复了正确的七字段输出约定，耗费 2 次请求、估计 ¥0.03631296。对照支持“压缩链中的合同失真影响范围恢复”这一解释，不能凭两次生成宣布根因已经完全消除。两份新交接将 source_call_id 留成“本次 Read 的调用 ID”占位，本轮没有执行消费者，因此**不计为任务成功或完整交接质量通过**。

免费准备第一次因把来源身份键误写为 id 而失败，实际键为 message_id；未调用 API。修正后使用独立 r2 目录，原目录保留。不是 HTTP 重试，不拼接失败与成功。

## 下一步与停止修改规则

先处理评测读写基准的歧义，再隔离“输出合同直接保留 / 正确原文锚点可按需恢复 / 仅通用目录”的差异。比较实际产物、来源身份、错误累积和额外开销；不人工补模型答案，不引入语义真值字段，不用对本题专用的提示强迫召回，不凭一次生成成功马上改默认。

按用户最新修订：至少三轮实质修改收益很少时，停止该方向继续修改并讨论，Goal 保持 active；讨论后自动继续，无需用户恢复 Goal。本轮是对 340 修改的验证和归因，不以改批号重置此前修改记录。此结论没有触发新一轮生产补丁或追加重复长链实验。
