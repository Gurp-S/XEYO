# 批次36：多代任务交接不累积旧活跃状态

## 结构根因与修正

`memory/runtime.py::try_extend_c2`的回退扩展把“旧摘要含任务交接”与“本次摘要含最新任务交接”直接拼接。第二次真正折叠后，修订1和修订2的检查点同时呈现为任务交接，旧决定仍占据热层。首代原生WSC因小输入收益门拒绝时，同样进入此回退路径。这不是某个关键词噪声，而是把活跃状态当成追加日志的结构错误。

规则：模型Compact与容量强压经force路径产生新一代时，回退头只物化本次确定性摘要和按完整折叠来源重建的最新任务交接；上一代头/冷对象不改写。代内KEEP仍保留既有头字节。最新冷存档仍涵盖完整已折叠原文，不用热层累积旧交接承担存储职责。旧费用/轮数策略的非force辅助函数未接回主流程，其独立旧策略单测行为保留。

改动：`python/memory/runtime.py`；新回归`python/tests/wsc/test_multi_fold_lifecycle.py`。没有增加模型提示、语义关闭规则、付费请求或旁路开关。

回归覆盖WSC开/关、小/大负载四组合：首次失败验收v1与修订1 → 再次失败验收v2与修订2 → 成功v3与提交完成 → 新任务B及其详细定义。每阶段真实推进折叠游标、刷新工作快照、清空进程投影状态、hydrate并再投影。

- 四组合共16次真正折叠及16次重启恢复，最新声明和绑定验收正确；完成后无活跃任务A，任务B不继承任务A决定。
- 大负载原生臂每次断言原生投影确实存在；小负载原生开关臂断言实际走回退，避免两臂都回退却冒充原生验收。
- 原始消息不改；每次生成新代前后所有既有冷文本字节相同；恢复头与本次已发布头相同。
- 修复前两条最初小负载用例失败：第二代仍含修订1决定。最终相关110 passed（7.76s），四组合用例全部通过。不是实际模型长期不漂移的证明。
