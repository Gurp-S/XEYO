# 批次102：交接预算与真实提交边界（仅静态）

结构性根因：主循环在开始生成交接之前预扣一次 TodoWrite 工具配额，但交接模型可能先读取来源并发出多轮请求。每轮 begin_turn 会重置工具计数，最终实际执行 TodoWrite 的那轮并不一定持有预扣额度。交接内部也未复用主循环的美元/token硬停检查，不能仅用请求次数限制冒充费用限制。

不变量：工具配额属于工具真正执行的模型轮次；实际写入前的拒绝必须早于追加调用及任务状态变更。交接所有模型 usage 继续进入原 submit 的 BudgetTracker 和原 UsageEvent；不创建第二份预算、计费规则或模型配置。

修正：提取既有生成与提交协调到 memory/wsc_handoff_prepare.py。首次请求仍由主循环拥有并准入，后续请求、来源读取及最终写入共用原预算。事务接受 admit_write 回调，完成来源一致性及输入校验后、追加调用前占用真实写入配额。各执行边界复用美元/token硬停；不把耗尽预算转成继续折叠。phase要求、取消校验、调用/回执持久化、来源指纹和原 usage事件不变。

静态核对了生产主循环→共享准备→生成→事务→TodoWrite的调用及异常返回顺序。修改3个代码文件；未运行测试、编译、模型/API，各项0、费用0；未部署、未操作真实会话/冻结前缀或旧冷对象。现有独立事务调用未传新回调时保持兼容，这些调用不能当作生产预算证明。
