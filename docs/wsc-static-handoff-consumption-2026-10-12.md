# 批次111：交接调用不是主任务结果的消费凭证

结构性根因：WSC尾部保护原把最后一个assistant消息当作消费时间界限。强压/手动压缩的隔离交接也追加assistant TodoWrite和回执，因而交接后重新计算fold_cut/保护区可能把主任务模型尚未消费的工具结果判成旧材料。仅保留刚生成的交接回执不能满足未消费结果保全。

规则：消费属于主任务模型的时间轴；隔离交接调用不代为确认消费。复用既有执行回执metadata，在交接事务publish时保存compaction_handoff=true；原始工具正文、工具API和模型回执身份文本不增加指令。protect从唯一匹配的TodoWrite调用及其交接元数据识别隔离声明帧，计算最后主任务assistant时跳过这些帧；同时继续保护其后的结果及真实调用来源。既有handoff_source_presentation作为旧交接来源标识兼容。普通TodoWrite没有交接元数据时仍属于普通模型调用，不按工具名一律排除。

两个生产文件：memory/wsc_handoff_transaction.py、memory/wsc_execution_boundary.py。主循环、手动入口、force的pair-safe切点、新WSC头上界和恢复尾部已有protect接线，共用该规则，不另建消费状态机或额外保护游标。既有冻结头生命周期不改；本批次不能补救已在旧头里的迟到结果，T18仍保留。

静态核对合同（未执行）：

- 主任务Read调用→结果→隔离TodoWrite交接→强压：最后消费assistant仍为Read调用，Read及其完整结果在保护区。
- 主任务已经有后续正常assistant→交接：既有正常消费边界保留，不把所有历史结果无限加热。
- 多轮隔离交接：各可归因交接帧均不成为主任务消费界限；未知/重复身份不作唯一归因。
- 普通模型TodoWrite→结果：无隔离标识，不改变普通工具轮合同。
- 交接返回错误/取消：发布的事实仍属于隔离调用，原异常传播且不允许该事务继续折叠。
