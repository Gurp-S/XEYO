# 批次107：同批消息与重试确认核对正文（仅静态）

结构性根因：新批次用known集合筛选，但筛选结束后才记入known，同批同ID两条都能写入。失败重试也只确认日志中有相同ID便跳过，不确认其正文。因而原模型源、冷正文及重启恢复可能不一致，已有ID不能单独构成“这份来源已持久化”的证据。

规则：一个消息身份对应同一份逻辑消息字段。同身份同正文的重复可幂等；同身份不同正文不能静默确认或覆盖旧源。物理追加时间和正文inline/blob表示不改变逻辑身份。回溯仍由surface marker控制可见性，不授权改写旧行。

修正范围：提取transcript_blobs.message_fields作为原序列化字段的纯数据入口，row_from_message继续复用它并添加ts/外置正文。record_transcript的同步、异步和旧直写适配器均使用pending_messages筛选新批次，同批同正文只保留一次，不同字段报transcript_message_identity_conflict；发生冲突前不写blob、不更新known、不入队。正常批次仅缓存对象引用，只有真实碰撞才序列化比较，不增加每条消息的第二次正文序列化。

重试沿原disk lock/全源完整性核对及末尾修复机制：仅缓存本次待重试ID碰到的存储行；遇到已存在ID，严格读取/核对已有blob正文，忽略ts和外置表示字段后比较完整消息字段。内容不符或引用读取失败拒绝确认，旧完整源不改；同ID历史有多个不同正文不能任选一条算成功。未碰到ID的归档正文不读取、不缓存，避免全历史正文驻留或无关隐藏blob阻断。

静态检查：调用接线、新批次去重时机、已知集合更新时机、同批与重试内重复、inline/blob对照、失败队列/flush传播以及原无重试的快速路径。应覆盖回归包括同批重复同正文、不同正文在发布前失败、旧源不同正文重试不确认、ts不同但正文相同、blob/inline相同正文、坏blob不确认、归档碰撞和故障后顺序；按当前用户要求未编写或运行测试、编译、API，全部0、费用0。

尚未统一的实现边界：普通入口已有known_ids快速跳过同ID，不核对本次新对象与先前已接受/存储正文；重启/回溯重新装载已知集合的作用域亦需与不可变来源身份合同对齐。此批只覆盖同批及真实失败重试，不把这些未修改分支标成已修。固定方向继续复用现有序列化及来源准入，区分原始身份/可见性/物理耐久确认；不重写旧正文、不以每次全历史扫描代替身份准入，不从冲突历史自动建立旧任务。

修改3个代码文件：session/transcript_blobs.py、session/transcript_retry.py、session/record_transcript.py。无部署、无真实会话或冻结对象操作；新行逻辑字段/外置格式保持，字典字段顺序不作为身份。四块最终真实效果验收仍开放。
