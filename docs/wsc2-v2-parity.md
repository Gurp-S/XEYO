# WSC V2 补齐功能缺口（B）→ 再并进主链做真实负载验证（A）

2026-09-23 用户裁定：**先 B 再 A**；并给出长期授权——
**后续所有改动都可以自由牺牲"压缩那一枪"的前缀命中率**（折叠时重写整个头都行），
但 **两次折叠之间头必须逐字不变** 当硬不变量守（实测破坏它的代价是每请求贵 2.7 倍）。

## 0. 为什么 B 在 A 前

V2 现在替换掉的是 V1 头里的"现况摘要"（6,451 tok 里的一小段），
其余内容类它产不出来 ⇒ 直接进主链必然掉功能（§12 判定 REWORK 的原由）。
先把内容补齐，A 阶段才有意义：并进主链时"整份"可比，而不是"少一类"。

## 1. B1：分支结论类（V1 的 `[DECISIONS]` / `[PRUNED]`）

可行性已查：**不需要重造剪枝器**。V1 的卡片对象在装配状态里就能拿到
（`synaptic/project.py:64 class Projection`、`:378 state.frozen_cards`），
渲染层是 `synaptic/prune.py:291 render_card`（字段：`card_id / conclusion / files / error_sig / replay / nodes`）。

- **B1-a（本轮做）复用 V1 的剪枝判定，把卡片接进 V2 当 `DERIVED` 事实**：
  一条排除分支 = 一个事实，带 `conclusion / files / error_sig / replay / nodes`，
  来源记 `prune_card`，并**必须带 V2 自己的取回定位符**（`Read(会话文件, offset=首节点行+1, limit=节点跨度)`；
  卡片只给 `expand(branch://…)` 不算，因为 V2 的取回口径是普通 Read）。
  - V2 在这一类上能做到 V1 做不到的**唯一一件事**：退场。
    规则只用已有证据：卡片的 `error_sig` 对应的失败被"同签名重试成功"解决 ⇒ 该排除分支 `SUPERSEDED`，
    证据名 `same_error_resolved`。V1 的卡片**永不退场**（只按预算被挤掉）。
  - 验收：① 与 V1 逐条对账（同一状态点，V2 的 decision 事实数 = V1 卡行数，字段齐）；
    ② 退场规则的误删必须为 0（被退场的卡片若在 `t` 之后仍被再引用 ⇒ 判死该规则）；
    ③ 尺寸代价单独报（V1 卡行中位 2 行/点，实测见 `docs/wsc2-phase5.md` §9）。
- **B1-b（B1-a 之后，另开工单）V2 自算分支结论**：要 deterministic 判"某条路已放弃"，
  现有事件证据只能给"同目标连续节点以失败结束 + 之后该文件无写 + 被同签名成功替代"，
  覆盖面必然低于 V1 的 selection ⇒ **只有 B1-a 的收益被证实后才值得做**，否则是重造一遍更差的剪枝器。

## 2. B2：尾部骨架化

V1 把保留尾部的大节点压成一行骨架（`synaptic/assemble.py:153 _skeleton_of`，
`emitted_tokens` 按发射成本记账），这是"整份比 V2/V1 = 0.75~0.88"的主要来源。
- 做法：V2 的 full projection 复用 V1 的 `_skeleton_of` 判据原语（与 #31 同一招：同判据、不同成本模型），
  而不是自己再写一套摘要规则。
- 验收：两臂同点同尾同尺再量整份比；**保留率不得下降**（骨架化过的节点仍能按行取回）。

## 3. 不做 / 已关掉（防止 B 阶段顺手复发）

- 为命中率做差分台账、段序重排 ⇒ 已判死（省 88 tok = 真实请求的 0.2%）。
- 给事实加"保质期"来删 ⇒ 已判死（闲 ≥32 枪仍有 12.8% 事后被再用）。
- V1 重复行合并 ⇒ 真机只省 4.3% 且伤取回参数，已撤回。
- 引用任何 V1 尺寸前必须先过 `_sid_guard`（每点唯一 session_id）。

## 4. 顺序

B1-a（含对账与退场测试）→ B2（骨架化 + 整份重量）→ 汇总"补齐后 V2 的头 vs V1 的头"
→ 交给你裁 A（并进主链 + 真实负载冒烟，要花钱，另开授权）。
