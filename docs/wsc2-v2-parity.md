# WSC V2 补齐功能缺口（B）→ 再并进主链做真实负载验证（A）

2026-09-23 用户裁定：**先 B 再 A**；并给出长期授权——
**后续所有改动都可以自由牺牲"压缩那一枪"的前缀命中率**（折叠时重写整个头都行），
但 **两次折叠之间头必须逐字不变** 当硬不变量守（实测破坏它的代价是每请求贵 2.7 倍）。

## 0. 为什么 B 在 A 前

V2 现在替换掉的是 V1 头里的"现况摘要"（6,451 tok 里的一小段），
其余内容类它产不出来 ⇒ 直接进主链必然掉功能（§12 判定 REWORK 的原由）。
先把内容补齐，A 阶段才有意义：并进主链时"整份"可比，而不是"少一类"。

## 1. B1：分支结论类（V1 的 `[DECISIONS]` / `[PRUNED]`）

可行性已查：**不需要重造剪枝器**。V1 的卡片对象在装配状态里就能拿到
（`synaptic/project.py:64 class Projection`、`:378 state.frozen_cards`），
渲染层是 `synaptic/prune.py:291 render_card`（字段：`card_id / conclusion / files / error_sig / replay / nodes`）。

- **B1-a（本轮做）复用 V1 的剪枝判定，把卡片接进 V2 当 `DERIVED` 事实**：
  一条排除分支 = 一个事实，带 `conclusion / files / error_sig / replay / nodes`，
  来源记 `prune_card`，并**必须带 V2 自己的取回定位符**（`Read(会话文件, offset=首节点行+1, limit=节点跨度)`；
  卡片只给 `expand(branch://…)` 不算，因为 V2 的取回口径是普通 Read）。
  - V2 在这一类上能做到 V1 做不到的**唯一一件事**：退场。
    规则只用已有证据：卡片的 `error_sig` 对应的失败被"同签名重试成功"解决 ⇒ 该排除分支 `SUPERSEDED`，
    证据名 `same_error_resolved`。V1 的卡片**永不退场**（只按预算被挤掉）。
    **⇒ 这件事本轮被判死了**：按下面验收②的口径，真语料上误删 30.8%，加一致性闸后退场次数变 0。
    详见 §5.3，别把"会退场"当成 V2 的卖点写进任何对外材料。
  - 验收：① 与 V1 逐条对账（同一状态点，V2 的 decision 事实数 = V1 卡行数，字段齐）；
    ② 退场规则的误删必须为 0（被退场的卡片若在 `t` 之后仍被再引用 ⇒ 判死该规则）；
    ③ 尺寸代价单独报（V1 卡行中位 2 行/点，实测见 `docs/wsc2-phase5.md` §9）。
- **B1-b（B1-a 之后，另开工单）V2 自算分支结论**：要 deterministic 判"某条路已放弃"，
  现有事件证据只能给"同目标连续节点以失败结束 + 之后该文件无写 + 被同签名成功替代"，
  覆盖面必然低于 V1 的 selection ⇒ **只有 B1-a 的收益被证实后才值得做**，否则是重造一遍更差的剪枝器。

## 2. B2：尾部骨架化

V1 把保留尾部的大节点压成一行骨架（`synaptic/assemble.py:153 _skeleton_of`，
`emitted_tokens` 按发射成本记账），这是"整份比 V2/V1 = 0.75~0.88"的主要来源。
- 做法：V2 的 full projection 复用 V1 的 `_skeleton_of` 判据原语（与 #31 同一招：同判据、不同成本模型），
  而不是自己再写一套摘要规则。
- 验收：两臂同点同尾同尺再量整份比；**保留率不得下降**（骨架化过的节点仍能按行取回）。

## 3. 不做 / 已关掉（防止 B 阶段顺手复发）

- 为命中率做差分台账、段序重排 ⇒ 已判死（省 88 tok = 真实请求的 0.2%）。
- 给事实加"保质期"来删 ⇒ 已判死（闲 ≥32 枪仍有 12.8% 事后被再用）。
- V1 重复行合并 ⇒ 真机只省 4.3% 且伤取回参数，已撤回。
- 引用任何 V1 尺寸前必须先过 `_sid_guard`（每点唯一 session_id）。

## 4. 顺序

B1-a（含对账与退场测试）→ B2（骨架化 + 整份重量）→ 汇总"补齐后 V2 的头 vs V1 的头"
→ 交给你裁 A（并进主链 + 真实负载冒烟，要花钱，另开授权）。

## 5. B1-a 实测（126 点，每点唯一 session_id，零 API，`_wsc2_b1_parity.py`）

### 5.1 交付口径（行格式压缩之后）

| 检查 | 结果 |
|---|---|
| V1 `[DECISIONS]` | 385 行，**189.5 tok/点**（另一段 `[PRUNED]` 13 行、1,210 tok/点，那是可恢复性索引，V2 由 History Index 顶，不算缺） |
| 接进 V2 | **377 条**事实（385 行全认出来，解析失败 0）；同键合并 8 条 |
| **尺寸** | V2 `[EXCLUDED BRANCHES]` 3.0 行/点 = **121.0 tok/点 = V1 同类的 0.639×** |
| 这 121.0 的构成 | 结论本体 **91.8** ＋ 字段装饰 **26.2** ＋ 换行 3.0 |
| 行级出现率（占 377 条常驻事实） | 结论 1.0、错误签名 1.0、行定位符 1.0、行上有路径可指 0.793 |
| 退场 | **0 次**（§5.3，这条要把我上一版的话整个撤回） |
| 门禁 | `tests/wsc + tests/wsc2` = **322 passed / 1 xfailed**（本轮 +2 条） |

一句话：**V2 现在装得下 V1 的"已排除分支"，字段一字不丢，体积是 V1 的 64%。**

### 5.2 行格式怎么从 1.25× 压到 0.639×

初版 237.7 tok/点（比 V1 密 25%）。改了四件事：

1. 去掉 `branch[<键前 8 位>]` —— V1 发给模型的那一行里根本没有 id（`card:<id>` 是状态键，不发射）。
2. `files` / `err` 改成**按字面包含去重**：结论里已经写出来的路径/错误文本不再发射第二遍。
   V1 只硬编码免掉 `files[0]`；比较两侧都 casefold（Phase 5 实测只折一侧会假漏失）。
3. `err` 截断 60 → 40。
4. `rows=a-b` → `lines=<1-based>`：与 `Read` 的 offset 同口径（同 `history.py` 的 locator）。
   事实内部仍存 0-based 事件索引 —— `attach_decisions` 拿它当 `event_index`，存的时候 +1 会串位。

外加**一处明确不做**，因为它是我自己上一版写的计划：`files` 只留 basename。消融台
（`_wsc2_b1_ablation.py`，解析器修好之后重跑）：

| 变体 | tok/点 | 行上有路径可指 |
|---|---|---|
| 全路径（做的） | **121.0** | 0.793 |
| 只留 basename | 120.8（省 0.2） | 0.761 |
| 干脆不发 `files=` | 90.8（省 30.2，−25%） | **0.377** |

⇒ basename 白干（还倒贴覆盖）；`files=` 值 30 tok/点，但那 30 tok 买的正是 V1 注释里记过的那次事故
（185 条针漏失里 **17 条**是"卡里已经有这条路径、就是没渲染"）。不省。

**省在哪：**逐行台（`_wsc2_b1_perline.py`，10 点）量到 V1 一行 72.2 tok、V2 一行 45.2 tok。
V1 那 72.2 里 **36.5 tok/行是句柄表达式**（`Read(file_path='<绝对路径>', offset=…, limit=…)`），
V2 换成 `lines=a-b`。口径敏感性：本台的 offload 绝对路径比生产形状长 2 tok/行
（33 vs 31），换成生产路径整段比约 **0.64 → 0.66**，结论不变。

**体积的地板已经摸到**：121.0 里 91.8 是 V1 卡片结论的本体，逐字继承。这一段不再是格式问题，
再往下只有两条路——把结论截短（伤信息，要先量长度分布与 regret 才谈）或者让分支真退场（§5.3）。

### 5.3 撤回："退场 26 条、误删 0" 这句话的两半都是坏的

1. **"误删 0" 是构造出来的，不是测出来的。** 旧判据拿该签名**最早**出现的位置去比 t，
   而这条分支的存在本身就证明这个签名在 t 之前出现过 ⇒ 恒判 0。
2. 换成两条互相独立的判据（① 归一化签名在 t 之后重现＝主判据，与 `retire_decisions` 同源；
   ② 错误原话字面重现＝上界，偏严），同一台：**26 次退场里 8 次（30.8%）之后同一个错误又出现**，
   两条判据给出同一个数。
3. 再加一道一致性闸：**同签名若还有未解决的失败，就不许退场**。否则状态自相矛盾 ——
   `[UNRESOLVED]` 写着"这个错误还在"，`[EXCLUDED BRANCHES]` 却说"它已经作废"。

加完闸的效果：**退场次数 26 → 0**。也就是说，在 V1 喂卡面这条路上，
"同参数重试成功"这条证据**从来没有单独成立过** —— 26 次全部撞上"同签名错误仍挂着"。

⇒ 诚实的结论：V2 相对 V1 的"会退场"目前是**机制存在、真语料零收益**，
不许写进任何对外数字；上面那 36% 的体积全部来自格式，与退场无关。
机制本身留在库里（单元测试钉住，去掉一致性闸就红，已做变异验证），
A 阶段改吃 `frozen_cards` 对象后重测一次再判生死。

### 5.4 本台的边界（不许当成 V2 的缺陷）

- 吃的是 **V1 渲染出来的卡片行**而不是卡片对象 ⇒ 结论体已按"不含句柄"切齐，但
  `err` 是原话、不是归一化签名，join 天生偏松/偏严两边都有。
- 本台拿不到真 `nodes`，`lines=` 用的是"V1 行上有没有可执行句柄"的代理 ⇒
  **行定位符的可取回性没有被本轮证明**，A 阶段必须单独量。
- 结论按 320 字裁剪（与 V1 同尺），裁剪会让字面去重判不出来，方向是多写不是藏信息。
