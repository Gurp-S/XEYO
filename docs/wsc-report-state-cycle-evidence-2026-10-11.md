# 批次71：真实汇报后的状态更新与双折叠恢复

## 根因、规则、验证

步骤status更新可以只引用上一检查点以前的消息；即使新报告文本已经进入专用交接，新的completed声明仍未关联实际报告。这与来源ID保留但事实丢失是不同的生命周期缺口。

新增独立 `memory/wsc_handoff_progress.py`：此前显式作用域检查点中已有步骤的status发生变化时，声明绑定至少一个检查点之后的真实文本事件，或新的唯一完整非取消工具回执。机器注入、重复身份、旧消息、取消及歧义回执不能作为新进度来源。返回中性错误和变化记录；生成允许原6请求预算内修正，不代替模型判断完成、不根据关键词关闭任务。

来源校验只证明进度声明与新事件关联，**不证明语义完成**；不是每步骤的完整证明图，也不把未声明作用域的历史清单自动纳入新合同。

回归涵盖旧引用拒绝、新user/assistant文本、失败但完整的真实回执（仅事件来源，未宣称验收成功）、取消/重复/机器注入拒绝、不变状态/无旧状态，以及受控模型收到错误后绑定报告来源且保持completed，而非回退status。
