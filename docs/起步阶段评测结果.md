**总体判断：**
1. 模型底座四维全部达标（≥90%，代码 ≥97%）。工具调用在官方更难的 600 例题库下约 91–93%（simple/multiple/parallel 三个 Python 核心子项），跨语言（java/javascript）与非 Python 形态明显掉档（54–57%），多轮 base 72%、无关检测 72.5% 为中等水平——对外汇报建议用官方 Non-Live Overall 84.67% + 各子项，勿再用首轮自研 100% 口径。
2. HumanEval 在 8192 与 32768 两档分别为 97.56% / 95.73%：32768 档截断清零（/116、/145 两题超长思考均完整输出），但单次采样波动（±2 分）大于 max_tokens 提升的增益，证明前一轮 8192 结果的偏低并非「token 不足」导致，而是模型对极少数难题本身的真实能力 + 采样噪声。**对外取两档高分档 97.56% 并注明采样波动。**
3. MMAU 本地套件曾以唯一失败用例揪出 **P1 级产品缺陷**（`deepseek.py` 流式方法整体死代码），修复后满分——这是榜单类基准给不了的工程价值。
4. 思考模式是代码基准的成本大头（reasoning tokens 占输出 83–88%）。

## 二、P1 缺陷修复记录：`python/model/deepseek.py`

**缺陷（已存在多个提交，非本次评测引入）：** `_build_body` / `stream` / `_stream_httpx` / `_stream_stdlib` / `_complete_non_stream` 五个类方法被整体缩进进模块级函数 `_extract_sse_usage` 体内成死代码；`DeepSeekModelClient` 仅剩 `__init__/_headers`。

**影响面：** `engine/query_engine.py:822`（DeepSeek 主路径首轮即 AttributeError）、`memory/simulator/probe.py:94`、`scripts/kv_cache_probe.py:516`；`model/openai_compat.py` 仅用模块级辅助函数不受影响。项目自测 `test_vendor_models.py` 因未覆盖 `.stream()` 而长期漏检（契约缺口，建议补最小断言测试）。

**修复：** 纯结构移动（167 行回归类体 + 恢复 `_extract_sse_usage`），净 diff 约 ±15 行，无逻辑改动。

**验证链：** AST 结构核对 → `test_probe.py + test_vendor_models.py` 7/7（含真实 SSE 的 live probe）→ XEYO 客户端真实流式冒烟（20 chunks + usage 含 reasoning_tokens）→ MMAU 全套件 112/112。

## 三、第二轮官方 harness 执行细节

### 3.1 HumanEval（官方评分器）

- 环境：Docker Desktop Linux 容器 `python:3.11-slim`（用户无常规 WSL 发行版，docker-desktop 发行版不可用，经用户环境实际可行的 Linux 路径即容器）；官方 `human-eval==1.0` 源码安装（修补了两处与新 setuptools 不兼容的 console-script 入口点，判分逻辑零改动）。
- 协议：官方 `evaluate_functional_correctness`，多进程沙箱执行、退出码判分；生成侧 chat + thinking=enabled，补全提取规则与首轮一致。
- R2（max_tokens=8192）：**pass@1 = 0.9756**（160/164）。失败：/76、/116、/145（思考 token 跑满 8192 后正文被截断）、/158（真实断言错误）。
- R3（max_tokens=32768，全量重跑）：**pass@1 = 0.9573**（157/164）。164 题全部 finish=stop（**截断清零**，/116 思考 13557 token、/145 思考 21569 token 均完整跑完），但这两题思考充足后仍未做对——证明它们对模型是「真难题」而非 token 预算问题。失败集：/54、/59、/103、/147、/163、/116、/145（其中 /116、/145 连续两档失败，其余为采样翻转）。
- 结论：max_tokens 提升消除了截断偏置，但单次采样波动（±2 分）主导档位差异。**对外汇报取高分档 97.56%，并注明采样波动与思考开启。**

### 3.2 BFCL（Berkeley 官方）

- 环境：同容器；`bfcl-eval==2026.3.23`（PyPI）；数据集经 hf-mirror 拉取（BFCL v4）；容器 github.com 直连不通，宿主机 codeload/raw 域可用。
- 配置：`DeepSeek-V3.2-Exp-FC` handler，仅把其 `model_name` 补丁为 `deepseek-v4-flash-vision-exp`（base_url/api_key 走官方 DEEPSEEK 通道），FC 模式，temperature 默认（0.001）。
- R2 规模：600 例（simple_python 200 + parallel 400），22 分钟跑完。
- R3 全量补测：**990 例**（multiple 400 + parallel_multiple 200 + simple_java 100 + simple_javascript 100 + irrelevance 240 + multi_turn_base 200），约 3.5 小时（多轮条目每例含多 Turn×Step 串行 API 调用）。中途 API 余额 402 触发指数退避重试（充值后自动恢复续跑），最后一条多轮样例有两次单步解码失败（BFCL 按「跳到下一 Turn」处理，非致命），全程无 Traceback。
- 结果（官方 AST/多轮判分）：
  - simple_python **93.50%**、parallel **90.50%**、multiple **93.50%**、parallel_multiple **86.50%**
  - simple_java **57.00%**、simple_javascript **54.00%**（跨语言明显掉档）
  - irrelevance（无关检测）**72.50%**、multi_turn_base **72.00%**
  - **Non-Live Overall = 84.67%**（AST+irrelevance 聚合），Simple AST 68.17%
- 与首轮差值解读：自研套件参数全部显式给出、无干扰项，考察「参数抽取」；官方题库含更多边界形态，且 java/javascript/irrelevance/multi-turn 此前完全未覆盖。对外汇报统一用官方口径。
- R3 原始明细已持久化到 `artifacts/benchmarks/startup/wsl/bfcl/{results_round3,score_round3}/`。

### 3.3 MBPP / MMAU

- MBPP：Windows 侧 lite harness 重跑（官方数据集 sanitized 前 100、prompt 含前 3 断言、全量 test_list 判分），max_tokens 提至 8192：96% → **97%**。剩余失败 task_87/task_143 为真实错误，task_160 为 8192 下仍截断。
- MMAU：六能力组离线套件（工具契约/权限策略/会话与任务状态/记忆压缩与检索/用量账本/模拟器不变量），缺陷修复后 **112/112**。

## 五、复现

```bash
# Windows（lite 三件套 + MMAU）
cd python
python evals\bfcl_lite.py            # 自研口径
python evals\humaneval_lite.py
python evals\mbpp_lite.py            # 已升 8192
python evals\mmau_local.py

# 官方口径（Docker Linux 容器；脚本与产物在 artifacts/benchmarks/startup/wsl/）
docker run --rm -v "<repo>/artifacts/benchmarks/startup:/bench" \
  --env-file .../wsl/.env.eval python:3.11-slim bash -c \
  "pip install -q requests /bench/wsl/src/human-eval-master && \
   python /bench/wsl/gen_humaneval_official.py && \
   cd /bench/wsl/humaneval && evaluate_functional_correctness samples_official.jsonl \
   --problem_file /bench/data/HumanEval.jsonl.gz"
# BFCL：常驻容器 bfcl-run 内，handler model_name 已补丁，HF_ENDPOINT=https://hf-mirror.com
#   bfcl generate --model DeepSeek-V3.2-Exp-FC --test-category <简单/Python/多轮等类别>
#   bfcl evaluate --model DeepSeek-V3.2-Exp-FC --test-category <同上>
#   结果默认写到容器内 site-packages/result/、score/（未指定 --result-dir）；务必及时 cp 到 /bench 持久化
```

产物索引：`wsl/humaneval/{samples*.jsonl,_results.jsonl}` 与 `wsl/humaneval_32k/`（两档官方逐题判定）、`wsl/bfcl/results_round3/ + score_round3/data_*.csv`（R3 全量官方判分）、`startup/*_results.json`（lite/MMAU 汇总）。
