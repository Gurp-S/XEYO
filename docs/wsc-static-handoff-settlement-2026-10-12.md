# 批次104：交接取消及故障的事实结算（仅静态）

结构性根因：交接事务追加并持久化TodoWrite调用后直接await工具，异常分支没有终态结果。手动持久化回调还检查abort，可能把已经返回的成功结果挡在磁盘之外。取消后禁止新执行与保存已发生的事实是不同的边界，不能共用一个abort拒绝条件。

规则：取消停止后续模型/工具和折叠，但不抹去已有完整执行回执；保存结果仍必须持有原会话租约。调用未成功发布时不能进入工具；调用开始记录或生成输入都不是完成证据。没有完整结果就报告未知，不重放工具、不把未知升级为当前任务完成。

修正：manual_compaction.persist只核对执行所有权，执行/来源/压缩边界继续核对取消。共享交接准备与事务传入独立publish_guard和显式session_id，不从工具私有字段猜会话。成功回执统一经过租约检查、追加和持久化，取消检查随后阻断压缩。

工具异常时复用原execution_receipt.lookup：只有本次工具尝试期间新产生、名称/调用身份相符、returned且正文完整并通过已有正文摘要核对的回执可以恢复。执行前采集原回执作对照，不能用历史同ID记录证明本次成功。恢复的完整成功结果保留原执行元数据和已验证交接展示证据。缺失/截断/未知记录追加TOOL_OUTCOME_UNKNOWN，error且complete=False；不假报工具未执行。

调用持久化失败时不执行工具，追加TOOL_NOT_STARTED及complete=False，保留原异常；若后续存盘也失败，错误继续传播而不折叠，内存事实仍供既有同步重试确认。任何结算都不吞原工具异常，不返回成功，不修改冻结头，也不重放TodoWrite。失去所有权时不追加结果或保存，原执行回执仍由既有恢复机制处理。

静态核对事务成功/异常/取消/初次持久化失败/结果持久化失败，以及原执行回执记录、tool_result_message和Todo恢复的成功条件。未运行代码、编译、产品入口、API或真实会话重建；测试0、编译0、API0、费用0。修改4个代码文件：manual_compaction、wsc_handoff_prepare、wsc_handoff_transaction、query_loop。没有部署或实际操作保存会话。

应覆盖的回归（按当前用户要求未编写或运行）：工具返回后取消仍持久化真实ack但不fold；抛异常且无完整结果记录未知；post-hook失败且新完整回执存在保留真实结果；旧同ID回执不推广；调用持久化失败不执行；结算存盘失败下次重试恢复；租约失去后不结算到新所有者。现有底层回执日志是有界且可关闭的辅助证据，不是完整原文存储替身；不存在或正文过大时保持未知。

此批修正故障结算实现，不代表长任务语义、厂商容量、全媒体迟到结果、实际召回收益及线上迁移通过。四块最终验收仍开放。
