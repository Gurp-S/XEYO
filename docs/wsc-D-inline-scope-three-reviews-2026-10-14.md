# D 同项 scope：实施前三轮复审

## 边界与事故三问

结构性根因：当前专用生成请求要求模型独立维护 quote 数组和按位置对应的 scope 数组；模型可以生成长度不同或顺序不同的两个数组。Guard 正确拒绝，但协议允许无必要的双重表示错误。250 的同项原型已记录六份往返无损输出，整体接受及任务成功未提高，不能据此宣布语义问题已修。

结构规则：生成接口每个事实携带自身 scope；编译到既有持久格式后仍走原 Guard。编译器没有 scope 默认值、不猜 applicability、不注册 phase、不改变 retirement/provenance。旧持久格式不迁移，历史冻结头不修改。

回归：重排事实时 scope 一起移动；来源、quote、scope、disposition 完整往返；错 phase/引用/遗漏/双权威仍拒绝；被拒绝的原始模型参数及思考在下一请求原样保留；完整请求包括新 schema 后先计数；旧声明/空终态兼容。单独统计结构合同、机械接受与真实任务行为。

## 第一轮：职责与表示

v1：把现有 checkpoint 持久格式直接改成 scoped facts，并顺便加入 epistemic/version。

否决：会同时改变持久状态、恢复、投影、生命周期和机械校验，无法隔离增量，也没有迁移收益证据。

v2：只修改专用生成 wire schema，复用唯一 TodoWrite 提交格式。新增小编译模块，没有第二份状态、配置或持久化。

## 第二轮：失败、兼容与原响应

否决 v2 中先改 ToolUse.input 再重放的路径：被拒绝的模型原参数会被改写，破坏已修复的 provider frame 保真和输入计数。

v3：保留 wire ToolUse/frame；仅局部转换供 Guard/返回候选使用。错误反馈重放 wire 原参数；成功候选才返回旧 native 格式。整体 legacy 声明沿用既有 Guard；混用两种 scope 权威、缺一项 scope、有 scope 无 phase 拒绝，不猜填。未启用 phase schema 的旧调用完全不改表示。

## 第三轮：收益、公平性与复杂度

否决只拿 250 无数组错配就宣布任务增益，也否决把非法旧数组自动补齐作为 A/B 收益。

实施合同先验证实际 generate 与 native Guard、原始帧/容量/恢复。API 对照采用同一来源、预算、输出、任务工具，只切换 wire 编码，保留原失败；质量是否提升看实际产物/续接。旧 250 仅为历史证据，不拼接新成功率。若新行为无收益或退化，保持候选；若结构可靠且有验收收益，按用户最新授权直接默认接入。U2/U3完整状态协议、U4强制原 anchor、U6注册表及生产薄投影仍是独立 TODO，不因此关闭。

额外成本仅一个无状态编码模块、两个专用生成边界调用；零新 flag、零持久化迁移、零新增原文块。模型仍判断 scope；机械 Guard 不证明语义蕴含。每句新增描述只说明数据结构。
