# 批次53：交接生成的受限精确来源读取

## 根因与规则

交接生成此前只有 TodoWrite，主卡面虽然给出冷来源入口，却没有工具可执行读取。已经折叠且超过32K内联额度的规范无法进入该次生成工作集。只证明冷档可读，不能证明生成调用可访问它。

新独立 `memory/wsc_handoff_recall.py` 从本次不可变转录源快照按唯一message_id、字符offset/limit精确读取。文本返回原字符；结构化调用/结果返回原content JSON，并明确角色与分页范围。不能读任意文件、不能写任务、不能执行源中的调用。来源重复/不存在、布尔伪整数、负偏移、超量和额外字段拒绝。

`memory/wsc_handoff_generation.py` 专用工具增加 HandoffSource：模型自选是否读取及范围，每轮只有一个调用，最多4次生成请求/3次读取；每页最多4096字符，累计读取结果48K字节。每次请求重新测完整输入加2048输出预留，越界停止；每次usage独立计量，后续请求和读取分别消耗主预算中的回合/工具额度。读取帧仅存在于隔离生成请求，不追加原会话或改冻头。最后必须生成同一原子TodoWrite声明，仍走原引用校验与真实提交事务。

主 `engine/query_loop.py` 已传入后续回合及读取准入回调；此前事务预留的工具额度用于最终TodoWrite。没有通用任务工具、新任意文件入口或独立任务执行能力。

## 模型可见工具描述原文

`Returns an exact character range from one source message in this handoff transcript. No filesystem or task actions.`

参数：message_id、offset、limit。返回：message_id、role、offset、total_characters、content、next_offset。这是专用交接工具，不加入主工具注册表，也不替换主memory/Read工具。

## 验证

10条新回归：5种非法参数、重复来源；实际WSC已折叠长规范的头不含末尾关键约束，受控模型先读头10字符获取总长、再精确读末尾约束、最后真实ToolRegistry/TodoWrite及同步转录提交，规范引用存在。原source字节及主历史保持，隔离读取不进主历史。3请求usage各一次，额外回合准入2次、读取准入2次。

预算耗尽、4请求上限、第一次读取后新增完整输入越容量三项反控都停止，无额外请求和漏计usage。模型响应受控，不能冒充真实API自动选对范围。规范已由实际project冷存，但工具取值来自主转录快照，不通过文件Read扫描，未声称所有转录blob恢复路径已验收。

联合交接/持久化故障/普通容量准入/任务多代/厂商输入/旧C2/转录契约 **151 passed**。原容量测试专用工具契约改为精确两工具名单，成功/失败/usage/落盘接受项保留。首次定向15通过/1测试路径类型错误修正为Path后通过，未放宽生产判定。

本轮API请求0、费用0；原 XEYO 会话与冻结前缀不改，未重启服务。

## 剩余与固定下一步

身份表及枚举目前仍涵盖全部源，长转录可能使专用请求超过容量，此时安全停止，不是成功续接。固定下一步构建分页身份目录/受限索引，避免把全部历史身份强塞专用请求；必须保留唯一源和精确引用校验，不改变普通模型自主压缩/80%通知/85%强压方向。

固定4请求/3页是预算边界，不保证读完整个任意长规范。模型读取范围、声明完整性/相关性、真实复杂任务与长冷材料尚须API和离线行为证据，T16仍不勾选。不得以151绿色或工具可用声称全部治本。
