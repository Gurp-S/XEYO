## ① 结论："记忆系统可以落地、已完善、没有坑" —— 需要校准为更诚实的表述

### 可以落地的部分（已用数据 + 测试佐证）

- 默认链路（`XEYO_L5=project` + C2 gate 关）无运行时额外模型调用、不触 simulator，冷启动安全。
- 三个已发现的坑全部堵上且可验证：
  1. **v61 双 C2**：数据证实新会话 `sess_mtirqv0a_wagucr` 零 C2 事件（`c2_events.jsonl` 无增量）、`calibration.action=project`、`compact_cursor=0`。
  2. **收尾摘 tools 断链**：方案 A 落地后第 20 枪命中 90.8%（此前同类场景 6%），无 0%/1792 全断。
  3. **面板语义**：消耗 Token 改为会话累计（单调），不再因摘 tools / C2 而"倒退"；新增 `lastCacheHitTokens/lastCacheMissTokens/lastCompletionTokens` 单轮拆分，回退条只画最近一枪。
- 投影契约完好：transcript 零 T_now 泄漏（copy-on-write 生效）；无意外分叉（`predicted_hit ≥ observed_hit` 差值恒为 0，observed 全在 DeepSeek 256 块边界）。

### "没有坑"这半句不能说

- **84% 命中率是工具密集长任务的稳态下限**（每枪新增 = 上一轮输出 + 新工具结果 + T_now ≈ 4.1K tokens），是物理特性，不是缺陷。
- 其余机制**都还没开、也没经验收**：
  - 老化恢复未落地（`XEYO_TOOL_AGING` 按 T27 保留关闭）；
  - v61 未过证据门（A1 200+ 轮 live + A3 日监控写回 docs/12 表 D）；
  - C2 gate 是实验通道；
  - NightShift 是**触发式**（`query_engine.py:929 maybe_schedule` turn 收尾时调度）而非常驻；
  - 晋升置信度半自动。
- **推荐口径**："记忆系统默认策略可落地；扩展机制逐个 evidence-gated 开启，开一个验一个（`run-pytest-p0b.bat` + 真实日志对账）。"

### 数据佐证一览（本次测试会话 `sess_mtirqv0a_wagucr`，20 枪，22:35–22:40）

| 项 | 值 |
|---|---|
| 会话累计 | prompt 560,395 / hit 471,808 / miss 81,756 |
| 命中率 | 84.2%（本地模型 `predicted_hit` 与厂商 `observed_hit` 逐枪吻合） |
| 理论下限估算 | ≈ 87–89%（按"每枪新增"估算；差额为估算口径误差，非白付 miss） |
| 成本拆解（off-peak flash：hit 0.05 / miss 1.5 / out 4.5 元每M） | 输出 32.7K ≈ ¥0.147（50%）；miss 81.8K ≈ ¥0.123（42%）；hit 471.8K ≈ ¥0.024（8%） |

> 结论：核心的"可避免断链"已清零；剩余成本大头是输出（思考 2–3.5K/枪）与结构性新增，不是记忆缓存缺陷。

## ② 哪些机制没开、什么情况开

| 机制 | 现状 | 开启条件 |
|---|---|---|
| `XEYO_TOOL_AGING`（工具结果老化） | 关（T27） | 等 toolout 恢复机制落地；且仅当窗口紧张、工具结果占满上下文时 |
| `XEYO_C2_GATE=1` | 关 | 仅"会话逼近模型窗口"时：当前 1M 窗口模型 46K prompt 永不触发 → 不用开；换 128K 窗口模型且长会话 >100K 再开 |
| `XEYO_C2_LLM_SUMMARY`（LLM 摘要旁路） | 关 | 想要质量优先摘要、且接受每会话多一次模型调用（重放前缀打 warm cache，只增输出成本）时 |
| `XEYO_C2_CITATION` | 默认开 | 保留（行级引用锚点，可追溯） |
| 输出精简 `/output lite` | 关 | 建议开 lite——上一测试 50% 成本是输出（thinking），唯一直接打成本的记忆侧开关，走 T_now 不影响缓存 |
| `reasoning_effort=low` | 未设 | 模型配置，与记忆无关但收益最大（输出减半） |
| `XEYO_L5=v61` | 已关（用户级注册表变量已删） | 仅供测试/AB/对账（`memory_stack_eval`、`formula_live_ab`） |
| NightShift（触发式） | 已接引擎 | 保持；若做"常驻收敛"再扩 |

## ③ 计划新增的五项——逐项评估

| 新机制 | 有无基础 | 收益 | 破坏风险 / 落地注意 |
|---|---|---|---|
| **git 基线 diff 佐证晋升** | 有证据体系：`governance.py` 的 `evidence[]` + `promotion_confidence()` 分档（user=1.0 / verified_fact / agent 收割封顶 ≤0.6） | 高——把"有代码/事实依据"变成置信度加成，防幻觉记忆 | 低。落点 = evidence 词表加新类型（如 `git_diff`）+ 分档权重；必须同步 `test_evidence_integrity` 白名单；**只作加成不作充分条件**（diff 大 ≠ 内容对） |
| **rollout 分档摘要** | 已内建：`C2_QUOTA_*` 分档（error 400/取值 320/grep 220/user 200/默认 120）+ 追加式扩展 + 引用锚点 | 中（若指"按会话阶段分档"则需全新参数层） | 中。红线：**append-only，绝不重写旧摘要**（`try_extend_c2` 已强制）；先盘点现有分档再决定要不要加阶段维 |
| **保留期剪枝 + 限流门控** | 空白确凿（无 TTL/retention 扫描） | 高——控体积/噪声/重复 | **中高，最需小心**：剪枝会改 `topics/*.md` 行号 → 现有 citation 锚点直接失效（`note_file_citation` 按行区间定位）。必须"整条剪切而非行内截断"或同步重算引用；豁免 `user/confidence=1.0` 条目；与 tombstones/去重 `last_seen` 协同 |
| **citation 溯源** | **已实现且三层齐全**（note `source{kind,session_id,message_id}` → 检索块 `<citation_entries>`+`<rollout_ids>` → C2 行级 `⟦notes:msg:…⟧`） | 边际低 | –（先盘点现有实现再投入，只补表达层如正文内可点击跳转） |
| **后台常驻收敛 job** | 已有触发式：settle 后 `enqueue_main_session_candidates` + `maybe_schedule`（`query_engine.py:918-932`），子代理收割也已接 | 中（常驻=更及时） | 低：用 `server/job_registry`（T42）做周期任务；遵守 `.nightshift.lock` 并发锁与幂等；不动 KV、不进左段 |

**总体**：五项都在"记忆侧"扩展，不碰工具面冻结/MCP 红线/system 左段，对既有结构零回归风险低；验收走 `run-pytest-p0b.bat` + 契约测试（governance / evidence-integrity / nightshift 现有套件）。

## 附：与 DSH 的缓存命中口径对齐（本次一并落地）

- DSH（`dsh-client-ui-conversation/lib/client.js` `cacheHitPercent`）：`cacheReadTokens / (uncachedInputTokens + cacheReadTokens + cacheWriteTokens)`；会话级累计；**写档计入未命中**；100% 做高精度校验。
- XEYO（修复后）：`cacheHitTokens / (cacheHitTokens + cacheMissTokens)`；会话累计；DeepSeek 无独立 write 档 → `miss` 已含写入部分，与 DSH 口径等价。
- 差异仅展示层：XEYO 显示一位小数（撞 100% 时给高精度 99.9x，不谎报 100；全命中 100；无输入 null），与 DSH 语义一致、更克制。
