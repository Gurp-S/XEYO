## 1. 背景与动机

P3 终局 **61/89 = 68.5%**（Terminus 修正口径 64.8%，净提升 +3.7pp）。24 题失败逐题归因后收敛为三类**通用 agent 缺陷**（非题目特异）：

| 缺陷 | 证据（逐题轨迹） |
|---|---|
| M1 时间预算失效 | raman-fitting 专家估时 5min，agent 烧满 15min 仍在"分析数据"，交付物从未落盘；80%/90% 预算 notice 送达但被无视 |
| M2 自称完成≠完成 | query-optimize 未实测 runtime 就宣称"优化完成"；overfull-hbox 自称零警告判 0 |
| M3 空转循环 | write-compressor 12.8k in/92k out；regex-chess 4.9k in/77k out |

用户红线：**禁止"做题"式应试解法，必须是真正的 agent 能力优化**。

## 2. 改动设计（AGENTS.md 第 4 条旁路形态 + 第 7 条反巨石）

四项优化锚定**todo 列表 = 单一事实源**（认知层写、控制层读，判分器不可见，对所有任务生效）：

## 3. 事故与修复（实验副产物）

### 4.5 机制判定

- **纪律类（契约+nudge+停滞监测）✅ 有效**：翻绿与交付修复全部集中在原"超时零交付"型
- **效率证据标准 ⚠️ 单样本**：行为改善（5/6 稳定）未转化为翻绿
- **精度规则 5/6 ❌ 阴性**：mteb 系统性陷阱未破、pytorch 疑似反噬——提示词级验证规则对该模型到天花板
- **advice 声道**：本地重放验证送达畅通（定性为注意力稀释+计划惯性，非送达失败）

## 5. 分数外推

- **已实证：63/89 = 70.8%**（+2 翻绿）
- 全量重测期望 **63-67/89（70.8-75.3%）**：24 题失败中纪律型约 10-12 题（现实翻绿池），精度/知识型（约 12 题）需能力级手段（更强模型或结构化强制），软规则无效
- 75% = 67/89：在区间上沿，需精度类另有突破

## 6. 结论与建议

1. **纪律类机制成立**：todo 契约 + nudge + 停滞监测以旁路形态验证了收益，可按 AGENTS.md 第 4 条流程讨论并入主链路（需 GUI 侧灰度数据）
2. **精度类是下一个真问题**：提示词规则阴性 → 需结构化手段（如验收项与判分协议的强制映射）或模型层升级；mteb 语料陷阱值得一次根因定位
3. **评测基建**：harbor 并发路由已修复并实战验证；postpone3 建议标注污染嫌疑后择机复测
