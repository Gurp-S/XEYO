# 340：冷定位与交接呈现边界

用户在停议后授权按讨论结果继续。沿用既有 Goal 和质量底线，不重置低收益记录；本轮不扩展状态协议、不改生成提示词、不新增召回工具。

## 三轮复审与修订

1. 职责：目录负责给出可执行的原文地址，不能要求模型把另一行的 views 路径与命中 offset 拼接。每条命中增加已有来源的 file_path，与 offset/limit 组成原生 Read 参数。语义交接正文与引擎附加呈现由发布者划界；不让模型负责辨别和删除目录。
2. 失败与多代：既有密封文件不修改；同身份不同内容仍分别可读。正文边界随已有发布清单/生命周期哈希及原子工作快照一起提交。只有已验证、当前游标对应的提交头可用于生成输入替换；未知旧头或验证失败完整保留，不用正则裁剪。当前控制事实继续由原入口提供，尾部和媒体来源不变。生成失败、提交前/后中断、重启都检查旧/新整代一致性。
3. 收益与复杂度：不新建持久状态系统。正文已在头的开头，保存其字符边界即可，无须重复保存全文或另建文件；只在下一代生成请求里取出该范围，普通消费者冻结头不变。定位和呈现拆开验收；先失败合同再生产修复，之后原同源查询小规模 API。定位改善不能冒充历史/当前语义混用已解决。

## 本轮不变量、A/B 与停止条件

- 原生 Read 从单条命中读回完整来源；大记录分块、不同版本、重复执行身份、原始角色和回执保持准确。
- 同一语义产物与尾部：旧生成输入含 Runtime 目录，新生成输入只含已知正文；控制事实仍可见。模型自己写入的路径/目录引文不删除。
- 连续多代与重启，固定响应复制上代正文时，Runtime 目录不会递归进入生成正文。未知旧版混合头继续兼容，因此不能保证自动清除旧污染。
- 未发布候选不能替换已提交正文，源变化/取消拒绝仍有效；冻结头和旧证据字节不改。
- API 采用同源、同产物查询，记录定位/读取/使用各段和无压缩对照；保留全部失败，不修改旧成绩、不按失败追加重试。
- 仅将有机械收益且合同不退化的修复接入已有自然语言路径。默认开启、现场加载和整体语义验收另列。
- 本轮结果仍不稳定时先报告原因和剩余证据，不自动追加另一套提示或状态字段补丁；既有三次低收益停议规则持续有效。
