## 3. C 套：载体缺点（使用体验，硬事实）

| 编号 | 事实 |
| --- | --- |
| **C-1** | `Read(file_path=…, offset=…)` 把"路径 + 行号"当身份，视图重建后行号会静默指错内容；同一会话路径盘上有两份，`g-e3b0c44298fc1c14` 是**空串的 SHA-256** 却配 727 KB |
| **C-2** | 用 Bash 创建的文件，`Edit` 报 `write conflict (missing_read)`（不认 Bash 产物为基线，必须再 Read 一次才能改） |
| **C-3** | `bash_secret_read`：**同形态**命令三次里 1 次被拒（含会话路径的 here-string），报错不指出命中的 token ⇒ 判据不可推断 |
| **C-4** | `bash_write_target_unproven`：删**自己刚创建**的临时文件被拒一次（去掉同命令里的 `git status` 后成功）⇒ 与 C-3 同族：限制在执行层存在，但判据无法从报错推断 |
| **C-5** | 工具结果的**去向不可预期**：`Write` 落进 `docs/` 成功、落进 `.xeyo/tmp` 被拒；两条通道（Write / Bash）**都**会拒，但拒绝规则不同名（`protected_metadata` / `bash_*`） |
| **C-6** | `job_output` 长时间无输出，**分不清"在跑"还是"卡住"**：全量回归 528s 期间无法判断状态（缺少"最后活动时间/进度"这类事实） |
| **C-7** | `Edit` 失败只说 `String to replace not found`，**不给差在哪**：本会话连栽 3 次（tab vs 4 空格、换行方向写反、漏改调用点），含我自己刚写的文件（差一个"的"字） |

本表记录历史现象；批次 20 当前结算：C-1 不可变引用；C-2 精确内容验证后 CAS（竞争仍拒）；C-3 原文 #1812 的 Python `p.key` 属性误判经 AST 旁路纠正，并提供拒绝规则/类别/区间事实（真实凭据路径仍拒）；C-4 所有字面写目标证明；C-5 同源 scratch 权限；C-6 最后输出时间/输出量事实（不声称可判断真实进展）；C-7 有界候选差异。均已实现，默认旁路关。
