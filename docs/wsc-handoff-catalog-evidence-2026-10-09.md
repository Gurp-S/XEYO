# 批次55：交接来源目录分页验收

结构性根因：压缩前交接把全部来源身份及引用枚举再次放入请求，目录开销随历史增长；即使正文已收纳，交接请求仍可能超容量而无法建立可核验状态。规则：目录只首发有界身份集合，完整来源空间保留在只读分页目录中；引用验收仍针对完整原来源，不能以首发名单截断事实或恢复全部用户原话。

`memory/wsc_handoff_catalog.py` 首发最多32条、记录合计16KB；当前已提交状态及其绑定来源、最近用户身份和尾部身份参与首发。`HandoffCatalog` 按原始来源索引分页，每页最多16条、记录合计24KB；支持角色和原文字面查询，返回身份、角色、字符数、调用及回执身份。`HandoffSource`随后读取精确字符范围。目录和读取只发生在专用交接调用中，不增加主会话历史或改写冻结头。大历史的工具schema不再内联所有ID枚举，声明合法性仍由完整原来源校验。

目录工具描述原文：

> Returns source identities, roles, character counts and invocation identities from this handoff transcript. Optional literal text query and role filter. No task actions.

现有生成过程每次最多4请求、检索累计48KB、每次请求重新检查容量及2048输出预留。分页没有取消这些限制；复杂交接需要更多检索时会停止，不宣称有限检索可保证任意长任务完整续接。特别大的单条目录记录仍显式失败，不能当成信息为空。

新增 `tests/wsc/test_handoff_catalog.py`：5000条目录首发有界且保留旧用户身份；筛选后的游标准确并能从499定位4990；非法类型/越界/文件路径参数中性拒绝；500条受控生成实际经历目录查询→精确正文读取→TodoWrite精确引用，目录首发没有目标身份且schema没有全量枚举。检索、生成、容量边界联合 **26 passed**。修复role=[]时TypeError绕过规范验证的问题。
