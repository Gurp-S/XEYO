# 完整声明 schema 与执行协议一致：三轮复审

## 事故三问

296素材split臂第4个真实调用返回merge=true。专用generate只接受完整状态，Guard以handoff_full_state_required拒绝；但来源专用schema继承通用TodoWrite的merge:boolean，明确允许这个值。结构根因是可声明输入集大于专用执行器的协议，不是merge的语义问题。第1次截断和第3次其他非法声明都保留，不能把第4次当首请求。

规则：专用声明schema仅允许merge=false或省略，通用TodoWrite保持原merge能力。模型忽略schema时执行层仍拒绝；中性字段错误可在原有6次上限/容量/预算中续接，不执行非法声明，不静默改成false，不重试HTTP。

回归：通用schema仍允许true，专用schema不允许；false/省略合法、true/0/null/字符串非法；错误回放包含原merge=true及原思考，后续有效输出重新走全部Guard；持续非法/预算/取消/断流必须有界且不提交。保留来源/转录/冻结前缀。

## 第一轮：职责与最小边界

否决在to_native里把true改false：这是篡改模型参数，并会使整表替换与增量意图混淆。

v1：只收紧专用source_schema的merge字段，原native Guard原样保持拒绝。通用工具不改，不增加提示文字。

## 第二轮：失败闭环

否决只改schema后仍让同类机械错误直接终止生成：schema不是强制采样器，模型仍可能生成非法值，应该复用现有拒绝帧/有界续接。

v2：Guard给出字段、实际值及允许值等事实；沿用既有机械错误续接分支，原始参数不改，最多原6次请求、无HTTP重试。缺checkpoint同样报告字段缺失，不默认补空对象或新目标。

## 第三轮：证据、公平性与复杂度

否决把旧失败候选直接改为false再宣称模型修复；也否决对新schema使用旧响应却假装实际请求完全相同。

v3：schema合同单独验证，生成恢复用296原付费前部逐份body完全匹配后免费回放，保留旧schema作为隔离条件，只在新增错误反馈后发新请求；由此只证明恢复机制。新schema/控制分载体是否改善实际任务须另列，不拼接294/296或A1成绩。未通过的split仍不默认启用。

抽离本次实际触碰的source_schema函数到唯一schema模块，generator保留原导入名以兼容调用者。除merge专用限制外其他schema不变；唯一职责仍是来源/声明协议专用化，0新flag/持久状态/迁移。每次已付费请求、未知费用、失败及源码快照均保留。
