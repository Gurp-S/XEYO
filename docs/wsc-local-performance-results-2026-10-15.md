# WSC 331：单次操作内复用来源指纹

本轮只减少重复序列化和哈希，不改变模型语义、提示词、压缩触发、保存格式或冻结前缀。API 调用 0 次。已验证的候选直接接入原入口，不新增开关、缓存或抽象层。

## 三轮复审（实施前）

1. **定位重复工作与正确性边界。** `wsc_head_store.save` 开启发布契约时，为同一冻结区域分别计算 manifest 和记录字段的 seal；自然语言 `prepare` 成功时，为已捕获来源分别计算比较指纹和返回指纹。两者都重复执行完整 JSON 序列化与哈希。规则是只复用单次操作内同一份未修改输入的确定性结果。
2. **检查生命周期与失效。** 不跨请求缓存，不复用之前生成的 seal，不删除深拷贝。生成后最新来源、原始封套、Goal、取消状态仍重新校验；发布和恢复的独立校验全部保留。`save` 仍沿用调用者串行化会话修改的契约，本轮不声称新增跨进程并发安全。
3. **收益与回归准入。** 先在独立副本上运行旧实现/候选，以相同真实来源比较保存字节和完整候选。交替顺序运行，避免固定顺序偏差；收益成立后再接入。用现有生产入口测试覆盖改史、迟到、中断、冷证据和重启，不为这次局部简化新建复杂缓存或专用执行框架。

## 实现

- `python/memory/wsc_head_store.py`：本次 `save` 的 source seal 算一次，供 manifest 和记录共同使用。开启发布契约时从两次降到一次；未开启契约时仍一次。恢复读取依旧重新验证来源和证据。
- `python/memory/wsc_semantic_compaction.py`：生成后的当前来源与捕获快照仍分别计算指纹；通过比较后，将捕获指纹直接带入候选，避免第三次来源序列化。原始封套验证不变。

没有新增生产模块或新行为。头存储优化是共享生产路径；自然交接优化在其真实入口生效，但自然语言方法整体默认关闭的准入状态没有改变。
