## 0. 一页速览（30 秒版）

- **WSC = 一次上下文压缩的「执行投影」。** 它决定：当引擎决定要压时，**实际发给模型的那一枪长什么样**。
  【源码】`python/memory/wsc_projection.py:3` —— "C2 remains the trigger; WSC becomes the execution projection"。
- **它同时省两样东西**：① 模型眼前的 token（注意力）；② 前缀缓存被改写后退化成「未命中」而重算的那笔钱（重填钱）。
- **它不调用任何模型做摘要**：零 LLM、确定性（同输入同输出）、可逆（被剪的原文留在冷层，句柄可拉回）。
  【源码】`python/synaptic/project.py:4` —— "全流程零 LLM 调用、零随机性、零生产链依赖"。
- **折叠有经济闸**：`净省 ≥ θ × 重发面`，现行 `θ = 1.0`（= 30 ÷ 1 ÷ 30）。物理含义：**这一枪就不亏，不需要预测会话还剩多长**。
  【源码】`python/memory/runtime.py:1292`、`python/synaptic/cadence.py`。
- **一个真实体感（【本轮实测】离线、零 API）**：某 827 条消息的会话，原样发送 `262,803` token → WSC 热层 `6,597` token（压缩 **97.5%**），保留 184 个节点、剪掉 356 个、41 张剪枝卡、4 个钉住项。
- **它最锋利的一条承诺**：任何被剪掉/骨架化的节点，热层里必须留一个能把它**原样取回**的句柄；取不到就**不许静默降级**。
  【源码】`python/synaptic/coldstore.py:1-3`、`python/synaptic/project.py:266-330`。
- **它有两条轴，别混读**：①**压缩轴**（§3–§8.8）：什么时候折、折完发什么、多少钱；②**交接轴**（§6.9/§7.6/§8.9，2026-10-08→10-11，批次19–85）：折完之后**任务状态怎么交接、事实怎么不静默消失、迟到结果/超容量怎么不丢源、请求怎么准入**。轴① 的证据是成本/缓存数字；轴② 的证据是真实 API 小样本 + 离线反控，两套**不能混着读**。
- **它最吵的一条已知断链**：视图文件丢失时会回落成 `expand(...)` 引用，而 **`expand` 在生产里没有解析器**（取回面已统一到 `Read`）⇒ 那条兜底给出的引用模型执行不了。见 §10 的 D1。

## 1. WSC 是什么：定位与两种压力

两条独立的压力，WSC 同时针对：

1. **注意力**：长会话里"什么该留在模型眼前"。原始 transcript 动辄几十万 token，全塞进去既贵又稀释注意力。
2. **钱**：在 DeepSeek 这类**按缓存命中计价**的厂商上，成本的主要变量不是"发了多少 token"，而是**"有多少 token 从命中退化成未命中"**。

⇒ 直接推论，也是整套设计的分水岭：

> **"压得狠"和"压得省"是两件可能相反的事。** 一次压缩省下 3 万 token 的历史，却可能触发 5 万 token 的重填。

**WSC 在系统里的位置（调用链）**【源码】

```
用户/工具结果 → 消息存储
   ↓ 每一枪都构造一次投影
engine/query_loop.py      remaining_turns = 本轮预算剩余轮数（max_turns − turn_count，被 r_cap=96 封顶）
   ↓
memory/runtime.py::project_for_model
   ├─ decide()（离线 simulator 的调度器：keep / C1 / C2 + hardtop 判定）
   ├─ 要压时 → note_c2()（首压）或 try_extend_c2()（已压态：把游标往前推）  ← ★折叠经济门在这里
   └─ apply_c2_messages()
          ↓ XEYO_WSC=1 时优先走 WSC
memory/wsc_projection.py::project_c2_messages
   ├─ 决定"右段要不要折进头"（默认：跟随游标事件）
   ├─ synaptic/project.py::project(...)   ← 真正的组装（建图→闭包→剪枝→分段→预算）
   └─ 发射：[热层消息] + project_c0c1(尾部原始消息)
          ↓
model/_openai_common.py：最后一公里（把 tool 行转成厂商形状 + 丢弃无主 tool 结果）
```

## 2. 术语表（后文所有黑话）

| 术语 | 解释 |
|---|---|
| **上下文窗口 / window** | 模型一次能接收的最大 token 数。值来自**用户登记的模型登记表** `context_limit`，不是代码常数。【源码】`runtime.py:1541-1559` |
| **前缀缓存 / KV cache** | 厂商按"这次请求开头与上次相同多少 token"给折扣。命中部分按命中价，从**第一个不同之处**起全部按未命中价重算 |
| **命中价 / 未命中价** | DeepSeek flash 空闲档：命中 ¥0.05/百万、未命中 ¥1.5/百万、输出 ¥4.5/百万 ⇒ **未命中 = 命中的 30 倍**；高峰档（工作日 9–12、14–18）价格翻倍，倍率不变。【源码】`usage/pricing.py:27` |
| **重发面 / transition** | 一次改写让多少 token 从"命中"退回"未命中"。压缩把历史换掉 ⇒ 头之后的内容**整段**重算 |
| **折叠 / fold** | 把上下文头部的若干轮原始消息"折进"热层摘要；折叠后原文不再逐字发送 |
| **热层 / hot 层** | 折叠产物：一份结构化文本，作为一条 `assistant` 消息（`name=session_summary`）放在发射序列最前面 |
| **冷层 / cold 层** | 被折掉的原文不删除，留在一份**取回视图文件**里；热层用"句柄"指向它 |
| **句柄 / handle** | 热层里的一行引用，模型照着它能取回原文。五种：`node://12`、`branch://B1`、`reqs://5-120`、`head://<sha>`、以及生产形态 `Read(file_path='…', offset=…, limit=…)`。【源码】`synaptic/coldstore.py:16-37,49-60`、`synaptic/handles.py:13-31` |
| **节点 / node** | 证据 DAG 的原子单位 = **一条消息**。【源码】`synaptic/types.py:51` |
| **卡片 / card** | 一条"被剪掉的分支"的结论化索引：结论 + 涉及文件 + 错误签名 + 复现命令 + 节点列表 + 句柄。上限 24 张；超出**只合并无错误签名的卡**（带错误的卡永不丢弃，防重复犯错）。【源码】`synaptic/types.py:118-131,182`、`synaptic/prune.py:230` |
| **证据 DAG** | 节点图，四类边：`seq`（时序）/`use`（调用）/`file`（文件）/`err`（错误）。默认只用语法边（`soft_dag=False`）。【源码】`synaptic/types.py:21-24,172-174` |
| **闭包 / closure** | 生产组装模式：从"钉住集"（PIN/工作集/目标）出发，取**反向 2 跳可达**的节点进热层——这就是"哪些历史值得留在注意力里"的判据。【源码】`synaptic/closure.py:100,278-289` |
| **游标 / compact_cursor** | "已经折进热层的前多少条消息"。它是 C2 与 WSC 之间**唯一的接口** |
| **发射 / 请求** | ⚠️ 两个不同分母：一次请求前引擎会构造若干次投影（增量缓存路径 + 全量路径），**发射 ≠ 厂商请求**。实测 attempt2 重放 99 次发射 vs 账单 59 次请求，差 1.7 倍 |
| **水位 / watermark** | 主动压缩阈值 = `0.80 × context_limit`（可被 `XEYO_CONTEXT_COMPACT_RATIO` 覆盖，限 0.5–0.99）。【源码】`runtime.py:1942-1958` |
| **硬触发 / HardTop** | 逼近/越过窗口硬顶时的**强制**折叠，绕过一切经济判据。硬顶 = `window − reserve_tokens(2048)`。【源码】`simulator/params.py:48,91-92`、`runtime.py:1145,1739,2165` |
| **保尾 / keep tail** | 永远逐字保留的最近上下文：按**最近 K=3 个成对工具轮**，不看 token。【源码】`engine/compact.py:115-134` |
| **成对安全 / pair-safe** | 切点不得落在"一次工具调用"与"它的结果"之间，否则发出非法形状。【源码】`memory/runtime.py:334-347` |
| **日志档 / journal layout** | 默认布局：发射物是 `(段头, 行)` 按**首次发射顺序**排列，只追加、不重排、不改写。【源码】`synaptic/assemble.py:285-286,506-513` |

## 3. 核心机制：一条七步流水线（零 LLM）

【源码】`python/synaptic/project.py:1-5` 的模块头就是全部：

> 一次压缩 = **建图 → 文件状态 → 种子 → 反向闭包 → 加权背包 → 剪枝卡 → 组装**。
> 全流程**零 LLM 调用、零随机性、零生产链依赖**。

### 3.1 建图（证据 DAG）

- 输入是**消息列表**（不是"对话文本"）；每个节点 = 一条消息。【源码】`synaptic/graph.py`
- 四类边：`seq` 时序、`use` 调用（工具调用↔结果）、`file` 文件（同路径的读写）、`err` 错误（同错误签名的复发）。
- 默认 `soft_dag=False`：**只用语法上能确定的边**，不做语义推断。
- 产出 `graph_digest`（图指纹），用于确定性与复用判定。

### 3.2 文件状态（WORKING SET 的原料）

- 扫出会话里涉及的文件，为每个文件算：**内容 hash、最后修改发生在哪个节点、与上一版相比的 diff 摘要、被读过哪些行区间**。【源码】`synaptic/filestate.py`
- 这解释了热层里 `WORKING SET` 行长这样（真实样本，见 §9）：
  `[WORKING SET] …/file_edit_tool.py | hash=29d437e18c1c1204 | STALE (改于 #354) | diff: -if not base_hash: … | read: 170-239`
- `STALE` = 时效轴（去噪）打上的标记：**该文件已被后续编辑**，热层里记住的"当时内容"已过期。

### 3.3 种子（哪些节点天生必须留）

- 来源：钉住项（PIN）、当前工作集、目标/约束、区域内用户原话、错误节点。【源码】`synaptic/seeds.py`
- 【本轮实测】例子里 seeds = `pin_nodes=184 constraints=0 unresolved=46 todos=2`。

### 3.4 反向闭包（"值得留在注意力里"的判据）

- 从种子出发，取**反向 N 跳可达**的节点进热层；`hops` 由档位决定：Micro/Light/Hard = 1，Medium/Medium+ = 2。【源码】`synaptic/closure.py:100,278-289`；`py -3.11 -m synaptic levels` 输出如下。

| 档位 | 热层预算(tok) | 闭包跳数 | 卡上限 |
|---|---:|---:|---:|
| Micro | 8,000 | 1 | 8 |
| Light | 5,500 | 1 | 14 |
| Medium | 4,000 | 2 | 20 |
| **Medium+（生产）** | **3,000** | **2** | **24** |
| Hard | 1,800 | 1 | 32 |

### 3.5 加权背包（预算裁剪）

- 拿闭包候选 + 权重（新鲜度/是否错误/是否钉住/文件时效）做**加权背包**，在预算内选最大价值子集。
- 落选者带理由（例："预算不足落选"），审计表可打印。【源码】`synaptic/budget.py`、`synaptic/project.py:219-222`

### 3.6 剪枝卡（被剪掉的分支不再消失）

- 每条被剪分支 → 一张卡：结论 + 涉及文件 + 错误签名 + 复现命令 + 节点列表 + **句柄**。
- 上限 24，超出只合并"无错误签名"的卡；**带错误签名的卡永不丢弃**（防重复踩同一个坑）。
- 真实样本（§9）：`[PRUNED] Read /lea/XenYon code/python/prompt/pre_llm_inject.py 完成 → …；另 3 条同类记录；… expand(branch://set-4db87…)`

### 3.7 组装（热层的最终形状）

- 段清单（顺序即模型看到的小标题）：

```
[CONSTRAINTS] [UNRESOLVED] [DECISIONS] [PRUNED] [WORKING SET] [PATHS]
[MAIN] [REHYDRATED] [TODO] [NEXT] [REQUESTS]          (+ [HEAD] 换头时)
```
【源码】`synaptic/assemble.py:44-57,64-76`

- **顺序由"前缀失稳率"决定，不是内容重要性**：`实际次序 = 按各段历史上多大概率会改动升序排`——"放在前面反而最省 KV"。带滞回（`churn_margin=0.15`、`churn_dwell=4`）防止每枪换装。【源码】`assemble.py:442-454`
- **默认日志档 = 只追加**：`journal_layout=True` 时发射物按**首次发射顺序**排列；"按键去重会退化成原地改写，而改写正是要消灭的东西"。【源码】`assemble.py:285-286,506-513`
- **三桶预算**（Medium+ 生产档）：

| 桶 | 管哪些段 | 额度 | 超了怎么办 |
|---|---|---:|---|
| fixed | CONSTRAINTS/UNRESOLVED/TODO/WORKING/PATHS/REQUESTS/NEXT | **1,800** | 只降级**可降级**段（去重→摘录阶梯逐级减半到 16 字符→仅留句柄→关段）；**受保护事实不静默省略** |
| main | MAIN + REHYDRATED（+卡面计入） | **1,200** | 回缩预算**重跑背包**，落选者理由=预算不足【源码】`project.py:219-222` |
| index | DECISIONS + PRUNED（=卡面，**与 main 重叠记账**） | **1,600** 观测线 | **只报账不删**："此处只分桶 + 报账，一个字节都不删"【源码】`budget.py:267,459` |

- 账目行原样模板（每次投影可打印）：
  `fixed X/Y tok, main A/B tok(含固定段让渡 N), index I tok（内 决策卡 D / 句柄面 H；观测线 1600，不裁剪）, total T tok, requests=<模式>@<摘录字符数>`【源码】`budget.py:302-316`
- 档位还带一个 `journal_growth_tokens`（Medium+ = 3×3,000 = 9,000），是"日志能长到多大"的地板参照。【源码】`synaptic/types.py:355-371`

### 3.8 三条设计红线（WSC 版的"三样都要"）

【源码】`synaptic/project.py:4`、`docs/wsc-design-review.md` §10 O8

- **零 LLM**：摘要是**结构性抽取**，不是模型改写。好处：确定、可回归、前缀稳定。代价：语义能力弱（见 §11 的取舍）。
- **确定性**：同输入同输出（`synaptic/metrics.py::determinism_digest`；`synaptic check` 会拿最大几个会话跑两遍比指纹）。
- **可逆**：冷层存原文，句柄解析回**逐字节一致**的原文——"这让『可恢复信息保留』不靠自述，而靠往返比对证明"。【源码】`coldstore.py:1-3`

## 6. 控制与调度机制（谁在什么时候折）

### 6.1 触发权的归属

- **C2（压缩调度器）是触发者，WSC 只是执行投影**。WSC 自己**不决定什么时候压**。
- WSC 唯一的输入是**游标**（"已折进热层的前多少条消息"），唯一的输出是**这一枪发什么**。
- WSC 内部还有一层"右段要不要折进头"的判断，默认**跟随游标事件**（不是自己另算节奏）。【源码】`wsc_projection.py:7-26`

### 6.2 三道闸 + 一个硬顶（扩展闸，生产实际触发点）

> ⚠️ **口径张力（2026-10-12 发现，待核，别二选一）**：`memory/wsc_timing.py` 的模块 docstring 原文写 —— **"没有任何年龄、经济、绝对 token 水位、归档历史体量能放行自动折叠；唯一自动通路是容量压力（≥ 声明容量的 85%）"**；而本节记的 θ 经济门在 `runtime.try_extend_c2`（推游标那一步）。两侧读数并不自动一致：
> ① 账本里 wsc 臂的 `worth_fold` 放行 **298** 次 ⇒ θ 门**确实在放行**某些折叠；
> ② `wsc_watermark.py` 已确认**绝对水位旋钮退场**（`soft_watermark_tokens()` 恒 0）。
> ⇒ 待核问题：**生产里"自动折叠"的最终放行者到底是容量压力、还是 θ 门、还是两者按段分工**（首压 / 扩展 / 硬顶三条路径各自归属）。核法：定向读 `runtime.py` 的 decide/`try_extend_c2`/`note_c2` 与 `fold_events` 的 `arm+reason` 组合。**在核清之前，本节与 D1 并列陈述。**

顺序【源码】`memory/runtime.py:1131-1236`：

1. **收益闸**：区域字符数 − 摘要增量 ≥ `c2_min_gain_chars(4000)`；
2. **稀发闸**：区域字符数 ≥ `c2_extend_ratio(0.25) × 已冻结区`（防"每次挪一点点"）；
3. **经济闸（θ=1）**：`saved_net = 区域token − 头token ≥ θ × (头token + 尾部token)`。

外加 **冷却**：`turns_since_c2 < min_middle_edit_gap(4)` 时 decide 不给 C2【源码】`runtime.py:1726,1999`；
外加 **硬顶**：`force=True` 绕过以上全部，保证超窗必压。

### 6.3 θ 的来历（一行公式 + 一次 12 倍漂移事故）

- 判据：**折 ⟺ 净省 ≥ θ × 重发面**，其中 `θ = 价格比 × 安全边际 ÷ 回本枪数 = 30 × 1 ÷ 30 = 1.0`。
  【源码】`synaptic/cadence.py:17-30,62-90,100-113`（`theta_required()` 是这个式子的**唯一实现**）
- θ=1 的物理含义：**这一枪就不亏，不需要知道会话还剩多长**。
- **删掉的旧写法（重要，因为它是旧收益数的来源）**：旧第 3/4 闸乘的是 `remaining_turns`（= 本轮**预算**剩余轮数，不是"前缀还会被重用几枪"），把 `price_ratio × margin=60` 除在这个数上 ⇒ **有效门槛 = 60/remaining**；生产被 `r_cap=96` 封顶 ⇒ 0.625 倍，评测脚本传 8 ⇒ 7.5 倍，**同一份代码在两档之间漂 12 倍**。现在扩展闸不再读它，`c2_extend_min_remaining_turns` 一并删除。【源码】`runtime.py:1288-1290`

### 6.4 水位与硬顶

- 主动水位 = `0.80 × context_limit`（`XEYO_CONTEXT_COMPACT_RATIO`，限 0.5–0.99）。【源码】`runtime.py:1942-1958,2223`
- 硬顶 = `window − reserve_tokens(2048)`；逼近即硬触发，**不受 θ 约束**。【源码】`simulator/params.py:48,91-92`、`runtime.py:2165`
- 一条历史事故：在服型号 `deepseek-v4.1-flash-expires-on-0910` 实测 prompt 到过 **693,894**（n=2,662），而窗口前缀表缺 `deepseek-v4.1-` ⇒ 落 128k 兜底，**68.9% 的枪跑在假水位下**。已修 + 有守卫。【账单】

### 6.5 保尾与切点安全

- **保尾按轮数（K=3 个成对工具轮），不看 token**。【源码】`engine/compact.py:115-134` ⇒ 一条巨型工具结果可以整段留在上下文里（已知缺陷 D2）。

### 6.9 第二条轴：交接与连续性（handoff，批次 19–85 / 2026-10-08 → 10-11）

压缩轴管"这一枪多小多省"；**交接轴管"压完之后，任务还能不能接着做对"**。两者是不同机制，**证据也不能混读**。

- **交接生成器**（`memory/wsc_handoff_generation.py`）：当一次折叠可能让任务状态丢失时，引擎允许**一次专用交接调用**（生成一份"当前状态声明"）。预算：**6 次模型请求 / 检索累计 48KB / 48KB 响应 / 2048 输出预留 / 逐请求费用准入（≤0.5 元；部分实验合计 ≤0.4 元）**；读取额度 **`MAX_READ_CALLS=64`**，**跨批累计、不按批重置**（第 65 个在读取前**中性拒绝**）。到边界就**停止且不提交不完整交接**——**不靠丢来源让强压继续**。
- **目录分页**（`wsc_handoff_catalog.py`，批次55）：交接请求不再枚举全部来源身份。首发 ≤32 条 / 记录 ≤16KB；`HandoffCatalog` 按原始来源索引分页（每页 ≤16 条 / ≤24KB，支持角色与原文查询）；`HandoffSource` 再读精确字符范围。真实两会话：来源 845 / 1322 行**全部可达（845/845、1322/1322）**；目录全量 **178,927 / 240,795 字节** vs 首发+整个声明 schema **6,222 / 8,416 字节**（【账本】离线零 API，**只比目录开销**，不冒充厂商 token）。
- **验收输入分层**（批次64）：调用 `input` 与结果**共享内联总预算**，input 最多 2048 字节，超出只展示来源/字节数/未内联事实 + 独立 Read 入口（原输入不截断、不删除）。同源等长对照：头 **21,605 → 18,683 字符（−13.52%）**，移出调用 input 3,589 字节，真实 Read 逐行完整。
- **阶段协议**（`synaptic/task_phase.py`，批次66）：模型声明 `phase_state`（当前阶段 ID / 来源 / 原文工作集 / 逐项引用作用域 `task`｜`phase`），引擎只验**结构、唯一身份、来源、阶段基点**。**任务级事实跨阶段适用；阶段级事实只在当前阶段适用**；"来源来自历史" ≠ "该要求当前适用"。**状态：仍为离线验证阶段**——曾暂接主 query_loop，主请求失败后**已撤回**；普通 TodoWrite schema **不广告**阶段字段。
- **任务级事实不可静默消失**（批次68，`wsc_handoff_fact_disposition.py`）：上一活跃检查点里**已声明 task 作用域**的事实，下一条活跃声明必须同字段、完整引用、保持 task；删除/缩短/降级都要**显式 `fact_disposition`**，并有准确基点 + 之后唯一真实文本事件。离线反控：21 个变体（每条各做删除/缩短/降级）**旧来源ID检查 21/21 放行、新事实连续性检查 21/21 拒绝**。
- **晚到 / 未消费结果**（批次44、80–85）：大未消费结果合法配对可完整入交接/main（260,000 字符）；**420,000 在超容量前中性停止**，不丢源。迟到结果从"整行拒绝"改为**逐块转换**（`late_result_projection.py`）：只有迟到结果变成带来源的事实文本，正常工具结果与原 text 块保留；身份**逐块**判定（`result_identity`）；对外层/块身份矛盾 ⇒ **保源拒绝、不猜**。该候选 **`XEYO_LATE_RESULT_PROJECTION` 默认关闭**（批次85：联合 92 passed / 1 既有 xfail）。
- **请求准入与全库冲突分离**（批次84）：全库扫描会把**已被折叠覆盖的旧迟到/中断调用**当成拦路者，误拒完全合法的当前请求。改为：源读取/恢复**不删真实记录**；发送准入**只检查实际模型请求投影**（投影形成后、交接前、以及每次发送/协议回退前各查一次）。六场真实源里**五场**存在这种旧冲突；**12 个私有投影 + 落盘恢复后头一致 12/12**（其中"问候"两臂未折叠，不样本计数）。
- **卡面冷索引**（`XEYO_WSC_CARD_INDEX_ONLY`，默认关闭，批次73/74）：历史剪枝卡只留索引入口。同源等长：头 **19,973 → 14,196 字符**；**厂商完整请求 input 15,506 → 13,045（−15.87%）**。但真实历史查阅里模型**没用索引选位置**（读了归档前 140 行）⇒ **不算"索引导航"通过**；本批整体加权命中 **77.87%**，文件里明确拒绝拿某次 98% 宣称整体达标。

- **折叠归因**（批次75）：20 次真实快照 fold 中，尺寸 5 / 费用 12 属**旧自动规则**、forced 3 **来源未知**；GUI 相邻实发 25,813 → 14,253，支持"低水位早压"。同时补 `XEYO_USAGE_DIR` **私有隔离** ⇒ 离线实验不再污染生产账本。
- **架构隔离**（批次64）：展示范围校验移到纯算法 `synaptic/source_presentation.py`，**恒启产品契约**移到 `synaptic/main_policy.py`（`memory/wsc_main_policy.py` 保留兼容接口）⇒ 算法层不再反向依赖 `memory`。

**这一轴的状态口径（必须一起说）**：批次66/67 的真实 API 实验里**有成功也有失败**——阶段实施组旧严格评分仍 **3/4**（完整测试限制落在 decisions 而非 constraints），**普通 schema 组"旧禁令复活为当前 decision"直接失败**；批次68 的 21/21 只证明"来源 ID 保留绕不过事实生命周期合同"，**不证明模型会正确判断退休语义**。固定未完成项：**T13/H22**（任意冷材料召回、有效信息占比）、**T14d**（完整请求与厂商计量对齐、20 次真实 fold 归因）、**T16**（真实复杂任务多次 fold / 重启 / 真正超容量规范 / 阶段协议并入主生成）、**T18**（真实主循环迟到结果续接、多媒体、混合帧、**旧冻结代迁移**）。

## 7. 防御机制（分五组，逐条给出"防的是什么"）

### 7.1 形状类（防发出去的东西非法）

1. **成对安全（pair-safe）**：切点不落在 tool_call / tool_result 之间。【源码】`runtime.py:334-347`
2. **执行边界保护**：最新工具响应帧不进新头。【源码】`wsc_execution_boundary.py`
3. **丢弃无主 tool 结果**：最后一公里把孤儿 tool 行清掉（只记账 `usage/wire_drops.jsonl`，**发射形状一字不动**）。【源码】`model/_openai_common.py`、`docs/wsc-design-review.md` §11
4. **确定性守卫**：`synaptic check` 在最大几个会话上跑两遍比 digest；`assert_no_llm_dependency` 禁掉 LLM 依赖导入。【源码】`synaptic/metrics.py`、`__main__.py:_check`

### 7.2 可恢复类（防"信息真的丢了"）

5. **必可拉回**：被剪节点必须绑真句柄；未知句柄 `raise KeyError`，**不静默降级**。【源码】`coldstore.py`、`project.py:266-330`
6. **句柄覆盖核算**：`synaptic/handle_coverage.py` 区分"物理上可读"（Read 覆盖）与"按精确绑定可展开"（expand 覆盖）——两者不是一个口径。
7. **读回执独立判定**：`read_receipt.py` —— "原生读回执状态独立于返回内容"；只有显式成功的原生读（`is_error is False` 且工具是 `Read`/`NotebookRead`）才能绕过内容启发式。
8. **冷层原文逐字节保存**：`coldstore` 用 gzip + sha 校验；"可恢复"由往返比对证明，不靠自述。【源码】`coldstore.py:1-3`
9. **视图文件重写是唯一入口**：每次折叠重写视图，句柄指向行区间；相对路径优先（便宜 + 能解析）。【源码】`offload.py:78-99`

### 7.3 预算类（防"该在的没在"）

10. **三桶预算**（§3.7）：fixed / main / index，各自额度与降级阶梯。
11. **受保护事实不静默省略**：fixed 桶超预算时只降**可降级**段，去重→摘录阶梯→仅留句柄→关段；WSC 会打 `warn` 明确说"可能仍超预算"。【源码】`budget.py:319,371-389`；【本轮实测】例子里就出现了这条 warn。
12. **index 桶只报账不裁**：因为"真要压它只有一条路叫删句柄，而删句柄等于撤回『被剪节点必可拉回』"。【源码】`budget.py:267,459`

### 7.4 失败类（fail-open / 不污染）

13. **fail-open（三条出口）**：开关关、区域太小、收益门不批、**任何异常** ⇒ 调用方保留既有 C2 投影，绝不半成品上线。【源码】`wsc_projection.py:3-5`
14. **离线不写生产账本**：`XEYO_WSC_OFFLINE=1` 闸门 + 回归用例；生产不设该变量 ⇒ 行为不变。【账本】09-22 前 `wsc_index_usage.jsonl` 3,668 行里 **3,605 行是探针自己写的**，加闸门后已修。
15. **不重复缩短已提交的历史**：`wsc_unfolded_results.py` —— "模型自己拥有的历史在显式/容量折叠前保持不折；历史投影不得因为某条结果大就再偷偷截短它"。
16. **尺寸侧修剪仍未接主链**：`wsc_size_prune.py` 明确写"**尚未接入生产主链**"；形态取自 DeepSeek harness（超阈值工具结果只留头 4096 + 标记 + 尾 1024，加载期硬校验"头+标记+尾 ≤ 阈值"⇒ 修剪必然变小）。两条边界：固定头尾会删掉中间的错误/接口/约束 ⇒ 只在"完整原文已进冷层归档且入口可用"时才安全。

### 7.5 账本与归因类（防"数字骗自己"）

17. **口径守卫**：`prompt_basis` 标签 —— `input_tokens` 一律带来源标签（估算/厂商实发），发射面估算不许占用 `input_tokens` 这个名字；全树 AST 守卫禁止绕过账本。【源码】`usage/ledger.py`、`python/tests/wsc/test_prompt_basis_single_source.py`
18. **同一个式子只有一个实现**：`theta_required()` 是 θ 的唯一实现；测试锁"θ=1 ⟺ PAYBACK_SHOTS 常数"，并有"生产不许自己拼代数"的源码守卫。【源码】`synaptic/cadence.py`、`tests/wsc/test_cadence.py`
19. **token 口径不许退回"字符/4"**：`tests/test_token_meter_g66.py`
20. **账本分层**：数折叠认 `c2_events.jsonl`；数放行/拒绝认 `fold_events.jsonl`（放行和被拒都记）；判"折叠当枪"走 `usage/pairing.py`。**别用一个字段当所有分母**。

### 7.6 交接轴的准入与保全（2026-10-08 → 10-11 新增，别漏）

21. **来源保留 ≠ 当前适用**：历史来源可以继续供当前任务检索，但**不自动激活其要求**；适用性由独立 `fact_scopes` 控制（批次66）。反例保留："设计阶段的禁止修改"在实施阶段复活 ⇒ 已用普通 schema 组付费跑出失败证据。
22. **不猜身份**：多块结果借同一外层身份、外层与内层 `tool_call_id` 矛盾 ⇒ **保源 + 拒绝候选**，不按猜测选一个（批次83/84/85）。
23. **不静默补默认参数**：交接生成器参数错误 ⇒ 有界**中性失败回执**，不静默回落默认（批次66）。
24. **必填来源 schema**：全局 `context_message_ids` 明确必填（批次66/67）。
25. **读取额度跨批累计**：`MAX_READ_CALLS=64` 不按批重置（批次64 —— 此前"一批最多 3 个只读调用"是交接生成器的局部限制，**不是** XEYO 普通工具调度的全局限制；该表述曾被批64 明确纠正）。
26. **中性停止代替丢源**：超容量 / 超额度 / 最终估参越界 ⇒ **停止并把状态作为事实保留**，不重复交接、不丢来源（批次64/79）。
27. **展示范围校验在算法层**：`synaptic/source_presentation.py`；恒启产品契约在 `synaptic/main_policy.py` ⇒ 算法层不得反向依赖 `memory`（批次64）。

## 9. 举例：A → WSC 处理 → B（全部真实、离线、零 API）

**用什么数据**：本机真实会话 `~/.xeyo/sessions/sess_muzpwhpu_loivz9.jsonl`（就是"续修 WSC 那次"的转录），

### A：WSC 之前的发射面

### WSC 处理（trace 逐字）

## 11. 可以优化的面（每条写清"缺什么证据"）

- **O1 把"等产出口径"做成评测一等指标。** 现在两跑输出差 3.3 倍，钱的对比天然带偏。候选主指标：`每 1k 输出 token 的成本`、`900 秒内完成的工具轮数`、`到首次可验证提交的时间`。缺：写进评测台并跑 k≥3。
- **O2 保尾改成"轮数下限 + token 上限"双约束（治 D2）。** 缺：真实分布（单轮工具结果有多大）——逐枪 `region_tokens` 已在 `fold_events` 里。**注意**：曾扫过 M ∈ {∞,24k,12k,6k}，尾部确实变小，但**发射量只降 7–19%，成本反升 3–15%** ⇒ 这条已被判死一次，重开要有新理由。
- **O3 头要不要真闸（治 D3/D12）。** 现结论是"裁剪闸被实测否掉、只能报账"，但**取回率的分母现在有了**：【本轮实测】347 行头里只有 14 行发生过取回、合计 37 次 ⇒ 可以拿它论证"多数句柄从未被用过"。
- **O4 折叠的"粒度带"要不要显式控制。** θ=1 把小口折（<2,000 tok）从 40.0% 打到 0%，但 5 次折叠里 2 次靠硬触发兜进来 ⇒ 存在"推迟到边界"的倾向。缺：θ=1 下"硬触发占比 vs 会话长度"曲线（现在只有 1 个点）。
- **O5 把首压也接到同一个 θ（治 D4）。** 缺：首压侧单独的重放收益测（每会话只发生 1 次）。
- **O6 可恢复性闭环（治 D1）。** 要么给 `expand` 补生产解析器，要么把"视图丢失"改成**不折叠**（宁可不省，不发不可执行的引用）。缺：视图失效真实发生率。
- **O7 观测补齐（治 D9）。** 逐请求成本与 `arm` 的 join，把"哪一臂折的、折完那一枪命中率多少"变成可查记录。
- **O8 要不要引入 LLM 摘要。** 现设计是三样都要：**零 LLM、可逆、确定性**。权衡：LLM 摘要能提语义，但会破**确定性**（同输入不同输出 ⇒ 缓存/回归全废）与**可逆性**。这是产品定位选择。
- **O9 尺寸侧修剪（工具结果头尾裁剪）要不要上主链。** 现状：**未接主链**（`wsc_size_prune.py`），前提是"完整原文已进冷层且入口可用"。
- **O10 去噪/时效轴继续做深。** 现状：STALE 标记 + 错误签名卡 + 白留率 8.0% 的观测；缺"被标记过的节点之后是否真不再需要"的归属证据（严格归属只有 7%）。

**交接轴（2026-10-08 → 10-11）新增的优化面**

- **O11 阶段协议并入主生成（T16）。** 现状：普通 TodoWrite schema 不广告阶段字段，主强制接线**已撤回**（主请求失败）。缺：**无草稿主组合**的收益验证——批次67 的普通 schema 组正是失败反例（旧禁令复活为当前 `decision`，且只查 `constraints` 不足以发现复活）。

## 12. 设计不变量（改 WSC 前必须同意这五条）

1. **只给信息，不给导演**：热层、错误 detail、工具描述只承载状态/结果/事实；禁止建议、劝导、评价、奖励、"应该/优先/不要再"式文本。
2. **模型自决**：引擎不规划路线、不纠偏、不点评；WSC 不替模型决定"该记住什么语义"。
3. **限制只在执行层**：要拦模型，就让那条路径的工具持续静默报错（中性结果型措辞），不往注意力里塞说教。
4. **能静默就不说话**：引擎自己能做的（状态维护、清理、折叠、重建）静默完成；第一问永远是"能不能不进上下文"。
5. **可恢复性高于压缩率**：任何一次"剪掉"，都必须伴随一个**能真跑通的**取回引用；取不到就不剪（D1/O6 的方向）。

## 13. 一句话总结

> WSC 不是"更聪明的摘要"，而是**把"什么时候改写、改写后每一枪长什么样、改写掉的东西还能不能捞回来"这件事，做成一条有经济判据、有确定性、有账本、有可恢复承诺的流水线**。
> 它压得狠（真实会话 97.5%），但它真正的卖点是**压得省**（θ=1：这一枪就不亏）和**压得住**（断言式的句柄可恢复 + 账本可复现）。
> 它现在的短板同样明确：**成绩维度没有基线**（TB 26 绿全在关态）、**头没有硬上限**（D3/D12）、**取回几乎没人用**（347 行头 / 37 次取回）、**一条兜底引用在生产跑不通**（D1）。
> **而它还有第二条轴（2026-10-08 起在建，批次19–85）**：折完之后**任务状态怎么交接**——专用交接调用（6 请求 / 48KB / 2048 输出 / ≤0.5 元每请求）、来源目录分页、阶段作用域协议、task 事实不可静默消失、迟到结果逐块只读投影、请求准入与旧冲突分离、超容量中性停止。这条轴现在的形状是：**机制已实现且有离线反控，但模型行为尚未验收**（T13/H22、T14d、T16、T18 四项固定开放），且真实 API 实验里**有成功也有失败**、费用全部是**估价上界不是账单**。
> 一句话读法：**压缩轴的数字能拿去比价；交接轴的数字只能拿去判机制有没有坏——两套不许混着读。**
