# D 的回执身份、语义绑定与原生交接协议（258–267）

本轮是实质进展：复现两类机械缺口、保存旁路修复合同，完成负面消费对照、投影筛查和模型校准。没有达到完整 Goal，也没有将新机制并入生产。此前所有评分、失败、冻结头及未知费用保留。

## 先确认结构性根因与职责

1. **解码冷回执正文时遗漏执行元数据。** SourceRead 的 payload view 原先只给正文与哈希，原 block 中的执行身份、revision、late、complete、is_error 等不随正文返回。原文存档仍完整，但当前读取视图不完整。规则：元数据只从唯一绑定的原回执复制，不能从结果文字、编号或消息顺序推断。回归：字段原样、null/缺省、混合回执、超预算、精确范围、结构化载荷、重启与 seal。
2. **原生交接续接丢弃模型自己的协议帧。** `wsc_handoff_generation.generate` 重建读取/校验后的 assistant 时只有 tool_use，未保留已返回的 text/reasoning。DeepSeek 转换器没有凭空补思考；输入缺失发生在交接循环。规则：精确重放已完整结束的原帧，绑定原 call ID、顺序和参数；未完整流不发布，不能伪造思考。回归：真实原生读取路径、真实原生校验拒绝路径、原生签名块、参数错配、流中断、限额子客户端和 usage 记账。
3. **引用身份不等于继续工作所需的结果内容。** D 已选择当前结果的 verification_call_id，但热头没有结果正文。规则候选：只物化模型已选择的引用，复用原生调用/回执配对，完整小结果按预算投影，其余仍精确冷恢复；不能凭测试值、关键词或近期顺序指定“当前正确结果”。回归与行为验收分开，不能以结果可见宣布正确使用。

唯一职责仍是：模型选择语义状态与证据；引擎提供机械身份与原文；Guard 校验结构；投影表达已有声明；冷层存真实历史。未增加确定性取消/覆盖关键词规则。

## 267：原生交接协议帧的旁路修复

`python/memory/wsc_handoff_replay_candidate.py::ReplayModel` 包装专用交接客户端，复用 `assistant_text_message` 与原生reasoning block校验。只替换匹配原call ID、顺序与原参数的专用assistant帧；正文、思考、原签名块照原样重放。不更改交接Prompt、工具输入、Guard、源码来源或任务冻结头。

7类零API合同通过，包括直接执行当前 `wsc_handoff_generation.generate` 的两条A/B：

- 原生读取续接：旧帧丢正文/思考；包装后原文恢复、调用和参数一致。
- 原生校验拒绝续接：旧帧同样丢失；包装后恢复，错误仍由原Guard决定。
- 原生签名保留，显示增量不重复；实际usage被委托记账，不能用包装对象的None吞掉费用。
- 额度子客户端共享已结束帧，流中断不发布完整帧，同ID但不同参数拒绝。

此处只证明协议合同修复；尚未用真实原生thinking交接验证语义效果，因此不并入。评测旧 `MeteredNative` 同样不转发reasoning，要先有保留实际provider帧的适配，不能仅把thinking参数打开就报原生交接已测。
