# WSC任务生命周期组合验收（批次181）

新增 `python/tests/wsc/test_task_lifecycle_sequences.py`，检查通用生命周期，不增加会话特例或生产规则。预期目标、任务ID与回执ID从独立构造的事件事实给定，不从待测投影反推答案。

顺序为：旧任务声明及验收回执 → 首次折叠 → 旧异步调用 → 带新用户事件的旧任务完成声明 → 新任务声明及自己的验收回执 → 第二次折叠 → flush/cache清空/hydrate → 恢复发射。旧调用结果分别在完成事件前或新任务声明后到达。

12种组合 = 原生/兼容通道 × 两种迟到顺序 × 三组不同内容值。三组内容改变目标与执行文字，不代表已模拟三个不同业务系统；这些都是确定性事件和状态声明，没有调用真实模型。两个任务故意复用相同阶段名`report`，验证任务结束屏障不依赖阶段名碰巧不同。

通过的断言：

- 新任务目标、任务条目和验收回执仅属于新任务；旧目标未出现在当前任务pin。
- 迟到结果若作为后续执行事实出现，其`task_association`仍为`undeclared`，不会自动成为新任务验收。
- 旧结果在热层可见，或由冷层节点区间经生产Read读取；不能要求所有旧结果都消失。
- 第二次折叠之前，当前头逐字不变；首次来源与已生成冷文本字节未变。
- 两次实际折叠后，通过磁盘hydrate及缓存清空，恢复发射与第二次折叠相同。
