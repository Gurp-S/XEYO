A01 · 回合清理边界没有覆盖启动阶段

触发条件
读取首个 task_state_changed 后关闭流，或 PromptAssembler 在 build_system_parts 抛异常。
当前证据
两条路径均出现 turn_active=false、task_status=running；调用协程中的 WorkspaceContext 仍指向刚结束的会话。
结构根因
设置 agent_mode、task_state、取消域和工作区上下文发生在 739–788 行；835 行已向外 yield，提示词组装在 960 行。负责终态和上下文复位的 try/finally 到 984 行才开始。外层 finally 只释放互斥并保存 checkpoint。
影响与边界
独立 API/CLI 集成可以收到互相矛盾的状态；同一协程后续工具操作可能继承旧会话上下文。HTTP 提示词初始化失败也会保留不正确的引擎内部任务态。未据此声称所有普通 SSE 断连均触发，HTTP 有 detached runner。
修复边界
引入 engine/turn_scope.py，进入回合前就建立 finally；该作用域独占状态转换、ContextVar token、before-snapshot 任务与终态落盘。完成收尾后才释放互斥，恢复调用者原上下文，不能只 set(None)。

A02 · 嵌套异步流没有完整传递关闭，提前退出被记为成功

触发条件
真实 FakeModel 回合收到 assistant_delta 后，调用最外层 stream.aclose()；探针保留内层生成器引用以排除 GC 时机干扰。
当前证据
外层互斥已释放，内层仍打开且任务为 running；显式关闭内层后任务被标 succeeded，虽然没有消费到 Final/Result。随后收集到 shared_agent_budget ContextVar token 在不同 Context 中 reset 的异常。
结构根因
submit 使用 aclosing，但 submit_message → _submit_message_inner 以及后者 → query_loop 使用裸 async for。清理可能推迟到另一个 finalizer 任务；异常归类只捕获 Exception，没有把 GeneratorExit/CancelledError 建模为独立的结束原因。
影响与边界
关闭返回不等于资源已释放，旧回合清理可能与下一轮交错；共享预算上下文和任务终态不可信。此项与 A01 相邻但独立，扩大 try/finally 不能自动修复生成器所有权。
修复边界
每层拥有的异步生成器显式 aclosing，回合作用域必须等待全部内层清理。采用显式 TurnOutcome，只有完成正常终止协议才可记 succeeded；关闭/取消不推导为成功。
旁路 / A/B 验收
在首事件、首 token、工具等待、Final 和 Result 五个边界关闭；要求内层同步关闭、无后台 finalizer 异常、原上下文恢复、下一轮预算不继承。

A03 · 转录提交屏障按进程而非会话隔离

触发条件
只让会话 B 的写入失败，会话 A 正常落盘，然后调用 flush_transcript(A_path)。
当前证据
A 文件已含 1 条记录，flush_transcript(A_path) 仍抛 transcript append incomplete；现存 flush_path(A_path) 则返回 true。
结构根因
flush_transcript 的 path 参数被丢弃，等待整个进程的 _pending/_writing/_failed。QueryEngine 在 async 路径上同步调用它，未采用已有的按路径屏障。
影响与边界
一场会话的磁盘故障会误伤其他会话的完成判定。慢磁盘期间同步 Condition.wait 还会阻塞共享事件循环；默认等待上限 5 秒。后者是代码路径上限，非实测延迟。
修复边界
复用并收敛已有 transcript_barrier，提供 await flush(session/path, through_seq) 的提交回执；进程总排空仅供宿主关闭。不要新增另一套队列或去重表。

A/B 两会话并发写入，B 持续失败、A 正常、单独重试 B；断言故障归属、顺序、去重和 A 的终态，并用心跳确认慢 I/O 不堵事件循环。

A04 · 工作区配置仍通过进程环境串线

触发条件
XEYO_CWD 指向 A，当前 ExecutionContext 指向 B；A/B 的记忆配置设置不同值。
当前证据
隐式 get_value(XEYO_C2_LLM_SUMMARY) 返回 A 的 0，显式传 B 返回 1。依次 apply_to_environ(A/B) 会把同一个进程 XEYO_WSC 从 0 改成 1。
结构根因
extension.config.resolve_workspace_cwd 只认显式 cwd 和进程 XEYO_CWD；memory/runtime、l5_flag、aging 的若干 getter 没传 cwd。部分 WSC 开关直接读 os.environ，工作区配置桥接会覆盖进程全局。
影响与边界
同一服务承载多个工作区时，B 的记忆策略可能跟随 A；开关变动还可能改变正在执行的回合。探针证明配置归属错误，没有做真实长对话的 WSC 质量或费用测量。
修复边界
在回合入口解析不可变 ExecutionConfig/MemoryPolicy，显式注入本轮；环境变量只作为宿主启动默认值。不要靠每轮改 os.environ 模拟隔离。WSC 冻结前缀和发布/恢复协议保持独立约束。

A10 · 资源创建是隐式全局，关闭也仍是全局操作

触发条件
一个进程嵌入多个引擎/宿主，或持续创建关闭不同工作区的运行时。
当前证据
AgentRuntime._running 进程全局；shutdown 遍历所有运行项。MCP manager 按 cwd 全局缓存、shutdown_all_managers 全清。HTTP AsyncClient 按 loop 全局缓存，当前源码未见对应统一 aclose 生命周期。
结构根因
显式注入目前主要解决服务访问，没有定义 create/start/drain/close 的资源所有权。QueryEngine 没有完整异步关闭协议。
影响与边界
一个宿主关闭可能影响另一个宿主；嵌入式调用者难以确定何时释放连接和进程。连接泄漏规模、跨宿主真实取消效果本轮未做压力复现。
修复边界
