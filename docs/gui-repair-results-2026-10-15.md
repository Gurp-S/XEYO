# XEYO GUI 修复与验证（2026-10-15）

本轮实施队列、Goal 及 GUI 审计中的明确缺陷。保留并兼容用户确认的并发改动；没有提交、推送或构建 Windows 安装包。

## 队列与 Goal

- Goal 与队列改为独立卡片，共用多行编辑器。Enter 换行，Ctrl/Cmd+Enter 或按钮保存；失焦不提交，保存失败保留同一目标/消息的草稿。
- Goal 编辑携带开始编辑时的 revision。发生冲突时展示最新内容，用户选择使用最新内容或保留草稿继续编辑；不再自动用旧草稿覆盖新版本。切换目标身份/会话仍隔离旧编辑器。
- 队列提供上移、下移和拖动。后端在锁内比对完整待发送顺序，原子修改 sequence 并持久化；新增、取消、开始投递造成的旧请求返回冲突。投递中的消息保留位置和回执。重启后的实际投递顺序经过测试。
- 调整顺序只影响待发送消息；不会重新排序已经发生的聊天记录。仍沿用原有合并投递规则，不表示每条消息会分别执行一个完整任务。
- 上方任务面板设独立滚动范围，720×480 下编辑目标时仍可看到主输入框。保留并发任务的整体布局和尺寸规则。

结构性根因是把多行内容交给单行输入、把失焦等同保存、把“修改内容”与“覆盖新版本”混用，以及只有视觉顺序而没有可持久化的调序操作。新模块分别承担编辑、展示和锁内调序，未在 Composer 中再堆一套状态机。
