# WSC：API 不可用期间的确定性优化（328）

本轮只完成不依赖真实模型即可判断的改进。没有调用模型或计数 API，没有更换 provider，没有修改实时用户会话或既有冻结头，没有提交混合工作树。自然语言交接整体仍保持默认关闭。

## 三轮复审

1. **职责与结构根因**：费用结算不能依赖流关闭成功。冷对象存在不能替代可执行的身份定位；目录只陈述消息、执行身份与文件行范围，不判定最新事实、语义支持或生命周期。
2. **最小实现与失败模型**：复用既有不可变对象发布、内容哈希、JSON 分块、工具调用/回执解析以及原生 Read。范围从实际编码产物计算，不用消息序号冒充可读行号。不同回执即使执行 ID 相同也不合并。没有新增模型工具、Judge、去噪规则或摘要提示。
3. **准入与证据边界**：先在原实现运行反例，再接入真实入口并回归。用同一摘要、同一真实来源验证精确恢复、原证据字节和重启。静态定位正确率不当作模型有效恢复率；新增热入口和冷存储开销明确记录。

## 修复与接入范围

### 失败流记账

结构性根因：两个交接生成器把 `account(...)` 放在 `await stream.aclose()` 之后。关闭再次抛错时，已返回的 usage 没有进入预算记录。

规则：关闭可以失败，记账仍在 finally 执行一次，读取关闭结束后的 usage；未知 usage 继续保持未知。关闭异常继续向上传播，不产生成功交接、不自动重试。

新增 `python/memory/wsc_stream_cleanup.py`，由 `wsc_handoff_generation.py` 和 `wsc_semantic_generation.py` 复用。已有 D 主链路立即受益；自然语言分支也使用同一处理。

原反例 **2 failed / 2 passed**，修复后 **4/4**。另补两项：关闭时最后返回的 usage 被计入、无 usage 不编造费用。

### 冷证据精确目录

结构性缺口：原有入口只提供整份归档的 Read 地址和总行数；超长 JSON 行变成多行 chunk 后，消息序号不能用于精确行读取。

规则：每条压缩视图/原始封套记录都有独立的 `(view, source, message_id, role, offset, limit)`，另保留调用 ID 与回执调用 ID。`source` 为零基记录序号；`offset` 为原生 Read 的一基行号。相同执行 ID 的多份回执全部保留，不选取或宣布哪份有效。

新增 `python/memory/wsc_evidence_index.py`；`wsc_semantic_evidence.py` 在实际序列化时记录范围并发布冷目录。热头只新增一个事实型 Read 入口，目录文件绑定到既有 publication manifest。调用、原文、目录损坏验证沿用现有机制。

原实测断言失败：没有已发布的消息/执行身份目录。新实现通过真实发布→目录 Read→回执 Read→重启，以及目录篡改拒绝复用。混合长短记录、换行、Unicode、转义、多回执都覆盖。

该能力已接到真实自然语言发布入口，没有另建实验开关；整个自然语言方法的默认关闭状态未改变。模型行为收益仍待验证，不宣称已完成方法默认准入。
