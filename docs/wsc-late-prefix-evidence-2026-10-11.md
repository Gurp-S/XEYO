# 批次82：迟到结果追加稳定性与结果身份恢复

## 根因、规则、回归

上一批候选在结果真正到达时才把早先调用转成事实文本，后一次请求会回改此前已发调用区域。改为观察到跨帧边界时即建立事实表示；结果到达只追加结果记录。回归比较到达前请求与到达后请求的相同前缀。此证明限于候选已生效且已观察到边界后的追加，不代表任何旧冻结请求都可无损迁移。

另发现恢复与主配对修复用 role=tool 扫描结果，忽略原生 user/tool_result 记录，伪补 UNKNOWN/aborted。两处改为按结果身份扫描，原生邻接结果不再补重复记录；测试覆盖 hydrate 后再经过主修复，原对象内容保持。

身份检查按原始调用块计数，避免同一帧重复 ID 被集合去重后误判为唯一。未知、重复、缺 ID 的工具结果保留来源，主循环在发送前停止，不让清理删源；它们仍不进入实验候选。已跨帧但尚未返回的唯一调用可表示为调用事实，普通未闭合尾帧不在候选准入范围。
