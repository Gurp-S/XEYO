# WSC：多次折叠发布中断的恢复引用（330）

本轮围绕 WSC 多代交接的发布一致性。API 0 次、费用 0；没有改变提示词、模型、普通压缩触发、去噪或冻结前缀。自然语言方法整体仍默认关闭。本轮没有提交混合工作树。

## 三轮复审

1. **根因与正确性**：头文件和 working 游标分别保存。第二次折叠先覆盖头文件，然后 working 保存失败，会留下旧游标和新头。新头因游标不匹配被拒绝，但旧头已被覆盖，只能回放完整历史。第一次折叠失败仍能保住原文，不能证明多代交接连续性。
2. **最小结构修复**：复用 `synaptic.contracts.publish` 的不可变对象和 working 已有原子保存。在 working 中同时保存游标与已验证头的恢复引用；可覆盖头文件继续作为兼容缓存。避免新增事务数据库、后台工作、模型调用、语义规则或大规模重构。
3. **失败、迁移与回归**：分别验证写入新恢复对象前、working 提交前、working 提交后中断；旧会话先固定旧代引用，引用未持久化就不覆盖旧头。恢复继续检查会话路径、内容哈希、cwd、游标、来源封印、冷对象 manifest 和调用配对。仅机械收益可准入，不能冒称模型任务质量提升。

## 实现与接入范围

- `python/memory/wsc_committed_head.py`：固定已经验证的头，借 working 原子保存记录 `committed_head_ref`；兼容旧代迁移。它不生成或解释交接内容。
- `python/memory/wsc_semantic_compaction.py`：覆盖头缓存前保留已提交代；新头验证后创建不可变恢复对象，再将新引用和游标一同保存。验证 durable 引用后才更新内存。新发布边界必须严格前进。
- `python/memory/wsc_head_store.py`：支持读取指定的不可变头记录，仍经过原 load 校验；引用必须位于该会话的头目录、带对应会话文件名前缀及有效内容哈希。
- `python/memory/wsc_projection.py`：兼容头缓存不能提供当前游标的有效头时，尝试 working 中该游标对应的恢复引用。校验失败依旧回放完整来源，恢复本身不会生成新交接。

恢复读取接入公共真实投影入口；引用发布接入自然语言交接真实入口。未将原 D 的全部发布路径一并改造成新事务方案。自然语言方法的默认关闭状态不变。

## 前后证据

原反例：第一代发布成功，追加尾部，第二代头已写而 working 保存中断。重启后旧游标仍在，但旧头不能恢复，投影变成全部历史。修改前 **1 failed**，见 `_wsc_out/wsc-publication-recovery-330/before.xml`。

新增专项 **11/11**：

- 旧格式／带引用格式 × 三个中断位置，共 6 项。
- 有效引用能恢复；随后分别改坏头内容、来源正文、冷对象、会话引用，4 项均拒绝复用。
- 旧格式迁移引用保存失败时，旧头文件字节不变且仍能恢复，1 项。

其中来源改写测试通过 MessageStore 的正式替换入口使缓存失效；第一次夹具直接修改对象未刷新缓存的失败保留在 `after.xml`，不算生产缺陷或最终结论。

额外检查发现一条历史 head-store 测试仍假设普通恢复会自动生成头。加载本轮修改前的 projection 也同样失败，证据为 `legacy-test-baseline.xml`。测试已对齐既有约定：首次生成和改史后生成需显式 `new_generation=True`，普通恢复拒绝旧头后回放来源。没有为使该测试通过而改动生产触发规则。
