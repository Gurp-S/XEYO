# 12 - 工具输出老化清除(Aging Tool-Output Elision)设计与落地

> 版本:v1.0 · 状态:已落地(默认关闭,`XEYO_TOOL_AGING=1` 启用)
> 关联:`docs/10-完整记忆体系.md`(C0/C1/C2)、`engine/compact.py`、`engine/aging.py`、`memory/runtime.py`

---

## 1. 背景与目标

编码 Agent 的成本结构:`历史中累积的工具结果 ≫ 工具 schema > 系统提示词`。
长会话中旧 tool_result 以缓存命中价被每一轮反复计费。

KV 前缀缓存按字节匹配,会话中途改历史任意字节 → 整段 miss。
**压缩边界(C1/C2 复位点)是全流程唯一可以"免费"改历史的时机。**
本机制在该时机把 N 轮以前的工具输出在**投影视图**中确定性替换为带恢复线索的存根;
存储层(`MessageStore`)原文永不动。

## 2. 机制规格

### 2.1 触发

| 路径 | 触发方式 |
|---|---|
| 默认(project)/project+gate | `maybe_advance_aging_boundary`:滞后门 `≥ AGING_MIN_ADVANCE(默认8条消息)` 才把 `frozen_until` 前移到尾部保护区之前(pair-safe 切点);推进当轮一次 miss,其后投影字节稳定 |
| v61 公式通道 | 不介入推进(由 decide 经济学驱动),仅存根样式升级生效 |

### 2.2 存根规格(两档确定性)

```
近档(boundary-idx ≤ 64):
[elided {tool} {uid尾8}: {净化摘要≤60字} — re-run {tool} to see full output]
远档(boundary-idx > 64):
[elided earlier {tool}]
```

- 摘要取结果首行,经净化:单行化、剥 `<tag>`、压空白、限长(R20 注入面/R26 字节稳定)
- 总长 ≤120 字符(≈30 token)
- **豁免**(保留截断后原文,不老化):`is_error=true`、`TodoWrite`、`AskUserQuestion`
- 被老化的消息同步移除 `image_url` 块

### 2.3 参数映射

| 设计参数 | 落地 | 默认 |
|---|---|---|
| N(起老距离) | `XEYO_TOOL_AGING_MIN_ADVANCE` 滞后门 | 8 条消息 |
| K(尾部保护) | 复用 `KEEP_TAIL_MESSAGES` | 6 条消息 |
| 折叠带 | `FOLD_AFTER` | 64 条消息 |
| 开关 | `XEYO_TOOL_AGING` | 关(零行为变化) |

### 2.4 三条红线

1. 截断/落盘发生在写入时;老化只换投影层内容
2. 老化只作用于 `tool_result` 内部 text 与 image 块;消息结构/配对不动(R8)
3. 幂等且确定性:同输入两次投影逐字节一致;增量投影==全量投影(INV3/INV4)

### 2.5 恢复语义(v1)

所有被老化工具均可重跑再生(Bash/Grep/Glob/Read/Screenshot),存根提示 re-run。
`logs/toolout/{use_id}.txt` 文件级恢复(+哈希校验+清理策略)为 v2 增强。

## 6. 灰度测试报告

> 日期:2026-08-26 · 环境:Windows / Python 3.14 · 工具:`tests/test_memory_aging.py` + `scripts/aging_canary.py`

### 6.1 测试矩阵

| 态 | 范围 | 结果 |
|---|---|---|
| OFF(默认) | 全量套件(排除 7 个缺 fastapi/httpx 的既有模块) | **451 passed**,3 failed 均为环境性(与落地前基线完全一致)→ 零行为变化证实 |
| ON | 定向 61 项(aging/compact/query_loop×2/instruction/system_date/context_telemetry/permissions/catalog) | **61 passed** |
| 双态兼容 | `test_compact.py` 分别在关/开下运行 | 关=legacy `[compacted]`,开=`[elided …]`,断言已改双格式兼容 |

**灰度发现并修复**:test_compact 一处硬编码 legacy 存根前缀——属预期的格式适配点,已改为双格式断言;无其他破坏。

### 6.2 Canary 演练(逐轮投影,拟真混合负载:中文/代码/错误/TodoWrite)

| 规模 | 态 | 累计发送字节 | 终态上下文字节 | 推进事件 | 前缀违例 |
|---|---|---|---|---|---|
| 60 轮 | OFF | 2,599,842 | 84,778 | 0 | 0 |
| 60 轮 | ON | 999,206 | 27,248 | 14 | **0** |
| 120 轮 | OFF | 10,306,366 | 170,794 | 0 | 0 |
| 120 轮 | ON | 3,338,816 | 49,959 | 29 | **0** |

| 指标 | 60 轮 | 120 轮 |
|---|---|---|
| 累计发送节省 | **61.6%** | **67.6%** |
| 终态上下文缩减 | **67.9%** | **70.7%** |

5 项验收检查两档规模全部 PASS:基线零推进 / 违例=0 / 发生推进 / 终态缩减≥30% / 累计节省≥15%。
**复利验证**:120 轮比 60 轮的节省率更高,符合"会话越长收益越大"的设计预期。

### 6.3 观察项与放量建议

1. **推进频率偏高频**:60 轮发生 14 次(约每 4 轮一次)。每次推进=生产环境一次全量前缀 miss。
   缓解:将 `XEYO_TOOL_AGING_MIN_ADVANCE` 从 8 上调至 16 观察 miss/节省平衡点;
   或接入缓存命中价差的经济门(参照 `try_extend_c2` 的四闸门模式)。
2. 存根块/折叠计数为**逐轮累计口径**(每次投影重新计数),非唯一存根数,读数时注意。
3. 违例数恒为 0:推进之间投影逐消息字节稳定,KV 复用语义未被破坏——核心安全指标达成。

### 6.4 结论

机制在双态下均稳定:关闭零变化,开启后长会话累计发送节省 62–68%、终态上下文缩减 68–71%,
且无任何前缀稳定性违例。**建议**:保持默认关闭,先以 `MIN_ADVANCE=16` 在个人日常会话灰度一周,
观察审计事件 `memory.aging.advance` 频率与体感后再评估放量。
