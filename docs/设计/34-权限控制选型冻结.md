# 权限控制 · 选型冻结

> 状态：**部分解冻 · 策略/审计加强中**（2026-08-29）  
> OS 边界仍冻结；下列「解冻补丁」允许改策略默认与审计/远程确认环。其余底座合同仍须遵守。  
> 产品边界：本机编码 Agent + 微信遥控；**权限狱 + ASK 环**，不是 OS/容器沙箱。  
> **补丁（权限默认放宽）**：出厂缺省改为 `bash=default` / `write=risk`（只读命令与工作区安全写免确认）；max 档（never/allow）放宽工作区外读/写（如跨目录找日志）、外发工具随档位、XeyoUI 面板/流程图/浏览器导航免确认，且**兜底 ASK（`bash_default_ask`）在 max 档转为自动放行（`bash_max_allow`）**——`git push`/`npm install`/`跑脚本` 等命令在 max 档不再逐个确认。**硬边界不变**：危险命令黑名单、密钥/`.xeyo-policy.json`/`.git/.xeyo/.agents` 受保护元数据、工人沙箱、远程会话更严。

## 解冻补丁（2026-08-29 · 允许改动）

| # | 允许改动 | 口径 |
|---|----------|------|
| U1 | 缺省策略 | 无 `.xeyo-policy.json` 时：`bash=default`、`write=risk`、`remote_bash=ask`（放宽补丁）。本机自用可写 `"bash":"ask"` 恢复全确认 |
| U2 | 审计字段 | pending / denied / resolved 必含 `matched_rule`；Bash 另含打码 `command_summary`。桌面/微信 `store.resolve` 必须落 `permission.resolved` |
| U3 | filehelper | 与 iLink 同构：pending 推送到微信；`/allow` / `/deny` 可 resolve |
| U4 | 推送文案 | WeChat/桌面 prompt 用打码摘要，禁止超长原文密钥进推送 |

**仍禁止（未解冻）：** OS 沙箱、完整 Bash AST、Agent 写 `.xeyo-policy.json`、企业策略中心。

## 底座（不可改）

| 层 | 选型 | 说明 |
|----|------|------|
| 裁决入口 | **`evaluate_policy`** | Registry.run 唯一策略真源；工具内 `check_permissions` 只做纵深，ASK 须 `permission_preapproved` |
| 三态 | **allow / ask / deny** | ask = 挂起等确认，**禁止**生产路径把 ASK 静默降成 DENY 后当成功执行 |
| 路径狱 | **cwd + `allowed_paths` + realpath 前缀** | 区外写 DENY；symlink 指外按真实目标裁决 |
| 危险路径 | **`.git` / `.ssh` / 密钥类 → ASK** | Read/Write/Edit；Grep/Glob 默认排除密钥 glob |
| 审批模式 | **`always` / `risk` / `never`** | 默认 `risk`；`XEYO_PERMISSION_MODE` 或请求 contextvar；`never`/`allow`(=max) 放宽工作区外读/写（硬边界不变） |
| Agent 模式 | **`agent` / `plan` / `ask`** | plan/ask 只读工具闸；与权限三态正交 |
| 仓库策略 | **`.xeyo-policy.json`** | 跟仓库走；**Agent 不可写该文件** |
| OS 边界 | **仅 Windows Job 内存上限** | 杀进程仍 `taskkill /T`；**不做** AppContainer / bwrap / Seatbelt |

### 执行时序合同（严格）

```text
ToolRegistry.run
  → readonly_gate（agent 模式）
  → evaluate_policy(name, input, cwd, allowed_paths)
  → ALLOW  → execute + audit
  → DENY   → ToolResult(is_error) + audit permission.denied
  → ASK    → PermissionCoordinator.request → permission_pending
           → 用户 resolve → skip_ask 再 run / 或拒绝
```

- `permissions.gate.can_use_tool`：**兼容二元 API**（ASK→DENY），仅测试/旧调用；**禁止**新生产路径依赖它做挂起。  
- 无 coordinator 的 headless：仅白名单规则（如 `write_confirm_ask`）可自动放行；**`bash_default_ask` / `bash_secret_ask` / `bash_remote_ask` / `bash_policy_ask` 禁止自动放行**。

## 工具裁决表（终稿口径）

| 类别 | 工具 | 冻结口径 |
|------|------|----------|
| 恒放行 | echo / getTime / TodoWrite / JournalQuery | ALWAYS_ALLOW |
| 读路径 | Read / Glob / Grep | 区内 ALLOW；危险 ASK；区外非 max DENY（max 档 ALLOW，密钥仍 DENY） |
| 写路径 | Write / Edit | 区外非 max DENY（max 档 ALLOW）；危险 ASK；缺省 `write=risk` → 区内安全自动；`.xeyo-policy.json` **硬 DENY** |
| Memory | Memory | 走 memdir 禁闭分支（**不在** ALWAYS_ALLOW） |
| 外发 | Screenshot / SendToWeChat / WebSearch / WebFetch | 默认可问 ASK；max 档 ALLOW；Send 区外 DENY |
| 子 Agent | Agent | 一律 ASK |
| Shell | Bash | 见下节；工人另见「工人 Bash 合同」 |
| 未知 | 其他名 | 默认 ASK |

## Bash 合同（严格）

裁决顺序（不可调换）：

1. **黑名单** → DENY（含 Windows：`rd/del`、`Remove-Item -Recurse`、`-EncodedCommand`、`iex`、UNC 破坏等）  
2. **密钥路径提及** → ASK（`bash_secret_ask`）  
3. **仓库 / 远程策略** → `bash: deny` 或远程 `remote_bash: deny` → DENY；远程**一律 ASK**（`bash_remote_ask`）；`"bash":"ask"` → 全确认（`bash_policy_ask`）  
4. 出厂缺省 `"bash":"default"` 或显式声明：**短只读白名单** → ALLOW（`bash_readonly_allow`）；写目标证明后按权限模式（写区外非 max 时 DENY）；**max 档**兜底 ASK（`bash_default_ask`）→ 自动放行（`bash_max_allow`）；非 max 档其余 ASK（`bash_default_ask`）  
5. 写命令目标无法证明在工作区内（非 max 档）→ **DENY**（禁止 `bash_write_pass`）

远程判定：`session_id` 前缀 `ilink:` 或 `filehelper:`。

## 工人 Bash 合同（Phase 2）

子 Agent（`write_scope` 已激活）与主会话共用 `_evaluate_bash` 黑名单/密钥/策略文件门禁，但裁决收口不同：

1. **远程工人** → 一律 DENY（无法 ASK，不得静默放行）  
2. **`bash_readonly_allow`** → ALLOW（`worker_bash_readonly`）  
3. **其余** → DENY（`worker_bash_deny`），**永不 ASK**  
4. 运行时：默认 timeout 30s、上限 60s；禁止 `run_in_background`

工人默认工具基线含只读 `Git` 与上述 Bash；仍禁 Memory / 嵌套 Agent / 外发。不做 OS 容器。

## `.xeyo-policy.json` 合同

| 字段 | 冻结语义 |
|------|----------|
| `bash` | `default` \| `ask` \| `allow` \| `deny`；**缺省 = `default`**（解冻 U1） |
| `remote_bash` | `ask` \| `deny`；缺省 `ask` |
| `write` | 缺省 **`risk`**；`ask`/`always` → 等同 always；`allow`/`never` → 等同 never；`risk` 回退环境审批模式 |
| `deny_tools` | 工具名硬 DENY |
| `deny_commands` | 子串/正则命中 Bash → DENY |
| `allowed_roots` | 额外可读/写根（相对仓库根展开） |
| `bash_job_memory_mb` | Job 内存上限；最小 64 |

- 示例文件：`.xeyo-policy.example.json`（**不**当作运行时真源）。  
- 无策略文件 = 代码内缺省（`bash=default` / `write=risk` / `remote_bash=ask`）。

## 挂起 / 审计 / UI

| 项 | 冻结口径 |
|----|----------|
| 挂起存储 | `PendingPermissionStore`；同 `request_id` 幂等 resolve；TTL 到期按 deny |
| 事件 | `permission_pending` / resolved；任务态 `waiting_permission` |
| HTTP | `POST /v1/permission/resolve` → store.resolve（须写 resolved 审计） |
| 桌面 | `PermissionDialog`；用户确认后 `skip_ask` 续跑 |
| 微信 | iLink **与** filehelper：pending 推送 + `/allow`/`/deny` |
| 审计 | `.xeyo_audit/audit.jsonl`：pending / resolved / denied / tool.*；`matched_rule` + Bash `command_summary`（打码）；密钥不得入审计正文 |

## 明确不做（本冻结）

- macOS Seatbelt / Linux bubblewrap / Landlock / AppContainer  
- cmd.exe / PowerShell **完整 AST** 沙箱  
- 企业组织级策略中心、云端下发  
- 把 `excludedCommands` / 正则当唯一安全边界（OS 级强制属 backlog，非本版本）  
- 远程会话 Bash 自动放行只读白名单（远程必须 ASK 或 DENY）  
- Agent 可写 `.xeyo-policy.json`  
- Grep/Glob 扫出 `.env` / `.ssh` / `*.pem`（须保持排除 glob）

## 收益边界（勿对外夸大）

- **解决**：工作区外写盘可拒；危险路径/外发/子 Agent/Bash 默认可问人；仓库可关 Bash；远程可确认；事后审计可对账。  
- **不解决**：用户点了允许之后的任意 shell 仍是本机用户权限；无内核级文件/网络强制；不可当「不可信代码执行环境」。

### 已冻结补充口径（2026-08-29）

- Bash 工具内 `check_permissions`：ASK 仅当 `permission_preapproved()` 为真。  
- `readable_extra_roots` 优先 `WorkspaceContext.cwd`，禁止串会话读他人 memdir。  
- Registry headless **不得**把 `bash_default_ask` / `bash_secret_ask` / `bash_remote_ask` / `bash_policy_ask` 当自动放行。  
- Job Object：`TerminateJobObject` 不进杀进程热路径（防嵌套 Job 卡死）；限额 + KillOnJobClose 兜底。
