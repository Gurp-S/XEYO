## 0. TL;DR

把回溯从「前端状态机 + 乐观截断」重构为 **「服务端不可变时间旅行账本 + 前端投影/对账」**。用不变式 **I1–I7** 保证三件事永不发生：**性能差、丢失用户信息、失败回溯**。对外只有一个语义：**「把对话和工作区还原到这条用户消息发出的那一刻」**；`continue / restore` 只是内部实现细节。

---

## 1. 目标与范围

**目标**：达到市面成熟 Agent（Cursor、Claude Code、OpenAI Codex）的对齐水准，且在企业级约束下更强：

- ✅ 每个用户轮 = 一个可恢复检查点；
- ✅ 一次回退 = 对话 + 工作区一起还原，可撤销、可找回；
- ✅ 有完整时间线，可浏览任意检查点并回退/undo；
- ✅ 绝不碰用户 `.git`，绝不覆盖用户未提交的手写改动；
- ✅ 性能有预算、崩溃可恢复、重载一致、局部失败不窃喊成功。

**范围**：主会话 + agent 作用域工作区；侧聊对等 rewind UI、默认整树 restore、完整编辑器 VFS 明确不做（见 §12）。

## 2. 核心不变式 I1–I7

| # | 不变式 | 含义 | 违反时后果 |
|---|---|---|---|
| **I1 单调版本** | 会话 transcript 有单调递增 `revision`（水位线），回溯与正常追加都产生新 revision | 任何时刻都存在唯一「已提交前缀」 | 无法判断当前状态是哪一个 |
| **I2 前缀不可变** | 已提交前缀逻辑上 append-only；回溯永不原地改，而是写新前缀 + 旧尾迁入不可变 orphan | 时间旅行是「分叉」，不是「覆盖」 | 旧状态不可还原 |
| **I3 写前日志** | 顺序：**orphan 写 + fsync → 原子替换 transcript → 再改工作区** | 崩溃只丢「最后一步」，不丢历史 | 中间态损坏 / 半坏工作区 |
| **I4 服务端权威** | transcript 与 rewind 账本的唯一真源 = 服务端 `revision`；前端只是投影 | 前端是投影，重载按 revision 重同步 | 本地与服务端分叉 |
| **I5 幂等** | 每个逻辑操作绑定稳定 `idempotency_key`，重试 = 后端 `reused` 重放，绝不重复/冲突 | 丢响应可安全重试 | 重复截断 / 二次破坏 |
| **I6 无丢失 + 可恢复** | 被截断的尾永久落在不可变 orphan，直到显式 GC；每个 rewind 配产生逆操作的 undo；审计事件持久 | 任何一步都可倒回去 | 消息找不回（历史痛点） |
| **I7 用户数据安全** | 永不静默覆盖用户未提交改动；恢复按 scoped 路径；dirty 跳过；force 被拦；blob 引用计数 | 保护用户资产 | 手写代码被回溯吃掉 |

**推导规则（客户端必须遵守）**：

> **本地投影永远可逆，服务端 `committed` 才是「成功」的判定依据。** 确认→截断为了 <100ms 用乐观；但任何未达服务端 committed 的路径**必然回滚投影**，且**绝不在 commit 前让用户感觉「已成功」**。由此「快（乐观）」与「稳（不丢）」不再互斥：快是投影的体感，稳是账本的语义。

## 3. 用户语义：单入口「回到该时点」

- **对外只讲一件事**：`把对话和工作区还原到这条用户消息发出的那一刻`。
- `continue`（重发重试）与 `restore`（只回文件）**退化为内部实现细节**，不再向用户暴露双入口（对齐 Cursor / Claude Code 心智）。
- 前端呈现：**一条时间线**（每条用户轮 = 一个可回退点）+ 单一「回到该时点」按钮 + 单一「撤销回溯」。
- 无 checkpoint 的旧消息：仅允许「截断对话并重发文案」，并明示「工作区不会回滚」。

## 4. 快照基底：A 方案（自主 blob / shadow-git）

### 4.1 为何不用 git（硬安全边界）

- git reset 会**重置整棵工作区**，把用户尚未提交的手写改动一并抹掉——**直接违反 I7**，不可接受。
- git 不覆盖**对话 transcript**，仍需单独机制，等于只省一半。
- 必须依赖用户仓库状态（rebase/reset/未提交/超大树），**企业级 agent 必须在任何仓库里安全运行**。
- 双轨自适应 = 双倍正确性面 + 环境行为不确定，会把 v2/v3 竞态**制度化**，不取。

### 4.2 工程契约：实现 git 的算法，而非重造 git

对齐 git 保障等级，只需要 **4 个内部原语**；算法直接照抄 git 思路，量级可控：

| 原语 | 行为 | 对齐 git 能力 |
|---|---|---|
| `snapshot(paths)` | 按**路径作用域**把 agent 触及文件内容寻址成 blob（COW，只存 diff/新增） | git commit（对象） |
| `dedup` | 内容哈希，跨会话复用 | git object 去重 |
| `restore(paths, checkpoint)` | 只回写 checkpoint 里的路径 + 删 agent 新建路径 + **跳过用户手改路径** | git checkout/reset（scoped） |
| `diff / undo` | 按哈希差集得「两检查点间改动」；undo = 生成新 checkpoint 把 orphan 链回 | git log + revert |

**对照表（必须逐项打勾）**：廉价快照 ✅、去重 ✅、恢复 ✅、diff ✅、undo ✅、崩溃重放 ✅、索引可重建 ✅。

## 5. 数据轨迹与落盘

```
~/.xeyo/sessions/{sid}/
  transcript.jsonl        # 仅当前已提交前缀，单调 revision
  orphans/{rewind_id}.jsonl   # 被截断尾（不可变）
  checkpoints.jsonl       # 每条 user 消息的 COW blob 图（需 compaction）
  agent_file_index.jsonl  # AgentFileIndex upsert 账本
  rewind_events.jsonl     # 审计 + undo 溯源（latest-wins）
~/.xeyo/snapshots/{sha256}# 内容寻址 blob（引用计数，跨会话去重）
```

- **checkpoint = 该条 user 消息发出时、agent 作用域文件的 COW blob 图**；`checkpoint_id` 绑定 user 消息并随 `/messages` hydrate。
- 记录：Edit/Write/Notebook 走 `record_file_mutation`；Bash / 未走 file tool 走 **turn 起止 lstat 差量**（按白名单根 + 作用域剪枝，禁止整树扫描）。
- **崩溃顺序（I3）**：`orphan → fsync → 原子替换 transcript → 再改工作区`。Hydrate 只读 transcript。
- 每个文件加 `schema_version`；索引（AgentFileIndex / checkpoint / blob refcount）可重建。

## 6. 一致性模型（前端变「薄」）

前端只做三件事：**投影、乐观、对账**。其余全交给服务端账本。

1. **投影**：client 持有本地 `messagesById` + 已知服务端 `revision`；渲染是投影，不是真源。
2. **乐观**：点击即截断投影（<100ms 体感），但**必须可逆**——任何失败路径都回退到截断前投影。
3. **对账**：重载/差异以 `revision` 为准重拉前缀；进行中 rewind 按 `rewind_id` poll→settle。

### 6.1 客户端必修复项（历史反模式，本轮修死）

| # | 问题 | 修复 |
|---|---|---|
| **C1** | 幂等键含 `Date.now()`（`rewindV3Store.ts:328`）→ 重试新建/冲突 | 稳定键 `rw:{sid}:{target}:{attemptId}:{contentSha[8]}`；`attemptId` 在确认时生成、重试复用、新意图才换 |
| **C2** | poll `failed` 不回滚本地、且提前 `dropFallback`（`:342-353`）→ 消息消失 | 终态前**一律保留兜底**；任一 `failed`/超时**必先恢复截断列表**再置错 |
| **C3** | `bySession` 纯内存、重载丢进行中态 | 持久化扩版：`rewindId / attemptId / suffixBackup / settled` 全落盘；重载按 rewind_id 重对齐 |
| **C4** | 恢复旧文本（`restoreDialogState` 用 `slice(targetIdx)`） | 用 `suffixBackup` 定格快照（含 `editedText`） |
| **C5** | 前端把投影当真相 | 取消「本地截断即事实」的一切路径；只以服务端 committed 为准 |

## 7. 并发、崩溃恢复、审计、度量

- **单写者**：一个会话同一时刻只有一个 mutator；busy 时不 interrupt、直接 409；其它用 **revision 乐观并发**（提交时校验 revision，冲突则拒绝并请重试）。
- **崩溃恢复**：启动时扫描 WAL/journal（orphan、undo、account）重建索引（AgentFileIndex、checkpoint 索引、blob refcount）——「重启后一切还在」的保证。
- **审计**：每条 rewind 事件带 `who/会话、when、target、checkpoint、orphan_id、undo 引用、pill 摘要、status(committed/partial/recovery_required)`，可查询。
- **度量**：确认→列表截断延迟、transcript commit 延迟、restore 延迟、失败率（按 busy/conflict/idempotency/timeout 分层）、orphan 磁盘占用。

---

## 8. 生命周期与治理

- **blob 引用计数**：全局计数，`引用数=0 且未被任何未过期 checkpoint 引用` 才可回收。
- **checkpoint 保留策略**：见 §9.1。
- **compaction**：`checkpoints.jsonl` 需 compaction；orphan 按保留策略老化；blob 按引用计数回收。
- **迁移**：账本文件带 `schema_version`，读时按版本迁移。
- **跨会话 / 多 agent**：blob 内容寻址天然跨会话去重；scoped restore 按路径作用域；侧聊对等 UI 不做但数据层可支撑。
- **导出 / 取证**：成果状态可导出；审计可供合规。

## 9. 三条已定稿边界

### 9.1 blob GC / 保留策略

- **默认**：`保留最近 10 个可回退检查点`；**固定保留**（不参与 GC）：① 会话初始基线、② 手动/自动锚点检查点。
- **空间预算**：`单个 checkpoint ≤ Y` 且 `单会话 blob 总占用 ≤ X`，先到先清（防止「10 个超大 checkpoint」撑爆磁盘）。
- **GC 判定 = 全局可达性**（引用计数，跨会话不误删），保留数量只是展示层策略，两层不混。
- **设置可调**：暴露「保留数量」「空间预算」两个参数，并附危害说明：
  - **太小** → 无法回退较远时点，长任务/大乱局救不回来；
  - **太大** → 磁盘与恢复性能占用升高，且旧检查点(尤其超大树)拖慢 GC 与启动扫描。

> **实现状态（已落地，安全核心）**：`python/rewind/blob_gc.py` 提供全局可达性回收——
> 可达 = 所有会话 `agent_file_index.jsonl` / `checkpoints.jsonl` / `operations.jsonl` /
> `rewind_events.jsonl` / `orphans/*` 里的 `content_hash`/`before_hash`/`after_hash`（**最保守**，
> 共享 blob 跨会话不误删）；候选删除 = 快照目录 blob − 可达；仅在**空间预算超额**时按
> mtime 最旧优先删除不可达 blob。配置：`XEYO_BLOB_GC_ENABLED`（默认 0）、
> `XEYO_BLOB_GC_DRY_RUN`（默认 1，只报告）、`XEYO_BLOB_GC_MAX_BYTES`（预算）、
> `XEYO_BLOB_GC_KEEP_RECENT`（近 N 保留，已生效）。CLI：`python -m rewind.blob_gc`。
>
> **设置项已接线**（§9.1「设置可调 + 危害说明」）：后端 `python/rewind/blob_gc.py` 新增
> `rewind_gc_config_path()/read_rewind_gc_config()/write_rewind_gc_config()`（持久化
> `~/.xeyo/rewind_gc.json`，`XEYO_REWIND_GC_CONFIG` 可覆盖），`garbage_collect` 在未显式传参时
> 先读该配置（再退环境变量）。控制端点 `python/server/routers/control.py` 提供
> `GET/PUT /v1/settings/rewind-gc`（`require_loopback`，负数 400）。前端
> `gui/src/lib/api.ts` 加 `get/setRewindGcSettings`；`gui/src/stores/settingsStore.ts` 加
> `rewindGcKeepRecent/rewindGcMaxBytes`（持久化 + 归一化）；`gui/src/components/SettingsModal.tsx`
> 回溯 tab 加「快照清理（blob GC）」输入框与太小/太大危害说明。
>
> **保留性剪枝已落地**：`collect_reachable_blobs(sessions_root, keep_recent=...)` 支持按会话把
> 检查点引用限定到**保留集**（最近 N + 基线（ts 最早）+ 锚点（`anchor: true`，前向兼容）），
> 其余检查点专属引用成为剪枝候选；**`agent_file_index`/`rewind_events`/`orphans` 仍全量保留**

> **锚点写入方已落地（§9.1）**：`python/rewind/index.py` 新增 `mark_checkpoint_anchor(session,
> user_message_id, anchor=True)`（按消息找 checkpoint、以 `{...checkpoint, "anchor": true}`

### 9.2 恢复中间态

- 引入 v2 的 `recovery_required / partial` 语义到 v3：
  - `committed` = transcript + 工作区完成；
  - `partial` = transcript 完成、工作区**部分**恢复（见 §9.3）；
  - `recovery_required` = 工作区处于**中间态**，仅允许「从检查点重试恢复 / 放弃」。
- **可持久化、可跨重启 resume**：恢复中断后重启不能「忘掉」，必须能继续或放弃。
- 这是本方案相对 git reset 的优势：git reset 中断要硬解 git 状态，我们有 COW 检查点可重试。

> **实现状态（已落地，§9.2）**：`python/rewind/hotpath.py`
> - `_restore_worker` 恢复失败（异常或存在 `report["failed"]`）→ 事件置 `recovery_required`（而非 `failed`）；
>   仅用户手改被跳过 → `partial`；全量成功 → `committed`。
> - `RewindHotpath.recover(rewind_id, action, confirmed)`：`retry` → 置回 `restoring` 并从检查点重跑（幂等，`recovery_attempt+1`）；`abandon` → 终态 `recovery_abandoned`。
> - `mark_crashed_rewinds(sessions_dir)`：启动扫描，把 in-flight（`transcript_committed`/`restoring`）事件标记为 `recovery_required`（跨重启 resume）。
> - 路由 `POST /v1/sessions/{sid}/rewind/{rewind_id}/recover`（`action: retry|abandon`）。
> 前端 `rewindV3Store`：状态新增 `recovery`，`pollSettled`/`rehydrate` 把 `recovery_required`/`recovery_abandoned` 视为终态；新增 `recover(sessionId, action)`；`RewindV3Dialog` error 态在 `recovery` 时改呈「从检查点重试 / 放弃恢复」。
>
> **GC 自动化（已落地）**：`server/app.py` `_lifespan` 新增 `_blob_gc_loop()` 后台任务
> （`XEYO_BLOB_GC_INTERVAL_S`，默认 3600s；仅在 `XEYO_BLOB_GC_ENABLED=1` 时执行，阻塞 GC 走
> `asyncio.to_thread`）；`control.py` 加 `POST /v1/settings/rewind-gc/run` 手动触发一次。
> 注意：GC 读的 `enabled`/`dry_run`/`max_bytes`/`keep_recent` 默认源自环境变量/配置。

### 9.3 作用域记录完整性（尽力恢复 + 可重试）

当 agent 改了文件但未被 file tool / lstat 命中：

- **尽力恢复**：只回写「确认是 agent 触及、且未与用户冲突」的路径；
- **绝不复原用户操作**：手动改过/被锁文件不覆盖，不确定的一律归入「未恢复」，宁可少恢复、不可误伤害；
- **持久化 `partial` 标记**（不能只弹一次 toast）：使用户可①对缺失路径**重试恢复**、②**undo** 回退这次不完整回溯、③审计可见「本次回溯不完整」；
- **永不静默**：不完整必须可见可查，不以「回溯成功」掩盖。

## 10. 性能预算

- 确认 → 列表截断 **<100ms**（主线程，乐观投影）。
- transcript commit 典型 **<100ms**；≤20 文件后台 restore **<500ms**；Continue 端到端 **<600ms**；发送冻结 COW **<50ms**。
- 热路径零 `git add -A`、零整树读取、零必经 preview。
- 作用域严格 scoped：快照 = 被触及路径的 COW diff，恢复 = 只回写被触及路径，索引 = 只回受影响。

## 11. 验收 / 回归清单

1. 编辑历史消息 →「回到该时点」：模拟后端在 poll 前返回 `failed`，**被截断消息必须回列表**，弹窗给「撤销/重试/放弃」。
2. POST 超时（响应丢失）：重试**复用同一幂等键**，不新建 rewind、不报 `idempotency_conflict`。
3. 重载页面对进行中 rewind：能 poll 对齐、能 undo，不丢消息。
4. `restore`（只回文件）行为不回归；undo 后 `loadSessionMessagesWithBackfill` 正常回填。
5. 手动改过文件 + 回溯：**不被覆盖**，被标记/跳过并提示。
6. GC：跨会话共享 blob 不被误删；基线/锚点检查点不被回收；空间预算生效。

## 14. 验证限制（本会话实测约束）

- **pytest `tmp_path` 在沙箱下被拒**：本机（Windows 沙箱）跑 pytest 时临时目录
  （`%LOCALAPPDATA%\Temp\pytest-of-*` 与 `--basetemp`）均报 `PermissionError`，因此
  **后端逻辑用「工作区内固定临时目录 + 内联断言」验证**（`tempfile.mkdtemp` 在沙箱下也会卡）；
  已把等价逻辑写入 `python/tests/test_blob_gc.py` 供常规 CI 运行。

  现 `tsc -b` 已回到 0 错误。**GUI 改动应避开正在重构的文件**（`MessageList`/`useMessageListEditing`/
  `RoundHost`/`PromptBubble`），以免被覆盖。
- 回溯相关前端文件（`rewindV3Store`/`api`/`SettingsModal`/`settingsStore`/`WorkspaceRevertDialog`）
  不依赖上述重构中的文件，可独立编译。

### 14.1 部署要点（实测规避）

- **webview→loopback 必须带 `Access-Control-Allow-Private-Network: true`**：桌面 webview
  （`http://tauri.localhost` 等）fetch `http://127.0.0.1:*`（loopback）时，Chromium 要求预检响应带
  该头，否则真实客户端报 `Failed to fetch`。`python/server/app.py` 已加 `@app.middleware("http")`
  在预检响应上补该头。**改后端后必须重启服务**。
- **v3 回溯目标 id 需对齐服务端 transcript id**：本地 `ChatMessage.id` 与后端 transcript 的
  `id` 可能不一致（如回填/重载后）。`rewindV3Store.confirm` 现在先
  `loadServerSessionMessages` 并把目标 id 解析为服务端 id（id 命中即用；否则按唯一文本匹配；
  不唯一则报「找不到可回溯的用户消息」），再 POST `/rewind`，避免后端
  `target message not in transcript`。
