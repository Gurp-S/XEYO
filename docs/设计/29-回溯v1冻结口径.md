# 会话回溯（Rewind）v1 · 冻结口径

> 状态：**考古 / v1 实现记录**（2026-08-29）  
> **产品面已由 [`30-回溯v2对齐Cursor口径.md`](./30-回溯v2对齐Cursor口径.md) 取代。**  
> 本文仅保留 v1 合同原文，供对照与回归考古；新落地以 30 为准。

## 底座（不可改）

| 层 | 冻结选型 | 说明 |
|----|----------|------|
| API | `preview` → 确认 → `execute`（幂等 key） | 无「静默回滚」；执行须显式 `confirmed` |
| 对话权威 | **服务端 revision + transcript 前缀** | execute 返回 `retained_messages`；FE **replace**，禁止与 `/messages` 做 merge 自愈 |
| 截断 | 重写当前 jsonl **并作废**轮转归档（`.old*`） | 刷新/hydrate 不得把已截断回合拼回 |
| 确认后 | **不自动重发** | 截断后把编辑文案放回 Composer；由用户发送 |
| 文件恢复 | 有 `target_commit` → **shadow 差集**（`path_scope`） | journal 反做仅作无 commit 时的补充；默认非整树 |
| 冲突 | worktree ≠ HEAD（恢复路径上）→ **阻断** | **禁止** hash 漂移时 force 覆盖用户手改 |
| 消息 id | **客户端 id 为真源**（经 `user_message_id` 落盘） | 禁止「第几条 user」序号硬映射 |
| 落盘 | 引擎收下 user 后 **enqueue + `flush_transcript`**，再调厂商 | 403/断连后仍可编辑重发与 preview |

## 用户可见合同

| # | 场景 | 冻结口径 |
|---|------|----------|
| 1 | 编辑历史消息 | 先 `preview`；有冲突 → `blocked`，不可 execute |
| 2 | 确认页 | 可勾选 **「同时回滚工作区文件」**；取消勾选 = 只截对话，保留手改文件 |
| 3 | 有 `target_commit` / ops | 默认勾选回滚文件；展示将恢复路径（含 Bash 等无 journal ops、但有 shadow 差集的改动） |
| 4 | 无工作区改动 | 仅对话截断；文案说明不改文件 |
| 5 | 确认成功 | 历史截断；Composer 填入编辑后文本；**不**自动 `sendMessage` |
| 6 | 预览后工作区变 | `workspace_revision` **仅指纹 plan 路径**（`fingerprint_paths`）；Vite/测试噪声不得单独判失效 |
| 7 | `recovery_required` | 产品对话框：**从检查点恢复** / **放弃并保留文件**；禁止引导用户再次盲目 execute |
| 8 | 首轮厂商失败 | 用户消息已落盘；transcript 缺失时 FE 可退化为本地截断重发（不卡死编辑） |

## 后端合同（严格执行）

### Preview

- 目标：`target_message_id` 必须是当前 transcript 中的 **user** id（或唯一文本命中后的服务端 id）。
- `metadata` 必含：`retained_message_ids`、`workspace_revision`、`fingerprint_paths`、`restores_workspace`、`target_commit`（可空）、`shadow_paths`、`operations`。
- `restores_workspace == true` 当且仅当存在可恢复的工作区意图（`target_commit` 或 journal ops）。

### Execute

| 参数 | 冻结语义 |
|------|----------|
| `confirmed` | 必须为 true |
| `idempotency_key` | 同 key 重放返回同一 job，不二次改盘 |
| `expected_workspace_revision` | 与 preview 时 **同一 `fingerprint_paths` 集合** 计算；不一致 → conflict |
| `restore_workspace` | `false` → **跳过一切文件恢复**，只改 transcript/revision |
| `full_tree_restore` | 默认 false；仅显式 opt-in 才整树 shadow |

- 成功：`job.status == committed`，附 `retained_messages`。
- 部分失败且不可自动补偿干净：`job.status == recovery_required`，**HTTP 返回 job**（不单靠抛错丢身份）。
- 恢复 API：`POST /v1/sessions/{id}/rollback/jobs/{job_id}/recover`，`action ∈ {retry_checkpoint, abandon}`。

### 落盘时序（主会话 / 侧聊 / 子 Agent 侧链）

```
append(user) → record_transcript（入队）→ flush_transcript（硬落盘）→ 调厂商 / 首个 SSE
```

`record_transcript`  alone **不算**落盘完成。

## 前端合同

| 项 | 冻结口径 |
|----|----------|
| id 对齐 | 精确 id → 唯一文本；多条同文或零命中 → **报错**，不猜序号 |
| 确认 | `executeRollback({ restoreWorkspace })` 把勾选传给后端 |
| 成功投影 | 优先 `retainedMessages`；禁止依赖 GET `/messages` merge 补齐 |
| 恢复态 | `phase === recovery_required`；仅恢复/放弃，不重开普通确认回滚 |
| 阶段机 | `gui/src/lib/rollbackMachine.ts` 为 UI 相真源 |

## 明确不做（v1）

- 确认后自动重发 / fire-and-forget 重试发送  
- GET `/messages` 把 `.old` 拼回已截断前缀  
- hash 不对仍 force 反做  
- 默认整树 restore（须 opt-in）  
- 二进制文件可靠 snapshot（仍按文本路径；失败进 backlog）  
- 把 FE 当成跨进程事务协调器（截断权威在后端；FE 只投影）  
- 侧聊完整 rewind 产品面与主会话对等（侧聊仅保证落盘与 id；完整 UI 非 v1）

## 明确留给 backlog（不挡冻结）

- journal 反做与 shadow 差集的进一步单一化  
- busy / interrupt 与 preview 叠加重试的活锁边角  
- 二进制 / 大文件 checkpoint  
- Workspace 面板「单文件回溯」入口（见 `27-XEYO_Workspace计划书`；复用本 v1 API，不另起语义）  
- rollback 事件完全并入统一 EngineEvent / TaskState 投影  

## 验收（冷冻门禁）

以下任一失败即视为违反冻结，须修回归而非改合同：

1. 编辑历史 → 确认 → 刷新页面：被截断回合 **不再出现**。  
2. 确认后 **不会**自动发出模型请求；Composer 有编辑后文案。  
3. Agent 改过的文件（含无 Edit journal、但有 `before_commit` 差集）在勾选「回滚文件」时可恢复；取消勾选则文件原样。  
4. 用户在 Agent 之后手改过的、属于恢复路径上的文件：preview **blocked**，不得静默盖写。  
5. 预览后仅出现无关 untracked（如 Vite 产物）且不在 `fingerprint_paths`：**不应**报「预览后工作区有变动」。  
6. 厂商 403 后换模型编辑重发：不因「transcript 不可用」永久卡死。  
7. `recovery_required` 出现产品对话框，且 abandon 后可重新 preview。

## 变更纪律

- **冻结期内**：只允许修违反本文件的 bug 与测试；行为变更须先修订本文件并注明日期。  
- Feature flag / 整树 opt-in 默认值不得在无文档修订的情况下改成「默认整树」。  
- 与本文件冲突的旧注释、旧 UI 文案（如「确认并发送」暗示自动重发）以本文件为准并应删改。
