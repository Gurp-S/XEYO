# 51-工具系统全景机制（注册 / 执行 / MCP / 输出治理）

> 定稿：2026-09-05。本文是工具系统（能力层）的**机制全景**：注册-裁决-执行-治理四段地图、
> 内置工具家族与 MCP 双通道的具体设计、一次工具调用的完整实例、优点/缺点与未完成清单。
> 权威口径上游：`40-MCP与SKILL企业级融合设计.md`（冻结稿）、`43-bash专用工具路由设计.md`。

## 1. 设计背景：四个约束决定全部形态

1. **单一裁决点**——任何工具（内置/MCP/网关）必须走同一个 `ToolRegistry.run`，
   权限、审计、输出预算在执行前集中裁决；不允许任何"直接调函数"的旁路。
2. **tools 数组会话冻结**——schema 逐字节稳定是 KV 前缀的前提；会话内能力变化只能
   走"网关 + DENY 门"，不能改数组。
3. **故障隔离**——MCP server 是外部进程：启动失败/超时/坏 schema/中途崩溃都必须
   "skip-log 继续"，不能拖死会话。
4. **输出是预算品**——每个工具的返回都直接进上下文，必须有 cap；超限原文落盘可找回。

## 2. 四段地图与数据流

```
注册                裁决+执行                  治理
┌──────────┐   ┌───────────────────────┐   ┌──────────────┐
│ catalog   │   │ ToolRegistry.run      │   │ 输出预算      │
│ (内置工厂) │──►│  ① hooks PreToolUse   │──►│ 16k 闸+spill  │
│ mcp_manager│  │  ② evaluate_policy    │   │ fence γ4      │
│ (MCP 直挂) │   │     三态 DENY/ASK/ALLOW│   │ todo/dock 载荷│
│ Mcp 网关   │  │  ③ tool.execute       │   │ 审计 started/ │
│ (动态通道) │  │  ④ _apply_output_budget│  │ finished      │
│ slash(独立)│  │  ⑤ hooks PostToolUse  │   └──────────────┘
└──────────┘   └───────────────────────┘
     ▲                                        │
     │ reconcile push/pull（启停 → T_now 活页块）│ 全文落盘 ~/.xeyo/spill/
     └──────── .xeyo/settings.json ◄──────────┘（Read 找回）
```

| 通道 | 注册方式 | 会话内可变？ |
|---|---|---|
| 内置工具 | `catalog.py` 工厂表 → `register`（名对齐单表 `meta.py:53`，启动自检 `:398`） | 否 |
| MCP 直挂 | `mcp_manager.attach` → 注册名 `mcp__<server>__<name>__<12hex>` 哈希钉（`mcp_client.py:181`） | 否（attach 定型） |
| Mcp 网关 | 常驻注册一个 `Mcp` 工具（`mcp_gateway.py:76`） | action 动态，面不变 |
| slash 命令 | **独立注册表** `slash/registry.py`（不走 ToolRegistry） | 是 |

一句话：**注册有三条通道，裁决只有一个漏斗（registry.run），治理（预算/spill/围栏）
是出口统一税。**

## 3. 各段机制

### 3.1 注册与 schema 冻结

- 内置工具名对齐单表 `TOOL_META`（policy/预算/exposure 三属性一体），启动自检防漂移；
- MCP 注册名带 12 位哈希钉防跨 server 撞名；坏 schema 分级降级、超大转 hidden
  （`mcp_manager.py:295`）；
- `schemas()` 走 `_schemas_cache`，**register 即失效、此后逐字节稳定**
  （`tool_registry.py:118-124`）——"会话冻结"的物理实现；
- 暴露分级：hidden 工具不进数组但可经网关触及（enabled_probe 兜底）。

### 3.2 裁决与执行（`tool_registry.py:295 run`）

执行前五步：hooks `PreToolUse`（fail-closed，不能改参数）→ `evaluate_policy` 三态
（DENY 先于 grant）→ ASK 挂起（`PermissionCoordinator`）→ `tool.execute` →
hooks `PostToolUse`。`xml_tool_call` 是 GLM 裸 XML 的第二入口，产出 ToolUse 合入
同一漏斗（不绕权限）。斜杠命令 `/ls /git /run` 等**不走**本漏斗（独立注册表，
权限/审计自成体系——已知双真相）。

### 3.3 输出治理（出口统一税）

- **预算闸**：`_apply_output_budget`（`tool_registry.py:178`）——实例级 output_budget >
  静态 ToolMeta > 默认 16000 字符；Read/Bash 豁免防读回环（`meta.py:140`）；
- **spill**：超限原文落盘 `~/.xeyo/spill/<session>/`（O_EXCL+0600，7 天 TTL），
  预览进上下文 + 找回路径写在返回里；spill 失败 fail-open（不丢内容）；
- **todo/dock/ui 载荷**：TodoWrite 的结构化清单、XeyoUI 的桌面控制走 ToolResult 专用
  字段（metadata/ui），与文本内容分离。

### 3.4 内置工具家族（要点）

| 工具 | 核心设计 | 收益实测（六轮） |
|---|---|---|
| Glob | `rg --files --iglob` 封装；贪婪 pattern→目录摘要；≥40 命中折叠；60s 缓存 | 广搜 1319 chars 不泄洪 |
| Grep | 四模式（content/files/count/**symbols**）；content_index trigram 预筛 fail-open | 预筛缓存二建 309.8→46.7ms（-85%） |
| Read | 0.25MiB 预检+25k tok 上限；二进制黑名单；unchanged-stub 去重；**symbol 定位+pack 打包** | symbol vs 全量：**省 99.2% token**（20615→175） |
| Bash | Job Object 内存护栏 512MiB+树终止；45s 自动转后台；stdout 精简（pytest 省 93%）| 见 43 号设计 |
| Memory | notes/session.md/rollout 三路并发检索 + write/forget/retrieve | 逃生舱+碎片还原（47 号） |
| Agent | 子代理派生（scope 裁剪/深度 1/结算） | 见 48 号 |
| Git/Notebook/… | 只读五动作/cell 级编辑 | —— |

### 3.5 MCP 生命周期（`mcp_client.py` / `mcp_manager.py`）

- **启动**：stdio 传输、STARTUP_TIMEOUT 30s；required 失败不挡会话（T_now 警告）；
- **运行**：TOOL_TIMEOUT 300s；重连指数退避 0.5→30s（上限 10 次、uptime≥30s 重置）；
  `tools/list_changed` 全代替换（generation）带冲突回滚；
- **网关**：`action=call` 经 `resolve_tool` 只在 attach 时定型的已知集内匹配——
  身份绑定已知 McpTool 对象，**不从 args 取身份**（防伪造）；
- **启停**：`set_mcp_enabled` → reconcile push（T_now 活页块，digest 幂等）→
  移除即 DENY（`enabled_probe`）——停用即时生效且不可被 grant 穿越；
- **配置**：`.xeyo/settings.json` 三源合并（project > user > plugin），企业 deny
  一票否决，坏 JSON keep-last-good。

## 4. 一次工具调用的完整实例（虚构剧本）

模型吐 `Bash(git push)` → ① PreToolUse 钩子（未启用，跳过）→ ② evaluate_policy：
黑名单未命中 → 规则命中"写操作" → **ASK** → coordinator 挂起（TTL 180s）→
用户 allow → grant 落库（指纹=Bash+`git push`）→ ③ 执行：Job Object 内存限额 +
stdout 精简（git push 输出 214 tok）→ ④ 预算内直通（<16000）→ ⑤ PostToolUse →
审计 `tool.finished` → 结果进 tool_result（γ4 围栏在装配层统一加）。

**对照：Grep 大结果**——`Grep` 返回 22000 chars → 超无豁免预算？不：Grep meta
cap=20000，先自截 → registry 闸通过 → 直接进上下文；**对照：WebFetch 60k**——
cap 16000 触发 → spill 全文落盘 → 上下文得到 ~8k 预览 + `~/.xeyo/spill/.../x.txt`
找回路径 → 模型需要时 `Read` 该路径取全文。

**对照：MCP 启停**——用户在面板 disable 某 MCP server → reconcile push 发
`# 工具面变更` 活页块 → 网关/直挂对该 server 工具即时 DENY（probe 兜底）→
tools 数组**一字节未动** → KV 前缀无损。

## 5. 优点 / 缺点与情况说明

### 5.1 优点

1. **单一漏斗是真的**：三种注册通道汇入同一 `run`，权限/审计/预算/围栏无处可绕
   （对照：slash 是唯一在漏斗外的存量债务）；
2. **冻结红线有物理实现**：`_schemas_cache` + reconcile 只发块不改数组——
   会话内启停对 KV 前缀零损伤（审计确认 push/pull 路径逐字节比对通过）；
3. **MCP 故障隔离完善**：超时分层/退避重连/坏 schema 降级/required 不挡会话/
   哈希钉名——外部进程的每种死法都有预案；
4. **输出治理是统一出口税**：cap+spill+围栏在漏斗出口一次收齐，工具作者无需
   自觉（Read/Bash 的豁免清单化，防读回环）；
5. **工具家族质量高**：不自造 glob/regex 轮子（rg 封装）、错误信息对模型友好
   （Did-you-mean/候选清单）、Bash 有真实内存护栏（512MiB Job Object）。

### 5.2 缺点与情况说明

1. **双执行路径**：`mcp__*` 直挂走 run 全流程，网关 `action=call` 在 run 内直接
   `target.execute`——同一 MCP 能力两套执行/计量语义（六轮审计 #5）；
2. **冻结红线有一处隐性地雷**：MCP `tools/list_changed` 全代替换会走 register →
   清 `_schemas_cache`——与"attach 定型"注释冲突（触发取决于上游 server 是否发通知）；
3. **slash 双真相**：`/ls /git /run` 与内置工具能力重叠、权限/审计分叉，
   维护成本翻倍；
4. **目录多重副本**：registry._tools / manager.entry.tools / client._tools /
   runtime._tools 四处状态无单一权威；
5. **网关增量有限**："会话内新增工具"实际是"触及 attach 时已 hidden 的冻结工具"，
   `list_changed` 后 manager 侧不刷新 → 网关对新工具 fail-closed；
6. **bash_tool 写文件不进 rewind**（容错缺口，见 46 号/审计 §5.1）。

## 6. 耦合与解耦

- **工具 × 权限**：裁决内嵌 run（② 步），工具自身 `check_permissions`（filesystem
  硬 DENY）是第二道纵深——两层判定互相独立、结果取严；
- **工具 × 装配**：exposure=hidden 的工具不进 schemas 但占注册位（网关可达）——
  "可见面"与"能力面"分离是动态工具面的基础；
- **工具 × 容错**：输出预算/spill 在漏斗出口统一收；但 WriteStore/bash 子进程的
  文件副作用**不在**本层记录（rewind 缺口的根源——工具系统只管"返回值"，不管
  "副作用账"）；
- **工具 × reconcile**：启停 = 配置写 + 块发布 + probe 兜底，三步各自幂等。
