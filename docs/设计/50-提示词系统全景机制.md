# 50-提示词系统全景机制（system / T_now / env_channel / 预算）

> 定稿：2026-09-05。本文是提示词系统（装配层）的**机制全景**：四段拼装地图、
> 每段的具体设计、一次请求的完整拼装实例、稳定前缀与 KV 经济、优点/缺点与未完成清单。
> 权威口径上游：`32-LLM调用前注入选型冻结.md`（T_now 冻结稿）、`43-bash专用工具路由设计.md`。

## 1. 设计背景：四个约束决定全部形态

1. **KV 前缀缓存是一等经济约束**——请求开头改一字节，后面缓存全废（生产实测命中率
   median 93.9% 靠的就是前缀纪律）。铁律：**稳定内容靠左、易变内容只挂请求尾部**。
2. **易变与稳定的分界必须机器执法**——"哪些东西每轮都可能变"（状态/提醒/开关）不能
   写死 system，也不能靠开发者自觉；走登记表 + 契约测试。
3. **防注入是结构问题不是文案问题**——工具输出与外部消息都不可信，必须用消息结构
   （围栏、伪造 tool 对）隔离，而不是靠"请勿相信"的措辞。
4. **上下文是稀缺资源**——每个可见块都要回答"能不能不进上下文"（引擎能强制的
   一律不给模型看），进了的要过预算闸。

## 2. 四段拼装地图

```
一次 model.stream 请求 =
┌─────────────────────────────────────────────────────────────┐
│ ① system（稳定左段，会话级 memo）                              │
│    IDENTITY → CWD → TOOL_POLICY(+FENCE_POLICY) → XEYO.md     │
│    → custom/append（只许追加）                                │
│    〔刻意不进：date / model 名 / 工具名清单 / MEMORY.md 索引〕 │
├─────────────────────────────────────────────────────────────┤
│ ② 投影历史（C0/C1/C2 压缩态，字节稳定，见 47 号）               │
├─────────────────────────────────────────────────────────────┤
│ ③ T_now 易变块（env_channel：伪造 tool 对尾插，仅投影）         │
│    xeyo_env_notice 对：assistant(tool_calls) → tool_result    │
├─────────────────────────────────────────────────────────────┤
│ ④ tools schema（会话冻结，_schemas_cache 逐字节复用）           │
└─────────────────────────────────────────────────────────────┘
     发送前 normalize：假对转真 tool_calls/tool 消息（_openai_common.py:244）
```

| 段 | 变化频率 | 机制 | 预算 |
|---|---|---|---|
| ① system | 会话内不变（memo 键：model/names/instr_sig/sidemode） | `assembler.py:36/103` | XEYO.md 软预算 8k |
| ② 投影历史 | 压缩时跳变，压缩间字节不变 | `compact.py` + `runtime.py` | C0 8192/条；C2 摘要 12000 字符 |
| ③ T_now | 每轮可能变 | `pre_llm_inject.py` 登记表 | 总闸 6000 tok（`_trim_tagged_blocks:886`） |
| ④ schemas | 会话冻结 | `tool_registry.py:118` | schema 短 description 预算（`apply_schema_budget`） |

一句话：**①④ 是"冻结区"，② 是"跳变区"（跳变间稳定），③ 是"自由区"（但有过闸）——
三区边界全部由代码结构保证，不靠自觉。**

## 3. 各段机制

### 3.1 system 稳定左段（`prompt/system_prompt.py` + `assembler.py`）

- 段序锁死（`assemble_system_prompt_parts:147-204`）：IDENTITY → `CWD: {cwd}` →
  TOOL_POLICY(+FENCE_POLICY) → `# Instructions (XEYO.md)` → custom/append；
- **date/model/工具名刻意不进左段**（`system_prompt.py:65-71`）——换日/换模型/
  增减工具不打爆前缀；MEMORY.md 索引也不进左段（由 runtime 挂 T_now 尾部）；
- XEYO.md 每次会话 fetch 重读（`:134`），侧聊模式跳过注入（`:121-132`）；
- custom extras 只许 append（去重后追加），禁止插中间。

### 3.2 T_now 注入管线（`prompt/pre_llm_inject.py`）

- **登记表 `T_NOW_BLOCK_REGISTRY`**：每个块一行（类别 / 为什么必须在上下文 / 预算与门控），
  登记数硬顶 **22**（`:714`），加一必须删一；所有装配点必须带 `# block: <名>` 标记
  且与登记表一一对应——由 `tests/test_t_now_block_registry.py` 契约测试执法
  （登记数 ≤22 + 装配点双向核对 + 禁死登记）。**注意：运行时 `_tag_block` 无校验，
  执法是离线的**（绕过即静默失效，下次跑测试才红）；
- **三类预算**（F1）：directive/event 全保（构造处各自有界）；inventory 按配额填充、
  末块截断带 `…`；总闸 `T_NOW_TOTAL_BUDGET=6000` token（chars/4）；
- **D1 门控**：模糊指代类块在无上下文依据时静默不发（事件类静默即失，绝不门控）；
- 现役候选 20+ 项（Continue / Wrap-up / 子代理结算 / jobs 补投 / 文件冲突…），
  权威清单以登记表为准；Proposals digest 与 Memory index 块已下线。

### 3.3 env_channel 环境声道（`prompt/t_now_strategy.py` + `turn_context.py`）

- **机制**：全部易变块装进一对**仅存在于投影**的伪造 tool 对——
  `assistant(tool_calls: xeyo_env_notice) → tool_result`（`append_env_notice_pair:118`），
  工具名不进 tools 数组（`:98`）；不进 MessageStore/JSONL；尾插不动前缀；
- **发送前**：`normalize_messages_for_openai`（`_openai_common.py:244/278`）把假对转成
  真 tool_calls/tool 消息；
- **回退档 legacy**：厂商以结构类 4xx（400/404/405/413/415/422，`ENV_FALLBACK_STATUS:75`）
  拒绝假对且未吐 chunk 时，进程级备忘 + 当场以 legacy 重建重试（bg_wrap 身份标记 +
  尾插末条 user）——结构隔离降级为文案隔离；
- **为何是 tool_result**：模型训练里 tool_result 就是"环境声道"，注入内容与用户意图
  在消息结构上物理隔离——根治说话人混淆型注意力漂移（对照 legacy 的残留风险）。

### 3.4 γ4 围栏（`prompt/fence.py`）

所有 tool_result 在投影层包 `<tool_output tool=".." untrusted="true">`；外部用户消息
包 `<user_message untrusted="true" source="..">`。配套：`harvest_sanitize`（私钥块/
sk-密钥/AKIA/`key=val` 形态替换占位 + 行级注入句式替换）；`truncate_tool_content_
preserving_fence`（截断保围栏）。围栏在投影层添加、不污染 transcript。**已知缺口**：
inner 内容含 `</tool_output>` 字面量不转义，可提前闭合围栏（六轮审计 #16）。

### 3.5 厂商归一化（`model/_openai_common.py`）

DeepSeek/GLM/OpenAI 兼容层的消息形状差异在发送前归一；env 假对在此转真 tool_calls。
KV 前缀的字节稳定性最终由这一层保证（含 usage 读取：`stream_options.include_usage`
——主链路未开，见 49 号缺口）。

## 4. 一次请求的完整拼装实例（虚构剧本）

**会话第 37 枪**：用户在 GUI 发"继续修 rewind 的测试"。

① system：memo 命中（model/names/instr_sig/sidemode 未变），**零重构**——直接复用
上次字符串（含 XEYO.md 全文 6.2k tok；无 date/model/工具名）。
② 投影：签名命中 → 复用投影缓存；本轮无新压缩 → 历史段与上一枪逐字节一致
（35 轮 175k prompt 中 173k 命中缓存）。
③ T_now：本轮装配 4 块——`# 子代理结算`（上轮工人超时归因）、`# jobs 补投`（空，静默）、
`# 文件冲突`（无，静默）、`# 其他会话活动`（1 行）；4 块经 env_channel 合成一对
`xeyo_env_notice` 假对（412 tok）尾插到历史之后；前缀仍逐字节不动。
④ schemas：`_schemas_cache` 命中（会话内第 37 次复用，零重序列化）。

**发出**：prompt 48k、命中 47.4k（98.8%）、单枪 ¥0.0041。若此刻 C2 触发，
② 段一次性重建（唯一合法的"前缀跳变"），下一枪命中跌到 ~30% 后爬回——
这就是 47 号 §5.2 的"锯齿"。

## 5. 优点 / 缺点与情况说明

### 5.1 优点

1. **三区边界结构化**：稳定左段（memo+锁段序）、跳变区（缓存签名）、自由区
   （登记表+预算）——KV 命中率 median 93.9% 是这套结构的生产实证；
2. **env_channel 是注入隔离的正解**：伪造 tool 对让易变块与用户意图在消息结构上
   物理隔离，且工具名不进 tools 数组（schemas 冻结红线不受影响）；4xx 回退 legacy
   是真实兜底而非摆设；
3. **登记表 + 契约测试**：T_now 块"加一必须删一"有机器执法（离线），装配点双向核对
   防幽灵块；
4. **压缩与注入的时序正确**：env 假对在投影**之后**尾插——压缩永远接触不到假对，
   tool 配对永不破坏（六轮审计核实）；
5. **schema 短 description 预算**：工具描述有独立预算闸（`apply_schema_budget`），
   工具面膨胀不直接打爆请求。

### 5.2 缺点与情况说明

1. **登记硬顶仅测试执法**：运行时 `_tag_block` 不校验注册名——绕过登记直接 append
   会静默生效，直到下次跑测试才红（成本极低的 fail-fast 缺失）；
2. **token 预算非一等公民**：`BudgetTracker.max_tokens` 默认 None；上下文超限靠
   `maybe_force_compact_on_pressure`（依赖 `model.context_limit`，CLI/DeepSeek 路径
   不设置 → C2 全哑，六轮审计 #15）；
3. **legacy 回退档残留说话人混淆风险**：结构隔离降级为"文案隔离"（bg_wrap 头），
   弱模型仍可能把尾插指令绑到用户请求——回退即降防；
4. **fence 不转义闭合标签**：工具输出可自带 `</tool_output>` 击穿"不可信"标注；
   `_INJECTION_LINE_RE` 仅行级黑名单；
5. **可观测性缺口**：T_now 块与 env 假对不进 transcript（排障只能抓最终 messages）；
   `UsageEvent.context_breakdown` 无 env 单块归因；
6. **双预算常量冗余**：`T_NOW_EXTRA_BUDGET=6000`（:253）与 `T_NOW_TOTAL_BUDGET=6000`
   （:700）语义重叠；旧 `_trim_blocks_to_budget:613` 疑似死代码。

## 6. 耦合与解耦

- **装配 × 压缩**：注入在投影之后是硬时序（③ 依赖 ①② 完成且不再变更）；
  C2 gate 与投影缓存已解耦（缓存签名含全部可变字段，47 号 §6）；
- **装配 × 工具面**：schemas 会话冻结由 registry 保证；会话内启停经 reconcile 发布
  T_now 活页块（digest 幂等），**永不触碰 `_schemas_cache`**——"移除→DENY"由
  权限层执行，装配层不感知；
- **装配 × 记忆**：MEMORY.md 索引经 T_now 注入（`runtime._append_memory_index:1232`），
  记忆正文走 Memory 工具按需检索——装配层只给"指针"不给"正文"（防污染设计）；
- **装配 × 厂商**：归一化收口在 `_openai_common`（叶子模块），新厂商接入不碰装配逻辑。
