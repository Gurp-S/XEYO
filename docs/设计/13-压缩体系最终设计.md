# 13 - 压缩体系最终设计（综合 Claude / Codex / OpenCode / Cline / Cursor / AutoGPT）

> 版本：v1.0 · 状态：设计总纲（落地随 `docs/11` 分期）
> 关联：`docs/10-完整记忆体系.md`（六层+公式 v6.1）、`docs/11-记忆体系落地步骤书.md`（分期落地）、`docs/12-压缩质量验证计划书.md`（质量/成本验证）、`engine/compact.py`、`memory/runtime.py`、`memory/simulator/decision.py`
> 定位：把 XEYO 已有的压缩实现与主流 Agent 的压缩策略做最终合成；**不改公式（v6.1 已锁）**，只定体系、分期与灰度。

---

## 0. 一句话

**XEYO 最终压缩体系 = Claude 的五段渐进骨架 × Cursor/OpenCode 的非破坏可回溯 × Codex 的"handoff"改造成确定性按类型摘要 × Cline 的智能引擎（v6.1）× 自己的"KV 前缀稳定 + r 实测"护城河。**

它最核心的差异化不是"更会压"，而是"**压得便宜、压得可回溯、压得可测量**"。

---

## 1. 三条不可违背的硬约束（地基）

任何策略不得破坏这三条，它们是 XEYO 区别于主流 Agent 的护城河：

1. **非破坏性**：权威历史 `~/.xeyo/sessions/{id}.jsonl` 永远 append-only。压缩只作用于**送模型的投影**（`engine/compact.py` / `memory/runtime.py`）。丢的是"暂不呈现"，不是"信息消失"；任何时刻可重压/重算。
2. **KV 前缀字节稳定**：`compact_cursor` 只前进；冻结边界 `c1_frozen_until` 不回退；`MEMORY.md` 导航索引只在 `T_now` 尾部、不进 system 左段；query_loop 有增量投影缓存。DeepSeek 缓存价差敏感，一次前缀 miss 的代价压倒一切。
3. **质量闸**：`Q ≥ θ` 才允许压；必须压时 `argmin D`（丢最少）；近 6 条原文保留（`KEEP_TAIL_MESSAGES`）；错误/结构化工具结果豁免。

---

## 2. 架构骨架：六层记忆 × 投影层

```
C0 截断 → C1 冻结占位 → C2 摘要游标 → [可选 LLM session.md]
        └───────── 都只改投影，不动 JSONL ─────────┘
```

| 层 | 职责 | 落点 | 参考来源 |
|---|---|---|---|
| L1 指令 | `XEYO.md` 文件族规则 | `memory/instruction.py` | 全 Agent 通用 |
| L2 短期 | 会话权威历史 | JSONL（append-only） | 全 Agent 通用 |
| L3 工作 | 进度/游标/投机/缓存状态 | `{id}.working.json` | Claude working memory |
| L4 长期 | **跨会话知识库** `MemoryNote` + 治理 | `~/.xeyo/memory/{ws}/` | Claude `Memdir`（结构化"智慧"，压缩可复用，不必每次从头摘） |
| L5 投影 | 本回合送模型的压缩视图 | `engine/compact.py` + `runtime.py` | XEYO 核心 |
| L6 休眠 | 空闲时蒸馏进 L4 | `nightshift.py` | Claude AutoDream |

**关键**：L4 的存在让"LLM 摘要"从"每次压缩都重新生成"变成"**复用已蒸馏的结构化知识**"——这正是 Claude Code 五段流水线里 LLM 摘要能兜底、能省钱的原因（Memdir 复用）。

---

## 3. 渐进压缩动作（Claude 五段骨架，XEYO 落地）

从便宜到贵，**默认只跑到保本为止**：

| 动作 | 做什么 | 成本 | 触发 | 当前默认 |
|---|---|---|---|---|
| **C0** | 单条 tool_result 截 16K 字符 | 忽略不计 | 写入时 | ✅ 常开 |
| **C1** | 游离区旧工具结果 → 稳定占位符（legacy `[compacted]` 或老化 `[elided…re-run]`） | 低 | 边界推进 + 滞后门 | ✅ 常开 |
| **C2** | 前进 cursor，更早消息 → **确定性摘要**（`id:kind:tokens::类型片段`）或 `session.md`；只追加不重写 | 一次 miss | 三闸 + 冷却 | ⛔ 关（即将灰度） |
| **LLM 摘要** | `session.md` 任务语义（Goal/Current/Completed/Discoveries/Open/Next） | 高 | 仅当 C2 确定性不足且值得 | ⛔ 关 |
| **aging** | 富存根（净化摘要 + `re-run` 提示），豁免 error/TodoWrite | 低 | `XEYO_TOOL_AGING` | ⛔ 关 |

> 该列"默认跑到哪"对应 **C2 灰度**：验证"从 C0+C1 升到 C2 后，命中率/成本/质量三者是否同时变好"。

---

## 4. 智能压缩引擎（Cline 的"智能"）× 决策经济学（v6.1 公式）

`memory/simulator/decision.py` 已是完整的"选压不压、压哪种"智能层：

```
S0 冻结 → HardTop（必要性：窗口溢出选 D 最小）→ {4,8,16} 三个 horizon 各自 argmin J
        → 多数投票 → 安全闸 → a*
```

这一层吸收了 **Codex 的"Handoff 摘要"**（到阈值就压）与 **AutoGPT 的"最近优先 + 保留关键类型"**（尾部 `K=3`、豁免关键工具法），但把它变成**经济学驱动**而非固定阈值——`Q / τ_switch / β / α_win` 让"当压才压"。

---

## 5. 确定性 + 按类型动态摘要（XEYO 强化点，`memory/summarize.py`）

Codex/Cursor 的"手写 handoff"，XEYO 改造成更省的版本——**一律不 fork LLM**，只在确定性不够时才升级 `session.md`：

| 内容形态 | 抽法 |
|---|---|
| grep / rg | 只留 `N matches in M file(s): path @line :: 样本` |
| 报错 / 栈回溯 | 首 4 行外层调用 + 尾 3 行内层调用与异常 |
| read / 文件 | 保留开头若干行 |
| bash / 长文本 | head + tail |
| 短内容 | 原样返回 |

并配 **r_summary 实测**：`live 语义 ≈ 0.583`、`离线术语留存 ≈ 0.687`、`字面下界 ≈ 0.275`（`memory/simulator/fidelity.py` 离线可测 + `memory_stack_eval --r-probes` 语义可测），让"该不该信这个摘要"有数字依据，而非沿用 0.6 假设。

---

## 6. 可回溯 + 跨会话（OpenCode/Cursor 强项，XEYO 加强版）

XEYO 不做"真删"，做的是**投影 + 可找回**：

- **会话内**：JSONL 不动，任何时刻可重压/重算（`compact_cursor` + `c2_summary_text` 冻结 + `working.json` 恢复）。
- **跨会话**：值得留的事实经 NightShift 过晋升闸进 L4，靠 `memory.search` 找回。
- **信源分离**：四种真相（Event / Task / Knowledge / Projection），UI 只是视图。

这比 OpenCode 的"时间戳隐藏"和 Cursor 的"历史存文件可 grep"更彻底——XEYO 连"隐藏"都不需要，原件就在盘上。

---

## 7. 调度：静默自动 + 手动兜底（Claude `/compact`）

- **自动**：公式驱动 + NightShift 空闲整理（`nightshift.py`：24h / Candidate 数 / 体积 / 冲突 四门闩 + 文件锁）。
- **手动**：**`/compact`（缺口①，放后面）**——自动阈值前用户想主动压时触发一次 C2 投影，回显"已压缩到 cursor N"。

## 8. 灰度与测量门槛（Codex / 质量验证）

C2 灰度前必须锁好三根"验收棒"（`python/scripts/memory_stack_eval.py` 已有）：

| 信号 | 门 | 现测 |
|---|---|---|
| 命中率 | 日 ≥95%，稳态 ≥98% | 140 轮尾窗 99.09% |
| 成本 | C2 相比 project 必须省 | live 约省 24%（超长档） |
| 质量 | `avg_Q ≥ 0.55`、`r/θ` | θ*=0.5，avg_Q=0.568 |

**灰度路径（保守，推荐）**：`XEYO_L5=project` + `XEYO_C2_GATE=1`——只对超长会话单开 C2，其余还是 C0+C1。**备选（实验通道）**：`XEYO_L5=v61` 每轮 decide。

## 10. 明确"不做"（防跑偏）

- ❌ 不删 Event Truth；不为找记忆再 fork 一轮模型；不为续命发空请求；不把 `MEMORY.md` 当事实库。
- ❌ 不学 Codex 用"删除 assistant/tool 换摘要"去动审计历史——XEYO 用投影层拿到同样效果，却永不丢原件。
- ❌ 不引入 MCP / Team 共享 memdir / GrowthBook 全家桶（`docs/10 §2.7`）。
