# 14 - 压缩保真度提升与验收计划

> 版本：v1.0 · 状态：计划（待执行）
> 关联：`docs/设计/13-压缩体系最终设计.md`（体系总纲）、`docs/设计/10-完整记忆体系.md`（公式 v6.1）、`docs/实施计划/12-压缩质量验证计划书.md`（质量/成本验证）、`docs/设计/XEYO评估.md`（LoCoMo 成本）
> 定位：把「压缩摘要对**取值/细节事实**保不住」这个根子修掉 → 用直接测量标定当前类型感知摘要 → 迭代优化 → 用 LoCoMo‑Refined 做记忆系统级验收。

---

## 0. 目标与成功标准

| 阶段 | 成功标准 |
|---|---|
| **A 取值保真** | 代码/文档的取值摘要能保留 `key=value` 事实；取值类语义 r 从 **0.1 → ≥0.6**；离线 `--measure-r-summary` 的 read 分型 r_term 与取值探针都改善 |
| **B 直接标定** | 产出对应当前类型感知摘要的 `r_summary / r_stub / θ* / 命中率 / 成本`，写入 `docs/12` 表D，`--apply-r` 回填 overlay |
| **C 迭代优化** | 连续 3 次测量循环，r（结构/取值）与成本/KV 同时不劣化 |
| **D LoCoMo 验收** | LoCoMo‑Refined 在 XEYO 记忆系统上达到可接受保留率（≥ 无压缩基线的 90%） |

**根因（已实测佐证）**：`docs/设计/10-完整记忆体系.md` §4.7 参数表（θ=0.35 / α_win=0.55 / τ_switch=0.85 / g=64 / β=8 …）被 Read 摘要压成 `140 lines :: 694→### 4.7 计算公式 v6.1…`——**只留标题、丢了取值**。取值探针：原始全文 **r=1.0**，当前类型感知摘要 **r=0.1**。

---

## Phase A — 解决「取值事实保不住」（先做，`python/memory/summarize.py`）

### A1：新增取值抽取
- 新增 `_extract_value_facts(lines, *, limit=8)`，识别并抽 `key=value` 事实：
  - 行模式：`^\s*[A-Za-z_][\w.]*\s*=\s*\S`、`^\s*[A-Za-z_][\w.]*\s*:\s*\S`、markdown 表格行 `^\s*\|[^|]+\|[^|]+\|`、`默认 X` / `default=X` / `(default: X)`。
  - 过滤：值去引号/注释；跳过 `None/True/False/[]/{}`；只保留值为"数字 / 短字符串 / 简单字面量"（高价值），避免把代码局部赋值当定义。
- `_read_summary` 改为**内容自适应**：
  - 命中取值 ≥ 该内容行数 10%（且 ≥3 条）→ **优先取值**：`{n} params :: {name}={value}, …`。
  - 否则走现有结构分支（`{n} lines :: 签名行 :: 头部`）。
  - 超长用 `_clip` 截断（首 + … + 尾）。

### A2：挂到通用长文本分支
- `extract_tool_summary` 的默认长文本分支（bash/其它）先试取值抽取，失败再 head+tail（守护"文件/命令输出含参数表"的通用情况）。

### A3：验证（离线，0 成本）
- 单测：`test_read_param_table_keeps_values`（§4.7 → 含 `θ=0.35`、`α_win=0.55`、`g=64`）、`test_read_code_constants_kept`、`test_value_not_over_generic`（普通代码段不误判）。
- 跑 `--measure-r-summary`：read 分型 r_term 目标从 ~0.078 → ≥0.3。
- 复测 ilink §4.7 取值探针（10 题）：当前摘要取值 r 从 0.1 → ≥0.6。

### A4：边界/失败
- 结构+取值并存时：60% 预算取值、40% 结构/头部。
- 用 `r_term` + `r_literal` 双口径确认抽取不劣化。
- 防误判：加 `_looks_like_code_local_var` 过滤（`self.` / 单字母 / 循环变量 / `tmp` 不当取值）。

## Phase B — 直接标定（`--r-probes` + `--hitrate-live`）

### B1：真实长会话（当前缺失，必须补）
- `run_hitrate_live` / `_real_session_api` 硬编码 `AB_REAL_SESSION = ~/.xeyo/sessions/sess_msy1p5ev_up68xw.jsonl`（**已丢失**），且分档需 **≥80 条**（ultra=api、long=api[:80]、medium=api[:45]）。现有 `ilink…` 仅 19 条，不够。
- **改动**：`AB_REAL_SESSION` 支持 `XEYO_REAL_SESSION` 覆盖（默认回退原路径）。
- **产出真实会话**：用 XEYO 自身跑多轮编码任务（实现+重构+测试跨多文件），让 agent 读多文件、产生 ≥80 条、含大 Read 与多轮，落盘 `~/.xeyo/sessions/`。成本约 1~3 元（标定投入）。

### B2：构建题库
- 为新增真实会话的**中间段 M** 生成 `scripts/probes/ab_real_probes.json`（沿用 schema `{id, layer, q, expect_contains[]}`，≥20 题×3 层 + `session_summary`）。取值题 ≥40%（对齐 Phase A）。
- 可先确定性抽取候选事实（路径/标识符/参数值/行号），再由 `--r-probes` 判答，人工抽检 ≥10%。

### B3：运行与落盘（带新 key）
- `--r-probes`：`orig / c2_det / c2_new / c2_sess / c1` 五档 → 各档 r，`r_probe_c2_new_*` 为头条。
- `--hitrate-live`：project vs c2 分档逐轮打 DeepSeek，记真实 hit/miss/cost。
- `--hitrate-clean`：复算干净口径（冷首轮 + 每轮增量 + 过渡全 miss）。
- `--theta-scan` + `--measure-r-summary`：θ* 与离线口径。
- `--apply-r`：把 `r_summary/r_stub` 回填 overlay（从真实源取值，不再被合成源拖低）。

### B4：边界/失败
- 无 ≥80 条真实会话 → 先降级构建源 + 临时缩小分档，并标注"非完整分档"。
- live 调用失败 → 记录 error 行，不中断整批。
- 若 Phase A 未达标、取值 r 仍低 → r_summary 取偏低值（反映真实），回到 Phase A 再修。

## Phase C — 不断优化（A/B 测量循环）

- **快循环**（0 成本）：`--measure-r-summary`，每次改摘要器/闸门后 30 秒读出 `r_term / r_literal / per-type`。
- **慢循环**：`--r-probes` + `--hitrate-live`，每次 Phase A 改动后跑一次。
- 优化项（按测量优先级）：摘要器（取值粒度、grep 统计、报错行数、max_text 分配）、闸门（θ、`c2_extend_decouple`、`c2_min_save_ratio`）、KV（命中率 ≥98%、长/超长成本省 ≥20%）。
- 各次测量写入 `docs/12` 表D，`--accept` 打勾形成可追溯记录。

**目标矩阵**：`r_structure ≥0.9`、`r_value ≥0.6`、`命中率≥98%`、`长/超长成本省≥20%`、`medium 不劣化`。

## Phase D — LoCoMo‑Refined 记忆系统级验收

- 前置：Phase C 达标。
- **接入**：`git clone https://github.com/mem-eval-suite/LoCoMo_refined`（`docs/设计/XEYO评估.md` 已列），取数据集（对话+问题），把 XEYO 当被测 agent（多会话/跨会话，触发 `memory/runtime` 投影 + `memory/memdir` L4 + `session.md` + `nightshift`）。
- **成本预算**：参考 LoCoMo 约 **1.88 元** + XEYO 推理额外开销 → **2~5 元**；先 `--limit 5`（子集）冒烟，再全量。
- **验收口径**：压缩/会话边界后，agent 对早期事实的回答准确率 ≥ 无压缩基线的 90%。结论写入 `docs/12`（表D）与 `docs/设计/XEYO评估.md`。
- **边界**：LoCoMo 测内存系统（L4/L6）而非仅压缩 r；若偏低，**回到 Phase C/A**（先修摘要保真/记忆治理，再复测）。

## 验收标准（分阶段闸门）

| 阶段 | 通过条件 |
|---|---|
| A | 取值 r（语义探针）0.1→≥0.6；`--measure-r-summary` read r_term ≥0.3；单测全绿 |
| B | 产出对应当前摘要的 `r_summary/r_stub/θ*` + 命中率/成本；表D 有记录；`--apply-r` 回填 |
| C | 3 次循环后 r_structure≥0.9、r_value≥0.6、命中率≥98%、长/超长成本省≥20%、medium 不劣化 |
| D | LoCoMo 保留率 ≥ 无压缩基线的 90%；成本 2~5 元内；结论写入 docs |

## 假设

1. 需要一个"真实长会话"（≥80 条、含大 Read、多轮）作标定源——当前缺失，Phase B 前置用 XEYO 自身生成。
2. DEEPSEEK 新 key（`sk-e90a…`）可用于 live 标定；成本预算 2~5 元（Phase B+D）。
3. Phase A 取值抽取用**确定性启发式**（key=value / markdown 表 / 默认值 + 字段过滤），不引入 LLM 抽取。
4. LoCoMo‑Refined 属**系统级**验收，不替代 `--r-probes` 对压缩公式 r/θ 的直接标定。
