## A.1 基础题（概念 / 原理）

### Q1. Agent 的「运行时内核」应该切几层？为什么？

**答**：XEYO 切三层——`QueryEngine`（状态容器 + 依赖注入）/ `query_loop`（**无状态 async generator**）/ `TurnRunner`（生产者-订阅者扇出）。三层切开的判据是**「谁持有状态」**：engine 持有会话态，loop 每轮重建，runner 只管分发。这样做的收益是**引擎不碰传输**——同一套 loop 可以跑在 HTTP/SSE、CLI 进程内、TUI attach 三种入口上。（第一册 §1.3）

### Q2. 同会话并发提交怎么防？用锁还是标志位？

**答**：用**布尔标志快速失败**，不是 `asyncio.Lock` 排队。理由：用户连点两次发送，正确行为是**第二次被拒绝并告知「正在处理」**，而不是排队等第一轮跑完（可能几分钟）。`finally` 里复位标志，**不等 finalizer**。（第一册 §1.4）

### Q3. 慢订阅者会阻塞生产者吗？

**答**：不会，直接踢掉。事件队列 `maxsize=512`，满即断开该订阅者。理由是**不能因为一个慢 UI 让整轮生成卡死**。（第一册 §1.6）

### Q4. 为什么模型层抽象只有一个方法？

**答**：`ModelClient` Protocol 只有 `stream()`（`model/client.py:9-15`）。不做「generate / chat / complete」那套——因为**流式是唯一需要的形态**：非流式只是流式的退化（收完再返回）。少方法 = 少抽象 = 厂商适配的边界更清楚。（第二册 §3.2）

### Q5. provider 是怎么选的？注册表吗？

**答**：**不是注册表，是 `if/elif`**（`server/session_pool.py:420-454`）：`fake` → `FakeModelClient`，`anthropic` → `AnthropicModelClient`，其余 → `OpenAICompatClient`。`PROVIDER_PRESETS`（`model/openai_compat.py:357`）**只是一张 base_url 表，不是类注册表**。面试里不要把它说成「可插拔注册表」。（第二册 §3.3）

### Q6. 为什么 Anthropic 必须写原生适配器？

**答**：6 条协议差异，**核心是 thinking 的「不透明签名」必须回传**——它是加密的，不能自己拼，也不能丢。走 OpenAI 兼容层就做不到。所以「有兼容层就万事大吉」是错的。（第二册 §3.4）

### Q7. 你们用了 prompt cache / cache_control 吗？

**答**：**全仓没有显式 `cache_control`**（只有 `anthropic.py:308` 一处注释）。缓存靠的是**「前缀逐字节不动」的结构保证**：静态 system 前缀只放不变的内容，一切易变内容走 T_now 尾插。这样厂商的自动前缀缓存自然命中。（第二册 §3.8）

### Q8. 上下文工程的核心三句话？

**答**：① 静态前缀只放**不变的**；② 易变内容**全部尾插**（不污染前缀）；③ 注入有**硬预算 + 硬准入**（T_now 登记表，机器执法）。（第二册 §5）

### Q9. T_now 是什么？为什么不用普通消息？

**答**：T_now 是「每轮可能变的模型可见内容」的注入管线。它把内容装进一对**仅存在于投影的伪造 tool 对**（`assistant(xeyo_env_notice) → tool_result`，`turn_context.append_env_notice_pair`）。好处：① 不进 MessageStore/JSONL；② 不进 tools 数组（schemas 冻结红线不受影响）；③ 尾部追加，KV 前缀逐字节不动；④ tool_result 是模型训练出的「环境声道」，**注入内容与用户意图在消息结构上隔离**，根治说话人混淆型漂移。（第二册 §5.4）

### Q10. T_now 有多少块？上限是多少？

**答**：**登记 20 块 / 常量 `T_NOW_BLOCK_HARD_CAP = 21`（`pre_llm_inject.py:826`）/ 执法断言是 `<=`** ⇒ 实际存在 1 个空位，与「硬顶=存量」的自述不符。对外统一口径就说这三个数。（第二册 §5.5.2，C-01 定论）

### Q11. env_channel 被厂商拒绝时回退到什么？

**答**：**回退 `skip`（本轮不注入），不是 `legacy`**。`t_now_strategy.py:65-79`：env_channel 被结构类 4xx 拒且未吐 chunk → 记进程级备忘 + 当场**以 legacy 重建重试**一次；但**如果连重建也不行，就 skip**。`ENV_FALLBACK_STATUS` 集合 = `{400, 404, 405, 413, 415, 422}`（**含 405**，AGENTS.md 漏写）。（第二册 §5.4，认知纠正）

### Q12. 工具面能在会话内热加载吗？

**答**：**不能，这是红线**。原生工具面 = **会话起点快照**，attach 时决定哪些 MCP 工具进 `schemas()`；此后 **tools 数组会话内冻结、零前缀重缓存**。会话内新增工具的唯一通道是 **`Mcp` 网关工具**（`action=list|describe|call`）。契约测试用**逐字节比较**锁死：`assert _schemas_bytes(reg) == before`。（第三册 §6.3；第九册 §24.3）

### Q13. 工具 schema 是自动生成的吗？

**答**：**手写**。因为 `description` 是**模型可见文本**——自动生成会失控，人写才能控词（「首句功能 → 参数 → 禁止项」）。（第三册 §6.2）

### Q14. 权限有三态？判定点有多少？

**答**：三态枚举在 `permissions/filesystem.py:32-35`。`evaluate_policy_impl`（`policy.py:1391`）实测 **11 个判定点**（「8 支」无依据）。**未知工具兜底 = ASK**（fail-closed）。（第四册 §9.2）

### Q15. 授权指纹含参数吗？

**答**：**不含**。`store.py:444`：`"v2:" + sha256(["mcp-tool", name])[:32]`，`args` 不进指纹（`:419`）。这是**有意的**——指纹只认身份 → 对参数注入免疫。`v2:` 前缀使 v1 凭据自然失效。MCP 工具名也一并归一。（第四册 §9.6）

### Q16. 指纹的 TTL 是多少？

**答**：**普通 180s / 危险 60s**——收紧即时、放宽延后；危险操作 TTL 更短。（第四册 §9.3）

### Q17. 记忆用了向量检索吗？

**答**：**没有**。全仓无 embedding / cosine / `np.dot`（`grep` 仅命中 `search.py:8` 一处注释的「非向量」说明）。检索 = 关键词 + **CJK ngram（不用分词器）** + sqlite 结构化过滤 + 重排。`search.py:1` 明令**禁止在检索层调模型**。（第五册 §12；第九册 §23.4）

### Q18. 记忆索引会自动注入上下文吗？

**答**：**不会**。`_memory_index_live_enabled()` 恒 `return False`（`engine/query_loop.py:356`，2026-09-09 用户裁决，源码含裁决注释）。记忆靠 **Memory 工具显式读写**。（第一册 §1.8，C-11）

### Q19. MCP 支持哪些传输？

**答**：**只有 stdio**（类型层面约束，`mcp_client.py:547`）。HTTP/SSE 只是预留。退避**随稳定性重置**（0.5→30s，10 次），`start()` **绝不抛异常**。（第六册 §14.1）

### Q20. DAG 调度器在产线上用了吗？

**答**：**没有**。`run_task_batch`（`scheduler.py:1054`）全仓仅被 `tests/` 调用；`SessionPool.scheduler_for`（`session_pool.py:887`）**零调用方**；`subagent_runner` 的 `decompose_tasks*` 也无外部调用方。
但**数据结构与工具函数已接线**：`Task` / `toposort` / `build_tool_whitelist`（被 `agent_tool.py:444` 引用）/ `repair_task_graph`（`subagent_runner.py:1032`，仅 dormant 链）。
统一口径：**「已实现 + 有测试 + 执行器未接线」**。多代理的产线路径 = `Agent` 工具 → `subagent_runner.run_subagent` → 每子代理一条独立 `query_loop`。（第六册 §15.3，C-04 定论）

### Q21. 前端状态用什么？为什么不用 Redux？

**答**：Zustand，**按领域切 store**（chat / settings / workspace / explorer / rewind / remote…）。`storeRefs.ts` 收敛跨 store 引用，避免循环 import。布局档位写到 `html[data-pane-layout]`，**由 CSS 负责切换 → 零 React 重渲染**。（第八册 §20.2/20.3）

### Q22. SSE 断线怎么处理？

**答**：两条。① **cursor 重连**：订阅 URL 带 `cursor`（`GET /v1/sessions/{id}/turns/current/events?cursor=`），重连只取增量不重放；② **60s 空闲看门狗**（`lib/api/core.ts:25/55`）——SSE 可能「TCP 没断但服务端不再发数据」，只看 `onerror` 发现不了。（第八册 §20.4）

### Q23. 本地后端端口为什么必须单 worker？

**答**：`workers=1`（`server/__main__.py:84`）是**架构约束不是偷懒**：`SessionPool` / `JobRegistry` / `InboxRegistry` 全是进程内单例，多 worker 会各自持一份 → 会话状态分裂。多入口共享靠**端口文件**（`~/.xeyo/backend_port`）而非多进程。（第七册 §18.3）

### Q24. 本地 API 的安全边界？

**答**：**两层**。① CORS **显式白名单**（9 项：5173×2 / 1420×2 / 1421×2 / tauri×3），注释明确写「不能用 `*`：`*` + 凭证是规范禁止的组合，且等于对任意网页开放本地 API」；② **loopback 门禁**（client host ∈ {127.0.0.1, ::1, localhost, testclient}，非本机 403，除非显式开 `XEYO_ALLOW_REMOTE_CONTROL` 且带 `X-Remote-Token`）。
关键认识：**CORS 是给浏览器看的，curl 之类完全绕过它**。（第七册 §18.2/18.5）

## A.2 项目题（「你做过什么」）

### Q25. 讲一个你最有技术判断力的决定。

**答（推荐：下线记忆自动召回）**：我们发现「记忆自动注入上下文」这个功能在真实使用中收益不明显、但每次注入都在消耗前缀稳定性和注意力预算。所以做了一个**明确的裁决：恒关**（`query_loop.py:356` 硬编码 `return False`），改成「模型显式调 Memory 工具读写」。
我的判断依据是：**能进注意力的东西必须有明确收益，否则就是负担**。这个决定的价值不在于「砍了功能」，而在于**我们把「记忆该不该自动进上下文」这个问题从默认开启变成了有证据才开**。（第一册 §1.8）

### Q26. 讲一个你定位过的真实 bug。

**答（推荐：transcript 轮转方向反）**：`session/record_transcript.py:81-97` 的 `_maybe_rotate` 归档链**搬移方向写反了**——`olds` 顺序是最旧→最新，代码先 `unlink(olds[0])` 再 `os.replace(olds[0], olds[1])`，导致 `.old2` 从不产生、**实际只保 1 代**（`_ROTATION_KEEP=2` 名不副实）。
定位方法：**逐行亲读 + 语义裁决**（两次子代理的反向读法都被驳回）。我的结论是「行号级取证可以外包，语义级裁决不可以外包」。
第二个同源 bug：`:134-140` writer 批次失败**仍推进 `_written_seq`** → `flush_transcript()` 假成功、静默丢整回合。（第四册 §10.1.3，C-05 定论）

### Q27. 讲一个你踩过并做了结构性修复的事故。

**答（推荐：薄壳 venv）**：发布事故——用户装完应用打开**连不上后端**。根因是 venv 的 `Scripts/python.exe` **只是一个 launcher**，真正的 DLL 和标准库在**构建机**上，拷到目标机后没有对应 Python → 启动即死 → 壳拉不起后端 → 前端误报「无法连接后端」。
**修复不是「下次注意」**：改用 python-build-standalone 的 `install_only` 包（自带 DLL + 标准库 + VC 运行时、可重定位），并加**构建期硬断言**（`build_slim_venv.py:348` `verify()`）：① `python.exe` 存在；② `python3xx.dll` 存在；③ `site-packages` 在 `sys.path`；④ `pyvenv.cfg` 的 `home` 必须是 `.`。
第二个坑：`pyvenv.cfg` 写成 `home = .`（**带空格**）会被解析成空基准路径 → 所有第三方包 `ModuleNotFoundError`。所以必须写 `home=.`，并用断言 4 钉死。
三问回答：**结构性根因** = 「拷过去能用」这个假设从未被验证；**让它不再发生的规则** = 装机正确性前移到构建期断言；**回归测试** = `verify()` 四条断言。（第八册 §21.4）

### Q28. 讲一个你发现的并发事故。

**答（推荐：容器路由的 ContextVar）**：容器路由早期用**环境变量**承载「当前是否在容器里跑」的身份。并发跑多个 trial 时，`os.environ` 是进程全局的 → **A 任务把环境改成容器态，B 任务读到的是 A 的容器身份** → 串容器。
修法：改用 **ContextVar** 承载容器身份（`tools/container_routing.py:19-29`）。ContextVar 天然按 async task 隔离，并发下不会串。
同类根因还出现在别处（`extension/reconcile.py` 的全局 digest 无 session key），统一口径是：**「进程全局」的东西在多会话/多任务环境下都是隐患**。（第三册 §7.5；第六册 §14.1.6，C-06）

### Q29. 讲一个「我们知道它没做完」的诚实案例。

**答（推荐：C-04 DAG 调度器）**：`scheduler.py` 有完整的任务 DAG 实现——拓扑排序、工具白名单、超时清扫、断点续跑，**还有测试**。但我在做审计时用全仓 grep 发现了两个硬事实：`run_task_batch`（`:1054`）只被 `tests/` 调用；`SessionPool.scheduler_for`（`session_pool.py:887`）**零调用方**。
结论：**它是「已实现 + 有测试 + 执行器未接线」**，产线上跑的多代理路径是另一条（`Agent` 工具 → `run_subagent` → 每子代理一条 `query_loop`）。
我的处理方式是把这件事**写进文档并给出精确接线表**，而不是含糊说「我们支持 DAG 调度」。**发现并披露未接线能力，比讲它能体现工程判断。**（第六册 §15.3.4）

### Q30. 你在成本上做过什么优化？

**答**：先定**成本不变式**：① **输出最贵**（官方口径输出占 51%，我们本地推算占 83%）；② **缓存命中占 token 量 86%、但只占钱约 12%**。⇒ **优化只盯输出 token**。
做法：工具结果治理（`pytest` 输出 token 1126 → **78**，−93.1%）、结果外置与回读、写代码精简注入块。
P2 全量 89 题新价 **¥26.48**，其中输出 ¥22.08（83%）——所以「省输入」基本没用，「省输出」才是杠杆。（第二册/第三册收益表；`changedetect/budget.py:18/21/25-29`）

### Q31. 讲一个你没上某项技术、但有实验依据的决定。

**答（推荐：不上向量检索）**：我做了 `evals/retrieval_bench.py`，纯离线、无 API，基线是词法检索，指标 hit@k。结果是**分层的**：code 域 **1.0（5/5）**，notes 域（中文自然语言）**0.4（2/5）**。
所以结论不是「向量没用」，而是**「向量该上的地方是 notes 检索，不是代码导航」**——代码符号是精确 token，词法够用；自然语言查询和笔记标题没有共享词，词法就不够了。
这个实验的价值是**把立场之争变成了可测的问题**，还如实暴露了短板。（第九册 §23.4）

### Q32. 你们的测试是怎么保证「全绿」是真的？

**答**：三点。① **xfail 只有一处**（`tests/test_bash_isolated.py:25`，且是 Windows pwsh 条件标记，不是永久挂账）；② **契约测试用逐字节比较**（`assert _schemas_bytes(reg) == before`），改一个字符就红，糊不过去；③ 提交门里有 **`evals.changedetect check`**（L0 模型可见文本面 + L1 决策轨迹，零成本、零假红）。
诚实的缺口：**没有 pre-commit**，本地门靠人跑，CI 只在 push 后生效。（第九册 §24.2/24.3/24.4）

### Q33. 你在前端做过什么性能设计？

**答**：TUI 的时间线**物理切两段**——`<Static>` 冻结区（历史消息，只渲染一次，之后从渲染树摘出去）+ 实时区（`streaming` 的 assistant / `running` 的工具）。
理由是 Ink 是**整屏重写模型**：如果历史参与 diff，一个 100 轮会话每来一个 token 都要重画 100 轮内容。
GUI 侧对应的是：**布局档位写 `html[data-pane-layout]`，切档位零 React 重渲染**。（第八册 §19.2/§20.2）

### Q34. 「换个入口就看不到历史了」，你怎么排查？

**答**：先怀疑**换了数据源**，不是丢了数据。我们数据三层：权威在**后端 JSONL**（`~/.xeyo/sessions/*.jsonl`），前端 IndexedDB 只是派生缓存。
而 IndexedDB **按 origin 隔离**：dev 是 `http://localhost:5173`，release 是 `http://tauri.localhost`（identifier `com.xeyo.agent`，`tauri.conf.json:5`）。**换入口 = 换 origin = 换库。**
排查顺序：① 看后端 JSONL 数据在不在（在 → 没丢）；② 看 `%LOCALAPPDATA%\com.xeyo.agent\EBWebView` 下有几套 `http_*` 目录（有几套就有几个 origin 的库）；③ 结论 = 前端读的是另一个库。（第八册 §21.7）

## A.3 系统设计题

### Q35. 设计一个「本地 Agent 的多入口共享后端」。

**答**：核心决策三个。
① **单进程单 worker**（`workers=1`），因为引擎状态在进程内存里（会话池/任务注册表/收件箱都是单例）。
② **端口文件互相发现**：`~/.xeyo/backend_port` 写 `{port, pid, started_at, engine_version}`；端口被占时从 requested 起**探 50 个**；僵尸按 pid 存活清理。`engine_version` 用于**防「旧壳连上新后端」**。
③ **桌面壳先探测再拉起**：`wait_health(3s)` 成功就复用，失败才 spawn；守护线程每 10s 探活，**连续 30s 不健康**才杀进程树重启（避免启动中误判导致重启风暴）。
（第七册 §18.3；第八册 §21.1）

### Q36. 设计 Agent 的「回滚到某一轮之前」。

**答**：三件事——**存什么 / 怎么找 / 怎么原子**。
存什么：**内容寻址 blob（SHA-256）**+ 每轮 COW 检查点（检查点本体只是 `[[path, hash]]` 清单）。
什么时候存：**用户消息发出、模型动手之前**冻结（回滚语义 = 「回到你还没改之前」）。
怎么原子：每步写独立 journal；transcript 重写走**临时文件 + rename**；进程中途崩了，lifespan 里 `mark_crashed_rewinds` 标成 `recovery_required`。
GC：默认 **dry-run**（要显式 `XEYO_BLOB_GC_ENABLED=1`），可达集 = 「保留检查点 + 保留 turn + **锚点**」引用的全部 hash；提供 **`anchor` 端点**让人把「这个状态有用」变成 GC 的可达性输入。
（第七册 §16）

### Q37. 设计「Agent 改了 20 个文件后要撤销」，和 git 有什么不同？

**答**：**语义不同、边界不同**。
语义：git 的提交粒度是「你想提交什么」，我们要的是「**每一轮自动冻结**」——用户不会为每轮 commit。
边界：仓库可能有 git（那我们就用 `workspace_revision` 读它的状态），也可能没有；**回滚必须对「无版本控制的目录」也成立**，所以底层是自建内容寻址存储，不是 git。（第七册 §16.7 追问 1）

### Q38. 设计「会话内的后台长任务」，要点是什么？

**答**：四条。
① **输出无上界 → 环形缓冲 + 游标**（`_Ring`，内存有界，模型每次只读新增部分）。
② **唤醒而非轮询**：`JobRegistry.consume_wake`，整条路径挂在**回合结算枢纽**（单一回调槽 + 三租户 inbox/goal/jobs 分发 + 异常全隔离）。
③ **物理上限**：默认 **6h**（`JOB_NO_TIMEOUT_MS`），挡住「卡在等 stdin 的僵尸」这类 runaway job。
④ **owner 即安全边界**；**后台 job 不随会话 abort 级联**（`job_registry.py:255` 注释明说），要停必须显式 `job_kill`。
（第七册 §17.3/17.4；第十册 §25.8）

### Q39. 设计「长任务自动接着做」。

**答**：三层。① **Goal** 落盘、跨轮存活（`goal_state.py:70`，`GoalStore:268`）；② **轮驱动** `GoalRoundDriver` 在每轮结算后判断要不要续（`on_turn_settled:204`）；③ **合成轮** `synthetic_round` 负责「代人类发一轮」。
最关键的细节：合成轮必须**复现上一轮人类请求的环境**（`note_request_env:41` / `env_for:49`），否则模型会看到「一轮没有人类指令的对话」，行为会漂。
两条刹车：**单会话至多一个在途合成轮**（防抖 + 复检）；**人类消息一到就让位**（`yield_to_human:164`）。（第七册 §17.2）

### Q40. 设计「多 Agent 并行改同一个库」。

**答**：**进程内子代理**和**跨进程 worker** 两种范式，各自解法不同。
进程内：子代理 = **独立 `query_loop` + store 独立 + abort 共享**；消息 **park 不打断**；结算走**单一槽 + 三租户分发**。
跨进程（`coord/`）：DAG 入表 → **CAS 认领 + scope 路径租约** → 每 worker **独立 worktree** → **唯一可写主分支的 reconciler 做三路合并**（串行收敛）→ findings 打回，`REOPEN_LIMIT=3` 熔断转 blocked。
（第六册 §15.2/15.4）

### Q41. 设计一次「改动收益验证」。

**答**：三层金字塔，噪声从零到有。
**L0 surface**：模型可见文本面（system / tools / T_now / slash manifest）字节级快照，**1 字符灵敏、零成本**，进提交门。
**L1 trace**：引擎决策轨迹（注入载荷 + FakeModel 回放事件），**分支级灵敏、零成本**。
**L2 ab**：真模型配对 A/B（McNemar + bootstrap），**必须自报 MDE**，低于 MDE 一律标 `inconclusive`；**不传 `--budget` 直接拒绝运行**（先看报价再决定）。
诚实边界：L0/L1 只能告诉你「变了」，不能告诉你「变好了」。（第九册 §23.7）

### Q42. 设计一套「评测防自欺」机制。

**答**：四道守卫 + 一条报告纪律。
① **报告口径**：禁止只报单一 `accuracy`，必须带 standard/strict/Δ/leakage_rate 四字段（防混「纯编码」与「编码+检索」）；② **严格环境**：评测前隔离 git 历史（防偷看提交记录）；③ **污染门**：环境不干净就拦；④ **盲审**：transcript 送第三方盲审。
共同约定：**fail-open**（守卫自己出问题不能把分数搞丢）。
**主动披露**：这四道守卫的 docstring 写「默认关」，但实现上因为全局升格谓词默认 `True`，**未设专用 env 时实际是开的**——文档与实现已经对不上。（第九册 §23.8）

## A.4 场景题

### Q43. 模型陷入死循环调同一个工具，你怎么处理？

**答**：三道防线，**红线是「永不拒绝执行」**：`RepeatCallGuard` 在 3/5/8 次逐档**建议**；`ZeroHitTracker` 检测「换花样但全零命中」；`IdenticalResultFold` 把「同签名 + 输出逐字节相同」连续 3 次**折叠**成一行。
不阻止执行的理由是引擎理念：**限制只在执行层表达，不替模型决策**。结果照给，但让模型看见「这是第 3 次相同结果」这个事实。
不误伤的保证：判定用**语义 key**（Grep/Glob 归一化引号/路径/默认参数），并有**分页续读豁免**（`is_pagination_continuation:146`）——宁可漏报，不可错杀。（第十册 §25.5）

### Q44. 上下文快爆了怎么办？

**答**：三级 + 一个质量门槛。
**C0 / C1 / C2**：C1 是**无损占位**（`[compacted] name: prior result … archived`，原文不删，模型可以重新调工具拿）；C2 是**有损摘要**。
**信任语义不同 → 门槛不同**：C1 无损所以便宜、先做；C2 有损所以必须先过**质量门槛 `Q ≥ θ`**（`memory/runtime.py` 的 `decide`）。
**语义豁免优于时间豁免**：计划与用户原话**永不压**。
**决策权归属**：`XEYO_L5` 默认 `project`，**不是每轮 decide**——避免频繁决策本身成为开销。（第五册 §11.2/11.3）

### Q45. 用户发消息时后台任务正好完成了，会怎样？

**答**：两个机制可能同时想「提交一轮」，需要让位。
① **`yield_to_human`**（`server/goal_round_driver.py:164`）：语义是「**人类消息让位**——作废在途的合成轮预约」，`chat.py:742` 在 busy 闸之前调用。
② **`session_presence` notice**（`session_presence.py:325`）：语义是「**多会话/多 Agent 同时改文件** → 广播冲突事实」。
⚠ 这两个**同名不同责**，很容易讲混。能说清「一个管人机让位、一个管多会话冲突」，说明是读进去的。（第七册 §17.5）

### Q46. 工具返回 200 万 token 的输出怎么办？

**答**：**不让「无界的东西」直接进上下文**。
① 超阈值（**16000 字符**，Bash/Read 豁免）→ **落盘 + 路径回引用**（`tools/spill.py:86/98/111`）；
② 后台任务输出走**环形缓冲 + 游标**；
③ 长文档用**折叠视图**（实测返回 token 9728 → 6992）。
⚠ 已知软肋：`offload_read_tool.py:46-62` **无独立的权限/路径校验**（hidden 工具，execute 只做 abort + `is_file` 检查），依赖「模型不会幻觉调用 hidden 工具」。（第三册 §6.5，C-08）

### Q47. 用户说「你刚才那个功能怎么没生效」，你怎么查？

**答**：先分**「显示 == 生效」**这一类问题。我们有专门的 `memory_switches.py`，原则是 **settings 为唯一权威，环境变量不再参与**（`get_value:157-174` 明写）。
但有两个真实的「显示与实现不一致」案例必须知道：
① **诚实度守卫**：docstring 写「默认关」，实际因全局升格谓词默认 True 而**默认开**（第九册 N9-6）；
② **厂商权威用量**：文档说「双口径」，实际 DeepSeek 通路 `vendor_ok` 恒 False，**只有本地口径**（第九册 N9-1）。
排查第一步永远是：**grep 这个开关名有没有真的注册进 `memory_switches`**。（第九册 §22/§23.8）

### Q48. 模型回复里提到了一个我没说过的斜杠命令，你怎么看？

**答**：这是我们的**漂移类别 L543**——「跨任务幽灵 slash 引用」：回复里出现本轮用户文本中根本没有的 slash 命令。
同族漂移还有 **L404**（说话人混淆：把注入块当用户说的）和 **L475**（元叙事税：不干活、讨论注入本身）。
⚠ 注意这三个是**漂移类别代号，不是行号**（`drift_judge.py` 只有约 282 行）。
判定分层：**正则层离线 ¥0**（首选）+ **LLM 复核层**（`--live`，只有正则不确定时才用）。（第九册 §23.5）

### Q49. 安全审计说你们的 Bash 能执行 `rm -rf .`，怎么回应？

**答**：**承认，这是真实缺口**（C-07，逐行正则实证）。
`permissions/bash_policy.py:22-36` 的根删黑名单**只防 `/`**，正则锚定方式导致 `rm -rf .` / `rm -rf *` 在默认档 **ALLOW**，而且绕过 `.git` / `.xeyo` 元数据守卫。
正确回应是三段：① 这是**已知且已披露**的缺口，不是「没这回事」；② 它不是唯一防线（还有路径边界 realpath、写作用域、审计留痕）；③ **修法是补充正则 + 回归测试**，不是「注意点」。
同类还有：`bash_readonly_allow` 无工作区边界（`bash_policy.py:631-648`）→ Bash 只读白名单成了 Read 路径狱的旁路。（第四册 §9.4.2）

### Q50. 为什么选 SSE 而不是 WebSocket？

**答**：因为**单向推送**（服务端→客户端）+ 已有 HTTP 栈。重连语义天然（HTTP 请求重发），带 `cursor` 就能续订取增量。
代价是双向要靠**额外的 POST 端点**（`/v1/interrupt`、`/v1/slash`）——这个代价我们接受。（第八册 §19.3）

### Q51. 远程通道（微信）为什么只跑最终回合？

**答**：`FinalOnlyRunner`（`channels/runner.py:192`）。三条理由：① 微信的**交互节律不同**（用户不会盯着看工具调用过程）；② 中间过程（工具调用、权限询问）在远程渠道**没有合适的 UI 表达**；③ 所以远程是**降级形态**：能力受限但可用。
代价如实说：远程用户**看不到过程、无法中途审批**。（第八册 §21.5）

### Q52. 桌面应用装到用户机器上打不开，怎么分层排查？

**答**：三层——**壳能不能拉起进程 → 进程能不能跑起来 → 跑起来能不能通**。
① 壳错误槽：`BACKEND_SPAWN_ERROR` / `get_backend_error`；
② 解释器是否**真正可用**：`python_exe_usable()`（`lib.rs:266`）真的跑一次 import 探测，不只看文件在不在；
③ 端口文件 `.xeyo/backend_port`。
根因案例见 Q27（薄壳 venv）。（第八册 §21.9 Q1）

## A.5 编码题

> 这类题考的是「能不能在 30 分钟内写出正确的骨架」。答案给的是**判分点**，不是完整代码。

### Q53. 写一个「只读并发 / 写串行」的工具并发编排。

**判分点**：
① 分区判定与加锁判定**同源**（同一个 `is_concurrency_safe` 标记驱动，不许两套逻辑）；
② 只读工具并发、写工具串行，读写之间加**读写锁**；
③ **并发上限 10**；
④ 不安全的工具**串行 + 加锁**；
⑤ 并发结果**保序**（模型看到的结果顺序必须与 tool_use 顺序一致，否则模型会错配）。
证据：`tools/orchestration.py:31/85/247/304`。（第三册 §7.3）

### Q54. 写一个「工具结果超阈值落盘 + 路径回引用」。

**判分点**：
① 阈值 **16000 字符**；**Bash / Read 豁免**（它们的输出模型必然要全文）；
② 落盘后返回**路径 + 摘要 + 保留期**（不是只给路径）；
③ 路径必须可用 `Read` 读回（回引用闭环）；
④ 落盘失败要**降级为截断**，不能整条结果丢失。
证据：`tools/spill.py:86/98/111`。（第三册 §7.4）

### Q55. 写一个「事务化文件写入」。

**判分点**：
① 意图与操作分离：`ChangeIntent` / `EditOp`（`engine/write_store.py:31/47`）——这是**回溯可用的前提**；
② 写入走临时文件 + `os.replace`；
③ 写前记 rewind 前置快照；
④ 写后追加审计事件；
⑤ **失败要回滚到写前状态**，不能留半写文件。
（第七册 §16；第四册 §10.1）

### Q56. 写一个「流式工具参数拼接」。

**判分点**：
① tool_call 的 `arguments` 是按 chunk 增量到达的**字符串片段**，必须累积；
② **JSON 能解析就 emit**（不等流结束）+ **去重**（同一 index 只发一次）；
③ 处理「同一 index 的 name 只在首个 chunk 出现」；
④ 流中断时未闭合的调用必须在收尾时补齐（配对修复）。
证据：`model/_openai_common.py:57/81/127/137`；`anthropic.py:329/404/433/452`。（第二册 §3.5）

### Q57. 写一个「未配对 tool_use 的修复」。

**判分点**：
① 扫描 assistant 消息里的 `tool_use`，找没有对应 `tool_result` 的；
② 补一条**错误结果**（不是空结果）：运行期 `[tool aborted]`；hydrate 期**只读工具 → `TOOL_NOT_STARTED`，其他 → `TOOL_OUTCOME_UNKNOWN`**；
③ ⭐ **不能统一标「未执行」**——写操作的副作用不能假设为未发生，这是本题最关键的分点；
④ 只在 submit 入口 + abort 路径各做一次，**不要每轮全量扫**。
证据：`query_loop.py:218/244/707`；`session/hydrate.py:73`。（第十册 §25.7）

## A.6 排错题

### Q58. 提交门在本地过了，CI 挂了，可能是什么原因？

**答**：三个高概率方向。
① **CI 少一步也少环境**：本地 `check.ps1` 跑 `evals.changedetect check`，CI 的 python job **不跑**这一步——所以 CI 挂的原因通常**不是**这一步，而是环境差异（CI 是 ubuntu + py3.11 + node20）。
② **平台差异**：`tests/test_bash_isolated.py:25` 有 Windows pwsh 条件 xfail —— 反过来，Windows 本地过、Linux CI 挂是经典情形。
③ **缓存/依赖**：CI 用 `pip cache` / `npm cache`，本地 `npm ci` 在有 `node_modules` 时**被跳过**——依赖漂移本地发现不了。
正确动作：本地重跑一次**清空 node_modules** 的完整门。（第九册 §24.1/24.4）

### Q59. 测试莫名其妙过/不过，怀疑测试污染，怎么查？

**答**：先看隔离设施有没有生效。`python/tests/conftest.py:5-25` 把 **5 个数据目录**（`XEYO_SESSIONS_DIR` / `XEYO_USAGE_DIR` / `XEYO_HOME` / `XEYO_SNAPSHOTS_DIR` / `XEYO_SPILL_DIR`）**全钉到 tmp_path**；还有 ContextVar 权限模式复位（`:28-39`）、单例重置（`:99-126`）、sidecar `unapply`（`:129-144`）。
如果新写的测试**没有走 conftest 的 fixture** 就手动改了环境变量，就会漏出隔离网——这是最常见的污染源。（第九册 §24.2）

### Q60. `py -3.11` 跑 pytest 正常，managed python 3.13 报 collection error？

**答**：**预期行为**。managed py3.13 **缺 fastapi** → collection error。项目要求 **`>=3.11`**（`python/pyproject.toml:9` `requires-python`），且 `XEYO.bat` 里断言 `sys.version_info[:2]==(3,11)`。
统一口径：**所有 pytest 结论必须用 `python/.venv/Scripts/python.exe` 或 `py -3.11`**。另外沙箱内全量 pytest 不可靠（竞争假失败），单跑要加 `--basetemp=<全新路径>`。（项目记忆 + 第四册 §10 附注）

### Q61. 一个 MCP 工具在会话中途被禁用，模型还在调它，会怎样？

**答**：**DENY，且不可被 grant 穿越**。
`permissions/policy.py` 的**「停用即 DENY」分支先于 grant 两分支**判定，`移除→DENY` 门。模型即使幻觉调用（schema 里还留着名字），执行路径会返回 `permission_reason == "mcp_disabled"` 的 DENY。契约测试专门锁这个：`test_disabled_server_execution_path_survives_freeze`（`test_freeze_invariants.py:149-165`）。
换句话说：**「会话内不新增工具」管的是 schema 冻结，「停用即时生效」管的是执行**——两件事分开做。（第六册 §14.1；第九册 §24.3）

### Q62. 你们的「工具面变更」提示在多个会话里串台了，怎么定位？

**答**：查 `extension/reconcile.py:21/23` 的 `_PENDING` / `_LAST_DIGESTS` —— 它们是**模块级全局**，键只有 `kind` 字符串，**没有 session key**。
后果：多会话并行时，A 会话的「工具面变更」活页块可能被投给 B 会话（措辞像「用户停用了 X」）。
这和 Q28 的容器路由串台是**同源根因**：进程全局状态在多会话下就是隐患。修法：按 session 隔离。（第六册 §14.1.6，C-06）

### Q63. 网关日志显示「占用无上限」，是哪里在泄漏？

**答**：查 `engine/process_ledger.py` 的孤儿回收。`sweep:237` 做孤儿回收 + **grace 60s**；`reap:200` 先 probe（死 → 静默除名，活 → cleanup）；Windows 用 `taskkill /T /F`（`:100`）。
⚠ **但这个台账默认是关的**（`XEYO_PROC_LEDGER`，`bash_tool/runner.py:312`），而且**没有实时消费方**——它只在 CLI `selfcheck` / `snapshot`（`:374`）里看。所以「我们有进程台账」这句话要加限定。（第九册 §22.4，N9-4）

### Q64. 用量页面显示的成本和我自己算的对不上，查什么？

**答**：四个可能，按概率排序。
① **口径不一致（最可能）**：评测侧用**新价**（hit 0.02 / miss 1.0 / out 4.0，`changedetect/budget.py:18`），运行时定价表仍是**旧价**（flash 低峰 `(0.05, 1.5, 4.5)`，`pricing.py:26-29`），且带 peak×2。同一会话两个页面会系统性偏差。（第九册 N9-5）
② **峰谷时段**：北京 09–12、14–18 是高峰（×2），跨了时段就对不上。
③ **归因**：账本按 `vendor` 而非 `provider` 计费——如果 base_url 被改过，归因可能换了厂商。
④ **`_MAX_LINES = 80_000`**：账本超 8 万行后是**截断**而非全量（`usage/ledger.py:16`）。
（第九册 §22.1）

### Q65. 用户报告「回滚之后文件和历史对不上」，你的第一反应？

**答**：先确认是**哪条轨道**的回滚——rewind 有**三代并存**：v2（`service.py:266`，保留作**降级路径**）、v3（`hotpath.py:328` + `index.py:128`，**当前主路径**，GUI 的 `rewindV3Store.ts` 对接它）、v4（`index.py:573` `sync_index_from_ledger`，**索引与 journal 的一致性修复层**）。
然后按已知边界排查：**回滚是按消息锚定的**（`GET .../rewind/checkpoint/{mid}` 按消息取检查点），所以文件和历史本应一起走；但 **C-09 的三条旁路**（`workspace_fs.py` 直写 / `write_store.py` 写路径 / 后台 job）**不经过 rewind 检查点**——如果用户是通过 GUI 保存或后台进程改的，回滚覆盖不到。
⚠ 注意：C-09 里「后台 bash job 无事实超时」这一子项**已修复**（现在默认 6h 上限，见第十册 N10-1），但「不经权限/rewind/审计」仍成立。（第七册 §16.2/16.7；第八册 §18.8）
