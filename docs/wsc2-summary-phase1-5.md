## 0. 一句话总账

**结构状态层（文件版本 / 未解决错误 / 请求 / todo）已被证明能用 deterministic 增量做出来：
四路事后召回 1.000、版本错配 0、增量成本 µs 级且不随历史上升，热层状态段只有 V1 的 0.17×（逐点均值口径）。
但 #43 重算后要说清：干净口径下 V1 的 file 召回 mean 0.988 ⇒ 两臂实质打平，
"V2 赢在召回"是探针 bug + sid 污染造出来的；而"去噪靠删""传输层省钱"两条路都被实测判死，
压缩率也从收益项降级为代价项。**

> ⚠️ **本文件所有 V1 侧数字已按 #43 重算并更正**（过程见 `docs/wsc2-phase5.md` §8–§9）。
> 三个探针 bug 叠在一起才造出旧值：① 跨点共用 `session_id` → V1 头被进程内 `_STATE` 冻结头污染
> （抬高 40.6%；证据要遮掉句柄里的 session 文件名再比，第一版拿逐字比得到的"0/126 相同"无效）；② `v1_hit` 只 casefold 了 haystack 没 casefold needle
> → 大写路径永不命中，V1 file 召回被误报 0.751；③ 聚合助手把中位数取整到 1 位 → 4.4% 被打成 0。
> **规则**：跨点采样禁止共用 sid；引用任何比值必须同时写聚合口径（逐点均值 / 中位除中位 / 总量比）。

## 3. 判死 / 回退清单（六项，全部有数）

1. **传输层（Phase 4 整层）**：稳态命中 0.999 ⇒ 排序与差分台账没有钱。T4-1 改动**已回退**（patch 存 `_wsc_out/t4-1_ordering.patch`），T4-2…T4-5 作废，未花钱。
2. **臂②相关性寿命真删**：不存在零误删阈值，积极删反而拉低主指标 ⇒ 保守 KEEP 保住。
3. **压缩率当收益指标**：换算后折叠净亏 ⇒ 降级为代价项（够用就折）。
4. **V1 句柄上限**（更早的 #18）：¥0.00007/枪，省钱不成立。

6. **V1 段内路径行合并（真接生产路径后）**：模拟说 −16.8%，真路径只有 **−4.26%**，
   且"句柄行不降 / 被丢路径仍可见"两条不变量在真实路径上守不住 ⇒ **代码已撤回**
   （留档 `_wsc_out/dedup.py.bk`），见 `docs/wsc2-phase5.md` §7。

- **V1 臂所有绝对尺寸与以它为分母的比重要重算**（跨点共用 `session_id` 被进程内会话状态污染：
  共用 sid 15.0k vs 每点唯一 sid 10.8k tok/点）。V2 臂不受影响。零成本，但**重算前不许引用**。
- ~~**V1 旧口径数字待重测**~~ ⇒ **#43 + §9 已全部重算完**：Phase 3 句柄占比 **6.9%**（旧 15.6%）、

  不能拿 60 个前缀快照相加；② **度量台自检未落地**——"同一输入在共用 sid / 唯一 sid 下不等 ⇒ 拒跑"
  这条还没写成探针里的硬闸，目前只靠人记得（最容易被下一次会话破坏的一条）。
- **约束/决定类**：V2 只做到"有来源、寿命未定"，**没有能认改写的复用尺** ⇒ 该类 Recall/Precision 至今无分母。

- **折叠当枪的厂商样本只 1 会话 12 次**（工单 #11），任何"折叠经济学"的普适说法都没底座。
