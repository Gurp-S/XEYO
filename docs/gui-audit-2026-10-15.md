# XEYO GUI 审计（2026-10-15）

## 结论与范围

最先处理两处可复现的整窗崩溃，其次修正界面给出的错误信息，再收拢轮询、设置页挂载和工作区重复实现。视觉问题主要集中在小窗布局、字号与灰色层级、设置的信息组织；没有必要推倒现有主题系统和聊天渲染体系。

本报告把发现归并为 **27 个修复/整理项**，其中两项 P1。它们包含已复现缺陷、源码确认的行为、待测性能风险和设计建议，不能全部理解为已经证明的性能事故。

- **P1**：常规操作可导致整个界面不可用。
- **P2**：影响正确性、可用性，或有明确资源浪费路径，适合近期处理。
- **P3**：维护成本与体验优化，按收益安排。
- **浏览器复现**：隔离 Chromium 中实际操作/注入固定数据所得。
- **源码确认**：实现路径明确，但不等于已验证真实后端或生产性能。
- **建议/待测**：需要产品选择或生产 A/B 数据。

覆盖方法为全局清点、关键路径深读和浏览器抽验。清点 `gui/src` 下 393 个非测试 TS/TSX 文件（包含生成代码、基准入口等，不能称为 393 个生产业务模块），约 8.7 万行；33 个 CSS 文件，约 1.05 万行。数量仅用于定位维护热点，不是质量分数。

检查了应用入口、聊天与输入框、侧栏、工作区文件/Git/终端/命令记录、文件预览与 Markdown、模型选择、设置、用量/扩展/诊断入口，以及相关 store、API 门面和样式组织。浏览器检查包含 1440、1280、960、800、720 像素窗口和浅色/深色主题。720×480 是当前 Tauri 配置允许的最小窗口，并非任意手机适配要求。

边界：运行的是 Vite 开发构建；业务 HTTP 接口被拦截，使用固定响应或离线错误；没有请求真实模型，没有执行终端命令。未验证 Tauri 原生能力、真实后端成功链路、生产包启动速度和长期内存曲线。没有跑全量测试或把源码阅读当成测试通过。没有修改业务代码；保留了审计前已有的 GUI 混合改动。

## 第一批：正确性与交互

### F01 · P1 · 关闭“流畅”可让整个 GUI 崩溃

**证据：浏览器复现 + 源码确认。** 没有打开文件预览时，把设置的 `smoothness` 从启用改为关闭，整个应用进入错误页：`Rendered fewer hooks than expected`。主审计通过设置 store 触发与开关相同的状态变化；未把后来未运行的真实开关点击补充脚本计入证据。

结构性根因是 [FilePreview.tsx:770](<D:/lea/XenYon code/gui/src/components/FilePreview.tsx:770>) 在 `!smoothness && !mounted` 时提前返回，但 [789 行](<D:/lea/XenYon code/gui/src/components/FilePreview.tsx:789>) 后还有 `useContext`、`useCallback`、`useEffect`。渲染条件变化改变了 Hooks 调用数量。这不是代码高亮性能问题，也不能靠捕获异常治本。

**结构规则与低复杂度修法：** 全部 Hooks 必须在条件返回之前；或者拆成无条件挂载的状态容器和可按需挂载的预览内容。不要为这个问题新增复杂状态机。

**验证：** 旁路前后使用相同用例，覆盖流畅开/关、预览开/关，以及以关闭状态启动后打开再关闭预览；断言没有 Hooks 异常且文件关闭保存语义不变。

### F02 · P1 · 空会话打开“命令记录”会无限更新并整窗崩溃

**证据：浏览器复现 + 源码确认。** 冷启动、`activeId=null`、会话数为 0，点击“更多工作区工具 → 命令记录”，报 `Maximum update depth exceeded`，同时有 `getSnapshot should be cached` 错误。

[WorkspaceToolPanel.tsx:74](<D:/lea/XenYon code/gui/src/components/WorkspaceToolPanel.tsx:74>) 的 Zustand selector 在没有消息时每次创建 `[]`。对于当前订阅机制，相同状态得到不同引用，形成更新循环。

**结构规则与修法：** 空集合快照保持引用稳定。可以直接沿用 [useMessageListStore.ts:14](<D:/lea/XenYon code/gui/src/hooks/useMessageListStore.ts:14>) 的 `EMPTY_MESSAGES` 模式，或订阅可空原值后在 hook 外兜底。无需改造整个 store。

**验证：** 同一组测试覆盖无会话、会话历史尚未加载、有消息三种情况，检查可正常进入、退出和切换会话。

### F03 · P2 · Git 文件状态被转换丢失，所有类型都显示为 M

**证据：浏览器复现 + 源码确认。** 固定响应包含新增 A、删除 D、未跟踪 ?? 三种文件，实际行文本均为 M。

[WorkbenchChanges.tsx:39](<D:/lea/XenYon code/gui/src/components/review/WorkbenchChanges.tsx:39>) 把 staged/unstaged/untracked 合成 `ChangedFile` 时丢掉状态；[44 行](<D:/lea/XenYon code/gui/src/components/review/WorkbenchChanges.tsx:44>) 只按 `created ? 'A' : 'M'` 展示，而前面的转换没有填写 `created`。问题在数据模型转换，不在颜色或图标。

**修法：** 保留 Git 状态的独立视图模型，复用已有 Git 状态行的展示能力；会话工具改动与 Git 工作树改动只复用外壳，不强行共用会丢信息的数据类型。

**验证：** A/M/D/R/??，同一文件同时有暂存与未暂存变化；核对状态、文件打开和 diff 来源。不要只测试三个字母是否显示。

### F04 · P2 · “复制命令”复制的是参数 JSON

**证据：浏览器复现 + 源码确认。** 输入为 `{"command":"echo hello"}` 时，界面显示 `echo hello`，剪贴板拿到的却是整个 JSON。

[WorkspaceToolPanel.tsx:43](<D:/lea/XenYon code/gui/src/components/WorkspaceToolPanel.tsx:43>) 已解析 `commandDisplayText`，但 [134 行](<D:/lea/XenYon code/gui/src/components/WorkspaceToolPanel.tsx:134>) 按钮复制 `c.input`。

**修法：** “复制命令”使用与显示一致的命令字段；若确实需要原始输入，另设明确命名的“复制工具参数”。顺带收紧命令历史收集条件：目前收集工具输入的范围比 shell 命令更宽，不要把所有工具输入都视为可执行命令。

**验证：** JSON command、纯文本、非 shell 工具输入三类，分别检查显示与复制契约。

### F05 · P2 · 模型列表截断后又用截断长度冒充总数

**证据：浏览器复现 + 源码确认。** 登记 8 个模型，当前选中第 8 个；打开列表只见前 5 个，底部写“5 个已登记模型”，当前模型不在默认列表中。

[ModelPicker.tsx:104](<D:/lea/XenYon code/gui/src/components/ModelPicker.tsx:104>) 无搜索时 `slice(0, 5)`，有搜索也最多 40 个；[302 行](<D:/lea/XenYon code/gui/src/components/ModelPicker.tsx:302>) 使用截断后的长度。用户可以搜索其他模型，但界面没有正确说明列表不完整。

**修法：** 小规模模型列表直接滚动展示全部；若必须限量，显示“当前展示 / 匹配 / 总计”并提供展开入口。当前选中项应可见。模型选择身份也应包含账号，不能只比较 provider 和 model。

**验证：** 0/5/8/超过 40 个模型、当前项在尾部、同厂商不同账号同名模型。

### F06 · P2 · 第二条消息的标题链接可能跳到第一条消息

**证据：浏览器复现 + 源码确认。** 两条消息各有“相同标题”及其锚点，页面产生重复标题 ID；点击第二条的链接，实际滚动目标为第 1 个标题。

[XyStreamdown.tsx:78](<D:/lea/XenYon code/gui/src/components/XyStreamdown.tsx:78>) 和 [MarkdownView.tsx:39](<D:/lea/XenYon code/gui/src/components/MarkdownView.tsx:39>) 使用全局 `document.getElementById`，而标题 ID 的唯一性只在单份 Markdown 内有意义。

**修法：** 在当前 Markdown 宿主内查找锚点，或给每份文档增加命名空间并同步转换 href；复用同一套局部锚点解析，不为聊天和文件预览各维护一份。

**验证：** 同名标题跨两条消息、消息与文件预览并存、中文和编码后的 hash、流式追加标题。

### F07 · P2 · 扩展加载失败，被同时解释为“已关闭”和“未安装”

**证据：浏览器复现 + 源码确认。** 接口返回 503 后，页面同时显示“加载失败”“扩展层当前关闭”“未安装插件”。后两句话都不是这次响应能支持的事实。

[PluginsPanel.tsx:474](<D:/lea/XenYon code/gui/src/components/PluginsPanel.tsx:474>) 把未知开关折算为 false；[712 行](<D:/lea/XenYon code/gui/src/components/PluginsPanel.tsx:712>) 和空列表分支据此输出确定状态。

**修法：** 明确区分 loading/error/success-empty/success-data。仅在成功取得设置后断言“关闭”，仅在成功取得列表后断言“未安装”。可以保留上一次成功快照，同时说明刷新失败。

**验证：** 首次 503、有缓存后 503、成功空列表、成功关闭、成功启用。当前扩展开关放在配置文件是源码中的既有产品决策，本审计不把“没有 GUI 总开关”列为 bug。

### F08 · P2 · 从宽窗缩小后，侧栏覆盖聊天和输入框

**证据：浏览器复现 + 源码确认。** 从宽窗依次调整到 800、720 像素时，已打开侧栏仍保持打开并变成覆盖层。720×480 时聊天列布局宽约 419px，左侧抽屉覆盖其中约 248px，输入框左侧也被遮住；可以手动收起，但缩放后没有完成相应的抽屉交互。

[ReviewLayoutBehavior.tsx:6](<D:/lea/XenYon code/gui/src/components/review/ReviewLayoutBehavior.tsx:6>) 只在首次挂载判断 900px 断点，没有监听跨断点变化。CSS 则在窗口变化时立即切换定位方式。

**修法：** 让断点状态成为布局与交互共同依据，监听 `matchMedia` 变化；小窗抽屉提供明确遮罩、关闭和 Esc。保留用户主动展开/收起选择，不要用每次 resize 强制覆盖偏好。

**验证：** 宽→窄→宽、窄窗启动、主动打开抽屉、工作区开关，特别覆盖产品允许的 720×480。见截图 `chat-720.png`、`chat-800.png`、`chat-960.png`。

### F09 · P2 · 设置页缺少进入焦点与可访问名称

**证据：浏览器复现 + 源码确认。** 点击设置后焦点仍在外侧“设置”按钮；页面内 `role=dialog` 没有 `aria-label/aria-labelledby`。从关闭按钮反向 Tab 可以到侧栏调整柄。

**验证：** 纯键盘进入、导航、保存、退出；新旧布局分别检查，不能一套焦点陷阱套两种页面。

### F10 · P2 · 工作区标签有 tab 语义，却没有对应键盘导航

## 第二批：性能与资源使用

### F12 · P2 · 隐藏的设置标签仍挂载、请求和轮询

**证据：浏览器复现 + 源码确认。** 只打开外观页，停留约 10.5 秒，记录到 3 次 `/v1/local-models` 请求。开发 StrictMode 导致两次初始请求，其中约 10 秒后的一次是隐藏组件的周期轮询；不能把三次都当成生产重复请求。

设置各节主要靠 `hidden` 类隐藏；[LocalModelSetting.tsx:92](<D:/lea/XenYon code/gui/src/components/LocalModelSetting.tsx:92>) 初次加载，[104 行](<D:/lea/XenYon code/gui/src/components/LocalModelSetting.tsx:104>) 每 2/10 秒轮询，只检查整个文档是否可见，未检查账号标签是否活跃。外观页初次打开也触发了权限、记忆设置等隐藏节的读取。

**修法：** 活跃标签懒挂载或传入 `active` 控制副作用；账号未保存草稿独立保存，不要因切标签卸载而丢失。只在显示时读取无需后台更新的数据。

**A/B：** 相同 30 秒外观页停留，统计分接口请求量和挂载节点；再验证切标签草稿保留、本地模型启动期间状态及时刷新。

### F13 · P2 · 若干轮询没有防重入和可见性边界

**证据：源码确认；延迟影响待测。**

- [Sidebar.tsx:302](<D:/lea/XenYon code/gui/src/components/Sidebar.tsx:302>) 每 5 秒为多个工作区读取 peers，没有前一轮在途检查、同一 effect 内的响应新旧序号，也不检查文档是否隐藏。
- [WorkbenchChanges.tsx:25](<D:/lea/XenYon code/gui/src/components/review/WorkbenchChanges.tsx:25>) 每 5 秒读 Git，即使 scope 是“本轮”；检查工作区 open，但没有页面可见性/在途检查。CSS 隐藏不等于 React 卸载。
- [FilePreview.tsx:445](<D:/lea/XenYon code/gui/src/components/FilePreview.tsx:445>) 的活跃文件轮询每 700ms 调度，缺少在途互斥。现有路径/会话身份检查应保留。

请求耗时超过间隔时会重叠；前两个轮询同一轮生命周期内，后发先至的结果可能被先发后至覆盖。本次没有施加网络延迟来测资源峰值，不给出虚构的 CPU/延时收益。

**低复杂度替代：** 沿用 [useSessionGoalLive.ts:20](<D:/lea/XenYon code/gui/src/hooks/useSessionGoalLive.ts:20>) 已有的在途保护和可见性模式，必要时配合 AbortController/请求序号。优先“完成后再调度”的小 Hook，避免建设复杂全局轮询平台；相同工作区 Git 状态的多个消费者可共用快照。

**A/B：** 12 秒延迟接口、隐藏窗口、切工作区；统计同时在途数、请求数和最终快照身份。后台必须继续的任务另作明确策略，不能全局一刀切停止。

### F14 · P2 · 终端输出无累计上限，渲染全部历史块

**证据：源码确认；大规模耗时未测。** [terminalSessionStore.ts:61](<D:/lea/XenYon code/gui/src/stores/terminalSessionStore.ts:61>) 与 [66 行](<D:/lea/XenYon code/gui/src/stores/terminalSessionStore.ts:66>) 不断复制并追加 `lines`；[WorkspaceToolPanel.tsx:458](<D:/lea/XenYon code/gui/src/components/WorkspaceToolPanel.tsx:458>) 全量 map 到 DOM。同根工作区持续运行时没有累计输出上限。命令历史的 30 条上限不等于输出上限；单次后端输出截断也不解决累计增长。

**修法：** 分离输出保留策略与可见窗口。先提供清空/导出和明确的容量边界，再按实际规模选环形缓冲或窗口渲染。保留运行序号与根路径校验，避免旧命令输出串入新工作区。

**A/B：** 相同输出语料连续追加，比较 DOM、追加耗时、内存趋势、滚动与复制。不要以静默丢失输出换取漂亮指标。

### F15 · P3 · 文件目录在每次渲染中重新处理，并一次挂载全部文件

**证据：源码确认；实际用户目录规模未测。** [WorkbenchFiles.tsx:31](<D:/lea/XenYon code/gui/src/components/review/WorkbenchFiles.tsx:31>) 每次 filter/slice/sort，[42 行](<D:/lea/XenYon code/gui/src/components/review/WorkbenchFiles.tsx:42>) 全量 map。`filter` 已创建新数组，紧跟的 `slice` 没有必要。

**修法：** 先缓存按 entries/query 计算的结果，移除多余复制；只有大目录证据充分时才引入简单固定行高虚拟列表。不要因为这里缺窗口化而改造已经窗口化的聊天列表。

**A/B：** 同样的 100/1000/10000 项目录，测筛选输入到画面的延迟和 DOM 数；验证键盘、菜单、打开文件不回退。

### F16 · P2 · “流畅”偏好同时决定代码高亮是否移到 Worker

**证据：源码确认；流畅关闭下的端到端性能因 F01 未完成。** [CodeBlock.tsx:93](<D:/lea/XenYon code/gui/src/components/CodeBlock.tsx:93>) 中 `skipPrism`、`useWorker` 都依赖 smoothness；关闭后，聊天代码走 [156 行](<D:/lea/XenYon code/gui/src/components/CodeBlock.tsx:156>) 的同步 fallback highlighter。

**修法：** Worker、流式纯文本与动画开关分离；只在 Worker 实际失败时走受控 fallback。先修 F01，再用同一长代码流比较主线程长任务与交互延迟。
