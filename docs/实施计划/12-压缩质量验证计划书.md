### 关键修正：C2 不是「不省钱」，是旧实现+口径误导（8/19）

- **旧结论的来源**：① append-only 修复前，每次 decide 到 C2 都整段重写摘要（`c2_summary_text=""`），churn 反复摧毁前缀缓存 → ultra 命中率崩到 91%，miss 成本吃掉压缩收益；② 官方用量统计受上一轮并发进程残留 warm cache 污染，把 project 的 99.75% 当基线，属假象。
- **修复后干净口径**（`--hitrate-clean`，冷首轮整段 miss + 非过渡轮只计增量 + 过渡轮整段 miss，官价 hit=0.05 / miss=1.5 元每 M）：

| 档位 | 模式 | 输入token | 干净命中率 | 成本(元) | 说明 |
|---|---|---|---|---|---|
| ultra | project | 458,484 | 91.66% | 0.07834 | 基线 |
| ultra | c2 | 258,791 | 87.58% | 0.05953 | **省 24.0%，输入 -44%** |
| long | project | 118,752 | 77.12% | 0.04534 | 基线 |
| long | c2 | 72,669 | 70.98% | 0.03421 | **省 24.5%，输入 -39%** |
| medium | c2=project | 39,308 | 76.40% | 0.01542 | 中小不压缩，命中率=project |

- **命中率向 99% 收敛（数学本质 + live 直接实测）**：稳态命中率 ≈ 1 − 每轮新增 token / 当前提示大小，随提示线性增长而逼近 1。**超长会话 live 实测（8/19，append-only 合成长会话，逐轮真实 cache 用量）已直接测到 ≥99%**：
  - **80 轮**：c2 尾20轮 98.30%（末轮 98.67%，提示 33.7k、miss 447）；project 尾20轮 98.14%。
  - **140 轮**：c2 **尾20轮 99.09%**（稳态 98.37%、总输入 4.05M、errors=0）；project 尾20轮 99.04%（总输入 4.27M）。→ **c2 尾窗命中率 ≥99% 且比 project 少 5.0% 输入 token**。
  - 真实会话（含文件重写尖峰，每轮有效 miss ≈973 token）收敛更慢，需提示 ~100k（约 200+ 轮）达 99%；方向与合成一致。
- **中对话 ≥97% 达标**：medium 档（6 轮）live 命中率 99.32%，c2=project（中小不压缩）。
- **短对话冷启动**：设计上不计入（首轮冷 miss、过渡轮全 miss 在干净口径中单独统计）。
- **结论修正**：C2（append-only 扩展版）在超长会话**既省钱又保质量**（新摘要 r=0.917 / session.md r=1.0）且**尾窗命中率实测 ≥99%**。θ 扫描（离线省 32%）、干净口径（真实会话省 24%）、140 轮 live（省 5.0% 输入且尾窗 99.09%）三重确认；生产默认关闭的形态保留，超长会话（公式 HardTop 且 Q≥θ*）可单开 C2。
- **C1 效果不变**：C1 冻结/占位路径未改动；`c2_extend_decouple` 默认 False 时不进入任何新分支；`test_runtime_c2` 的 C1 相关测试全绿。
- **遗留杠杆（已落地为开关，默认关）**：压缩态扩展目前被 `decide` 的 θ 门卡死（C2Q 首压后掉到 0.46 < θ=0.5），尾部会随会话无限增长、省幅封顶。已实现 `c2_extend_decouple=True`（overlay/Params）把「扩展触发」与 θ 解耦，由 append 四闸门独立控制；默认 False 保持现有行为。离线模拟提示：放宽闸门在重工具会话会把命中率从 92% 拉到 ~70%（提示变小所致），因此需先用更长 live 会话验证命中率影响，再决定是否放宽 `c2_extend_ratio`。
