## 1. 完全采纳项细化

### A1 —— ω 缓存冷却平滑因子（优化 4）

- 公式：`Ĥ_t(a) = ρ_t · g · ⌊LCP/g⌋ · ω(Δt)`，`ω(Δt) = max(0.4, e^(−Δt/T½))`；`T½` 默认 60 分钟（可调）。
- 落点：`cache_model` 的 decide 输入侧，**只改 Ĥ 的估计，不碰 Q/J/投票公式**（这是四个核心优化里唯一不碰公式的，故最先完全采纳）。
- 行为：挂机 1 分钟 ω≈0.99，决策几乎不变；挂机 4 小时 ω=0.4 下限——预测命中率温和打折，不再“反正 miss”触发 HardTop 把短问候当长任务压。
- 开关：`XEYO_CACHE_COOLDOWN_OMEGA`，默认 0（回退现行 TTL 硬跳闸），灰度后改默认。
- 依赖：`WorkingSnapshot` 需补 `last_projected_at`（wall-clock），flush/hydrate 持久化；与 P1 缺失 2（ProjectionDigest 重启恢复 lcp_keep）正交。
- 验收：cache 决策单测（TTL 过期 + 短输入 → 不 HardTop；窗口满 → 仍压）；`--hitrate-live` 重跑尾窗命中不降；A3 快照观察一周。

### A2 —— 压缩索引 + retrieve 还原（参考点 1）

- 机制：C2 压缩时，把左区被折叠的**结构化原子**（stack / kv / path / json——确定性摘要里只留一行或零片段的内容）全文写入 sqlite `fragments(msg_id, kind, text, sha, turn)`；已上线的 citation 锚点 `⟦notes:msg:i:kind⟧` **即还原 id**，两个机制天然同构。
- 工具面：`Memory(action=retrieve, id="notes:msg:12:tool_result")` 返回原文片段（单次 ≤4KB 封顶）；db 缺失时回退“按 msg 下标从转录 JSONL 取原文”——**转录永远是最终真相**。
- 摘要尾部加一行提示（随摘要冻结，不破坏字节稳定）：`[C2] 被折叠细节可用 Memory(action=retrieve,id=…) 找回`。
- 定位：把 v61 从“有损压缩”升级为“可还原压缩”，闭环综述 F3（压缩后访问失败）。
- 开关：`XEYO_MEMORY_RESTORE`，默认 1（纯增量；关掉只停写 fragments，不影响读回退）。
- 验收：折叠后 retrieve 字节级还原 stack 原子；缓存前缀不变性测试；`test_memory_tool` 不回归。

### A3 —— C2 逃生舱（完全采纳，v1 语义定稿）

- **v1 语义（字面版）**：最近 **1 条完整 Traceback**（stack 原子原文逐字保留，≤2KB 封顶）+ 最后 **3 个不同文件路径**（优先取工具调用参数 Read/Edit/Write/Grep 的 args，输出正则兜底）。
- 位置：`apply_c2_messages` 在得到摘要文本（**无论来自 session.md 还是确定性摘要**）之后，追加固定小节 `[C2] 逃生舱:`，并随 `c2_summary_text` 一起冻结——保证与摘要来源无关、字节稳定（KV 命中不回归）。**不得挂在 `deterministic_c2_summary` 层**，否则 session.md 优先路径会绕过它。
- 预算：逃生舱先扣（固定预留 ~2.5k 字符）再分剩余预算；相对 C2 省 40% 输入可忽略。
- 老报错不丢：更早的 Traceback 折叠为一行 + citation 锚点，经 A2 retrieve 找回全文。
- v1.1 观测项：“未被后续成功信号覆盖的 Traceback”语义（字面版可能恰好选中已修复的错误），真源跑一周后决定是否升级。
- 识别复用：`fidelity_segmenter._traceback_block` / stack 原子即现成报错识别器。
- 验收：极小预算下逃生舱在场；fold/dedup 不吃掉它；`c2_summary_extension`（EXT）不覆盖它；session.md 来源路径同样在场；多条 Traceback 选择的确定性；A1/A2 重跑尾窗命中不降（预期只升——逃生舱位于摘要头部）。

### A4 —— 词法检索保 P0 + 清单 sqlite 化（两步走）

**定位铁律：sqlite = 派生索引/缓存；文件（memdir md、session.md、rollout、转录 JSONL）永远是 source of truth。** 库可随时删除全量重建，零数据丢失风险；人仍可直接编辑 md 文件。

- 库：`~/.xeyo/memory/{wsid}/memory_index.sqlite3`（WAL，单写者=server 进程，CLI 只读）。表：`notes` / `fragments`(A2) / `session_deltas`(A5) / `edges`(C1) / `meta(schema_version, last_rebuild)`。
- 写路径（write-through upsert，全部沿用现有原子写习惯）：`session_md.maybe_update`、`archive_session_rollout`、memdir 笔记写入、rewind 截断。
- 自愈：按 `(mtime, size, sha256)` 签名懒重解析（同 `extension/reconcile.py` enabled_probe 模式）；`py -3.11 -m memory.reindex --rebuild` 全量重建；**fail-open**：任何 sqlite 异常回退现行文件扫描路径——P0 词法召回永不回归。
- 两步走（关键决策，规避 FTS5 CJK 坑）：
  1. **第一步（P0）**：sqlite 只做“存储 + 预解析缓存”——查询仍用现有 Python 词法评分（NFKC / CJK bigram OR+门槛 / recency bonus **零变化**），收益 = I/O 与一致性；
  2. **第二步（P1+）**：FTS5 trigram 候选过滤 + 现有评分终排，必须用探针集 A/B 验证召回不降后才可切默认。
- 注入面不变：清单块仍走 T_now INVENTORY 双闸（≤2500）+ digest 幂等（缓存前缀红线）；内容变 top-K + 计数 + 指针，详情走工具拉取。top-K 排序必须确定（score 主序 + id 决胜）保证同状态同字节。
- 开关：`XEYO_MEMORY_SQLITE_INDEX` 走 `memory_switches.py` 注册表 + GUI「记忆系统开关」面板加一行。
- 额外收益：跨会话 session.md 检索（现为逐文件扫）与 A5 delta 日志同库索引；C1 边表同库。

### A5 —— session.md 差分重写（两阶段）

- 数据模型：`~/.xeyo/sessions/{id}/session_deltas.jsonl`，行 = `{turn, seq, ts, author: det|model, section, op, value, value_sha}`；**物化 session.md = fold(deltas)**；每 N 条 delta 写一条 fold checkpoint（快照 sha）限制重放成本。
- 按节合并策略：

| 节 | 合并 op | 封顶 |
|---|---|---|
| Goal | set_once（首个非空定稿） | 300 字 |
| Current state / Next action | last-wins | 400 / 300 字 |
| Completed | append + 去重，超限压缩为计数行 | 20 条 |
| Important discoveries | append | 15 条 |
| Key facts | append + kv 去重 | 24 条 |
| Open questions | append / remove（按内容 sha） | 10 条 |

- **Stage 1（确定性，先做）**：`maybe_update` 从“全量重写”改“diff → 追加 delta”；确定性抽取器每轮照跑（它就是 diff 源）。**所有读者不改**（C2 左段、跨会话检索、memory_tool 继续读物化文件）。
- **Stage 2（模型 delta，门控 `XEYO_SESSION_MD_MODEL_DELTA` 默认 0）**：模型轮末产出 `{changes:[{section,op,value}]}`；校验（schema / 每值长度 / `_FORBIDDEN` 令牌 / turn 单调）失败即弃。**作者权限分权：事实节（Key facts / Completed）只允许确定性作者写；模型只可写叙事节（Discoveries / Current / Next）**——事实可信与叙事绑定两头兼顾（P3 诊断：session.md 叙事吸收 100% = 绑定杠杆）。
- 回滚改进：rewind 不再整文件删除（现 `clear_after_rollback`），改“截断 turn > rewind_turn 的 delta + 重放重建”——回滚不再失忆。
- C2 消费护栏：物化文件按节封顶；超 C2 预算 → 头（Goal/Current）+ 尾（Next/facts）切片，其余回退确定性摘要（物化文件同时是 C2 左段文本，`runtime.py:697-701` 优先读它，必须防爆）。
- 错误包容：模型 delta 错一条只废一条（日志重放可回退）；append-only 优先，模型无 delete 事实节权限。
- 验收：属性测试 `fold(deltas) == render(messages)`；幂等（seq 去重重放安全）；rewind 截断；封顶；禁词；`test_session_md.py` 扩展。

### A6 —— 评测源切换 + 源健康门

- **真录协议**：≥3 条真实会话（调试马拉松 / 重构 / 文档运维各 1，200+ 轮），日常使用顺带录（录制免费）；冻结 JSONL 为固定评测源；设 `XEYO_REAL_SESSION_SRC` / `XEYO_HITRATE_SESSION`。先 1 条跑通，再补 2 条防单源偏差。
- **源健康门（评测入口前置，硬性）**：unique_ts 占比 ≥80%、tool_result 密度、traceback/kv 原子计数下限；不达标**报错拒绝**——杜绝 12× 循环副本病态复发（原 real 源 unique_ts=69 教训）。
- 探针生成：表A 事实题从同一会话**确定性抽取**（fidelity_segmenter 的 stack/kv/path 原子即探针源），无需人工出题。
- **TB 2.1 定位**：不接官方 harness（docker/Terminus 集成成本高；其任务通常到不了 200 轮上下文压力、不天然触发 C2）；其“可校验能力基准”职能由**自制 2~3 个带验证脚本的长任务**替代（§2 通道 C）。

## 2. 三通道评测：顺便评测 XEYO、顺便校验 v61

> 回答“有什么可以顺便评测 XEYO、顺便校验 v61 的能力”——核心解锁：**decide() 是纯函数 + 转录冻结 ⇒ 离线策略评估（OPE）**。同一批冻结真录会话，喂 XEYO 记忆评测也喂 v61 决策对账，零额外录制成本。

| 通道 | 测什么 | 数据源 | 成本 | 产出 / 门槛 |
|---|---|---|---|---|
| **A：XEYO 记忆能力** | 表A-real 探针（保真/绑定）；A1/A2 hitrate（投影/缓存）；A3 日常快照 | 真录冻结会话 + 生产 ledger | 探针判定离线免费；hitrate-live 少量 key | Δ≥−5pp、事实层无 0/3、尾窗 ≥98–99%、输入省 ~40%、日快照趋势 |
| **B：v61 决策校验（OPE）** | J_pred vs 实际账单误差；Q 校准（Q 与实测保真的相关）；档位选择正确率；HardTop 误触发率；ω / 公式变体对比 | 同一冻结会话**逐轮离线重放 decide()**（零 LLM 调用） | **免费** | 每会话校准报告；B1/B2/B3 证据门数据（§3） |
| **C：端到端抽查** | 任务成功率 + 成本（C2 / v61 on-off A/B） | 自制 2~3 个带验证脚本的长任务 | 少量 key | “压缩不降任务成功率”的最终证据 |

- “顺便”机制：A 通道录制 = 日常使用本身；B 通道纯函数重放零成本；C 通道仅 2~3 个任务；A3 计划任务照旧。
- B 通道的“实际值”来源：转录 + ledger 里可确定性算出每轮真实 token 消耗与缓存命中（转录冻结 ⇒ 实际账单已知），与 decide() 的预测逐轮对账。
- B 通道同时是**所有公式变体的唯一准入测试台**：红线解除后，任何 Q/J/投票改动都必须先在此对比，见 §3。

## 3. 条件采纳证据门协议（B1 / B2 / B3）

共同协议：真录冻结会话（≥3 条，含 1 条 200+ 轮）重放；基线 = v6.1 现行公式；变体 = **策略参数化分支**（同一代码路径，参数切换，非 fork）；指标 = 通道 A 保真 + 通道 B 成本校准；门槛全达标才合主干，主干保留 `XEYO_L5` 开关回退。

| 项 | 变更 | 验收门槛（绝对收益） | 备注 |
|---|---|---|---|
| **B1 Pareto 替代 J** | `F = {a \| C_biz ≤ 1.15×C_keep, D_a ≤ θ}` 内非支配排序，删 λ_q | 同成本预算下保真 **+≥3pp**，或同保真下成本 **−≥5%**；“省小钱丢大脸”案例（丢高价值原子省 <5% 成本的决策）**清零**；J_pred 误差不升 | 文档预期“根治过度压缩/过度保守摇摆” |
| **B2 s_i 驻留分** | `q_i = r_i·s_i/λ(z_i)`；traceback=1.2 且 λ 强制 1，kv=1.0，grep=0.6（κ=1.2），日志=0.3（κ=1.8） | **stack 原子压缩后存活率 ≥95%**；整体保真不降；成本影响 ≤2% | 逃生舱 A3 v1 只保最近 1 条，s_i 是**全覆盖版**，二者互补（s_i 过门后逃生舱保留为双保险） |
| **B3 动态 Horizon** | `R_base = min((L_limit−L_cur)/ΔL_avg, 24)`，锚点 {base−2, base, base+2} | J_pred vs 实际账单**中位误差下降 ≥25%**（文档声称 40%，取保守门槛）；合成场景档位分级仍正确（窗口 30%/0 待读 → 仅 4 档；75%/5 待读 → 16 档参与，不回归 P1 缺失 3 验收） | r_estimator 刚重做成约束分级，本变体在其上叠锚点，不推翻“R=约束非选择器”原则 |

风险备注：B1/B2 动 Q/J ⇒ 压缩投影字节随公式版本变化。合入时 `compact_checkpoint` 加公式版本号，旧 checkpoint 按版本识别不迁移（重建即可），并全量重跑 §5 回归清单。

## 4. 远期与地基（DAG / RL 家族讨论结论）

### C1 —— DAG 因果边表（本轮地基，不重构压缩）

- 真实缺口：C2 按位置扁平压缩，因果链（grep→read→edit）跨被压区断裂；逃生舱只保最近 traceback，更早的因果上下文会断。
- 便宜前驱：sqlite `edges(from_msg, to_msg, kind)`，确定性抽取——tool_use→其 tool_result 配对、assistant 引用的 citation id、rewind 修正边。`retrieve(msg_id)` 可沿边走因果链。
- 成本：一张表 + 抽取函数，不改压缩、不碰 Q。
- 真 DAG 压缩（图上计权折叠、分层摘要、任意节点钻取）= **v7**，须通道 B 证据后立项。

### C3 —— RL 家族：取思想，不取训练（无训练环，模型走 API）
