## 1. F1 —— s_i 驻留分：落地评估结论 = **维持不采纳**（证据：保栈与省成本不可兼得）

> 本版把 F1 从「条件采纳→准备过门」改为**维持不采纳**，因为把证据门改对（全网格标定 + 判部署形态 + 同标尺归一）后，实测**推翻了「重校准后过门」的乐观前提**——s_i 的「栈存活 14/14」是靠「整窗不压缩（全 keep）」换来的，成本 +44%，远超 ≤+2% 成本门。且 **A2（retrieve 字节级还原）+ A3（逃生舱保最近 traceback）已覆盖栈安全需求**。

### 1.1 实测（证据门已改对，见 §1.4）

| 指标 | 基线(冻结) | 部署形态(s_i + θ 全重校准) | 门限 | 达标 |
|---|---|---|---|---|
| 栈存活 | 6/14 | **14/14** | ≥95% | ✅ |
| 保真（同标尺归一） | 0.5775 | 0.6755 | 不降 | ✅ |
| 成本比 | 1.00 | **1.4439** | ≤+2% | ❌ |
| 校准决策 | 部分 C2 | **keep 14/14（C2 0 次）** | — | — |
| **裁决** | | | | **不采纳** |

### 1.2 为什么「栈存活」是假成功

- 校准后 `cal` 决策**全是 keep、C2 一次都没触发**。机制：s_i 把「丢栈」惩罚得极重 → 压缩分支的 Q 塌到 ~0.16 → 重校准后 θ 一低，压缩反而被 Q 门拒掉 → 只能 keep。
- 结论：**s_i 的「全覆盖死保报错栈」在当前 v61 成本结构下与「省成本」不可兼得**（与 B1 同构：要么保栈多花钱，要么省钱丢栈，没有免费的中间解）。不是 bug，是「单一天然的 Q 门把保栈/省成本做成二选一」的架构产物。

### 1.3 维持不采纳的理由（三项）

1. **栈本来就丢不了**：A2 `retrieve` 把被折叠栈**字节级找回**，A3 逃生舱把**最近一条 traceback** 留在上下文里。s_i 的「死保」是 belt-and-suspenders，却要 +44% 成本——**边际收益不值**。
2. **A2 + A3 已用极低成本覆盖** s_i 想解决的「报错栈别丢」。
3. **机制保留为 env 门控变体**（`XEYO_V61_SI`，默认关），作为「宁可多花钱也要保栈」的**备选与可复现参考**；若要启用，须按 §2 护栏重审 + 另立更高的成本预算门。

### 1.4 已落地的机制层改动（无论结论如何都保留，属 harness 正确性修复）

- `v61_evidence_gate.py::gate_b2_si()`：**θ 标定改全网格**（14 场景，不再 `grids[:6]`）；**裁决判「部署形态」**（s_i + θ 重校准变体），原始变体只作对照；**Q 同标尺归一化**（s_i 缩放 ~0.24，直接比原始 Q 是错标尺）再比；显式报告**校准成本比**与**校准决策 keep 占比**。全部零生产改动（默认关，与冻结公式逐位一致）。

## 2. F2 —— scale-drift 护栏：把 B2 失败「机制自动拦截」

### 2.1 B2 病根（为什么值得提炼成护栏）

B2 真正的病根是**「评分」与「阈值」之间的漏抽象**：`s_i` 改变了 Q 的**标尺**（keep 分支 Q 降到基线的 **24.9%**，因为噪声 chunk 从 `1/λ` 降到 `s/λ`），`θ` 阈值没跟上 → 安全网全失准 → 14/14 触发 L4 兜底强制 C2 → 栈存活 0/14。机制本身没错，错在「改标尺的改动没强制要求同捆重校准」——这靠人在证据门里跑半天、看明细才可能发现。

### 2.2 怎么做（通用、可复用，不只治 s_i）

在**证据门 harness**（`v61_evidence_gate.py`）里新增一个通用断言，作为所有「改评分标尺」项的前置门：

- **触发条件**：本会话启用了任何会**重加权评分/原子权重**的开关（`XEYO_V61_SI`、`XEYO_ATOM_SEGMENT`，以及未来的「信息论 Q」「查询感知重排」「Shapley 加权」——它们统一归口到这类改动）。
- **检测**：全量网格上算 `drift = median( Q_variant(keep) / Q_base(keep) )`。
- **裁决**：
  - `0.5 ≤ drift ≤ 2.0` → 放行，但要求**本次变更连同 `theta'` overlay 一起提交**；
  - `drift < 0.5` 或 `> 2.0` → **REFUSE**：门直接判失败，强制「先交付 θ/diag 重校准，再进下一轮」。
  - 该改动的 `Q` 分布（分位数）必须一并快照到 `.diag_memory_cost/*.json`，供后续对比。

### 2.3 收益

- **从「靠人发现」到「机制自动拦截」**：以后任何 s_i 类、信息论 Q、查询感知重排、Shapley 加权等「重新加权标尺」的变更，都会在证据门里**自动触发**该检查并强制同捆 θ 校准；不再靠人跑半天看明细才意识到「哦，标尺漂了」。
- **堵住一整类系统性回归**：B2 这种「机制对了、交付不完整」的失败会**在第一道门就报红**，避免类似「改了标尺→θ错位→L4兜底→栈全灭」的级联失败反复发生。
- **成本极低**：一条 harness 断言 + 一张 overlay 校验；但它让所有「重加权类」参考技术（G1/G2/F4）都能安全落地——这是 F1/G1/G2/F4 共用的地基。

## 3. F3 —— GraphFlow：确定采纳 → L4 代码知识图谱（远期 v7）

### 3.1 采纳什么

GraphFlow 定位（[GitHub: Roarpeng/GraphFlow](https://github.com/Roarpeng/GraphFlow)，[npm: @roarpeng/graphflow](https://www.npmjs.com/package/@roarpeng/graphflow)）：**本地优先的代码知识图谱 + 上下文 harness**，MCP + DeepSeek Harness（dsh）插件。核心是 **Memory + Hooks + Skills 三位一体**，把代码仓库抽象成 AST/符号级知识图谱，从而实现代码密集场景下的大幅 token 压缩（README 口径 ~98%）。

**对 XEYO 的价值**：XEYO 是代码 agent（gui/cli-ts/python 三段）；现有 L4 长期记忆用**扁平 markdown 全文**。GraphFlow 给的是把 L4 从「重复解析源码」升级成「**符号级/结构化图**」。

### 3.2 怎么接（面向 XEYO 现有地基，不是照搬）

- **记忆层**：在已建好的 `memindex.py` sqlite 骨架上扩一张**代码符号/引用表**（symbol → file/line、定义/调用边），替代/增强 L4 按 md 全文扫。
- **符号理解**：接已有 **33-符号级代码理解（Serena + CodeGraph）** 方向，用其做结构化索引来源；GraphFlow 补的是这块的**记忆层封装**（Hooks 驱动增量更新 + Skill 封装检索）。
- **能力闭环**：读代码成本从「重新解析」降到「图谱查询」，代码知识**可增长、可增量更新、可引用定位**。

### 3.3 为什么标「⏳ 远期 v7」

这是**结构性大改**（要动 L4 数据模型 + 符号索引 + 增量 hook 管线），不属于本轮落地。正确姿势是**确认方向 + 立档**，别现在动手；立项前须过通道 B（OPE）证据。**方向已立档：`v7-L4代码知识图谱立档.md`**（含落点、边界、证据门与红线）。

## 4. F4 —— 查询感知：换落点到「检索侧」重排（解 D2 死结）

### 4.1 为什么换落点

D2 原方案（压缩时按查询加权）与 **C2 摘要字节冻结（KV 前缀红线）** 硬冲突——压缩路径里做查询感知会破坏前缀恒等。**但同一个思想「换个落点」就完全干净：检索侧**。

### 4.2 怎么落地（零 LLM、保证确定性与 P0 召回不回归；已合入）

- **改动位置**：`python/memory/search.py` 三条检索打分式——`search()`、`search_session_notes()`、`search_rollout_summaries()`。它们现在是 `score = lexical + confidence + recency_bonus`。
- **加一个查询感知重排**：把「**重复命中单一词**」无限加分的 raw lexical，改为「**每词命中封顶**（`_QUERY_TERM_CAP=3`）」的 `query_reweight_score`——广度（覆盖不同查询词）主导深度（重复命中单一词）。只对**已命中集重排**，不动候选集（**召回集不变，只调序**）——这是 A4 铁律「P0 词法召回永不回归」的关键保证。
- **确定性**：`search.py` 首行声明「禁止在本函数里调模型」，故 query_reweight_score 用**纯词法**，不进模型。保证「score 主序 + id 决胜」，同状态同字节（A4 规则）。
- **不进压缩路径**：完全在 memory_tool 的 `search`/跨会话/rollout 召回侧，**不碰 C2、不碰 KV 前缀红线**。
- **开关**：`XEYO_MEMORY_QUERY_REWEIGHT`（`memory_switches.py` 注册表），默认关（=与既有评分逐位一致）。

### 4.3 探针集 A/B（已落地，见 `tests/test_memory_query_reweight.py`）

- **门限**：召回不降（ON/OFF 命中集合逐条一致）+ 命中排序改善（目标命中 top-K 更靠前）。不达标不切默认。
- **实测**：探针「重复 30 次 pnpm 的窄语义笔记 A」vs「覆盖全部查询词的笔记 B」——OFF 时 A 靠 raw 词频（30）领先；ON 时 A 被词频封顶、B 广度主导 → **B 反超**；且 ON/OFF **召回集一致**（4 项断言全过）。
- **诚实注记**：词频封顶/覆盖广度是**纯词法**信号，与现有 lexical 有正相关——在“自然语言全覆盖笔记本就词频最高”的探子里它不改变序（B 本就第一）。它的净价值是**抑制「单一词无限重复」的假高分**（高频窄语义场景），而非全面重排。真正的大幅精度提升需要**语义/意图检索**（embedding），XEYO 已在 `search.py` 明示「跨语种语义留给日后 embedding」——本项是**低成本、零风险的词法侧第一步**，不承诺语义级改善。

### 4.4 收益

- 检索侧去掉「重复命中单一词的假高分」，让覆盖整条查询的笔记排到前面——减少「召回一堆不相关笔记」的噪音，从而**减少模型为找正确记忆多发的检索调用**；**解掉 D2 死结**（从「放弃」改为「换赛道落地」）。零 LLM、确定性、召回不降、默认关。
