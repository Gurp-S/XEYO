# XEYO GUI 启动与长会话性能优化

本次优化启动依赖和工作区变更统计的整轮重复解析。保留共享工作区的并发改动，没有提交、推送或生成 Windows 安装包。完整原始数据与源码指纹见 [A/B 数据](gui-startup-performance-2026-10-15.json)。

## 实测结果

生产构建使用冻结的基线源码，优化版仅覆盖本次文件；其他任务后续修改不进入 A/B。Chromium 151，4 倍 CPU 降速，每个场景、每个版本各 5 次，新浏览器上下文，顺序交替，以下为中位数。后端统一即时返回模拟 503，历史来自隔离 IndexedDB，未访问用户服务、会话或模型。

| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 空会话启动 JavaScript 加载量 | 6.75 MB | 1.16 MB | 减少 82.7% |
| 空会话脚本执行时间 | 1200 ms | 437 ms | 减少 63.6% |
| 空会话输入框可用 | 663 ms | 692 ms | 慢 29 ms，约 4.4% |
| 首次可见内容 | 692 ms | 96 ms | 优化后首先显示启动状态，不等同于输入可用 |
| 历史会话 JavaScript 加载量 | 6.82 MB | 3.08 MB | 减少 54.9% |
| 历史正文、公式、高亮代码、图表全部可见 | 2675 ms | 2258 ms | 快 15.6% |
| 历史会话输入框可用 | 638 ms | 730 ms | 慢 92 ms；完整历史仍更早显示 |

加载量为主页面记录的未压缩 JS 资源字节，观察窗口包含输入框出现后 5.5 秒，覆盖旧版空闲预加载。它不是安装包体积或进程内存。全部构建 JS 总量基本持平：6.936 MB → 6.929 MB，收益主要来自按需加载。空会话可输入时间没有改善，不把更早出现加载状态解释为整个程序已经更早就绪。

长会话采用同一份 1,000 次工具记录、100 次单工具结果更新，7 轮交替测试。每次输出均与原整轮算法深度比较一致；时间不含断言和计数器，重解析数量另外实测。

| 工作区变更统计 | 原整轮算法 | 增量投影 |
| --- | ---: | ---: |
| 100 次更新耗时中位数 | 1536.27 ms | 12.61 ms |
| 工具记录解析数量 | 100,000 | 100 |

耗时减少 99.18%。增量结果已预热，首次打开仍需解析该轮工具；每次更新仍扫描消息引用及汇总贡献，不宣称整条 GUI 数据链变为常数复杂度。

## 根因与修复规则

启动依赖方面，设置和 Markdown 通过静态导入进入主依赖图，Mermaid 与约 1.13 MB 的文件图标包还会无条件空闲预加载。设置改为首次打开加载，之后保留实例；Markdown 预处理与解析器拆开；图标和图表按实际使用加载。打包保留 Mermaid 自身的图表拆分，避免可选渲染器把共享依赖拖入首屏。主应用文件从 1.20 MB 降至约 0.63 MB，另有约 1.9 KB 的启动入口。

窗口方面，原生 setup 在 UI 初始化链上等待健康检查，启动脚本又先启动并等待后端。现在由 Tauri 的一个后台线程负责启动和守护，轻量界面先显示，服务就绪与应用代码加载并行。没有登记的存活进程时，跳过原先无意义的首次健康等待。显示隐藏窗口不再依赖可能被暂停的动画帧。聊天恢复等到后端就绪并同步实际端口；失败时仍可查看本地对话。启动和退出通过同一个锁协调，退出后不会迟到启动另一个子进程。开发脚本保留其原 Python 解释器和端口配置。

长会话的根因是任何消息数组变化都会重新分组并解析整轮工具 JSON、输出及 diff。新的独立投影以不可变工具消息为弱引用缓存键；旧格式的调用和结果配对同时参与失效判断，只重新解析变化的工具。继续复用既有配对及文件变更规则，保留队列过滤、历史轮选择、大小写路径合并、错误修正、重排、删除、撤销与替换会话的行为。隐藏工作区仍不订阅并处理更新。

按需加载另有两条兼容约束：带标题的文件定位等待正文真正挂载；可编辑 Markdown 的整个编辑区在解析器准备好后才挂载，避免加载占位进入保存内容。

## 验证范围

- 定向前端检查：10 个文件、69 项通过；单独运行的解析 A/B 另含 4 项通过。常规运行跳过耗时基准，功能断言仍执行。
- 原生生命周期：2 项退出竞态测试通过，Rust 离线编译检查通过。
- 生产前端与模拟原生接口：窗口先显示、就绪前零后端请求、首请求使用迁移端口、关闭取消等待、启动失败后的本地历史入口通过。
- 浏览器设置检查：首次加载焦点、隐藏页面停止请求及侧栏兼容通过。
- 浏览器 Markdown 检查：同名标题定位和关闭动画后代码高亮通过；生产冷启动同时验证实际公式、代码 Worker 和 Mermaid 图像。
- TypeScript、冻结生产构建及共享工作区生产构建通过。保留原有宠物模块未使用函数提示和可选大文件块提示。

首次开发浏览器检查遇到共享 Vite 缓存被并发服务改写，以及 Worker 首次预编译触发页面重载。改用独立缓存并完成预编译后对应检查通过；生产构建测试不依赖开发缓存。

未测 Windows 安装版从进程启动到可用的总耗时；原生检查不能替代这一数据。Python 导入、模型加载和开发模式首次 Rust 编译仍可能耗时。此次未修改 Python 引擎，也未运行全量后端测试。

## 复测入口

在 `gui` 目录使用 `scripts/build-startup-ab.mjs` 创建 before，再按显式文件列表覆盖 after。before 产物被保护，另一次比较应指定新的 `STARTUP_AB_DIR`。`scripts/benchmark-startup.mjs` 读取两份冻结产物，`STARTUP_SAMPLES` 默认 5。

设置 `XEYO_PERF_REPORT` 后运行 `src/lib/workbenchChangesProjection.test.ts` 可重跑解析 A/B。`scripts/verify-desktop-startup.mjs` 对生产预览使用模拟 Tauri 接口，默认地址为 `http://127.0.0.1:5188`，可用 `STARTUP_URL` 修改。浏览器脚本需要本机 Playwright Chromium。
