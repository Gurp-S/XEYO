# XEYO 全问题治本方案

日期：2026-10-11。范围：用户提供的整段复盘（1–15、Q7 及上轮七项），加本轮源码审计已发现的缺口。不是宣称扫描并发现了整个仓库的所有潜在缺陷。

本文件是完整设计方案，尚未实现、尚未并入默认行为。依据是实际源码与 `ab-results.json`；没有原始 rollout 的历史调用次数、收益率和压缩数字，不作为验证结论。

## 决策原则

最优方向是统一执行事实、写入事务和查询来源，而不是每个现象新增一个提示或开关。保留模型自决：引擎记录发生了什么，执行层落实明确合同，模型自行决定是否查询、检查、继续编辑。台账不能推测“下一步任务”；检查不能把“能编译”包装成“正确”；历史红不能用退出码推断归属。

需要纠正上轮方案的一点：`tools/fileio/syntax_check.py` 明确允许 WIP 写盘。因而缺少强制语法拒绝并不全是漏门禁；一刀切 compile gate 会改变产品合同、阻塞分步编辑。治本方案保留草稿写入，默认事实与严格提交分开，严格模式必须显式启用且旁路验证。

有两条无法诚实承诺的绝对保证：Harness 无法从合法字符串替换推断用户全部意图；普通文件系统锁也无法普遍阻止不遵守锁的外部编辑器。前者用行为合同和负对照验证，后者明确管理范围、检测冲突并保留可恢复证据，不把边界藏起来。

## S1：统一写入事务，消除直接写入覆盖与虚假变更证据

**证据与根因**：`tools/file_edit_tool/file_edit_tool.py` 在校验时缓存全文，`call` 又使用该缓存；直接 `_persist` 没有内容基线比较。已有 A/B 中，外部写入 99 后仍覆盖成 2。WriteStore 的内容哈希比较拒绝了该场景，但锁属于每个实例，不能提供工作区内多实例/跨进程的全局保证；固定 `.xeyo.write.tmp` 也存在同目标多写者争用的结构风险，尚未单独复现。

**方案**：以现有 WriteStore 为提交入口，旁路引入独立 `engine/write_transaction.py`，承接本次触碰的事务核心，不做无关大重构。

1. Edit、Write、NotebookEdit 和受控文件操作使用同一入口。校验阶段只生成不可变请求，实际当前正文在提交事务内读取。取消 `_last_*` 作为跨调用隐式传参。
2. 每工作区共享锁域：进程内所有实例共用规范路径锁；XEYO 多进程通过同一写入代理或协作式 OS 锁协调。容器由容器侧服务落实同样合同，不能拿宿主锁冒充容器锁。
3. 事务内完成权限核对、当前版本读取、基线比较、精确应用、检查、编码、原子替换。创建文件必须明确 `expected_absent`，不能把空哈希当万能放行；旧文件首次 Edit 可使用本次实际验证正文的哈希，无须恢复已经撤销的强制先读门禁。
4. 路径、容器身份、编码/BOM、换行共同参与版本口径；原子写入使用同目录唯一临时文件并独占创建，失败只清理本事务临时文件。
5. 返回 `operation_id / before_version / after_version / changed_ranges / persist_status / checks`。diff 来自事务实际 before/after，不来自模型输入摘要或校验旧缓存。
6. 只有提交确认后更新 ReadState/Glob/工作集；拒绝操作只记录失败审计，不发布成功变更事件。journal 写入失败明确标记证据不完整，不伪装“没有改过”。

**Bash 边界**：任意 shell 程序可写任意文件，靠命令文本分析不能完整代理。需要强隔离时，Bash 在受控快照/写层运行，再提交差异；普通工作区保留兼容执行，观察到的外部变化标为来源未知。不能为兼容 Bash 路径承诺事务互斥。

**外部编辑器边界**：协作式锁只保护协作写者。管理范围外的编辑器可能在检查与替换之间写入；可加末次版本检查降低窗口、保留前后证据和冲突状态，但这不是数学意义的 CAS。只有可强制访问的受控工作区/写入代理才能承诺所有写入串行。不会把“先比一下 hash，再 replace”称作消除了全部竞争。

**验收**：直接/Store 两路的外部改动样本均不覆盖；多实例、两进程、创建竞争、同毫秒 mtime、删后重建、Windows 大小写、CRLF/BOM、容器路由均有定向对照。拒绝不改变磁盘和成功状态；成功 diff 必须匹配真实 before/after。多文件提交暂不扩展；若未来增加，单独设计恢复协议，不能声称普通多个 rename 是跨文件原子事务。

## S2：变更证据保留，替代“剥掉 diff”与“常驻完整 diff”

**根因**：工具已经生成 diff，`prompt/tool_result_diff_digest.py` 默认删掉它；原对话将问题误判为工具没有 diff。现有 full 档证明了证据能到模型，但完整 diff 反复发送成本不必要。

**方案**：新增独立投影 `prompt/mutation_receipt.py`，消费 S1 的实际提交结果。

- 第一次结果保留每个改动 hunk 的范围和有界 before/after。普通小编辑可直接给完整小 diff；多 hunk 和长行使用严格字符/条目预算。
- 裁剪必须带 `total_hunks / shown_hunks / complete / evidence_ref`；不固定“前 5 行”然后把后续删除静默丢掉。截断后的全部差异仍可按 operation_id 定位查询。
- 投影按不可变 operation_id 发布；不改 transcript、UI、原始 ToolResult。后续上下文折叠保留身份与取证引用，不重复常驻大 diff，也不凭空重写已经冻结的前缀。
- 兼容现有 `digest/full`，候选档单独旁路验证。不得只改工具回执而漏掉 query_loop 中重建、回放和压缩出口。

**验收**：合法半行删除在小编辑回执中可见；多 hunk 被裁剪时不谎称完整；长行、围栏文本、图片混合结果不被误解析；append 稳定、幂等、原记录不变。测实际模型可见字符与重复发送量，不只比较 UI 文本。

**保证边界**：解决“证据被删掉”，不保证模型必然注意、必然读对或自动发现所有语义损坏。

## S3：统一检查事实，保留 WIP，严格提交单独提供

**根因**：WriteStore 的 Python/JSON 检查只记布尔，Edit 不返回该结果；Write、Diagnostics 各有另外一套检查。`ast.parse` 还会接受顶层 return，未定义名称能通过 compile。多个检查口径与“不可用 = 无错”混淆造成假安全。

**方案**：独立 `tools/fileio/validation.py` 统一候选内容检查与事实结构，复用现有 Diagnostics 后端，不复制 lint 配置。

- 草稿提交保留当前 WIP 语义；返回实际 `persisted=true`、检查类别/范围/工具版本、`passed/failed/unavailable/skipped/timeout`、行列与有界诊断。不加 `Hint`、建议或下一步动作。
- Python 用不写 pyc、不执行用户源码的 compile 作为编译检查；JSON 使用解析检查；TS/JS 的语法与项目类型检查区分。Ruff F821/项目诊断可补未定义名称，但以项目配置和真实后端为准，不能保证动态 Python 名称解析。
- 快速局部检查在有界预算内完成；昂贵项目检查可按需或异步完成，事实绑定 operation_id 与 after_version。旧版本的迟到诊断不能贴到新版本。
- 严格提交是独立 opt-in 合同：先在候选快照/暂存层完成一组相关编辑，检查最终候选，通过后由 S1 提交；现文件始终是先前版本。无需强迫每次中间编辑都能编译。
- 原文件已损坏时，草稿可继续修复；严格提交必须满足显式选择的标准。二进制 0/1 错误数不能证明“错误没增加”；若允许按基线提交，比较实际诊断身份/位置，不能把两份不同错误都当同一个红。
- 超大文件、缺后端、语法版本不匹配明确返回未检查。严格策略对未检查怎么处理是配置合同，不能在引擎里偷偷 fail-open 或 fail-closed。

**语义损坏最优处理**：对已明确的需求用独立行为断言验证，例如本事故断言错误输出保留首行；对照还必须允许一次用户要求的合法删除。引擎不从 diff 猜“这行重要”，不按删除行数拒绝，不自动还原。没有可执行行为合同的任意业务意图不能保证完全不误改。

**验收**：4 个无效 Python 样本在严格提交中拒绝且磁盘不变；草稿模式仍可分步编辑；未定义名称/合法误删有各自诊断或行为测试；合法删除负对照通过；语法版本、后端缺失/超时、已有错误修复、跨文件依赖及迟到结果不误报“通过”。

## S4：持久会话工作集，解决重复寻找、状态漂移与归属不明

**根因**：存在 `synaptic/filestate.py`、ReadState、JournalQuery 和 task checkpoint，但来源粒度不同：文件状态可能来自输入摘要；presence 只留 64 文件、10 分钟；JournalQuery 先取固定数量再筛会话，无分页完整性事实。TTL 热状态不是全会话操作账。

**方案**：以 S1 提交事件和实际 Read 观测为来源，独立 `session/workset_index.py` 构建可丢弃、可重建的查询索引。复用已有 journal/回执存储，不另建平行的事实数据库。

- 记录会话/调用/操作身份、规范文件、实际版本、读区间/视图、最后改动区间、检查状态和来源引用。写失败不算编辑点，Undo/Rewind 也是有来源的状态变化。
- 扩展 JournalQuery 的按需查询：会话成功编辑点、文件当前观测、操作详情、分页 cursor 与总数。过滤先于分页；用现有会话树身份定义是否包含子会话，不能注释写“含子 agent”而只比较字符串完全相等；旧无 session_id 记录明确 `unknown_owner`，不算当前会话。
- 热工作集有上限，但完整查询从持久来源读取；TTL 仅控制当前在场提示。工作集淘汰、正文过期、历史已删除均有准确状态，不报成“从未发生”。
- 原始需求、约束、决策继续使用现有 TodoWrite/task checkpoint 的显式来源；引擎不自动生成计划、评价完成程度或猜测模型的下一步。文件台账不能替代任务声明。
- Git summary 只能关联某个当前版本的已记录写入。归属分成有证据的本会话操作、可见的其他已记录操作、未知；同文件多写者/外部变化只列事实，不把整份 git diff 领为本会话。

**验收**：65+ 文件、过 TTL、重启、压缩、过滤稀疏会话、Undo、同文件多写者、失败后重试都能正确查询；跨会话遵守可见性合同。不能因“没记录”推断“别人写了”。实测比较完成同任务的回读次数；允许必要的新鲜度读取，目标不是一律消灭 Read。

## S5：开关单一来源与按需解析，消除默认值重建

**根因**：有 `engine/env_switches.py`，但审计的 10 个事实开关只有 1 个登记。谓词、注释、A/B FLAGS 和测试隔离分别维护；“工具描述事实”和“范围读结构提示”被混称。

**方案**：扩展现有开关定义：类型、默认值、合法值解析、废弃状态、影响域、精确事实语义及来源位置。生产谓词、测试隔离和 snapshot pin 从同一解析定义导出。

- 运行时返回 effective/default/raw/source/config_generation。配置来源必须符合本项目已有配置链；没有真实溯源记录就标 unknown，不推断由用户设置。
- 本会话触碰的开关从实际修改操作和配置事件建立候选集合；由当前源码定义/配置解析出状态。代码中字符串出现只表示引用，不等于默认值已经改变。
- 按需查本会话触碰项或完整注册表，不常驻 world_state。开关解析配置世代变更时失效缓存。
- 事实显示开关与权限开关分离；调低展示不得改变可写目录，禁用 A/B 输出不得停止资源清理。
- 已退休的恒定行为不制造假 on/off；registration completeness 检查发现真实调用点漏注册，不用自动扫描结果猜复杂默认语义。

**验收**：unset/0/1/非法值、配置覆盖、宿主污染、进程内变化、退役项、两个结构事实开关及 A/B 实际生效状态。不能只比较 env 字符串。收益是少重建状态及更准确报告，尚待任务级 A/B 证实。

## S6：运行身份、稳定环境缓存与实时权限事实

**根因**：portfile 已有 PID/启动时间/版本，但不能证明代码已加载；env_facts 默认开态没有保存 collect 结果，已有缓存中的 scratch 又可能随权限收窄而残留。scratch 缺席可以有多个原因。

**方案**：独立 `engine/runtime_identity.py` 与环境事实分层。

- 后端运行实例发出不可变 instance_id、PID、真实启动时间和配置世代，由当前活进程查询；旧端口文件只是发现线索，不是存活/加载证明。不靠字段缺失反推版本。
- 发布版本从不可变构建快照加载代码，加载版本可由构建身份确认。开发模式若没有可信 loader 源字节记录，则只能报告启动时磁盘摘要与已知加载范围，明确 `loaded_identity=unknown/partial`。延迟 import 或 reload 需模块加载世代，不能假设整个进程是一份同启动源码。
- 磁盘工作树版本另查；包含脏文件摘要。不得用现场 HEAD 代替 loaded 版本，也不能用一个函数 code hash 代表整个引擎。
- shell/时区/桌面等稳定事实正确缓存；权限与 scratch 每次从同一执行谓词计算，缓存权限必须按 scope/config 世代失效；无值缓存使用显式 sentinel，不写成 `cached or collect`。
- scratch 的协议相对路径统一 `/`，真实 OS 路径在执行边界转换；解决当前 Windows 两条测试的口径不一致。路径比较仍按规范真实路径，不用显示字符串比较。
- 环境字段只报事实；只在变化或首次决策确需时投影。是否调整现有常驻 env 行需单独 A/B，不以错误旧注释作为合同。

**验收**：启动/重启、旧 portfile、磁盘变化但进程未变、reload/懒加载、权限收窄/切换、scratch 开关变更、Windows/POSIX、容器；两次稳定查询只探测一次稳定项，实时权限没有缓存旧值。

## S7：输出和临时资源生命周期独立于模型可见事实

**根因**：原复盘把 OFF 态遗留归因于模型没看到路径，随后认为默认开就消失。默认开不能修复异常退出、OFF 对照与模型没清理。Bash truncate、registry spill、background log 已有各自持久化/保留机制，但管理口径分散。

**源码纠正**：当前 `bash_tool/truncate.py` 在截断正文里直接附 `full at ...`，不依赖 execution facts 的显示开关。因此“OFF 就一定拿不到路径”并非当前源码事实，历史残留也未重新复现；后续对照必须区分正文路径、metadata 路径、容器可读性和资源实际归属，不能先假定根因是路径没展示。

**方案**：独立 `tools/artifact_lifecycle.py` 作为现有存储的共同引用与管理接口，复用各目录，不搬历史数据。

- 原文写入成功、确认内容完整之后，才发布 artifact_id、路径/路由、内容摘要、原始字节/字符数、保留范围及引用关系。写失败不提供假路径，不在容器失败时静默回落宿主证据。
- 截断事实统一来自该引用；显式区分执行完成与显示完整。输出预算 seam 与工具自带截断共用事实结构，防重复和互相覆盖。
- 资源归属到会话/操作/评估运行；A/B 临时目录 finally 清理，崩溃后由引擎回收。正常输出原文按保留策略保存；仍被任务/回执引用的证据不能盲目按 mtime 删除。
- 清理不依赖是否展示路径，不要求模型自删。只删引擎拥有且范围验证通过的资源；符号链接/路径越界拒绝。已过期证据返回 expired，不能声称可恢复。
- 写入验证包含完整字节数；短写、满盘、权限失败有测试，不能只看拿到文件名。普通用户草稿在 `.xeyo/tmp` 的权限仍走专属窄豁免，不扩大整棵元数据权限。

**验收**：ON/OFF、取消/崩溃/重启、跨容器、重复引用、满盘/短写、到期、非引擎文件、symlink；同一个 artifact 可取回原文且 hash/字节数相符。默认开只改变展示，不能决定 GC 成功与否。

## S8：工具观测合同统一，消除隐藏模式、分页不明与定位猜窗

**根因**：Read 的结构模式由“不传三个参数”隐式触发；符号、分页、工具描述、回执多个位置各自描述能力。总数、范围与结果完整性并非同一概念。

**方案**：独立 `tools/observation_contract.py` 统一事实，沿现有 Read/Grep/structure_map/codeindex 来源。

- Read 旁路增加明确 `view=auto|body|structure`；auto 保留旧调用语义，body/structure 明确选择。冲突参数返回中性 invalid_argument，不猜模型意图。视图失败不能用“0 entries”冒充确无条目：区分 available/empty/unavailable。
- 范围读只在确有结构能力的大文件决策点提供有界事实：总行数、当前视图、实际返回范围、可用视图及版本。不是每个 schema 每轮新增长说明。新参数增加的 schema 成本也计入 A/B。
- 符号起止、结构条目和 symbol=正文同一索引/版本；索引与正文版本不一致则失效重建或明确 unknown，不返过期行号。
- Grep 每模式定义 records 的单位、总数口径、匹配文件数、返回数、偏移/next_cursor、是否截断。路径数字不能参与源行数排序。
- Read/Grep 的行号、offset、limit、symbol 语义保持向后兼容；分页跨文件变化使用版本绑定 cursor，快照不可用则明确失效，而不是静默跳行或重复。
- 生成工具描述从真实合同派生；文案只含能力/参数事实，不包含“pass ...”“use ...”“Hint ...”式导演句。原对话的“事实方案”必须按实际开关名和能力区别报告。

**验收**：无范围/范围/符号/显式视图、阈值关闭、无索引、解析失败、多个同名符号、带数字文件名、空页/末页、总数与输出裁剪、翻页前外部修改。旧调用兼容，能力能发现；真实任务 A/B 才能证明少猜窗口和少回读。

## S9：版本化合同与健康判定，修复“旧红归因”和“异常也绿”

**根因**：baseline_run 根据整次退出码归因；缺少 who-pins；L1 将异常转成可比字符串，异常与 golden 相同就报告无变化。源码已定位 multi_turn：`trace.py` 用 `user_message` 产生 Message，然后助手分支调用 `.get`，类型混用发生在夹具构造阶段，不能据此声称生产多轮必然坏。

**方案**：独立 `evals/changedetect/contract_index.py`、`evals/baseline_compare.py` 与 trace 结果结构化，复用现有 changedetect。

- who-pins 依次返回显式 surface/contract 标签、静态引用候选、隔离实测依赖；分别标注置信范围与 unknown。动态 Python 全依赖不是静态搜索能完备推导的。
- 每次结果冻结源码指纹、测试源码、环境实际解析值、运行时/依赖版本、用例身份、收集状态、失败阶段与诊断指纹；前后源码漂移则本次不可归因。
- 基线与当前逐用例比较：pass→fail、共同相同失败、失败指纹改变、fail→pass、缺失、skip、超时、收集失败。同 node_id 的不同错误也不能归为同一旧红。
- 已知红必须绑定可比身份和原因；不会用任意旧提交的一条红豁免当前新增回归。修复两条 WSC 旧断言前确认用户裁定的现行合同，分别保留数字行分页和稳定 matches 行为断言，不直接删除测试。
- L0/L1 分别报告 changed 与 healthy。未声明期望的异常、无 Final、无检查后端使健康门失败，即使字节与 golden 相同；期望错误需显式 case/类型/阶段，不用宽泛 allowlist。
- multi_turn 使用 `assistant_text_message` 正确构造角色，Message/dict 转换只在明确协议边界发生。先跑健康断言再允许更新 golden，避免把异常冻成新正常。

**验收**：基线红 X/当前红 Y、同用例不同失败、测试缺失、开关被 fixture 重置、后端不可用、环境/源码漂移；multi_turn 必须实际经过循环并产生预期 Final；异常即使匹配旧 golden 也拒绝通过。

## S10：输出首行判决，保留稳定收执身份

**根因**：surface check 先印索引；收执固定身份字符被认为吵，但身份承担 WSC 迟到结果绑定与 append 稳定合同。

**方案**：CLI 首行输出同一结果对象的判决/健康/退出原因，变更明细有界，完整索引仍由 list 查询；机器 JSON 使用同一对象，不从渲染文字重新猜 exit code。严格失败、收集失败、无 golden 分别有明确状态。

收执身份保持现有稳定合同。不要为了几十字符取消 call_id 或关闭头部。可去掉重复的同义事实，按 S2/S8 的事实预算控制新增字段；任何更改身份载体需单独版本化迁移和完整迟到绑定验证，本任务没有收益证据支持这样做。

**验收**：无变化/变化/严格失败/收集失败首行一致，退出码与判决一致，明细按需可取；收执图片/正文/迟到/重建/折叠/恢复始终绑定原 call_id。S10 是摩擦优化，不宣称消除写入事故。

## S11：shell 错误来源与静默维护，保留模型自决

**根因**：PowerShell 参数语义由模型写错；引擎前置编码片段又可能混淆实际错误来源。已有 `classify_error_origin` 和 parse-only 对照，这个方向正确；无证据支持为了两次模型语法错误新增常驻劝导。

**方案**：环境 shell 身份来自实际执行 argv；需要时按需查该 shell 语法合同。运行错误只返回 launch/prologue/requested_command/unknown、退出码、真实位置和原文证据。parse-only 用同版本、同选项和原请求做无副作用判定；判不了返回 unknown。

不自动改写用户命令，不重跑有副作用命令，不追加“下次请...”提示。权限拒绝、missing_read/stale、后端缺失采用统一结构类别，恢复所需的当前版本/路径来源按权限可见性提供。引擎能独立完成的缓存更新、临时资源清理和状态恢复静默完成。

**验收**：`&&` 后赋值、前缀失败、命令本身失败、启动失败、普通输出恰含 ParserError 文本、判定不可用；单次命令副作用最多执行一次。现有 syntax 行保持独立旁路，不能拿未经复验的历史 2.2% 直接决定成本收益。

## S12：任务事实与压缩后恢复，解决工作集漂移但不虚构遗忘事故

**证据边界**：原对话没有 compaction 发生证据。已观察的是开关/工作集漂移；现有 TodoWrite/task checkpoint 已具显式来源能力，因此不需要另造“引擎规划器”。

**方案**：复用 checkpoint 与来源链接，S4/S5 的按需索引在压缩后仍可查；显式用户需求/约束、已确认决策、验证 call_id 和最近提交状态各有来源和版本。原始工具证据按 S7 生命周期存储。可重建索引与不可替代来源分离，不能在 compaction 时一起删掉。

声明的完成、工具返回、检查通过是三个不同事实；压缩不把助手说“完成”变成执行证据。缺失/过期来源显示 unknown/expired，不能猜测重建内容、自动重放副作用或补出不存在的决策。

**验收**：压缩前后查询同一操作/开关/约束来源一致；进程重启、任务切换、Undo、旧检查版本、来源过期、会话隔离、迟到结果不串任务。这是恢复合同验证；还需真实任务对照才可报告模型遗忘减少。

## 实施与 A/B 准入

现有 A/B 只有 10 组机制实验、9 个评估测试，不能当成以下全部方案的收益证据。

**第一批：执行正确性与健康门**。S9 的异常/归因门、S1 事务与证据、S6 实时权限缓存。先旁路、同输入比较；对已知失败做专门回归，不全仓泛跑。健康门先明确，再接受候选的通过结果，避免“评估工具自己坏了但仍绿”。

**第二批：模型可见与可恢复事实**。S2/S3/S4/S5/S7 的结果结构和按需查询。继续复用原始 store，新模块只负责本次所需的事实/投影/索引；数据版本兼容和回滚不丢原始来源。草稿兼容和事务互斥是先验验收项。

**第三批：工具发现与显示成本**。S8/S10/S11/S12 的旁路验证。是否进入默认主链取决于该项净收益，不能用语法样本 4/4 的数字为所有展示改动背书。

**开关原则**：少量按域旁路开关统一登记；单个观测字段不再各造开关。事实展示、验证策略、执行权限、资源保留属于不同合同，不能因减少开关数把它们重新绑成一个总开关。新的能力先独立显式入口验证，默认兼容保持。

**实验分层**：

- 确定性机制：锁内提交、拒绝后的磁盘/状态不变、真正落盘 diff、临时资源清理、实际检查状态、版本/分页/身份准确、压缩/重启恢复。
- 独立因素：diff 与编译分别 A/B；组合需要时用 2×2，避免当前原型两项一起开却把结果全归给一个因素。
- 真实任务：固定任务集、同源码和模型/配置/预算、独立工作区/会话，随机配对执行。明确最后行为断言；记录成功率、误改/覆盖/来源错误、必要与重复读取、恢复调用次数、实际输入/输出/缓存 token、延迟和资源残留。
- 负对照：合法删除、必须暂时写坏再修好的编辑、旧坏文件修复、未知语言、不可用检查、外部写者、要求查完整原文的任务。阻断正确工作同样算候选失败。
- 结果绑定运行实际值与源码 hash；测试 fixture 把开关清掉的实验无效。重跑前后状态和清理以引擎记录判断，不要求模型自报。
- 预先定义每一机制的零容忍合同；任务收益报告分母、失败身份与不确定性。小样本未出现事故不等于全场景零风险，未产生净收益或代价过大则保持旁路。

**“全部完成”的可核对标准**：覆盖清单每项都有对应实现/保留决定、合同回归与实验结论；确定机制不再复现，负对照不破坏兼容；未知/过期/未检查不被标成已验证；新红单独归因；没有靠删测试/更新异常 golden 伪造通过。对不可通用证明的业务语义、外部非协作写者和未发生的遗忘，保留清晰边界，而不是用“完全修复”吞掉它们。
