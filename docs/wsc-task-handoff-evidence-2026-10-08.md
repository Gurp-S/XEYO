## 根因与规则

先前检查点保存了结构，却缺少明确的任务目标声明，输出主要是一行 JSON。模型可把来源下标误当步骤/回执 ID，或自行补出未提交决定。消息 UUID 只在压缩 source 内可见，使模型声明原文引用缺少方便且可核验的入口。

结构规则：任务目标由检查点 `objective` 明确声明，不从首条历史请求派生；将同一已提交状态确定性呈现为交接文，分开目标、步骤身份/进度、声明决定/约束、执行回执、关联原文和未知项。完成声明不等于验证成功。`@latest_user` 是显式来源别名，绑定到声明回执之前的最后一条人类文本，不随 merge 更新或“继续”漂移。普通 ID 仍须唯一匹配。原文按行缩进呈现，内容及换行保留，来源仍可实际 Read。

新模块 `python/synaptic/task_handoff.py` 无模型调用，不推理目标过期、不产生下一步路线；机器状态仍是权威。工具 schema、状态投影及算法登记接线，旁路默认关闭。未改原会话、既有冻结头、线上开关或原冷对象。

回归覆盖别名锚点、目标声明、步骤 ID 和来源编号分离、声明完成与失败回执并存、原文按行保留/冷回读及字节分账守恒；评测器防止把 `#4` 身份误用直接认定为旧目标复活。
