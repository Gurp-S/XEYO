# 方案：用户目标的时效轴（Stale-Goal Retire）

> 2026-10-08 立。针对本会话暴露的**真实缺陷**：
> 你随口一提的「chatgpt 总是打开半天不出现」被当成**活跃目标**持续注入，
> 而它早已被你自己修好 ⇒ agent 白跑一趟（本会话实证：12 次工具调用）。
>
> 本文只写**可复核事实 + 可执行规则**，不写印象。

---

## 1. 现象与实证

| 项 | 事实 |
| --- | --- |
| 注入形态 | 每轮注意力里出现 `[CONSTRAINTS] 目标: chatgpt总是打开半天不出现,或者说只有进程前台不出现…` |
| 来源 | 会话**首条实质用户消息** |
| 你的后续声明 | 「…这个问题我自己已经修复好了…」（被记为 `[REQUESTS]` 里的一条，**不影响**目标行） |
| 后果 | agent 按目标行去排查 ChatGPT（进程/窗口/WebView2），**白跑** |

---

## 2. 结构性根因（精确到行，可复核）

```
synaptic/freshness.py:604-608   analyze() 聚合 5 类降级器
    _error_superseders / _filestate_superseders / _todo_superseders
    / _constraint_superseders / _dead_paths
                                  ↑ 没有「用户目标(goal)」这一类

synaptic/seeds.py:241-244        user_nodes 过滤**已含** n.idx not in superseded   ← 挂钩点现成
synaptic/assemble.py:118-120     goal pin = seeds.original_task = user_nodes[0]     ← 首条消息，永久 PIN
```

⇒ **一句话**：引擎的时效轴（freshness）覆盖了 error / 文件状态 / TODO / 约束 / 死路径，
**独缺"用户目标"**；而 PIN 里 `goal` 取的是首条用户消息，语义是"永不压缩"
⇒ 首条消息永久占据目标位，**没有任何退休路径**。

这与账本「坏处 1：`[UNRESOLVED]` 曾是本陈旧账」是**同一族**（陈旧上下文歧义），
只是这次暴露在**目标轴**上，而那条在错误轴/约束轴上。

---

## 3. 规则：让它在结构上不再发生

新增**第 6 类降级器**，把"用户目标"并入与其它四类**同一套**时效轴。

### 3.1 落点（最小侵入，不新增架构）

| 文件 | 改动 | 说明 |
| --- | --- | --- |
| `synaptic/goal_staleness.py`（新模块） | `goal_superseders(graph, region_end, user_nodes) -> list[Downgrade]` | 遵循「新逻辑一律进新模块」；只在 `freshness.py` 触碰的那一行改成调用它 |
| `synaptic/freshness.py` | `analyze()` 里加 2 行：调用 + `downs` 求和 | 与既有 4 个降级器**同形**，不引入新概念 |
| （其余全自动） | `seeds.collect_seeds` 的 `user_nodes` 过滤 / `assemble` 的 goal pin / `[REQUESTS]` 渲染 | **无需改动**：挂钩点已存在 |

### 3.2 判据（确定性、闭集、保守优先）

照 `freshness.py:440-481 _constraint_superseders` 的**既有模式**（它已在做"用户显式改口 +
主题重合 ⇒ 降级"，连"bigram 弱信号要抬高门槛"的经验都写在注释里）：

1. **关闭标记**（新闭集 `_GOAL_CLOSE_MARKERS`，**不复用** `_OVERRIDE_MARKERS`，以免改动既有约束语义）
2. **实体重合**（token 交集，沿用既有分语言阈值：拉丁词 ≥2 / 仅中文 bigram ≥3）
3. **时间序**：声明必须**晚于**被关闭的目标
4. 任一不满足 ⇒ **不动**（宁可不退休，也不误退休——"不误降级"是既有实现的原则）

### 3.3 行为

产出 `Downgrade(idx=旧目标节点, by=声明节点, cls="goal", key=目标摘要, why="用户声明自行解决且主题重合")`
⇒ 进 `superseded` ⇒ 自动发生：

- `user_nodes` 排除它 ⇒ `original_task` 落到**下一条**实质用户消息 ⇒ `goal` pin 换成**当前目标**
- `[REQUESTS]` 不再列它
- **原文不删**（"降级不删除"是引擎既有原则）：冷层句柄 + `Read` 仍可召回
- `trace` / `by_class["goal"]` 留审计

---

## 4. 回归测试（4 条，先红后绿）

1. **正控**：关闭声明 + 实体命中 ⇒ 旧目标进 `superseded`，`goal` pin 换成下一条
2. **反控（保守）**：关闭声明但实体不命中 ⇒ **不退休**
3. **不丢内容**：退休后原文仍可从冷层召回
4. **前缀不变性**：退休前后，除 `goal` 那一行外**其余段逐字不变**

---

## 5. 上线方式（引擎铁律 4：旁路验证，有数据才并主链）

- 开关 `XEYO_STALE_GOAL_RETIRE`，**默认关**
- A/B 三个指标：
  1. 「已声明关闭后目标行仍出现」次数 → 期望 0
  2. 误退休（其后用户又要求继续该目标）→ 记入 `mis_downgrade`
  3. 前缀断裂增量 → 期望 **= 目标真实切换次数**（多出来的都是误退）

---

## 6. 代价（必须知情，不掩盖）

- 目标真正切换时，`goal` 行**内容会变** ⇒ **前缀断一次**。这不可避免：
  正确的当前目标必须替换过期的旧目标。
- 这与你定的「源版本变化时不能假装恢复成功」一致：**该断就断**，且只在**强信号**时断。

---

## 7. 对你给的方案的三点修正（重要）

1. **不做第 4 步**（在系统提示里写"只执行 active_goal 中描述的任务"）——
   它违反引擎铁律 1「注意力里只出现信息，不出现导演」。
   退休后该目标**不进** `[CONSTRAINTS]`，信息层本身就是干净的，**不需要**任何导演句。
2. **"检查点 + recall" 引擎已有，不必引入新架构**：
   - 存储无损：会话 jsonl + 冷层句柄（`coldstore`）+ `Read` 召回 ✓
   - 检查点：`[CONSTRAINTS]` / `[WORKING SET]` / `[DECISIONS]` ✓
   - 用户原文逐字保留：`[REQUESTS]` + PIN 的 goal ✓
   ⇒ 缺的**只有"用户目标退休规则"这一条**（本方案要补的正是它）。
3. **关键词启发式必须闭集 + 分语言阈值 + 保守优先**，而不是新造一套：
   `_constraint_superseders` 已踩过这条路（"只有中文 bigram 重合时要求 3 个——bigram 是
   弱信号，抬高门槛换取不误降级"）⇒ 复用它的经验。

原方案三处需要修正：§8 单个 `chatgpt` 不满足 2，本现场还命中中文 `修复`；既有门槛是有拉丁词时总重合 ≥2。§3 的下一条实质消息不是最新目标，本现场为 #66。§4 第四条不能保证全量新建投影只有目标行变化；实际验证既有冻结行不改写，独立新投影的请求分组/行号变化保留完整差异。

## 12. 批次 21：无关闭声明的请求投影
