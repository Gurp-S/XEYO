# D 优化 Goal：六个研究方向与严格执行要求（2026-10-14 追加）

本节追加到当前 Goal objective，保留此前全部 WSC 机制、Prompt、旁路准入及质量不退化要求。以下是执行与验收合同，不是向 XEYO 工作模型注入的提示词。完成本节文件更新不代表完成优化 Goal。

## 总目标、边界与固定优先级

**让 Runtime 用尽可能少且干净的 Context，向 LLM 投影尽可能正确的当前 Work State；当投影不足时，能够准确识别并恢复真正需要的历史 Evidence，同时保证这种状态在长期、多次压缩中不会持续漂移。**

主方向仍为 D：优化语义交接质量、精确冷召回与生成失败后的续接，保持确定性层薄而可靠；以 A1 为对照，达到 A1 或更好的工作效果，同时保住既有质量。新机制、Prompt、schema 或工具接口先独立旁路验证，证明增量收益后才并入。预算增加不构成并入依据。

严格按以下顺序处理，不能以低优先级收益抵消高优先级退化：

1. State Correctness（状态正确性）。
2. Semantic Handoff Quality（语义交接质量）。
3. Long-Horizon Stability（多代稳定性）。
4. Adaptive Recovery（按需证据恢复）。
5. Safe Denoising（安全去噪）。
6. Projection Efficiency（投影效率），以及横切的 Economics（经济性）。

静态字段评分与行为评分分别报告；验收优先看真实 continuation / task success，不能靠字段齐全、JSON 合法或存档存在来替代下一轮任务成功。遇到质量与开销冲突，先满足质量门槛，再按可测收益判断开销准入。

## 1. Semantic Handoff Quality：语义交接质量

衡量继续工作所需信息是否交给下一轮模型，不以摘要长度、文笔或历史覆盖量作为质量代理。

- 检查当前 Goal、完整 Active Request、Active Constraint、Decision / Failure / Progress、当前 applicability；检查具体值、关键路径和重要原因。
- 静态指标：各 Work State 字段正确数 / 应检字段数，分别报告遗漏、错误、无依据新增及不确定状态。
- 行为指标：下一轮能否直接继续未完成任务、完成验收；报告 continuation success、task success、为补救交接缺失增加的调用、错误执行及恢复后成功率。
- 生成可接受率、无效输出率、失败后可续接率独立报告。输出合法只证明机械合同通过；不能据此宣布语义正确。

**严格执行要求：**

1. 当前语义由 LLM 声明，机械真值由 Runtime 提供；不能靠确定性关键词替代取消、覆盖、解决、重开等理解。
2. 重要证据不能只保留调用 ID。核实下一轮实际收到的内容是否足以继续，或是否能够自主找回并正确使用证据；存档可读不能冒充行为通过。
3. 新交接失败不得发布非法状态、覆盖上个有效 checkpoint 或丢掉新增事件和未消费结果。保留失败记录，验证恢复后能继续；禁止人工补答案再归为模型成功。
4. 不确定必须保留不确定，用户偏好不能升格成禁止；null 不得被适配器静默改成 false。最新适用范围不能被历史重要性覆盖。
5. 同样输入、工具权限和验收条件下，与原 D 及 A1 比较。Prompt 的每句新增规则必须有消融证据；删除后没有稳定下降的句子移除。

## 2. State Correctness：状态及转换正确性

机械状态与语义转换是两类独立指标，不能混成单一正确率。

### Runtime 可机械判断的状态

包括 ToolResult AVAILABLE / CONSUMED、File CURRENT / STALE、phase/source 是否存在、checkpoint 是否匹配、execution identity，以及来源、版本、seal、cursor、提交和恢复一致性。

目标为声明的机械合同 **100% correctness**：完整列出合同、场景、通过数、失败数和未覆盖项。有限测试通过不等于对所有运行情形证明 100%。AVAILABLE / CONSUMED 的判定事件必须明确定义，进入一次模型请求不能被描述为模型已经理解或正确使用。

### LLM 判断的语义 State Transition

覆盖用户取消旧要求、新要求覆盖旧要求、问题真正重开、约束真正解决、phase/scope 改变。分别测：

- Semantic State Transition Accuracy = 正确语义转换数 / 应判断转换数。
- Active State Loss Rate = 错误丢失的活跃状态数 / 应保留的活跃状态数。
- Resolved Intent Revival Rate = 无有效重开依据却复活的已解决意图数 / 已解决意图的复活检查机会数。
- Retired Constraint Revival Rate = 无有效恢复依据却复活的退休约束数 / 退休约束的复活检查机会数。
- Wrong Supersession Rate = 错误覆盖判断数 / 应判断的覆盖机会数。
- Wrong Scope Transition Rate = 错误范围转换数 / 应判断的范围转换数。

**严格执行要求：**

1. 对每类真值明确唯一所有者与合法转换条件。Guard 校验来源、绑定和转换结构，不重新发明另一份语义 authority。
2. 包含正例、否定、条件、引用、明确重开与只是提及历史的反例；缺省判断不能绕过这些检查。
3. 验证迟到回执绑定到正确 execution/call/version，旧回执不能冒充当前结果；文件曾经读取不能冒充仍然 CURRENT。
4. 重启只可复用通过 seal、来源、cursor、发布状态等检查的 checkpoint；存档被后续追加不能使此前密封版本失效。失败恢复不得掩盖旧证据污染。
5. 模型错误、引擎错误、检索接口错误、协议/评分错误分列；追到模型实际请求与原始来源再归因。保留原失败，不用修订评分抹掉它。

## 3. Safe Denoising：安全去噪

同时报告删除噪声与误删有用信息，目标是尽可能删除可证明冗余，Useful Information Loss 趋近 0，而不是尽可能提高删除比例。

- Noise Removal Rate = 删除的已标注真实噪声量 / 原有已标注真实噪声量。
- Useful Information Loss Rate = 错误移除且没有在所需时有效恢复的有用信息量 / 原有应保留或恢复的有用信息量。
- 分别报告有用信息的热层移除、精确冷层留存、行为恢复失败，不能把“在磁盘上”统一计为无损。

**严格执行要求：**

1. 噪声与有效信息按来源和工作需要独立标注，预先确定按信息单元还是 token 计量，不能删除之后才把被删内容定义成噪声。
2. 删除只接受已证明冗余/可重建、精确冷证据或权威失效依据；删除热点材料的可恢复性和实际有效恢复均需验证。
3. 包含无关历史、重复来源、旧失败、仍影响当前工作的失败、关键原因、精确值、未消费结果及后来再次需要的信息。
4. 禁止发现一个样本的噪声就增加一条样本专属规则；比较同一输入下去噪前后行为、字段、召回和多代漂移。有效信息损失增加时不准入。

## 4. Adaptive Recovery：按需冷证据恢复

链路固定为 NeedEvidence → DetectNeed → Locate → Read → UseCorrectly，各阶段分别记录，不再仅用句柄覆盖率代表恢复能力。

- Retrieval Trigger Precision = 确实需要历史证据的恢复触发数 / 全部恢复触发数。
- Retrieval Trigger Recall = 正确触发恢复的需要证据机会数 / 全部需要证据机会数；漏查优先于减少多查处理。
- Evidence Retrieval Accuracy = 读到正确证据的有效读取数 / 全部证据读取数。
- Effective Recovery Rate = 成功发现、定位、读取并正确用于回答/决策的需要证据机会数 / 全部需要证据机会数。

**严格执行要求：**

1. 查询决策属于模型；引擎提供事实型索引、精确定位和可执行读取，不增加“优先去查”等导演文本，不靠强制调用工具制造成功。
2. 冷层保留完整原文和精确工具结果；message/source/call 身份、版本、地址命名空间和内容 seal 必须可核验。召回证据不自动更新语义状态。
3. 同时包含真正需要查和热层已经足够的题，避免“所有题都读历史”被算成优秀；需要证据的标注独立于模型是否调用。
4. 检查索引可发现性、分页、精确片段、错误来源、重复身份、中文字符、重启、迟到和媒体；具体能力分别验收，不拿文本读取代替媒体使用。
5. 工具执行成功、模型拿到正确内容、最终正确使用三者分别记账；无答案、猜测、错误引用或只列路径均不算有效恢复。
6. 冷单题只能证明定位能力，必须再通过与当前任务状态混合的续接问题；不得用冷单题成功关闭综合任务缺口。

## 5. Projection Efficiency：上下文投影效率

衡量达到相同工作质量需要多少 token。可报告 TaskUtility / HotContextTokens，但质量门槛是前置条件，不用一个加权比值掩盖严重错误。

**严格执行要求：**

1. 同等 continuation/task success 下越薄越好；分别报告 checkpoint、hot head、最近原文尾部、工具 schema、恢复返回和完整请求的 token，不能混用口径。
2. 每种确定性展开都要证明职责与增量收益；模型已经表达的状态不能再默认展开成大段历史输入输出、来源正文、旧路径或失败卡面。
3. 证据基础设施在模型上下文外保留；发现确实需要时按需支付索引/读取开销。不得以裁剪热层为理由削弱真实证据和恢复能力。
4. 冻结前缀在折叠之间逐字节保持不变；新事实只追加到当前请求。80%事实通知、85%强压及模型主动普通压缩的既有授权边界不因本次优化改变。
5. 容量基于当前完整请求及实际模型容量；厂商免费预计数可用，估算明确标注，不能以累计 usage 或卡面大小冒充容量。

## 6. Long-Horizon Stability：多代稳定性

评估 State 0 → compact → State 1 → compact → … 的真实累积效果，报告 1、3、5、10 次压缩后的正确性与漂移轨迹。

- State Drift Rate = 相对当前权威状态发生漂移的应检状态单元数 / 同代全部应检状态单元数。
- 各代分别报告活跃事实消失、已解决事实复活、provenance 断裂、scope/phase 漂移、数值变形、Goal 偏移；补充整条任务链成功率和首次失败代数。

**严格执行要求：**

1. 每臂使用自身上一代产物继续，不能把其他臂或 gold 的正确状态补进去；同一外部事件时间轴、相同工具能力和验收条件。
2. 各代加入实际任务进展与状态变化；反复压缩一份不变文本不能证明长期稳定性。基于真实会话的控制扩展、离线机械检查与真实现场行为分别标注。
3. 覆盖 restart、phase/scope change、late result、文件 stale、完成后重开、取消、未消费结果，以及生成截断/非法输出/缺字段/网络或余额失败后的续接。
4. 持久状态、密封来源、近期尾部和执行回执共同恢复；仅反序列化成功不算 restart 验收通过，恢复后还要继续任务并用对来源。
5. 每类能力的证据范围明确；未跑到 10 代不能报告 10 代通过，失败或预算中断不得拼接其他实验成绩成为完整链。

## 横切指标 Economics：经济性最后验收

包括 input/output token、实际 cache hit/miss、compaction generation cost、recovery cost、latency、总调用数、生成失败开销、最终 cost per successful task。

**严格执行要求：**

1. cost per successful task = 同一任务集全部执行/生成/恢复/失败成本 / 成功任务数；零成功时明确不可计算，不能排除失败费用。
2. usage、账单和估算分列；没有 usage 的请求保留保守费用预留。LCP、可能命中缓存和情景价格不能冒充真实命中/账单收益。
3. 质量门槛通过后才比较成本；不得固定不适合短窗口测试的缓存命中率为强制验收目标，也不得拿不同输入长度、缓存条件或输出上限作公平成本结论。
4. 用户本次明确授权 **累计与每轮 API 总预算无上限**，替代旧累计额度与旧每轮额度。继续节约调用，复用可复用证据，禁止无研究收益的消耗。
5. 既有单次上限仍为 **¥2.5**，HTTP 重试为 **0**；预算授权不等于账户余额。402/余额不足立即停止外发并通知用户；保留未知费用和既有流水，不伪造余额、不假设命中。
6. 模型收到校验反馈后的新请求属于独立调用，不能伪装成免费重试；每次均有请求哈希、使用量、费用与结果记录。历史失败请求不重新发送。

## 统一执行、准入与完成标准

1. 修改前回答：结构性根因是什么？什么规则让它结构上不再发生？如何以正反例与故障场景验证？责任和状态时间轴明确后才实现。
2. 先注册假设、正确性边界、失败模型、指标分母、A/B、调用/输出上限和停止条件；一次只改变一个可归因机制。组合收益不能归到未经消融的单机制上。
3. D/A1 同源、同题、同权限、同输出/调用条件；有意不同的原生条件另列。没有原生模型能力的 A1 只作已说明的对照，不宣称赢过 Codex/Claude 原生压缩。

5. 预先冻结评分依据，来源可核验；null、未知、缺答案、未触发、未覆盖、N/A 分开。分母为零报告 N/A，不当成 100%；未回答所要求的内容计失败，不要求的字段不计错。

7. 每个候选同时列收益、注意力/调用/延迟/费用开销，以及新增状态、持久化、迁移、失败、恢复和维护复杂度。质量不退化，开销凭收益准入；没有稳定增益保持旁路或删除。
8. 保留固定 TODO、原始失败、请求/产物哈希、源码身份、密封源与重建记录。已完成项打勾并链接其适用证据，未完成项写明下一步、责任和验收缺口；不得暗改方向或缩小 Goal 宣布完成。
