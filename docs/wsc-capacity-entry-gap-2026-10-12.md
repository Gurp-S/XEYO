# 批次154：容量入口断链，暂停交接

## 已确认的引擎缺口

正常 CLI 配置和 `build_chat_engine` 未传容量；`build_default_engine` 不读取厂商模型元数据，只在客户端容量为空时读取显式 `XEYO_CONTEXT_LIMIT`。兼容客户端另支持 `XEYO_CONTEXT_LIMIT_TOKENS`，原生 DeepSeek 构造时容量为空。因此无显式容量、且生成 usage 未声明容量时，当前完整输入即使很大也没有80%通知或85%自动强压。未知窗口不猜是正确边界，容量来源未贯通是未完成实现，不能把本地夹具设定容量的验收当正常入口已经可用。

结构性根因：容量解析、配置和引擎创建之间没有统一传递合同。现有 `model/vendor_models.py` 已能解析权威整数容量，但 CLI 创建链未接入它。不是模型决策错误。

## 离线复现

`_wsc_out/wsc-capacity-entry-154/probe.py` 实际创建两类生产客户端，隔离工具挂接及 QueryEngine 初始化，禁止 HTTP、无会话持久化。生产 `decide` 使用900000输入计数夹具：

| 客户端 | 容量来源 | 最终容量 | 通知 | 自动强压 |
| --- | --- | --- | --- | --- |
| OpenAICompatClient | 无显式容量 | None | 否 | 否 |
| DeepSeekModelClient | 无显式容量 | None | 否 | 否 |
| OpenAICompatClient | 显式环境容量 | 1048576 | 是 | 是 |
| DeepSeekModelClient | 显式环境容量 | 1048576 | 是 | 是 |

四项断言通过，结果保存于同目录 `report.json`。不是真实900K请求、厂商用量、完整 query_loop 或修复后回归。生产修改0、API0，预算累计估算0.8765684/剩余0.1234316元保持。
