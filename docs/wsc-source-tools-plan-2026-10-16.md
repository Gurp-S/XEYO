# 364：来源读取接入真实工具边界

承接363的局部收益，不改变语义交接、冻结头、普通压缩时机或状态规则。原文Read/Grep继续可用。

## 第一轮复审：结构性根因与最小责任

363的能力收益来自精确来源正文和调用身份可同时访问；评测器却预先固定了存档，不能证明生产换代、重启和会话隔离正确。将这类绑定复制到工具类变量会产生跨会话和跨代串读。

复用现有已提交head引用、内容寻址对象和AddressedSources，不创建第二套索引、语义状态或发布事务。SourceCatalog默认读取持久化working选中的代，返回snapshot；SourceRead携带snapshot。后续分页也携带snapshot，不能静默换代。工具不接受任意路径或session参数。

## 第二轮复审：失败、归属和不变量

- 来源版本由不可变head摘要标识，在可信执行会话的命名空间解析；工作区、源封印、publication对象必须验证。
- 默认入口不读取可能领先于已提交游标的可变head缓存。显式旧snapshot表示该会话历史发布存档，不声称仍是当前状态或已理解的事实。
- 未发布、旧格式无原始JSONL、损坏、错误会话/工作区、缺执行上下文都中性失败；原文入口保留。不自动回退到另一代。
- SourceRead的字符范围、原始消息与调用ID保持绑定；媒体不冒充完整文本。
- 不改已有冻结字节，不在热头复制目录。工具schema稳定，成本计算加入新schema与snapshot参数。
- 读取型工具不提供新的文件访问授权：只访问当前可信会话已发布的证据对象。

## 第三轮复审：证据、复杂度与准入

一份绑定模块、一份工具适配器，复用现有reader/catalog与ToolRegistry。避免查询循环钩子、后台维护器、全局存档缓存或新的语义判定。

先用真实发布和ToolRegistry覆盖：已提交代/领先缓存、跨代同ID、重启、跨会话/工作区、损坏、缺上下文、参数和输出边界、冻结字节。再同一真实GUI交接以原生工具做files/source对照，控制历史、交接、问题与调用上限。另测旧解释纠正和迟到身份；未调用Source工具的成功不当作其边界证明。

机械检查通过且实际任务无观察到退化、有独立恢复收益，直接注册主路。若未通过，保留原结果，不把旧候选成绩替代新接口成绩。小样本不证明整体超过A1，多代独立任务仍属Goal未完成验收。

## 复审后发现的独立契约修复

现有Compact.description仍声称任务事实必须来自TodoWrite，且超过既有短描述200字符合同；359已将自然交接设为默认，不再要求全量声明。

1. 根因：工具入口描述越界承诺了一个具体压缩实现的输入条件，执行路径改变后描述过期。
2. 不变量：Compact只声明自己接受压缩请求、在下一次模型调用边界执行；不替生成器宣布语义/任务状态前提。采用对新旧路径都成立的事实描述，返回体与调度代码不变。
3. 验收：保留旧描述于364实现封存，比较schema改动与请求回执不变；运行原有目录/schema预算和自然交接默认/生产测试。不借此改变交接提示或新添状态。

364付费原生工具对照未通过质量门槛：撤回新工具注册及绑定模块，完整实现和17项检查封存于实验目录。Compact的独立契约修复保留。
