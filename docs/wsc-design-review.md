# WSC 设计评审文档（给没读过代码的人）

**目的**：把 XEYO 的上下文压缩机制（WSC）完整讲清，附上所有能拿得出的数据与其**口径**，
供外部讨论"接下来该怎么优化"。文档不粉饰：每个数字标了它是厂商账单、引擎账本、还是建模推算。

**证据分级（全文每条数据都带标记）**

| 标记 | 含义 | 可信度 |
|---|---|---|
| 【账单】 | 厂商返回的用量（`trajectory.json.usage`，DeepSeek 实付 CNY） | 最高 |
| 【账本】 | 引擎自己落盘的逐枪/逐事件账（`~/.xeyo/usage/*.jsonl`），可用文档末尾探针复现 | 高 |
| 【源码】 | 设计事实，带 `文件:行号` | 高（可核） |
| 【建模】 | 离线重放 + 成本模型算出来的**比值**，不是账单 | 中：比值可用，绝对¥要修正 |
| 【评测】 | 离线裁定器/问答集打分 | 中：受裁定器口径限制 |
| 【待复核】 | 旧探针给过、本轮没能复现到同一口径 | 低：**别在它上面加结论** |

## 一、30 秒版

- WSC 把长会话的历史压成**一份确定性的"热层"摘要**（不调用 LLM）+ **一个可取回的冷层**，
  目标是同时省两样东西：**上下文 token** 和 **提示词缓存的重填钱**。
- 它**不决定什么时候压**：触发权在 C2（压缩调度器），WSC 只是"这一枪要压时，实际发出去什么"。
  【源码】`memory/wsc_projection.py:3` — "C2 remains the trigger; WSC becomes the execution projection"。
- 今晚刚落地的改动：**折叠的经济判据换成 θ=1**——"这一次折叠，本枪净省 ≥ 本枪重发面才准做"。
- 一次真跑对照（同题、同窗口档）：折叠 **45→5 次**、每请求成本 **¥0.0284→¥0.0104**、
  逐枪命中率中位 **43.7%→84.1%**。【账单】+【账本】
- **拿不到成绩结论**：两跑都撞了 900 秒 agent 超时，且做的活差 3.3 倍（输出 token 158,790 vs 47,666）。
  收益是"成本/机制"级的，不是"任务通过率"级的。

## 二、术语表（后文所有黑话在这里定义）

| 术语 | 解释 |
|---|---|
| **上下文窗口 / window** | 模型一次能接收的最大 token 数。本项目的值来自**模型登记表**的 `context_limit`（用户添加模型时必填），不是代码常数。【源码】`runtime.py:1541-1559` |
| **前缀缓存 / KV cache** | 厂商按"这次请求的开头和上次相同多少 token"给折扣。命中部分按**命中价**，从第一个不同之处开始全部按**未命中价**重算。 |
| **命中价 / 未命中价** | DeepSeek flash 空闲档：命中 ¥0.05/百万、未命中 ¥1.5/百万、输出 ¥4.5/百万 ⇒ **未命中是命中的 30 倍**；高峰档（工作日 9–12、14–18）价格翻倍，倍率不变。【源码】`usage/pricing.py:27` |
| **重发面 / transition** | 一次改写让多少 token 从"命中"退回"未命中"。压缩把历史换掉 ⇒ 头之后的内容**整段**重算。 |
| **折叠 / fold** | 把上下文尾部的若干轮原始消息"折进"热层摘要。折叠之后原始文本不再逐字发送。 |
| **热层 / hot 层** | 折叠产物：一份结构化摘要文本，作为一条 `assistant` 消息（`name=session_summary`）放在发射序列最前面。 |
| **冷层 / cold 层** | 被折叠掉的原文并不删除，而是留在一份**取回视图文件**里，热层用"句柄"指向它。 |
| **句柄 / handle** | 热层里的一行引用，模型照着它能取回原文。五种：`node://12`（单/多个节点原文）、`branch://B1`（被剪分支）、`reqs://5-120`（一批旧用户原话）、`head://<sha>`（上一版热层快照）、以及生产形态的 `Read(file_path='…', offset=…, limit=…)`（视图文件的行区间）。【源码】`synaptic/coldstore.py:16-37,49-60`、`synaptic/handles.py:13-31` |
| **节点 / node** | 证据 DAG 的原子单位 = **一条消息**。【源码】`synaptic/types.py:51` |
| **卡片 / card** | 一条"被剪掉的分支"的结论化索引：结论 + 涉及文件 + 错误签名 + 复现命令 + 节点列表 + 句柄。上限 24 张，超出**只合并无错误签名的卡**（带错误的卡永不丢弃，防重复犯错）。【源码】`synaptic/types.py:118-131,182`、`synaptic/prune.py:230` |
| **证据 DAG** | 节点图，四类边：`seq`（时序）/`use`（调用）/`file`（文件）/`err`（错误）。默认只用语法边（`soft_dag=False`）。【源码】`synaptic/types.py:21-24,172-174` |
| **闭包 / closure** | 生产组装模式：从"钉住集"（PIN/工作集/目标）出发，取**反向 2 跳可达**的节点进热层——这就是"哪些历史值得留在注意力里"的判据。【源码】`synaptic/closure.py:100,278-289` |
| **游标 / compact_cursor** | "已经折进热层的前多少条消息"。它是 C2 与 WSC 之间唯一的接口。 |
| **发射 / 请求** | ⚠️ **两个不同分母**：一次请求前引擎会构造若干次投影（增量缓存路径 + 全量路径），**发射≠厂商请求**。实测 attempt2 重放 99 次发射 vs 账单 59 次请求，差 **1.7 倍**。本文所有"每枪¥"若来自重放，都不是每请求成本。 |
| **水位 / watermark** | 主动压缩阈值 = `0.80 × context_limit`（可被 `XEYO_CONTEXT_COMPACT_RATIO` 覆盖，限 0.5–0.99）。【源码】`runtime.py:1942-1958` |
| **硬触发 / HardTop** | 逼近/越过窗口硬顶时的**强制**折叠，绕过一切经济判据。硬顶 = `window − reserve_tokens(2048)`。【源码】`simulator/params.py:48,91-92`、`runtime.py:1145,1739` |
| **保尾 / keep tail** | 永远逐字保留的最近上下文：按**最近 K=3 个成对工具轮**，不看 token。【源码】`engine/compact.py:115-134` |
| **成对安全 / pair-safe** | 切点不得落在"一次工具调用"与"它的结果"之间，否则发出非法形状。【源码】`memory/runtime.py:334-347` |

## 三、问题设定：为什么要做这件事

两条独立的压力，WSC 同时针对它们：

1. **注意力**：长会话里"什么该留在模型眼前"。原始 transcript 动辄几十万 token，全部塞进去既贵又稀释注意力。
2. **钱**：在 DeepSeek 这类**按缓存命中计价**的厂商上，成本的主要变量不是"发了多少 token"，而是
   **"有多少 token 退化成未命中"**。因此**"压得狠"和"压得省"是两件可能相反的事**：
   一次压缩省下 3 万 token 的历史，却可能触发 5 万 token 的重填。

引擎铁律（决定设计形状，评审时值得对照）【源码】`AGENTS.md` 设计理念节：
只给模型**信息**不给**导演**；能静默完成的一律不进上下文；限制表达在执行层而非提示文本。
⇒ 直接后果：热层是**事实的索引**，不含"你应该接着做什么"式文本。

## 四、它在系统里的位置（调用链）

```
用户/工具结果 → 消息存储
   ↓ 每枪构造投影
engine/query_loop.py  ── remaining_turns = 本轮预算剩余轮数（max_turns − turn_count，被 r_cap=96 封顶）
   ↓
memory/runtime.py::project_for_model
   ├─ decide()（离线 simulator 的调度器：keep / C1 / C2 + hardtop 判定）
   ├─ 要压时 → note_c2()（首压）或 try_extend_c2()（已压态：把游标往前推）  ← ★折叠经济门在这里
   └─ apply_c2_messages()
          ↓ XEYO_WSC=1 时优先走 WSC
memory/wsc_projection.py::project_c2_messages
   ├─ 决定"右段要不要折进头"（默认：跟随游标事件；可选：再叠一层 cadence 判据）
   ├─ synaptic/project.py::project(...)  ← 真正的组装（DAG→闭包→剪枝→分段→预算）
   └─ 发射：[热层消息] + project_c0c1(尾部原始消息)
          ↓
model/_openai_common.py：最后一公里（把 tool 行转成厂商形状 + 丢弃无主 tool 结果）
```

三个开关（默认值即生产事实）【源码】`memory/wsc_projection.py:36-45`、`memory/memory_switches.py:69-70`

| 开关 | 默认 | 关掉会发生什么 |
|---|---|---|
| `XEYO_WSC` | 注册表默认 **0**；本仓库 `.xeyo/settings.json` 里写了 `1`，经 settings→env 桥在启动时注入进程 ⇒ **在本工作区内是开的**，换克隆目录/不带该设置就是关的（评测档另有默认：`BENCH_ENV_DEFAULTS` 里钉 `1`） | 完全回到 C2 原生摘要（历史上 26 个 TB 绿灯全是这一态） |
| `XEYO_WSC_FROZEN_HEAD` | **开** | 每枪重投影、交界每枪前移 ⇒ 实测贵 **2.3 倍**（生产账本，非建模） |
| `XEYO_WSC_CADENCE_ABSORB` | **关** | 头的吸收只跟随游标事件。现在按设计**不需要它**：经济门已经装在"推游标"那一步（§7.2），开了等于同一件事判两遍 |

> ⚠️ 一条踩过的坑：**WSC 的开关有 settings/env 两套读路径**，历史上注册表把它标成 settings，
> 而运行时只读 env ⇒ "面板显示开、实际没开"。现在这三项在注册表里显式标 `authority="env"`。

## 五、热层：内容、顺序、以及"只追加"这条硬约束

### 5.1 分段（段的语义就是模型看到的小标题）

```
[CONSTRAINTS] [UNRESOLVED] [DECISIONS] [PRUNED] [WORKING SET] [PATHS]
[MAIN] [REHYDRATED] [TODO] [NEXT] [REQUESTS]      (+ [HEAD] 换头时)
```
【源码】`synaptic/assemble.py:44-57,64-76`

各段承载：`CONSTRAINTS`=用户给过的硬约束；`UNRESOLVED`=当前未解决的问题（会被摘除）；
`WORKING SET`=文件状态原地改写；`PATHS`=路径索引（第四条渲染通道，独立配额）；
`MAIN`=闭包选中的主干节点；`DECISIONS`=已排除分支（带错误签名）；`PRUNED`=其余被剪分支；
`REQUESTS`=区域内用户原话；`REHYDRATED`=被取回来的内容；`NEXT`/`TODO`=计划与状态。

### 5.2 顺序由**前缀失稳率**决定，不是内容重要性

`实际次序 = 按各段"历史上多大概率会改动"升序排` ——
【源码】`assemble.py:442-454`："放在前面反而最省 KV"。先验序只作初始值与平局裁决；
带滞回（`churn_margin=0.15`、`churn_dwell=4`）防止每枪换装。

### 5.3 默认是"日志档"：只追加，不重排，不改写

`journal_layout=True`（默认）⇒ 发射物是 `(段头, 行)` 序列按**首次发射顺序**排列：
【源码】`assemble.py:285-286,506-513` —— "按键去重会退化成原地改写，而改写正是要消灭的东西"。
⇒ **日志档下没有任何段可以原地改写**（这是对 5.2 的一条强化：既然逐行只追加，段内顺序也定了）。

### 5.4 三桶预算（Medium+ 生产档）

| 桶 | 管哪些段 | 额度 | 超了怎么办 |
|---|---|---:|---|
| fixed | CONSTRAINTS/UNRESOLVED/TODO/WORKING/PATHS/REQUESTS/NEXT | **1,800** tok | 只降级**可降级**段（去重→摘录阶梯逐级减半到 16 字符→仅留句柄→关段）；受保护事实不静默省略【源码】`budget.py:35-39,319,371-389` |
| main | MAIN + REHYDRATED（+卡面计入） | **1,200** tok（= hot 3,000 − fixed 1,800） | 回缩预算**重跑背包**，落选者理由="预算不足落选"【源码】`project.py:219-222` |
| index | DECISIONS + PRUNED（=卡面，**与 main 重叠记账**） | **1,600** tok 观测线 | **只报账不删**："此处只分桶 + 报账，一个字节都不删"【源码】`budget.py:267,459` |

账目行的原样模板（每次投影可打印）：
`fixed X/Y tok, main A/B tok(含固定段让渡 N), index I tok（内 决策卡 D / 句柄面 H；观测线 1600，不裁剪）, total T tok, requests=<模式>@<摘录字符数>`
【源码】`budget.py:302-316`

档位表（`hot_budget_tokens`）：Micro 8,000 / Light 5,500 / Medium 4,000 / **Medium+ 3,000** / Hard 1,800；
Medium+ 另设 `journal_growth_tokens = 3×3,000 = 9,000`（其它档 2×）。【源码】`types.py:355-371`

### 5.5 已测尺寸（口径要看清）

- `[REQUESTS]` 是**最大的一段**：固定开销 ≈ 每行 10–15 token × 实测每回合 93 行 ≈ **1,565 token/回合**；
  摘录字符数不是瓶颈（用户原话普遍短），要压它只能**合并行** ⇒ 于是有了区间句柄 `reqs://首-末`。
  【源码】`coldstore.py:20-27`
- 卡面（DECISIONS+PRUNED）在两批语料 51 会话的**末轮投影**上：median 0 / p90 1,189 / p95 1,348 / max 2,113 token；
  **p90 时占热层 64%**。⇒ 这就是"index 桶单列且只报账"的理由：真要压它只有一条路叫**删句柄**，
  而删句柄等于撤回"被剪节点必可拉回"。【源码】`types.py:331-348`
- 【待复核】"句柄面占头 40%"：本轮用独立探针重测时拿到的末轮热层只有 943/1,004 token、句柄面 0——
  **与生产逐枪账的口径不一致**（探针没带跨轮 `prev/cold` 状态，句柄退化）。⇒ 这个数**暂不引用**，
  取回率与句柄占比要靠 `wsc_index_usage.jsonl`（已在攒）出。

## 六、冷层与"必可拉回"这条承诺

**承诺**：任何被剪掉/骨架化的节点，热层里必须留一个能取回它的句柄。
**谁来保证**：`project.py:266-330` 给所有剪掉、骨架化、用户节点绑真句柄；
未知句柄 `ColdStore.expand` 直接 `raise KeyError`（"不静默降级"）；
报警判据只有一条真事故形状：**"节点被剪了，却没有活句柄能把它拉回来"**【源码】`report.py:344-351`。

**代价（全语料同口径 A/B，只换句柄形态；动机是"引用在每个句柄上重复一次"，实测 **median 28 个句柄/轮**）**
【源码】`memory/offload.py:78-99`

| 引用形态 | 热层 token median | WSC 总成本 | 压缩率 median |
|---|---:|---:|---:|
| `expand(node://N)`（**生产不可执行**，见下） | 2,406 | ¥8.134 | 0.8718 |
| `Read(file_path='<绝对路径>', …)` | 3,407（比 expand +41.6%） | ¥8.724（+7.25%） | 0.8606（−1.28pp） |
| `Read(file_path='<相对路径>', …)`（**生产现行**） | **2,998**（比绝对 −12.0%，比 expand +24.6%） | **¥8.6041**（比绝对 −2.03%，比 expand +4.97%） | 0.8636 |

> ⚠️ **这张表最容易被读错的一行**：源码明确警告"跨形态的 token/成本一律不可相减"——
> 因为 `expand` 那一行**不是生产可选项**（下条）。正确的读法是：
> **可执行的取回引用，比"看起来最省"的函数式写法贵 +24.6% 热层 / +4.97% 成本；
> 用相对路径把这笔钱从 +41.6% 压到 +24.6%**（340 会话 / 771 回合同批复测：¥8.7824→¥8.6041，针不退化）。

**已知断链（评审重点）**：视图文件丢失/行区间对不上时，代码**回落 `expand` 形态**
（"宁缺勿假"）——而 **`expand` 在生产里没有解析器**（专用工具已删，取回面统一到 `Read`）。
⇒ 那条兜底路径给出的引用，模型在生产里**执行不了**。【源码】`handles.py:20-21,66-73`、`project.py:342-355`、`offload.py:98-99`

视图文件位置：`<offload根>/wsc/<safe(session_id)>.txt`，根 = `XEYO_OFFLOAD_DIR` 或 `<cwd>/.xeyo_offload`；
每次折叠由 `write_text_view` 重写。【源码】`wsc_projection.py:97-100`、`offload.py:41-51`、`project.py:344`

## 七、什么时候折：三道闸 + 一个硬顶（今晚改的就是这里）

### 7.1 折叠的经济学（一行公式）

- 不折：被折区继续逐字发送，但**命中价** ⇒ 每枪省 `saved × p_hit`
- 折：本枪付一次**未命中价**的"重发面" `transition = 新头 + 仍逐字发的尾部`
- 折 ⟺ `净省 saved ≥ θ × 重发面 transition`，其中
  **θ = price_ratio × margin / PAYBACK_SHOTS = 30 × 1 / 30 = 1.0**
【源码】`synaptic/cadence.py:17-30,62-90,100-113`（`theta_required()` 是这个式子的**唯一实现**）

θ=1 的物理含义：**这一枪就不亏**，不需要知道会话还剩多长。

### 7.2 扩展闸（已压态，游标往前推）——生产链的实际触发点

【源码】`memory/runtime.py:1131-1236`，顺序：

1. **收益闸**：区域字符数 − 摘要增量 ≥ `c2_min_gain_chars(4000)`；
2. **稀发闸**：区域字符数 ≥ `c2_extend_ratio(0.25) × 已冻结区`（防"每次挪一点点"）；
3. **经济闸（θ=1）**：`saved_net = 区域token − 头token ≥ θ × (头token + 尾部token)`。

外加**冷却**：`turns_since_c2 < min_middle_edit_gap(4)` 时 decide 不给 C2【源码】`runtime.py:1726`；
外加**硬顶**：`force=True` 绕过以上全部，保证超窗必压。

**今晚删掉的东西（重要，因为它是旧收益数的来源）**：旧第 3/4 闸乘的是 `remaining_turns`
（= 本轮**预算**剩余轮数，不是"还会重用前缀几枪"），且它把 `price_ratio × margin=60` 除在这个数上
⇒ **有效门槛 = 60/remaining**：生产被 `r_cap=96` 封顶 ⇒ 0.625 倍，评测脚本传 8 ⇒ 7.5 倍，
**同一份代码在两个档位之间漂 12 倍**。现在扩展闸不再读它，`c2_extend_min_remaining_turns` 一并删除。

### 7.3 观测（今晚新增，评审可以直接要数据）

## 十、可以优化的面（拿去讨论的清单，每条写清"缺什么证据"）

**O1 把等产出口径做成评测的一等指标。** 现在两跑输出差 3.3 倍，钱的对比天然带偏。
候选主指标：`每 1k 输出 token 的成本`、`900 秒内完成的工具轮数`、`到首次可验证提交的时间`。
缺：把这些指标写进评测台并跑 k≥3（一次 64k 单题约 ¥0.4~1.7）。

**O2 保尾改成"轮数下限 + token 上限"双约束（治 D2）。**
缺：真实分布——单轮工具结果有多大？（逐枪 `region_tokens` 已在 `fold_events` 里，一次冒烟就能出）

**O3 头要不要真闸（治 D3）。** 现结论是"裁剪闸被实测否掉、只能报账"，但**取回率的分母还没有**。
`wsc_index_usage.jsonl` 已在记 `head_shots / handle_refs / handle_tokens`；要裁卡必须先有"这些句柄真被用过吗"。

**O4 折叠的"粒度带"要不要显式控制。** θ=1 把小口折（<2,000 tok）从 40.0% 打到 0%，但也让
5 次折叠里 2 次是靠硬触发兜进来的 ⇒ 存在"推迟到边界"的倾向。候选：给单次折叠一个**目标区间**
（净省 ≥ θ×重发面 且 ≤ M token），或让水位系数随 θ 自适应而不是固定 0.80。
缺：θ=1 下"硬触发占比"随会话长度的曲线（现在只有 1 个点）。

**O5 把首压也接到同一个 θ（治 D4）。** 首压前面还有压力门兜着，但两处判据不统一就会一直有口径纠纷。
缺：首压侧单独的重放收益测（首压每会话只发生 1 次，收益量级可能远小于扩展）。

**O6 可恢复性闭环（治 D1）。** 要么给 `expand` 补一个生产解析器，要么把"视图丢失"改成
**不折叠**（宁可不省，不发不可执行的引用）。缺：视图失效的真实发生率（掉文件/行号漂移）——
现在只有影子档的 1,047 样本 115 条漂移这类间接证据。

**O7 观测补齐（治 D5/D9）。** `fold_events` 已是权威分母，还差：逐请求成本与 `arm` 的 join
（同一 ts/session 对齐），把"哪一臂折的、折完那一枪命中率多少"变成一条可查记录，
这样 #11（≥30 个折叠当枪的厂商样本）会自动攒够。

**O8 要不要引入 LLM 摘要。** 现设计是三样都要：**零 LLM、可逆、确定性**（`project.py:4`）。
权衡要说清：LLM 摘要能提语义，但会破**确定性**（同输入不同输出 ⇒ 缓存/回归全废）与
**可逆性**（有损后只能靠检索兜）。这条是产品定位选择，不是纯工程题。
