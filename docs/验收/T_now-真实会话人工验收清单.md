# T_now 真实会话人工验收清单（L3）

> 状态：**待人工执行**（需起 XEYO + 弱模型 `glm-4.5-air` + 人工 GUI 操控）。
> 前置：`py -3.11 -m cli serve`（或已运行的 FastAPI）；工作区含 `pkg/XEYO.md` 与 `otherlib/XEYO.md` 两条规则；如测第 5 项需先准备一份待审提案。
> 判定：逐项独立做，符合=过；失败先分「观测误读 / 真失效」，再回 L1 单测 + L2 preview 定位。

| # | 操作 | 判定标准（过） | 会话id | 模型回复摘录 | 过/不过 |
|---|------|---------------|--------|--------------|---------|
| 1 | 事故重演：长对话干活几轮后突然发「帮我修改」 | 回复针对**对话上下文**继续任务，不再把背景块当任务对象；不冒「关于记忆索引…」类答非所问 | | | |
| 2 | 对照组：同会话发「继续改 pkg/foo.py 的校验」 | 正常执行并**遵守** pkg/XEYO.md 规则（限窗下规则在场） | | | |
| 3 | 限窗消失/恢复：切无关话题聊 30+ 轮再回 pkg 改动 | 中途回复**不受** pkg 规则影响（静默）；回触 pkg 后**恢复遵守** | | | |
| 4 | 记忆召回：问「我之前说过什么偏好？」 | 模型**主动调用** `Memory(action=search)`（recall 指引生效），不再依赖索引块 | | | |
| 5 | 提案计数：存在待审提案时让模型 search | search 结果末尾出现「另有 N 条 XEYO.md 写入提案待审（/proposals 查看）」 | | | |
| 6 | 拉取通道：输入 `/proposals` | 全量候选列表正常返回（旧功能未破坏） | | | |
| 7 | peer 边界：同工作区开两个会话 | T_now 只剩一行 beacon + 禁答行，**无「正在聊：」**；问「另一个会话在干嘛」模型去调 `Memory(action=peers)` | | | |
| 8 | Plan 衰减（可观察项）：批准计划后实施，首次成功写盘后 | 后续轮不再重复复述计划全文（计划块已静默；主证在单测） | | | |
| 9 | 续写纪律：任一工具调用后让模型继续 | 先续写原问题，不把工具结果当新指令（after_tools 合同未破） | | | |

## 判定原则
- 1/2/3 同一工作区相扣，按 1→2→3 顺序做；其余独立。
- 观测：GUI 聊天窗口；看模型「实际收到什么」用 `preview-t-now.bat`（只读）或 GUI 的「投影视图」/`/v1/audit`。
- 第 8 项为辅助观测，主判据在 `tests/test_p1_block_placement.py::test_approved_plan_decays_on_*`、`::test_query_loop_wires_plan_decay`。
