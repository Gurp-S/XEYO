## 零、总评

这份代码的**结构正确性**明显高于同体量个人项目：稳定前缀三保险、env_channel 环境声道、三态单向裁决、内容寻址快照、fail-closed 倾向、证据门纪律——都是真东西，不是包装。

但 09-04 那轮审计指出的核心问题，**6 天后仍然成立**，且性质高度一致：

> **XEYO 的问题不是"没写"，而是"写了但没接线 / 有边界但边界不止一处"。**

本次复核的 32 项旧缺口里，**已修 12 项**（多为安全项，修得干脆：NotebookEdit write_scope、插件信任劫持、bash 换行绕过、路由门禁补齐、Tauri 端口劫持、DeepSeek 账本黑洞、fence 转义、record_transcript fsync、context_limit 断链、token 口径主干）。

**仍在 20 项**，且**新发现 25 项**。最需要警惕的是三条横切模式：

| 模式 | 表现 | 后果 |
|---|---|---|
| **双轨并行** | 同一能力两套实现：rewind v2/v3、MCP 直挂/网关、GUI/TUI 两套 SSE、AskUserQuestion/权限 ASK 两套 store、C2 三个决策分支 | 每处 = 两个 bug 面 + 漂移 |
| **写了没接线** | Scheduler DAG（1110 行）、`incomplete_tool_uses`、`stage_clock.py`、`cgraph.py`、`cache_profile.py`、`clear_wrap_window`、memindex `edges` | 绿测试营造"已实现"假象 |
| **旁路绕主链** | `workspace_fs` 直写、后台 bash job、WriteStore 写路径 都不经权限/rewind/审计 | 引擎内辛苦维护的不变量被单点抵消 |

## 一、P0：开源前应修或加默认闸（6 项）

### P0-1　`workspace_fs` 直写绕过引擎三链路【仍在·最该先修】

`server/workspace_fs.py:196-239` 的 `write_file` / `delete_path`（支持 `recursive=true`）只受环境开关 `XEYO_WORKSPACE_FS_READONLY`（默认**关**，`:37-39`）约束，不穿引擎权限、不进 rewind、`_audit_write` 失败还静默吞（`:42-51`）。

> **定性修正（详见详析文档 §四）**：这不是"忘了接线"——它服务于 GUI Explorer 编辑器的即时保存（`explorerStore.saveFile`→`api.ts:738 writeWorkspaceFile`），模型不在链路上。问题是**安全边界没配齐**：默认允许写、不进 rewind（用户手动编辑无法回滚）。**修法**：默认反转（显式 `XEYO_WORKSPACE_FS_WRITABLE` 才可写）+ 审计失败告警，随后收敛进共享 write gate。

### P0-2　`usage.py` 是开放 SSRF 代理面【仍在】

`server/routers/usage.py:79-92` 用请求头 `X-Base-Url` 拼 URL 并 `urlopen`，无域名白名单 → 可带 Bearer 向任意地址发请求。同文件 `:25-28` 把 Authorization 直接当供应商 key 透传。

### P0-3　Tauri 自定义 command 可写全盘【仍在】

`gui/src-tauri/src/lib.rs:384-391` `save_text_file` 只判非空即 `std::fs::write` 任意绝对路径；`create_directory` / `git_init` / `git_clone` 仅校验"是绝对路径"（`:441-451`）。capabilities 未给自定义 command 加 ACL，**pet 窗口同权** → pet 侧 XSS 即全盘写。

> 注：`wait_health` 端口劫持已修（`:417-431`，校验端口文件 pid 存活）；`kill_python_tree` 已改用真实子进程 pid（`:197-205`）。这两项【已修】。

### P0-4　预览 iframe 仍 `allow-same-origin`【仍在】

`gui/src/components/BrowserPreviewPanel.tsx:347` sandbox 含 `allow-scripts allow-same-origin allow-popups-to-escape-sandbox`；`gui/src-tauri/tauri.conf.json:32` `frame-src` 含 `data: blob:`。模型可发 `data:text/html` 直达可执行上下文（同文件 `:28` 还显式禁用了 `msSmartScreenProtection`）。

### P0-5　后台 bash 作业：无超时 + 解绑 abort + 绕过 rewind【仍在】

`server/job_registry.py:38` `JOB_NO_TIMEOUT_MS = 86_400_000`（24 小时 = 事实上的无超时），`:254` 晋升 job 一律用它；`tools/bash_tool/destructive_guard.py:28-31` 自认"registry 后台 job 直通路径不快照"。→ runaway job 无保护，产物不可回滚。

### P0-6　GUI 侧 apiKey 明文落 localStorage【仍在】

`gui/src/stores/settingsStore.ts:913-958` 把 `apiKey` 与**整个 profiles**（各 profile 独立 key）明文 `JSON.stringify` 进 `xeyo-settings`；`rewindV3Store.ts:133` 还把会话文本片段落盘。

## 五、值得肯定的地方（不是客套）

避免只读负面清单，以下是经核实确实做得好的：

1. **装配层的前缀缓存纪律**——system 左段锁序、schemas 会话冻结、env 假对尾插不动前缀，三保险是真设计，非口号。
2. **裁决三态单向性**——`DENY` 不可被 grant 覆盖；指纹 v2 参数不进指纹（注入免疫）；这些有契约测试逐字节锁死。
3. **评测的"数据准入"纪律**——证据门 + 反作弊 shadow 模块 + 分数口径登记表 + 显式披露失败集与"并发修改事故"，工程成熟度高。
4. **多 agent 可调试性**——写冲突给出"行区间摘要 + 跨会话归因（session_presence owner_of）+ 重读指令"（`file_edit_tool/conflict.py:93-110`），罕见。
5. **安全项的修复速度**——09-04 到 09-10 六天内修掉 12 项（含插件供应链 P0、端口劫持、SSE 换行绕过），说明反馈闭环有效。
6. **前端类型卫生**——非测试代码 `any` 仅 2 处，stores 层零 `any`。
