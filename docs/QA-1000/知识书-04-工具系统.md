## 1. 工具契约：一个工具要实现什么

`python/tools/base_tool.py`(82) 定义最小契约 + 两个**静态声明**：

| 成员 | 含义 | 消费者 |
|---|---|---|
| `name` | 工具名（schema 与权限裁决的键） | registry / policy |
| `schema()` | JSON schema（会话内**冻结**） | prompt 装配 |
| `execute(input, abort)` | 执行体 | registry.run |
| `is_read_only()` | 是否**无副作用** | 只读模式网关 `readonly_gate` + 模式白名单 |
| `is_concurrency_safe()` | 能否与同轮其他调用并行 | `orchestration.partition_tool_calls` |
| `check_permissions(...)` | 工具内路径裁决（纵深防御） | 工具自己 |

**`is_read_only` 的语义是「无副作用」而非「不碰磁盘」**——`WebFetch` 声明为 `False`（`web_fetch_tool.py:64-67`），因为出站网络访问会产生外部副作用。这是面试常考点。

**两个静态方法不互相决定**，四种组合都要能举例：

| 组合 | 例子 |
|---|---|
| 只读 + 并发安全 | `Read` / `Glob` / `Grep` |
| 非只读 + 并发不安全 | `Write` / `Edit` / `Bash` |
| **非只读 + 并发安全** | **`Agent`**（注释：`同轮可并行多个 Agent；磁盘冲突由 WriteStore content-hash 收敛`，`agent_tool.py:105-107`） |
| 只读 + 并发不安全 | 少见 |

★ 「非只读 + 并发安全」的成立条件是**下层能收敛冲突**，而不是工具自身无副作用——这是「声明与正确性责任分离」的样板。

## 2. 工具注册与裁剪（三道）

| 出处 | 机制 |
|---|---|
| `tools/catalog.py`(492) | `build_default_registry()`：装配默认工具集 |
| `tools/tool_registry.py`(636) | `register()` / `schemas()`（浅拷贝 + 短描述预算）/ `run()`（权限 gate → execute → 输出预算 seam）/ `_apply_output_budget` |
| `tools/meta.py`(414) | `ToolMeta` 静态表：`read_only` / `concurrency_safe` / `policy` / `subagent_ok` / `subagent_baseline` / `exposure` / `short_description` / `output_budget` / `needs_read_state` / `needs_write_store` |

**三道裁剪**：

1. **`exposure="hidden"`**：不进 `tools` 数组（**tools 数组会话内冻结 = 零前缀重缓存红线**），但**保留注册** ⇒ 幻觉调用仍经 `run()` 权限三态（fail-safe）。示例：`offload_read`。
2. **模式裁剪**（`permissions/policy.py:120-125,386-412`）：`_MODE_TOOL_ALLOW` 表 —— `agent: None`（不限）/ `ask: READONLY_ALLOW | READONLY_ASK_ALLOW` / `plan: 上述 + PLAN_ONLY_ALLOW({ExitPlanMode})`；判定**优先读工具实例的 `is_read_only()`**（与实现同源，避免第二张名字表漂移）。
3. **子 agent 裁剪**（`tools/agent_tool`）：`scope=[]` ⇒ **移除 `Write`/`Edit`**（`agent_tool.py:137-144`），而不是让它们在工具内报错——「能强制的就不给模型看」。

★ 另有 **`side_mode()`（侧聊）**：请求级开关，**优先于 Agent 模式**，只放真只读工具（`policy.py:394-399`）。

## 3. 输出治理三层（**最高频面试题**）

### 3.1 三层与豁免关系

```
① 工具自带 seam（Bash / Read）
② registry 预算（16_000 默认；PREVIEW_HEAD=6_000 / PREVIEW_TAIL=2_000 + spill 落盘）
③ 提示词侧：Noisy stdout compacted（Bash 的 cmd_compact）
```

| 工具 | `output_budget` | 谁负责 |
|---|---|---|
| `Read` | **0（豁免）** | 自带：`MAX_LINES_TO_READ=2000` + `DEFAULT_MAX_TOKENS=25_000`（粗估 `len//4`）+ `MAX_SIZE_BYTES=0.25MiB` |
| `Bash` | **0（豁免）** | 自带 `truncate_for_model`（`DEFAULT_LIMIT=30_000` / `HEAD_CHARS=20_000` / `TAIL_CHARS=8_000`） |
| 其余 | 未设 → 16_000 | registry 预算 |

**豁免理由（必背）**：

- `Read`：「防 **read→spill→read** 循环」——若 Read 结果也落盘换预览，读那个 spill 文件又会产出超预算结果。
- `Bash`：「Bash 自带 raw→落盘→截断 seam，**避免双重截断/双重落盘**」——双重截断会把第一次截断抢救出的「中段错误行」再裁掉（抢救白做）。

### 3.2 registry 预算的细节（`tool_registry.py:179-234`）

四处早退：`is_error` / `content` 非 str / 空串 / `budget <= 0 或 len <= budget`。三级优先级：**实例属性 `tool.output_budget` > `ToolMeta.output_budget` > `DEFAULT_OUTPUT_BUDGET=16_000`**。

预览四段（`head` + 截断标记 + `tail` + 说明行）：

```
<head 6000>\n\n…[middle truncated by output budget]…\n\n<tail 2000>\n\n
[output truncated: 预算截断（非错误），原始 N 字符；full output: <path>]
```

元数据四键：`spilled=True` / `spill_path` / `original_chars` / `truncation="output_budget"`。**显式 `is_error=False`** = 双侧语义声明（模型不该当失败去重试、程序不该计入错误率）。

★ **`full output` 措辞超出事实范围**：spill 落盘的是 `result.content`（**工具已约束过**的内容），不是「工具的真实原始输出」。例如 `Read` 豁免预算、无 `limit` 时**静默**只给 2000 行；`Grep` 的 `files_with_matches` 默认 `head_limit=250`，spill 里也只有那 250 条。→ 应读作「本次工具结果的完整文本」。

### 3.3 Bash 的三层输出治理（`truncate.py` 96 行 / `cmd_compact.py` 370 行）

**`truncate_for_model`**：头 20k + 尾 8k + **中段错误抢救**（尾 8k 内无高信号错误行时，从中段抢救最多 **8 行 / 800 字符**，配 `[error excerpt preserved from truncated middle]`）；全文落盘 `bash-<uuid>.txt`；契约「模型永远能看到头部 20k、尾部 8k 与（有则）中段错误行」。

**`compact_command_output`**（九家族 / 六压缩器：pytest / vitest·cargo_test·go_test 共用 / tsc / lint / git / build；`_MIN_CHARS=4_000` 以下不压）：

★ **保真不变式**（`:78-83`）：

```python
	if _TRACE_HINT.search(text) and not _TRACE_HINT.search(compacted):
		return text          # 原文有错误信号、压缩后没了 -> 整段回滚原文
```

`_TRACE_HINT = re.compile(r"(?i)(traceback|exception|error:|FAILED|FAILURES)")`。

失效面（面试可指出）：`npm ERR!`、中文/符号失败形态、`cargo error[E0308]`（无冒号）、**非零退出码但无匹配行** 都不在 `_TRACE_HINT` 里 ⇒ 不受这层保护。

★★ **最关键的一处结构性发现**：`cmd_compact` 的 docstring 自陈「**不改原命令、不落盘**」；而 `truncate_for_model` 落盘的是**它拿到手的文本**。所以 `full at <path>` 指向的是**压缩后**的内容——**被压掉的通过行永久不在任何文件里**。这与 spill 的纪律（`tools/spill.py:1-13`「原始输出先落盘，截断只发生在模型可见投影」）**顺序不一致**，是本项目可提的结构性改进点（面试加分）。

## 4. 文件工具族（`tools/fileio/` 11 件 + 五件套）

### 4.1 五件套定位

| 工具 | 关键常量 / 机制 |
|---|---|
| `Read` | `MAX_SIZE_BYTES=0.25MiB`（可被 `limit`/`symbol` 豁免）· `MAX_LINES_TO_READ=2000`（无 `limit` 时**静默截断**）· `DEFAULT_MAX_TOKENS=25_000` · `IMAGE_EXTENSIONS={png,jpg,jpeg,gif,webp}`（**不含 svg**）· 12 个 `BLOCKED_DEVICE_PATHS` + `/proc/*/fd/{0,1,2}` · 行号前缀 `     1→`（右对齐 6 + U+2192）· `.ipynb` 走 cell 摘要（原文进 read_state） |
| `Write` | **`.ipynb` 拒绝**（引导 `NotebookEdit`）· 先读门禁（`errorCode 2`）· **行尾硬编码 `line_endings="LF"`（真缺陷）** · 同内容跳过落盘（`unchanged`）· 写后语法自检（`.py`/`.json`，只报**新引入**的错） |
| `Edit` | **正确保留行尾**（把探测到的 `endings` 一路传给 `_persist`）· `old_string=""` = 创建语义（仅空白文件）· 弯引号归一化 + `preserve_quote_style` · 校验缓存 `_last_*` 双向清理 |

| `Grep` | `DEFAULT_HEAD_LIMIT=250` · `MAX_COLUMNS=500` · `RG_TIMEOUT_SECONDS=30` · 四种 `output_mode` · `content_index` trigram 加速（**全或无**超集保证） |

### 4.2 三个高价值缺陷（面试可直接讲）

**① `Write` 把 CRLF 文件整份改写成 LF**（`file_write_tool.py:319,372`）

```python
old_content, _endings, encoding = read_text_file(full)   # 读到就丢（下划线前缀 = 有意忽略）
...
self._persist(full, content, encoding=encoding, line_endings="LF")   # 硬编码 LF
```

同一行里 `encoding` 被保留、`_endings` 被丢——**不对称处置是最强线索**。后果：语义改一行 → `git diff` 全文件、blame 失效。`Edit` 正确（`:434`→`:520` 传 `endings`）。

**② 三方缓存失效责任不收敛**：

| 缓存 | 键 | TTL/容量 | 写后失效 |
|---|---|---|---|
| Glob 查询缓存 | `("files", pattern, root, head_limit, off)` / `("summary", root)` / `("suggestion", pattern, root, cwd)` | 60s / 128 | ✅ `clear_glob_cache()` **全清**（Write/Edit/Bash 三处调用） |
| `content_index` | `root` | 30s / 8 root | ⚠️ 有 `clear_content_index()`，但 **`_invalidate_glob_cache` 不调用它** |
| `ReadFileState` | `normcase(normpath(abspath))` | **无 TTL** / 128 | ❌ **无外部写后失效**，靠 mtime 被动检测 |

★ `clear_glob_cache` 曾是**零调用者的死代码**（注释自陈）——「写后 60s 内 Glob 命中旧缓存，新文件存在但找不到」的幽灵窗口**真实存在过**。

**③ `Read` 的 `total_lines` 口径**

`all_lines = content.split("\n")` + `len(all_lines)` ⇒ 尾随换行产生 **phantom 行**（`"a\nb\nc\n"` → 4）。后果：① 输出多一行空行；② `offset=total_lines` 会得到「文件比 N 短」的**自相矛盾消息**；③ 无 `limit` 时静默截断 2000 行且**不透传** `total_lines` ⇒ 模型以为读全。

### 4.3 关键机制速查

| 机制 | 位置 | 要点 |
|---|---|---|
| `cat -n` 前缀 | `fileio/text.py:79-91` | 右对齐 6 + `→`；位数 ≥6 不补齐；`start_line` 可偏移 |
| 行尾归一化 | `fileio/text.py:22-28,50-51` | 探测**在归一化之前**；写回按 `line_endings` |
| BOM 处理 | `fileio/text.py:39-49,68-74` | 读剥 BOM；写回 UTF-16 时**补回** `FF FE`（否则下次读成乱码） |

## 5. Bash 工具族（`bash_tool/` 14 文件）

### 5.1 主常量与时间线

```python
DEFAULT_TIMEOUT_MS = 120_000 ; MAX_TIMEOUT_MS = 600_000
MAX_RESULT_CHARS = 30_000    ; MAX_COMMAND_CHARS = 100_000
BASH_PROMOTE_DEFAULT_MS = 45_000        # 前台超时未结束 -> 自动晋升后台 job（0=关闭）
WORKER_BASH_DEFAULT_TIMEOUT_MS = 30_000 ; WORKER_BASH_MAX_TIMEOUT_MS = 60_000
WRAP_WINDOW_BG_MAX_REMAINING_S = 120.0
```

三条时间线（**面试高频**）：晋升 45s（命令继续跑）→ 超时 120s（杀掉，可被命令族映射放大到 180–420s）→ worker 护栏 30/60s（**映射不生效**，连显式 timeout 也被夹）。

`timeout_map._FAMILY_TIMEOUTS_MS`：pip/uv/conda 300s · npm/pnpm/yarn 240s · **cargo 420s（全表最大）** · mvn/gradle 360s · **curl 180s（最小）** · pytest 300s。无命中回落 120s；`XEYO_CMD_TIMEOUT_OVERRIDES`（JSON）可覆盖（**lazy singleton 一次加载，不热更**）。

### 5.2 只读白名单与缓存失效（`bash_tool.py:57-112`）

`_PURE_READ_BASES`（60+ 命令）+ `_GIT_READ_SUBS`（15 子命令）→ `_command_may_mutate_workspace()` **五步判定**，失败取向 **fail-closed**：

| 步 | 判据 | 命中 |
|---|---|---|
| 1 | 空/多行（含 `\n`） | 判写 |
| 2 | `permissions.policy.bash_writes_file` 抛异常 | 判写 |
| 3 | 显式写特征 | 判写 |
| 4 | 含 `$(` 或反引号（命令替换） | 判写 |
| 5 | 逐段查白名单（git 查子命令） | 非白名单 → 判写 |

★ 注释给了成本论证：「**误清只损失一次缓存重建（~140ms），漏清是正确性事故**——误差单向朝安全」。

★ **白名单的能力边界（面试可指出）**：判定粒度是「**程序级**」，而这些程序有「**选项级**」写能力——`find` 的 `-delete`/`-exec`/`-fprint`、`tree -o`、`diff --output`、`xxd in out`、`iconv -o` 全部被判为「只读」⇒ **缓存漏清**；再叠加 `find` **不在** `destructive_guard.DESTRUCTIVE_PROGRAMS` 里 ⇒ **也不做快照**。两者缺口叠加 = 「破坏既成事实 + 不更新事实 + 无恢复点」。

### 5.3 破坏性快照守卫（`destructive_guard.py` 374 行）

| 项 | 值/机制 |
|---|---|
| 开关 | `XEYO_DESTRUCTIVE_SNAPSHOT`，**默认开**；`0/false/no/off/disabled` 关闭 |
| 上限 | `DEFAULT_MAX_FILES=50` / `DEFAULT_MAX_FILE_BYTES=10_000_000`（**设 0 会被夹到 1，不能关**） |
| 程序清单 | 三方言：POSIX（`rm`/`unlink`/`mv`）+ cmd（`del`/`erase`/`rd`/`deltree`/`move`）+ PowerShell（`remove-item`/`ri`）+ `rmdir` |
| 家族划分 | `_POSIX_FAMILY`（`/x` 是**路径**）vs `_WINDOWS_FAMILY`（`/x` 是**旗标**）——正确性必需 |
| 目标提取 | 跳过 `VAR=value` 前缀 / `sudo env time nice` / 重定向 token 及其目标 / `-x` / Windows 家族下的 `/x` |
| 结算 | `settle_destructive_plan`：**被中断/超时的命令按 `completed` 结算**（破坏可能已部分发生）→ 幂等三层（快路径 + 双检锁 + 逐条容错） |

★ **八条「不守卫」路径全部静默**（六条 `_plan` 早退 + registry 直通无 rewind ctx + fail-open 异常兜底）；`settle` 在 `plan is None` 时直接返回 ⇒ **「本次未被快照」在任何地方都无记录**。对照：`tool.spill` / `memory.aging.advance` 都有审计 ⇒ 守卫降级缺审计是明确改进项。

### 5.4 进程终止的平台不对称（**TOOL-06，仍成立**）

```python
	if os.name == "nt" and proc.pid:
		subprocess.run(["taskkill", "/PID", str(proc.pid), "/T", "/F"], ...)  # 整棵树
	else:
		proc.kill()          # 只杀根（注释自陈）
```

| 平台 | 主动树杀 | 被动兜底 |
|---|---|---|
| Windows | ✅ `taskkill /T` | ✅ Job Object `KillOnJobClose`（`DEFAULT_JOB_MEMORY_MB=2048`；**禁用 `TerminateJobObject`**，嵌套 Job 下会阻塞） |
| POSIX | ❌ 只杀根 | ❌ **无**（`JobHandle.assign` 在非 nt 直接 False） |

★ 最严重后果不是资源泄漏而是「**孤儿写工作区 → 覆盖用户改动**」；且 `process_ledger` 登记的是 `proc.pid`（孤儿不在账本里）。修法：`start_new_session=True` + `os.killpg`，并让账本登记**进程组 id**。

## 7. Web 工具族（SSRF 防御，**安全岗必考**）

### 7.1 `web_common.is_blocked_url`（`web_common.py:19-73`）

**八级判定**（返回原因码或 `None`）：

| # | 原因码 | 触发 |
|---|---|---|
| 1 | `empty_url` | 空/空白 |
| 2 | `invalid_url` | `urlparse` 抛异常 |
| 3 | `scheme_not_allowed:<scheme>` | 非 http/https（**回显实际 scheme**） |
| 4 | `missing_host` | 无主机名 |
| 5 | `private_host` | `_PRIVATE_HOSTS = {localhost, localhost., metadata.google.internal}` 或 `.localhost` 后缀 |
| 6 | `private_ip` | 字面 IP 属 private/loopback/link-local/reserved/multicast/unspecified |
| 7 | `metadata_ip` | 字面 IP 恰为 `169.254.169.254`（AWS/Azure 元数据） |
| 8 | `resolves_to_private_ip` | **域名 DNS 解析后逐结果检查**（多地址时任一私网即拒） |
| 9 | `dns_failed` | `socket.gaierror` → **拒绝**（注释：「DNS 失败 = 拒绝（不许放行）」） |

★ `localhost.`（尾点 FQDN 等价写法）必须显式列举，否则加尾点即绕过。★ 判定链顺序是「**先零成本后昂贵**」：scheme / 主机名 / 字面 IP 都不碰网络，DNS 是唯一系统调用。

### 7.2 WebFetch（`web_fetch_tool.py` 248 行）

```python
_CONNECT_S = 3.0 ; _READ_S = 12.0
_MAX_BYTES = 200_000 ; _OUT_CAP = 8_000 ; _MAX_REDIRECTS = 5
_CACHE_TTL_S = 15 * 60 ; _CACHE_MAX = 32
```

**重定向必须逐跳校验**（`:130-156`）：禁用自动跟随（`follow_redirects=False, max_redirects=0`）→ 循环内**两处** `is_blocked_url`（请求前 + 拿到最终响应后）→ `urljoin` 解析相对 Location → `await stream_resp.aclose()` **排空中间响应**（否则连接池耗尽）→ `for/else` 报 `too many redirects`。

**缓存键 = `_normalize_url(url)` + `prompt`**（`:111`）——`prompt` 决定 `focus_text` 挑哪些段落，**不进键就会返回与本次提问无关的正文且 `is_error=False`**（静默错误答案）。`_normalize_url`：scheme/netloc 小写、path 空填 `/`、**去 fragment 保 query**。

**内容分三路**：HTML（`html_to_text` 用 `_OUT_CAP*4` 预算 → `focus_text` 压到 `_OUT_CAP`）· 文本类 · **其他二进制 → 不报错**，返回「`Non-text body (N bytes); not extracted.`」（**成功 ≠ 可用**：报错会诱发无效重试）。

`html_to_text` 九步顺序的两个必守点：① `script`/`style`/`chrome` 必须**在标签剥离之前且连内容一起删**（否则 JS/菜单文本混入正文）；② **实体解码必须在标签剥离之后**（否则转义显示的 `&lt;div&gt;` 被当真标签删掉）。

`focus_text`：按**空行**切段 → 得分 = **命中 token 种类数**（breadth 而非 depth）→ 元组 `(score, -i, p)` + `reverse=True`（`-i` 让**同分按原文顺序**）→ 取前 5 段 + 两条与关系过滤（`>= max(1, min_keep-1)` **且** `(>=2 或 min_keep==1)`）→ 按原文顺序贪心装箱（**不回溯**）。无命中 → 头部 + `(no prompt match; head)`。

### 7.3 SSRF 的真实缺口（**面试压轴**）

**TOCTOU / DNS rebinding**：`is_blocked_url` 用 `socket.getaddrinfo` 解析一次，而 `httpx` **自己再解析一次**——两者之间是窗口。三个条件同时成立即可绕过：① 检查只返回原因码、**不交出解析到的 IP**；② 请求 URL 里仍是**主机名**；③ 两次解析**时刻不同**。攻击者只需「自己的域名 + 可控 DNS/TTL=0」：检查时指公网、请求时指 `127.0.0.1`/`169.254.169.254`。**重定向每一跳都有同一缺口。**

修法：① 解析一次、**用 IP 连接 + 设 Host 头**（代价：HTTPS 的 SNI/证书校验）；② 连接后校验 `peername`；③ 自定义 resolver 固定解析；④ **网络层兜底**（出站代理/防火墙禁私网）——最可靠但依赖部署。

★ 第二个常被忽略的面：**威胁模型不止 SSRF**——抓回的网页内容是**不受控文本**，本身就是「外部 → 模型」的注入通道。

## 9. 易错点清单（自测用）

1. `is_read_only` 不是「不碰磁盘」（`WebFetch` 是 False）；并发安全可以靠「下层能收敛」达成（`Agent`）。
2. 输出预算的**豁免是按能力划分**（自带 seam 就豁免），不是按重要性。
3. Bash 的 `full at <path>` 落盘的是**压缩后**文本；`cmd_compact` 不落盘。
4. 45s 是**晋升**阈值不是超时；worker 的 30/60s 是硬护栏，**命令族映射不生效**。
5. 静态 120s 会被命令族映射放大（cargo 420s），但被 `MAX_TIMEOUT_MS=600_000` 与 worker 护栏夹住。
6. `_PURE_READ_BASES` 的注释「任意参数都只读」**过于乐观**（`find -delete`）；且它**不参与权限裁决**，只影响缓存。
7. `WebFetch` 缓存键**含 `prompt`**；`fragment` 有意排除。
8. 重定向必须**逐跳**校验，且禁用自动跟随是前提。
9. `is_blocked_url` 通过 ≠ 请求安全（TOCTOU 窗口）。
10. `Diagnostics` 判定不出语言时必须**说明**，不能返回空（空会被读成「无问题」）。
11. `Skill` 的模型/用户可见性**是两套**；被禁用技能**不进目录**。
12. `Memory` 没有 `delete`；`peers`/`retrieve` 的数据源不同于 `search`。
