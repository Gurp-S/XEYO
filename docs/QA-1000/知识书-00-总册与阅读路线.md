## 0. 一句话认识 XEYO

**本地运行的编码 Agent**：Python 编排的「模型 ↔ 工具」多轮主循环引擎，配三种界面形态（Tauri 桌面 GUI / Ink 终端 TUI / Typer CLI），带企业级权限沙箱、流式 Stop、文件级回溯 rewind、多表面会话与微信远程通道。

技术栈的关键约束（面试常问）：

| 约束 | 事实 |
|---|---|
| **没有关系型数据库** | 数据层是 **JSONL 文件 + SQLite 派生索引（可删可重建）+ 前端 IndexedDB** |
| **没有 OpenAPI 规范** | 接口真源是 FastAPI 的 `@router.*` 装饰器（18 个 router 文件，100+ 端点） |
| **没有正式需求/设计规格书** | `docs/` 下多为复盘/审计类文档，**部分已过期**（本知识书标出过期处） |
| **单机单用户假设** | 大量机制建立在「一个会话同一时刻只有一个引擎在跑」之上（见 §7.3） |
| **Windows 优先** | 大量平台分支（PowerShell / taskkill / Job Object），且 **POSIX 侧部分保护缺失** |

## 1. 七层架构（用于定位任何代码的坐标）

| 层 | 名称 | 承载包 | 典型问题 |
|---|---|---|---|
| L1 | **决策层** | `engine/`（query_engine / query_loop / plan / scheduler / budget / abort） | 一轮怎么走完？什么时候停？ |
| L2 | **认知层** | `memory/` `prompt/` `codeindex/` | 给模型看什么？怎么压缩？ |
| L3 | **能力层** | `tools/`（21 项启用工具 + 110 文件） | 工具怎么注册、怎么裁剪、怎么执行？ |
| L4 | **控制层** | `permissions/` `rewind/` `session/` | 谁能做什么？怎么回溯？ |
| L5 | **容错层** | `engine/`（abort / budget / compact / repeat_guard / wrap_window / 各类账本） | 出错、超时、重复、崩溃怎么办？ |
| L6 | **安全层** | `permissions/` `audit/` `SECURITY.md` | 越权、注入、脱敏、沙箱 |
| L7 | **装配层** | `server/` `cli/` `channels/` `bridge/` `sidecar/` `gui/` `tui/` | 怎么接进来？怎么发出去？ |

★ 记住这张表的价值：**面试中任何问题都能先定位层**，再答题。例如「工具输出太长怎么办」= L3（工具自带 seam）+ L5（registry 预算）+ L2（记忆压缩）**三层都有机制**，只答一层会显得片面。

## 2. 一次请求的完整生命周期（背下来这一条，能答一半的题）

```
用户消息
  ↓
[L7] server / cli 入口 → SessionPool 取会话（租约）
  ↓
[L2] Prompt 装配：system 左段（L1 指令 + 记忆索引块）→ 历史投影 → T_now 尾插（默认 system_channel：尾部一条原生 system 消息；env_channel 伪造 tool 对已降为回退/对照档）
  ↓
[L1] query_loop：每轮
      ├─ 投影（compact / fold / 老化）→ 送模型（流式）
      ├─ 解析输出：text / thinking / tool_use
      ├─ 有 tool_use → [L4] 权限裁决（ALLOW / ASK 挂起 / DENY）
      │                     ↓ ALLOW
      │              [L3] ToolRegistry.run → 工具 execute
      │                     ↓
      │              输出治理：工具自带截断/落盘 → registry 预算（spill）
      │                     ↓
      │              tool_result 回填 → 下一轮
      └─ 无 tool_use → 回合结束（或等待续写指令）
  ↓
[L4] 落盘：transcript JSONL（异步写 + fsync）、sidecar、journal
  ↓
[L5] 回合结算：budget 记账、stage_clock、loop_ledger、goal 推进
  ↓
[L7] SSE 把事件推给 UI（GUI / TUI）
```

★ 三个「反直觉但重要」的细节：

1. **工具执行前后各有一次权限裁决**（registry 一次 + 工具内一次），靠 `preapproved` ContextVar 避免二次裁决把 ASK 判成拒绝（见 §4.4）。
2. **工具输出的截断发生在多个层次**，且 **Bash 豁免 registry 预算**（自带 seam），避免双重截断/双重落盘（见 §3.3）。
3. **T_now 注入不是「变化时才注入」，而是每轮都装配**——靠**字节一致**保证 KV 前缀命中，不是靠跳过（见 §3.4）。

## 3. 六条贯穿全项目的设计原则（面试加分项）

### 3.1 「注意力里只出现信息，不出现导演」

引擎可见文本（system prompt / T_now 块 / 工具结果 / 错误 detail）只承载**状态、结果、事实**；禁止建议、劝导、评价、奖惩、以及「应该/优先/不要再」式编排。

- **限制只在执行层表达**：模型反复走不该走的路 → 让该路径的工具**持续静默报错**，而不是往上下文里塞警告。
- **能静默就不说话**：引擎能自己完成的事（状态维护、清理、折叠、重建）一律静默（范本：`memory/instruction_maintain.py::reconcile_nested_state`）。
- **第一问永远是「能不能不进上下文」**：能强制的，一律不给模型看。
- **反例（可指出为改进项）**：`tools/agent_tool/agent_tool.py:38-57` 的 `_format_agent_tool_result` 在工具结果里写了 `"Instruction for main agent: …"` 指令文本——与本原则冲突；正确方向是把意图移回结构字段或上游修剪，而不是删掉（有观测到的行为偏差为动机）。

### 3.2 单向性（权限只能收紧，不能放宽）

三处实现，共同基础是 `_STRICTNESS = {"always": 3, "risk": 2, "never": 1}` + `stricter(a, b)`：

| 入口 | 机制 |
|---|---|
| 轮内审批模式切换 | `RuntimeModeStore.effective()` = `stricter(baseline, requested)` → **收紧即时、放宽延后到下一 turn** |
| 仓库策略文件 | `write` 只能**收紧**；`risk`/`never`/`allow` **不得**把用户更严的模式放宽（放宽只能走用户侧 env / grant / preset） |
| 权限 preset | `full` **只放宽「确认频率」**，不触碰 deny 黑名单 / 密钥 / 受保护元数据 / worker 沙箱 |

★ **硬拦不参与「取更严」的比较**——密钥、受保护元数据、worker 沙箱是**绝对值**。

### 3.3 同一治理职责只允许一层实现

| 工具 | `output_budget` | 谁负责截断/落盘 |
|---|---|---|
| `Read` | **0（豁免）** | 自带（`MAX_LINES_TO_READ=2000` + 25k 令牌闸门）——理由「防 read→spill→read 循环」 |
| `Bash` | **0（豁免）** | 自带 `truncate_for_model`（20k head / 8k tail + 落盘 + 中段错误抢救） |
| `Glob`/`Grep`/`Write`/`Edit` | 未设 → 默认 `16_000` | registry 预算（`PREVIEW_HEAD=6_000` + `PREVIEW_TAIL=2_000` + spill） |

即 **«凡是自带 seam 的工具都设 `output_budget=0`»**，按能力而非重要性划分。

### 3.4 字节稳定与 KV 前缀纪律

KV 缓存按**最长公共前缀**命中，所以「变化的字节位置越靠前，代价越大」。本项目的三个解法：

| 功能 | 改的东西 | 对策 |
|---|---|---|
| 工具输出老化 | 已发送投影里的旧 tool_result | **滞后门 8 条消息**（稀发） |
| C2 压缩 | 左区折叠成摘要 | **已压缩态跳过老化**（避免一轮双改） |
| 记忆索引块 | 每轮注入的导航块 | **改挂 T_now 尾部**（把变化挪到最末） |

配套的**派生态**：

- `WorkingSnapshot.c2_summary_text` **首压冻结复用**（每次 C2 投影注入同一份文本）；
- `CompactCheckpoint` 的 `anchor_cursor` / `anchor_frozen_until` / `anchor_summary` 在 resume 时**只前进**（`max`），摘要**只填空**；
- `_canon(messages)` = `json.dumps(..., sort_keys=True, separators=(",",":"))`，保证同一投影每次得到同一字节序列（LCP 才有意义）。

### 3.5 权威与派生必须分清

| 层 | 对象 | 权威性 |
|---|---|---|
| 权威 | **转录 JSONL**（含归档）、`topics/*.md`、`session.md`、journal | 行式追加的既成事实 |
| 派生 | `MessageStore`（内存）、`ws_index`、`memindex`（sqlite）、sidecar、blob、各缓存 | 可重建或可校验 |
| 纯缓存 | `_known_ids_cache`、glob/content_index 缓存、`_loaded` 标志 | 丢了只损失性能 |

三条规则：① **权威只追加**；② **派生必须可重建**（反例：blob 不可从转录重建 ⇒ 它其实是权威内容的外置部分，只能靠 `content_hash` 校验）；③ **修改权威必须同步派生物**（例如回滚要清归档、sidecar、`session.md`、delta、fragments，否则「已删内容复活」）。

### 3.6 「删除」必须覆盖全部派生副本

被删内容的副本散落在：当前 jsonl、归档（`.old1/.old2`）、`session_deltas.jsonl`、`session.md`、`.working.json`（尤其 `c2_summary_text`）、memindex 的 `fragments`、blob 目录。

★ 这是**结构性风险**：清理责任分散在 rewind 服务 / `session.record_transcript` / `memory.working` / `memory.session_md` 四处，**没有单一 owner**。改进方向是定义「回滚协议 / 世代号」，让每个持有派生状态的模块注册自己的回滚钩子。

## 4. 十个高频面试题的「标准答法骨架」

### 4.1 「一轮里模型要调工具，你怎么组织？」

答：**三层**——① `prompt` 侧只给工具 schema（会话内冻结，**零前缀重缓存**是红线）；② `orchestration` 按 `is_concurrency_safe` **分区**（可并行组 + 必须串行组），带 `_max_concurrency()` 与 `_tool_timeout_s()`；③ `ToolRegistry.run` 统一走权限 gate → `execute` → 输出预算 seam。
★ 加分：`Agent.is_concurrency_safe() = True` 但**正确性由下层 `WriteStore` content-hash 收敛**——声明的作用域（工具级）比收敛机制（会话级）更宽，且依赖调用方正确注入 store。

### 4.2 「工具输出太长怎么办？」

答：分三层说 + 说清**豁免关系**（§3.3），并指出 Bash 的 `full at <path>` 落盘的是**压缩后**文本（`cmd_compact` 不落盘），所以被压掉的通过行**永久不可达**——与 spill 的纪律（「原始输出先落盘」）顺序不一致，是本项目的一处结构性改进点。

### 4.3 「怎么保证长任务不卡住回合？」

答：**晋升**而非「等待或杀掉」。三层时间线：

| 时间线 | 阈值 | 行为 |
|---|---|---|
| 晋升 | **45 s**（`BASH_PROMOTE_DEFAULT_MS`，`0`=关闭） | 命令**继续跑**，控制权交还，结果由 job 通知/`job_output` 领取 |
| 超时 | **120 s**（默认，命令族映射可放大到 180–420 s） | **杀掉**命令 |
| worker 护栏 | **30 s / 60 s** | 子 agent 硬上限；**命令族映射不生效**（`parse_input` 侧排除） |

硬约束是「**进程不重启**」（副作用不可重放），靠 `StreamHandle`（泵线程持续累积 `buf` + `sinks` 可后挂 + `_abort_box` 可变槽免重启监视线程）+ `jobs_bridge.adopt_registry_job`（收编活句柄）。

### 4.4 「权限系统怎么设计？」

答：见 §3.2 的单向性 + 分册 07 的**六层结构**（能力面裁剪 → 角色档位 → 三态裁决+挂起 → 硬拦 → 执行层约束 → 系统层边界），并**明确每层不防什么**：

- 应用层权限防「模型走错路」，**不防「恶意进程」**；
- 判定不可能完备：命令字符串是**图灵完备源文本**（Bash 侧只能做形态匹配）；路径清单永远不全（密钥清单只有 14 文件名 + 4 后缀 + 4 目录）。
- 因此必须有 **输出侧脱敏 + 系统层沙箱** 兜底；本项目**缺系统层文件系统沙箱**（最大空白）。

### 4.5 「上下文压缩怎么做的？」

答：C2 压缩 = **确定性摘要**（非模型摘要）：全局字符预算 `C2_SUMMARY_BUDGET = 12_000` + 七档类型配额（错误 400 > 取值 320 > assistant 结论 260 > grep 220 > user 200 > 默认 120 > tool_use 80）。LLM 摘要旁路（`XEYO_C2_LLM_SUMMARY`）默认关，因为**实测吸收潜力高（96% 单次）但方差极大（同配置三次 62/92/83%）**，而摘要进 KV 前缀、一次坏摘要会污染后续很多轮。

### 4.6 「崩溃恢复怎么设计？」

答：**恢复是重建视图，不是重做动作**。三件事：① 转录行式存储天然容忍尾部残缺（跳过坏行）；② 未闭合 `tool_use` 补**确定性合成结果**（只读 → `TOOL_NOT_STARTED`；有副作用 → `TOOL_OUTCOME_UNKNOWN`，且 `is_error=True`）；③ 靠执行层门（`write_store` 的 `missing_read` 门 / `unchanged` 短路 / 语法门）**防重放副作用**——而不是在文案里写「不要重试」。
★ 诚实边界：`atexit` 只等 2 s 且写入线程是 daemon ⇒ 「尽力窗口」；SIGKILL / 断电覆盖不到。

### 4.7 「你怎么看这个项目的技术债？」

答：给**有证据的三条**（面试官最爱听这个）：

1. **判定与使用的 TOCTOU**：SSRF 的 `is_blocked_url` 与 `httpx` 的真实解析是两次解析（DNS rebinding）；路径狱用 `realpath` 判定、`open` 在之后（symlink 替换窗口）。
2. **多载体清理无单一 owner**（§3.6），回滚会漏载体导致「已删内容复活」。
3. **平台不对称**：Windows 侧有 `taskkill /T` + Job Object 双保险，**POSIX 侧只有 `proc.kill()`（只杀根）且无被动兜底** ⇒ 超时后孤儿进程继续写工作区（会覆盖用户改动）。

### 4.8 「为什么用 JSONL 不用数据库？」

答：单机单用户、写已串行化、无跨会话查询需求；JSONL 的收益是「追加即落盘 O(1) / 崩溃只损尾 / 可轮转 / 可重放 / 可人工查看」。SQLite 只用在**派生索引**（memindex，可删可重建，铁律：「文件永远是 source of truth」）。

### 4.9 「并发怎么保证正确？」

答：本项目的正确性建立在**「单写者」假设**上，且该假设**没有写成断言**，只体现在产品语义里（一个会话一个引擎）：

| 机制 | 作用域 | 注意 |
|---|---|---|
| `_disk_lock`（transcript） | **进程内** | 覆盖 `mkdir+rotate+append+fsync` |
| `_known_ids_cache`（去重） | **进程内** | 跨进程写同一会话会产生重复行 |
| `WriteStore` 分片锁 / 租约 / base hash | 会话/工作区级 | 防并发覆盖（后写者基于旧内容 → 被拒） |
| `threading.Semaphore(8)`（Agent 并发） | **模块级单例 = 进程级** | 措辞说「同会话」，实现是「同进程」 |

### 4.10 「你怎么定位一个陌生模块的职责？」

答（方法题）：① 读模块 docstring（本项目写得极好，常含「为什么」与事故编号如 G107/G78/T25）；② Grep 定义面（`^(def |class |[A-Z_]{3,} *=)`）拿常量与入口；③ 看**调用点**而不是实现——尤其注意「谁在写、谁在读、谁是权威」；④ 找**待确认/降级/TODO 注释**，它们标出设计边界。

## 7. 面试答题总纲（三条）

1. **先定位层，再答机制**（用 §1 的表）。
2. **每个机制都说三件事**：它防什么 / 它不防什么 / 失败时降级方向（大多数取舍都能用「误判方向的代价不对称」解释）。
3. **主动给边界与债**：面试官对「知道系统局限」的评价，远高于「把系统说成完美的」。本项目可用的三条债见 §4.7。
