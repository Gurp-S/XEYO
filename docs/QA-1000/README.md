## 已识别的项目事实修正（供后续批次复用）

1. **`README.md:210-214` 文档时效性冲突**：正文称「正在打」安装包，而 `:33-38` 已列出成品包与大小 → 以代码/表格为准。
2. **`npm` 命令口径不一**：`XEYO.bat` 用 `npm install`，`scripts/check.ps1` 用 `npm ci`。
3. **`XEYO.bat::FREE_PORT` 的 PID 复用误杀风险**：无「pid 是否仍属于 XEYO」校验，`taskkill /T /F` 可能放大破坏面。
4. **`XEYO.bat::START_LLAMA`/`:STOP_LLAMA` 语义矛盾**：「复用已存在进程」与「退出时杀掉」并存，缺归属标志。
5. **门禁盲区**：E2E、`cargo check`、Windows 平台、安装包构建、自包含性断言均不在 CI/本地门禁内。
6. **文档与实现的版本口径差**：`README.md` 写 Python 3.11+，`XEYO.bat` 实际强制 `== 3.11`。
7. **busy 心跳的隐含前提**（B02-0099）：`turn_runner.py:221-229` 的租约续期写在「消费事件帧」的循环体里 → 前提是「长回合必然持续产帧」。长静默工具（如挂住的网络命令）会让心跳停摆，存在被 stale 误回收的窗口；同仓库 `workspace_lock.py:192-200` 的 `_heartbeat_loop` 是**独立时间驱动**实现，是正确范式。
8. **等价档计数器是「每工具」而非「每内容」**（B03-0148）：`repeat_fold.py:94-95` 的 `_equi_seq` 以**工具名**为键。推论：交替模式（A,B,A,B…）会持续折叠；而「新旧内容穿插」会反复清零计数 → 漏折叠。
9. **老化默认关是「恢复机制未落地」的临时状态**（B03-0103/0135）：`aging.py:4-5` 明示「toolout 占位的恢复机制落地前保持关闭，避免原文不可找回」，且 `logs/toolout` 文件级恢复标注为「后续增强」。即：**删除能力已实现、恢复能力尚未实现**。
10. **`workspace_revision` 是检测而非阻止**（B03-0149）：它不参与写路径，只能给出「环境已变」的事实；Bash/外部编辑器/构建工具链的写入不受 `WriteStore` 三层防护（分片锁 / 租约 / base hash）覆盖。
