# WSC 媒体来源与正常调用前缀（批次118，仅静态）

本批次针对T18共享媒体分支的结构性前缀缺口，不执行测试、编译、API或部署。

## 根因与固定规则

113的候选把迟到到达行中所有结果及对应调用一起转换成事实，试图避免图片被错误归属于同行某个正常结果。这使媒体到达内容反向决定之前正常调用的表示，新增图片可能改写已经发射的正常调用。117已记录这一缺口。

正确边界：调用是否转换由已观察到的序列边界决定；媒体来自哪条消息/哪个结果由来源结构决定。媒体归属不能决定正常调用的历史表示。故移除整组扩展，不另建生命周期或猜媒体归属。

## 实施

仅修改现有叶模块`session/late_result_projection.py`：

- 调用转换集合只来自`displaced_calls`。到达行里的正常调用继续原生，不因同行迟到结果或图片而转成事实。
- 外层共享图片附来源消息ID、该行调用ID集合和原块位置，标为`source_message`；未声称属于其中任何单个调用。
- 嵌套图片附真实结果调用ID、正文块位置，标为`result_body`。每张图另有当前投影消息内的零基图片序号；OpenAI把文字合并成caption、图片集中排列后仍有明确映射。
- 同行正常结果若是结构化正文，原生工具ID/错误等字段保留，文本块以JSON保全边界，图片载荷换成正文位置引用；完整原图在事实载体中发送，不把base64串塞进文本。迟到结果保留原文本/原图块。
- 投影到达行把正常原生结果置于事实/媒体载体之前；该排序只属于请求编码，不改存档正文、原时间线、来源ID或旧冻结头。
- 每张图前的事实文字也打断Anthropic现有`_blocks_to_anthropic`中“紧邻上一tool_result的图片吸收进该结果”机制，避免共享图被默默归给正常结果。

没有改变候选默认关闭状态，没有修改厂商编码器或加入新开关/持久状态。没有重执行工具。

## 静态合同核对

已核对：调用集合不依赖媒体到达；同消息多结果身份唯一性；信封/显式结果共用117入口；未知块仍拒绝；正常结果ID保持；源对象无赋值写入；图的载荷出现一次；源位置及当前投影图片顺序可关联；OpenAI用户块的原生结果→caption/图片编码；Anthropic文字边界的图片吸收规则。

未来回归必须覆盖：旧迟到a、此前正常完整b、新正常c、到达行迟到a+正常c+共享图；到达前c调用与到达后保持同表示；正常c/迟到a各自嵌套图；共享与嵌套并存的序号；文本块完整；两厂商实际编码不丢结果/图片且不错误归属；磁盘恢复后重复投影一致。

静态推演只证明代码路径符合上述规则，不证明真实厂商接受/模型续接/缓存收益。跨界前曾经原生发射的旧迟到调用仍涉及请求代变化，旧冻结代迁移尚未验收；本批仅消除图片造成的额外正常调用改写，不能宣称整个请求前缀从不变化。

测试0、编译0、API0、费用0。差异格式检查通过；T18默认接入及四块真实效果仍开放，Goal不结案。
