## 事故三问

- 结构性根因：`original_task` 取首个实质用户节点，freshness 没有 goal 退休判据；“首条用户消息”被永久当成目标。
- 结构性规则：仅明确的用户关闭声明可以退休该目标；默认关闭的独立模块负责判据，已有 freshness / seeds / coldstore 消费其结果；冻结头仍按既有规则复用。
- 回归：正控及开关关闭等价、反控及否定/引用/时序、冷层无损和实际 Read、冻结前缀连续性，共四个测试函数。

## 方案前提修正

1. 原文实际是“我自己已经修复好了”，加入闭集；不收“撤销”。否定与条件表达限定在关闭分句；“这个问题”只关联相邻上一分句，不能用整条长消息里的例子凑重合。
2. 既有阈值实际是：重合集里有拉丁 token 时**总重合数 ≥2**，纯中文 bigram ≥3。不是“一个 chatgpt token 就满足 2”，也不是“必须两个拉丁词”。本现场命中 `chatgpt` 和中文 `修复`。
3. 旧消息若同时带硬约束，整节点降级会丢约束；本保守旁路对此不退休，留待目标与约束分离后处理。
4. 下一条存活实质消息不等于最新任务。本现场换到 **#66** 的载体审查请求；不声称完成 active_goal 的一般任务生命周期建模。
5. “除目标行外所有段逐字不变”不能成立于全量新建投影：目标晋升使既有重复约束行被合并，请求分组和冷层行号也变化。第四条按用户硬边界验证**既有冻结头/行不改写**。完整新投影差异另存，不掩盖。

## 根据原始对话判断 WSC 的问题

1. **生命周期与冻结发射互相脱节。** 目标永久 pin 是 G1；错误账重算 #16 也属于“已过时的信息仍像当前事实”。G1 旁路仅解决显式关闭的独立目标，新任务切换、混合约束目标及旧冻结头即时清账尚未解决。
2. **来源身份和视图身份是两层合同。** pin 按签名重新绑来源已修且此前有 51/51 证据；这不能修复旧冻结指针，也不能保证同路径的视图永不重写。G3 / C-1 仍开，不能合并成一句“#9 全好”。
3. **去重与状态变化不能只改一条展示通道。** #17 修了重复签名正文，不等于所有副本都退休；G4 及旧头残留要区分 fresh 投影、cold 历史、已发射冻结行。
4. **恢复入口存在不等于恢复正确。** #20 缺入口的前提已推翻；#18 标题化、#21 空壳签名已修。仍需把身份、源版本、可执行 Read、取回内容的合同连起来；PATHS 噪声 #19 尚开，不能靠长度/通用词过滤。
5. **验收曾产生假结案。** 早期把 shell/host 环境红当产品红，把一次能读当指针都可靠，把 WSC 头说成尾部不影响前缀，以及把用户“自行修好”出现时间说早了。应分别报告事实是否正确、恢复是否成功、冻结是否稳定、模型是否实际使用与任务是否成功。
6. **权限/环境/工具摩擦不能全算 WSC。** G2 的 scratch 宣告与权限 DENY 矛盾、C-2 Bash/Edit 基线、C-3/C-4 拒绝依据不透明、C-6 job_output 活动不可见、C-7 Edit 匹配差异不可见，属于相邻执行/载体层。尚开：#2 执行回执归因、#3 fail-open 留痕、#7 shell 语法事实、#13 门 JSON。

原始最早八条（#67）里 **⑥ 并非定义缺失**，它是“环境事实全靠临时探测”；它与后来重编号的①同源。原始①是“Bash 名称与实际 pwsh 不符”，不能沿用旧汇总的编号换位和“6 完成/1 缺失”计数。②草稿区后来实测不可写，不能继续算完成；④两套落盘根降级非缺陷，⑤仅恢复层归因收窄，⑧空壳文档仍延后。上述为历史结算纠正，不是本批另行改执行层。
