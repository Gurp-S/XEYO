# WSC：恢复尝试与交接后预算边界（329）

本轮仅修复可通过真实入口和可控模型响应证明的确定性错误。API 调用 0 次、API 费用 0；没有修改提示词、去噪规则、冻结头或默认压缩策略，没有新增开关，也没有提交混合工作树。

## 三轮复审

### 第一轮：正确性与结构根因

1. 失败事实不能成为永久禁止生成的条件。原 query loop 以历史 source_fingerprint 复用上次失败；但同一历史可以对应新的模型配置、容量和完整请求。上次失败不证明新尝试必然失败。
2. 交接是实际模型调用，会改变 token 和金额预算。原流程交接后只调用 `prepare_next_turn()` 检查轮数，没有检查新 usage 是否耗尽预算，可能多发一次主模型请求。

### 第二轮：选择最少机制

- 不增加模型、配置、Goal、提示词版本组成的新失败缓存协议。删除跨准备过程的跳过条件，继续保留失败记录供诊断。每次准备中的生成流程仍有既有次数上限，未增加 HTTP 重试。
- 抽出 D 原有的 token/金额检查供生成与续接共用。保留金额 `>=`、token `>` 的现有预算边界，不引入新的价格、余额或预算口径。
- 不改生成文本、来源、候选校验、原子发布和冷证据格式；不在模型注意力中添加信息。

### 第三轮：失败模型与准入

- 第一次交接失败、完整请求又超窗时，来源保留且不发送主请求。
- 恢复 working，重新注册已调整的工具 schema，保持历史字节和指纹不变；新的准备必须能重新生成。
- 预算足够时：自然语言候选成功后发布并续接；D 再次生成失败则保留完整旧窗口继续，不伪造成功提交。
- 交接后 token 或金额达到既有停止条件时：停止下一次模型调用；usage 保留，未提交候选不推进游标。
- 既有冻结、取消、持久化、原生 Read、重启及任务合同回归必须继续通过。

| 两条路径恢复后历史不变、完整请求已变化 | 两项均跳过交接生成 | 两项均进行一次新的生成尝试 |

| 两条路径交接耗尽金额预算 | 本轮未单独运行修改前金额反例 | 两项均在主请求前停止 |

每次成功续接的受控调用 usage 为交接 120 + 主调用 210 = 330 tokens；预算停止场景仅交接 120 tokens。金额测试使用固定响应内的费用字段，均为测试数据，不是厂商实际计费。

删除跳过逻辑意味着外部发起新的恢复尝试时可能再次产生交接费用；这是恢复能力的必要行为变化，并非节费声明。既有生成次数、轮数、token/金额与容量边界保持生效；未增加后台循环或 HTTP 自动重试。
