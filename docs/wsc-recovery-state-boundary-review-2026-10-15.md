## 1. 冷恢复：工具覆盖范围不同，不等于证据不存在

同一条 `late-read` 历史结果，当前入口表现如下。

| 入口 | 本轮离线结果 | 能证明什么 |
| --- | --- | --- |
| Memory.search | `(no memory hits)` | 搜索笔记、其他会话笔记和rollout摘要，不覆盖当前密封证据 |
| Memory.retrieve(call/message ID) | unknown fragment id | 此动作只接受旧C2 `notes:msg:<index>` 碎片锚点 |
| 原生Grep搜索证据目录 | 找到调用身份 | 当前目录具备身份搜索能力 |
| 原生Read读取目录指定行 | 返回 `late-read` 与完整旧版本结果 | 已存证据可通过现有读取路径恢复 |
| 生成期HandoffCatalog/Source | 定位消息并返回完整结果 | 生成期精确回查可用，不等于消费者拥有同名工具 |

源码：`python/tools/memory_tool/memory_tool.py` 的 `_execute_search` / `_execute_retrieve`，`python/memory/wsc_handoff_catalog.py`，`python/memory/wsc_handoff_recall.py`。

因此不能宣称“冷层整体不可达”，也不能把“Memory存在”算作“所有WSC证据都能通过Memory恢复”。此前消费者评测只开放Read/Grep/Write；本轮并未证明增加Memory后模型会更好。是否连接接口仍需以实际恢复收益决定，暂不实施。

## 2. 旧D确实把解释纠正纳入变更手续，但没有绝对禁止纠错

原用户消息：`修复查询语句；不要修改数据库表结构。`

历史assistant解释：`不要修改数据库相关代码。`

先用现有完整D校验器接受引用assistant解释的约束，再通过原生TodoWrite回执保存。随后改为引用同一条原始用户消息中的准确限制，原目标/任务/阶段不变。

| 候选 | 当前完整D校验结果 |
| --- | --- |
| 仅纠正旧约束，不加退休声明 | `handoff_task_fact_disposition_missing` |
| 加退休声明，但引用旧用户原文为事件 | `handoff_task_fact_retirement_event_invalid` |
| 增加一条assistant纠错说明并引用为事件，无新用户消息 | accepted |

结构原因：`wsc_handoff_fact_disposition.py` 按旧/新任务级fact的文本键计算差异；任何消失或替换都进入退休协议，并要求事件位置晚于旧检查点。它允许user/human/assistant文本事件，没有要求一定是新的用户授权，也没有证明该事件语义支持变更。

这支持“同一证据上的解释纠正被加上额外手续”的担忧，但不支持“当前D永远禁止模型纠正”或“必须重新找用户授权”。引用assistant声明只认证出处；它不应被视为用户控制或已证实真值。

## 3. 自然语言路径允许纠正；接受也不代表语义正确

两条隔离轨迹都先发布过宽的旧解释，再增加12条中性assistant观察，使下一次折叠有未折叠尾部；用户原文未新增、未变化。当前生成入口实际看到了原用户材料。

| 固定响应 | 当前prepare/publish/restart结果 |
| --- | --- |
| 限制只涉及表结构，旧解释过宽 | 接受，正文保持，重启后请求一致 |
| 用户已全面授权随意修改数据库表结构 | 同样接受，重启后保持 |

二者均标为 `SEMANTIC_UNVERIFIED`。这是该入口的边界：验证来源/Goal/版本/存储，不判断语义。第二条是固定提供的错误候选，不是本轮真实模型犯错，更不是实际数据库执行获得授权；执行权限不在本轮测试范围。

源码：`python/memory/wsc_semantic_compaction.py`。该路径没有经过旧D完整状态声明/退休协议；源码自然语言开关fallback仍为关闭，不能把本轮显式开启的隔离路径冒称用户现场已经切换。

## 4. 归因

- **模型**：可能误解约束、错误判断历史适用性、读到材料后仍使用错误。本轮没有运行真实模型，不能据此归因模型能力或宣布改善。
- **引擎**：旧D把文本替换纳入事件新鲜度合同，存在纠错手续负担；自然语言路径没有该负担，但来源选择、Goal附加、目录/位置与发布拒绝仍会影响模型条件，需分别审查。
- **工具接口**：Memory笔记/碎片与密封证据是不同恢复面；Read/Grep可用，不能只因Memory没命中就判证据丢失。
- **评测器**：脚本知道要查的身份和范围，成功读到不等于模型主动发现并正确使用；固定摘要接受不等于语义质量；预期错误被确认不等于产品通过验收。

## 5. 讨论后的候选方向，尚未实施

以“干预是否有独立收益”为单位审查，不预设Runtime旧语义比新理解更可靠，也不预设最新理解总是正确。

1. 保留可证明的执行/权限/来源/版本与发布边界；已接受语义声明保留可追溯性，不升级成不可纠正的控制依据。
2. 把“用户意图改变”与“依据原证据纠正解释”作为不同验收场景；纠正声明不回写用户历史，不产生新授权。尚不新增永久字段/状态机。
3. 先比较去除有疑问的干预：相同生成材料、交接正文、消费者角色/位置/尾部和工具，薄后台为基线；分别加入旧语义保留义务、语义状态注入和来源筛选。无法保持同一请求时，明确实验变量。
4. 正反例成对：旧解释错误应能纠正，旧解释正确不能无故遗失；完成后无新增需求应继续当前任务，验证发现旧错应能返工；旧文件不能冒充当前文件，但可解释历史决定。
5. 冷恢复继续以“定位→读取→绑定→正确使用”为目标；不因本轮发现不同入口就直接造新工具。讨论先于下轮修改。

**本轮结论是收紧设计与归因，不是WSC整体质量提升或Goal完成。**
