## 事故三问

**结构性根因**：检查点把超出热层内联预算的已定位原文列为未知来源，混淆“未显示”和“不知道在哪里”；原始冷视图按行读取，超长单行超过 Read 输出容量后，调 offset/limit 也无法分割；新增分块绑定原来未纳入物理覆盖审计，导致入口可读却被统计为不可恢复。另一个行为反例是模型不主动读已提供的来源，不能由入口存在推导解决。

**结构规则**：来源身份、可用性、内联状态分开；只有无法定位的来源标未知。超长单行生成独立的内容寻址 JSON 分块副本，声明字符偏移、原文 SHA256 和编码，旧权威原文与已发布视图不改。覆盖统计依据校验过的完整成员区间；第一页覆盖不等于完整来源可恢复。模型是否实际召回由真实调用及结果验收，不靠引擎注入“必须继续读”的指令。

**回归**：已知 35KB 来源有独立 Read 入口；超长单行原视图确实无法读，分块用产品 Read 多页重组后字符、Unicode、引号、反斜线、制表符、CRLF 和 SHA256 全一致；完整来源可恢复但第一页不误报完整覆盖；组引用、重复准备幂等、旧视图不改、默认关闭和真实分页回执范围均核查。
