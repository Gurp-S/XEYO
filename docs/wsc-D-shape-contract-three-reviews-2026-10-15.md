# D 声明形状与持久身份：三轮复审

## 事故三问与源码依据

结构根因：专用声明复用通用 TodoWrite 的宽松形状，但有独立的 Guard 前置条件；模型看见的 schema、Guard 的检查点、解析后的持久表示并不完全一致。303/before.json 已用原生 validate 免费复现：原始 `report` 和 ` report ` 被当作不同 ID 接受，parse_input 去除空白后得到两个 `report`。原始 ID 唯一不等于持久 ID 唯一。另有未完成任务的 objective/context 必需性未完整写入 schema，错误本来会立即终止生成。

结构规则：唯一性在最终持久身份空间检查；已经存在的必需形状在专用 schema 表达，运行时仍是执行权威。机械字段错误返回事实，复用原有最多六次生成预算；不自动补目标、不改模型参数、不靠词表判断任务完成。通用 TodoWrite 的解析/合并和旧持久格式不变。

回归：同一原始 ID、空/缺失/非字符串 ID、去空白后重复 ID 被拒；单独有周边空白的合法 ID 继续按原解析规则工作。活跃任务缺目标/空白目标/无 context 被拒并可在原预算内修正；终态/空清单的空目标继续合法。原始帧/思考/参数保持、完整预计数/费用/取消/预算有界，只有重新通过全部 Guard 的声明才进入真实 commit/restore/fold。

## 第一轮：职责与覆盖面

v1 只补 objective required 和 ID minLength。否决：这只覆盖已知两个 schema 症状，漏掉 parse 后的身份碰撞；也不能把所有 Guard 条件都复制成另一个运行时 schema validator。

v2 先列完整机械合同矩阵，分成可表达形状、跨字段/来源时序/持久事务，以及语义未知。schema 只公开已存在的形状条件，Guard 继续负责跨字段来源和运行时事实；唯一性改为最终解析 ID。无需新增框架、flag、持久字段或迁移。

## 第二轮：失败模型与兼容

否决直接禁止所有带周边空白的 ID：通用 parser 长期允许规范化，单个合法 ID 无需人为变成错误。也否决只改 schema：它不是强制输出，模型仍可能返回错误。

v3 在现有 Guard 中保留原始 ID 类型/非空检查，并将重复检查切到 parsed.todos 的实际 ID。保持旧错误码，增加结构化位置/重复持久 ID 等中性事实；活跃目标/来源缺失也用原错误码结构化。只有这两类已明确机械错误加入原 bounded 拒绝分支，不捕获任意异常，不扩调用次数，不 HTTP 重试。

schema 的非空用 minLength+pattern；跨字段 ID 唯一性不使用 uniqueItems 冒充，因为不同对象可以同 ID。JSON Schema pattern 与 Python Unicode whitespace 定义可能不同，执行层仍是最终检查；测试不宣称全部 Unicode 等价。

## 第三轮：验收、公平性与实施边界

否决为每个缺失字段另跑一轮付费问答、把合法输出当任务成功，以及拼接旧 294/300/302 成绩。先用原生 Guard/真实事务证据证明机械修复，不重写旧成绩。

最终实施：在唯一 source_schema 模块增加已存在的活跃形状；消除专用 ID 的“缺省自动生成”错误描述；在原 validator 检查最终 ID，新增中性错误详情，原 generate 复用拒绝回放。测试使用行为反例、原始 wire 回放、预算/取消及真实 commit/restore/frozen，不另造一个仿写 schema 的检查器。没有可用通用 JSON Schema 库时，明确 schema 部分是结构检查，不把它叫完整 validator 通过。

三轮已完成，随后实施和定向验证；有证据的机械修复按用户最新政策接默认入口。控制载体 split 候选不借本项启用，U2–U6、完整生产薄投影/冷恢复、真实多代/留出、228/A1 六轴验收继续待办，不缩 Goal。
