# WSC 厂商请求前计量（批次116，仅静态）

用户已授权：运行时允许免费的厂商预计数，其余明确标为估算。此授权不解除当前禁止运行测试、编译及API的限制。

## 正确性与边界

结构性缺口是把厂商编码后的JSON字节估参当成媒体/token计量。修复规则：计量源必须对应当前完整输入；通知载体、新交接及新折叠导致输入改变后重新计量。厂商预计数也不是生成usage或零误差实测。

- `model/anthropic_count.py`：复用实际请求编码器，向官方HTTPS `api.anthropic.com/v1/messages/count_tokens`提交模型、消息、system、工具及thinking等允许字段。只允许官方原生地址；网关不请求，禁止重定向。10秒超时、不重试，HTTP失败/无效响应回退估算；取消传播。
- `memory/wsc_counted_input.py`：同次请求准备内以完整编码输入摘要缓存预计数；只保存摘要与数字，不跨请求复用。当前client配置在准备过程中固定。变更消息/schema/媒体后无法命中旧输入摘要；失败也只缓存于该次准备。
- `memory/wsc_request_timing.py`：主链异步准备先预计数，再决定80%通知；通知加入后重新计数；交接更新后重新准备；一次确定性折叠后重新计数，保留输出余量及硬容量校验。同步离线路径仍明确估算，共用最终准入逻辑。
- `engine/query_loop.py`：实际主请求接上述异步路径。`memory/wsc_handoff_generation.py`：隔离交接每次真实发送前也预计数；来源挑选仍是预算估算，最终发送准入使用预计数或明确回退估算。
- `memory/wsc_timing.py`：计量依据为 `anthropic_count_tokens_prediction` 或原有明确估算；通知分别为“上下文已达80%（厂商预计数）”和“上下文已达80%（当前完整请求估算）”。通知送达确认仍只发生在成功请求后，不改冻结前缀。

厂商计数不改 `last_usage`、不冒充付费生成回执。其他厂商、兼容网关、计数接口失败仍使用完整编码请求的UTF-8估参；媒体误差尚未因此全面解决。没有引入跨请求缓存、旁路开关或新的持久状态。

## 依据与验证范围

官方依据：[Claude token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting)、[Count tokens API](https://platform.claude.com/docs/en/api/messages/count_tokens)。文档说明免费、支持文本/工具及相应媒体、可能存在小幅误差和不支持的输入形式。接口返回失败时沿估算路径，不把未知变成精确计量。

静态检查覆盖：主请求通知前后、交接新增输入、压后重测、交接实际发送、输出余量、失败回退、取消、网关边界。未来回归须验证真实count载荷与发送载荷一致、相同输入缓存/变更输入失效、通知跨85%、接口失败与取消、图文计数和压后重测。
