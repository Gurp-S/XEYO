# 应试性审查：两个副作用修复 + 53 号验证门控

> 2026-09-10。触发：用户红线「任何修改不能是『应试』修改」。
> 审查对象：①first_sniff 容器下注入空目录；②R4/#9 产物磁盘核对误报；③53 号验证门控收敛架构。
> 结论先行：**两个副作用都应当修，且能修成完全非应试**——因为它们的根因不是"评测形态"，
> 而是"引擎断言自己观测不到的事实"。反过来说，**"容器路由下跳过"才是应试修法，明确禁止**。
> 53 号骨架（完成门控 + 机械证据 + 双预算）是通用能力，但有 3 处必须脱敏、1 处必须剥离。

## 〇、判定尺子（四条，后续同类审查复用）

| # | 尺子 | 判"应试"的条件 |
|---|---|---|
| R1 | **产品受益** | 只有评测受益、真实使用零收益 → 应试 |
| R2 | **无评测分支** | 出现 `if 容器路由/bench_minimal/任务名` 才生效 → 应试 |
| R3 | **信息纪律** | 引擎注入了自己无法核实的事实、或给出命令/劝说/导演 → 越界（与「引擎只给信息」哲学冲突） |
| R4 | **可证伪的收益来源** | 收益只能靠「对标判分器/读测试目录」兑现 → 应试 |

一条修改通过 R1~R4 即非应试；任一条不过就改到过为止。

## 一、副作用 A：first_sniff 在容器路由下注入宿主空目录

**现状（已核代码）**：`engine/first_sniff.py:49` 的 `build_first_sniff_text(cwd)` 用
`os.listdir` 读宿主 cwd；`xeyo_harbor_agent.py` 把 cwd 设成 `logs_dir/workspace`（自建空目录），
真实工作区在容器 `/app`。于是首轮注入 `cwd: …/workspace` + `(空目录)`。
开关默认开（`XEYO_FIRST_SNIFF`），适配器未关 → 该误导事实当前**默认生效**。

**对真实使用有没有影响？**
- 真实使用（GUI，cwd = 用户打开的工作目录）→ **现状是正确的、且有益**（这正是 #8 的初衷：给首轮环境先验）。
- 缺陷面只有一个：**当引擎的观测面（宿主 os.listdir）与模型的工作面（bash 当前路由）不是同一个文件系统时，注入的是一份模型看不到的清单**。
- 今天只有评测适配器会让两者分离，但分离本身是通用问题（WSL / 远程工作区 / 沙盒工作区都会命中）。

| 修法 | 性质 | 判定 |
|---|---|---|
| 容器路由激活 → 不注入 | 只有评测受益；产品接 WSL/远程时还要再修一遍 | **应试，禁止** |
| 嗅探**走与模型相同的执行通道**（活动路由下 `ls`，宿主下 `os.listdir`） | 宿主行为字节级不变；非本地工作区下由「错误」变「正确」 | **非应试** ✓ |
| 无法确认观测面时**静默不注入**（不确定就不说） | 信息纪律（R3），产品同样成立 | **非应试** ✓ |

**推荐**：两者组合——优先"同通道嗅探"，通道不可用时静默。收益是真实的：容器/WSL 下嗅探
从"误导"变成"有效先验"，同时删掉一个通用错误（注入观测不到的目录清单）。

## 二、副作用 B：R4/#9 产物磁盘核对在容器路由下误报

**现状（已核代码）**：`tools/todo_write_tool/todo_write_tool.py:305`
`full = Path(self._cwd or ".").joinpath(path)` → `full.exists()`。
- 相对路径按工作区 cwd 解析 → 真实使用下**正确**（cwd 修正后）；
- 绝对路径按宿主路径 stat → 产物在容器/远程时**恒判"磁盘上不存在"**，而模型明明写了。

**对真实使用有没有影响？** 有，且**不需要评测理由就能立住**：
产物在 cwd 之外时（模型用 bash 写 `/tmp`、写挂载盘、写别的绝对路径），宿主 stat 同样判错。
换句话说——**"引擎对模型说『磁盘上不存在』，而引擎其实没有能力看那个文件系统"是一个通用正确性缺陷**，
评测只是让它显形的窗口。它也与 R3 冲突：这是一条**引擎自己都证不了的事实**。

| 修法 | 性质 | 判定 |
|---|---|---|
| 容器路由激活 → 跳过核对 | 评测专用分支 | **应试，禁止** |
| 核对**经活动路由执行**（`test -f` / `ls -l` 走同一个 bash 通道） | 宿主下结果不变；非本地工作区下变正确 | **非应试** ✓ |
| 观测能力不成立时**沉默**（既不断言存在、也不断言不存在） | 信息纪律 | **非应试** ✓ |

**推荐**：同通道核对 + 不可观测则沉默。注意保持既有措辞纪律（纯事实、无命令/劝说），
契约测试 `test_todo_output_facts.py` 继续锁死。

**顺带**：这两个副作用共用同一个机制（**观测域一致性**：引擎的核对/嗅探必须与模型的动作走同一通道），
建议一次性抽一个 `tools/exec_channel.py`（或在 container_routing 上加 `read_text/list_dir/stat` 三个只读原语），
两边共用。这就是"通用修复"，不是"评测补丁"。

## 三、53 号验证门控：逐项应试性裁决

| 53 号条目 | 性质 | 处置 |
|---|---|---|
| 完成门控状态机（DONE_PROPOSED→VERIFYING→REPLANNING→DONE_AS_IS）："完成"从模型声明变成引擎状态转移 | 通用能力；真实用户天天遇到"模型说做完了其实没做" | **保留**（非应试核心） |
| 证据来源 `test-suite`（环境里有测试就要求跑） | 通用强（产品：仓库有 pytest 就该跑） | 保留 |
| 证据来源 `property` 模板（文件类=产物存在+规模+语法有效；服务类=端口/进程存活） | 通用强，正是产品痛点 | 保留，**优先实现** |
| 证据来源 `spec`（从任务指令 regex 抽数值范围/规模约束） | 通用但**可靠性差**：TB 的 instruction.md 格式度高于真实用户需求，抽错会造出假证据 | **脱敏**：只在能可靠解析时启用，解析不确定 → 沉默，不得凭猜测立证据 |
| 覆盖差距检测（自测域 ⊊ spec 域 → 补一条证据） | 通用（"你只测了小用例"），但依赖上面的 spec 可靠性 | 保留，继承同一约束 |
| 双预算（验证预算独立、不可被探索挪用） | 通用工程原则 | 保留 |
| L1 结构化自审（JSON：最大规模测了吗/溢出查了吗） | **措辞面向数值题**，是评测题的语汇 | **脱敏**：改为通用 schema（你做过哪些验证/边界在哪里/证据命令是什么），且明确"不被信任、只做路由" |
| 失败标签 overflow/timeout/infra/wrong-approach | `infra` 是**评测专属概念**，真实用户无此语境 | **剥离 infra**，只留产品语义标签（未验证 / 重复同模式失败 / 超时） |
| REPLANNING 的"证据连续两次失败 ⇒ **强制**方法切换" | "强制换路"是**导演行为**，违反「引擎不注入建议/指令」红线 | **剥离强制**：只呈现事实（同一模式连续失败 N 次），换不换由模型决定 |
| P3 实验协议、A/B 对照、"目标 60.7%→75-80%" | 评测动作，不是产品功能 | 留在评测侧，**不得进入产品代码路径** |

**一句话**：53 号的骨架非应试；应试味全部集中在 3 处脱敏 + 1 处剥离上，改掉即可。

## 五、实现禁止清单（红线，写代码时逐条自查）

1. 不得出现 `if 容器路由 / XEYO_BENCH_MINIMAL / is_benchmark: 跳过或特判` ——

4. 不得注入命令/建议/评价/强制换路。
5. 任何"提分"必须能同时讲出**产品侧收益**；讲不出来的，不做。

## 六、解决方案（可直接开工的形态）

### 6.1 副作用 A/B：新增 `tools/exec_channel.py`（观测域一致性原语）

**只读三原语，走当前活动路由；不可观测一律返回 None，调用方沉默。**

```python
# python/tools/exec_channel.py（新，零依赖；不设置路由时字节级等价于旧行为）
def list_dir(path: str) -> list[str] | None:
    """活动路由下列目录。宿主=os.listdir；容器=docker exec ls -1a -- path。
    失败/超时/路由不可用 → None（不可观测）。"""

def stat_path(path: str) -> tuple[bool, int] | None:
    """(is_file, size)。宿主=Path.exists/stat；容器=test -f + stat -c %s。
    不可观测 → None。"""

def read_text(path: str, *, limit: int = 4096) -> str | None:
    """按需读一段文本（供 future 核对器）；不可观测 → None。"""
```

- 路由判定复用 `tools/container_routing.current_container()` + 环境变量回退（与 bash/job 一致）；
- 容器分支复用 bash_tool 已有的 docker SDK exec（建议把 `_docker_exec_with_timeout` 提为公共函数，避免第二份实现）。

**接线两处（各自 3~5 行）：**

| 位置 | 现状 | 改后 |
|---|---|---|
| `engine/first_sniff.py::build_first_sniff_text` | `os.listdir(os.path.abspath(cwd))`，空目录 → 注入 `(空目录)` | `exec_channel.list_dir(cwd)`；返回 `None` → 返回 `""`（不注入）；容器路由下注入**容器内真实工作区**清单 |
| `todo_write_tool.py::_materialization_facts` | `Path(self._cwd).joinpath(path).exists()` | `exec_channel.stat_path(resolved)`；返回 `None` → **该条不加行**（不输出任何断言） |

验收（两条都不含评测分支）：
- 宿主路由回归：现有 `test_pre_llm_inject.py` / `test_todo_output_facts.py` 全绿即证明"宿主行为不变"；
- 新增容器路由单测：打桩 `current_container()` 返回假 id + 假 exec 返回 → 断言 first_sniff 注入容器清单、todo 核对按容器结果出事实；
- 不可观测路径单测：exec 抛错 → 断言 first_sniff 返回 ""、todo 不加行（沉默纪律）。

### 6.3 A 类（超时截断，~10 题）如何缓解

**A 类的结构性事实**：模型走在正确道路上、只是没到终点就被外部墙钟硬杀（rstan MCMC 7400/8000、dna-assembly 只差 primers.fasta、raman-fitting 拟合一半、extract-moves OCR 仍在跑、write-compressor 思路已对）。**不是智力问题，是"时间感知 + 落盘纪律"问题。**

现状已具备的（不用改）：promote 长命令自动转后台（TB 里生效，45s 阈值）、墙钟水位播报（R1' notice 通道）、缺口行（R4/wrap_gap）。
**真正的缺口：R1' 硬停默认未武装**（`budget.arm_wall_stop(None)`，margin=0）→ 引擎知道 deadline，但不提前收尾。

| 措施 | 落点 | 性质 | 说明 |
|---|---|---|---|
| **A1 收尾武装** | 装配层：`XEYO_WALL_HARD_STOP=1` + `XEYO_WALL_STOP_MARGIN=90~120` | 装配（非改语义） | 外部硬杀前先进入引擎自己的收尾窗口。产品侧等价诉求=长任务被 Ctrl-C/关窗时优雅落盘 |
| **A2 收尾窗口三件套** | `engine/budget.py` + `wrap_gap.py` | 通用能力 | ①把"已登记未落盘产物"作为事实列出（已有）；②配额窗内允许继续调用工具完成落盘（R3' 已有）；③**窗口内拒绝启动新的长命令**（`command_duration_risk > 剩余时间` → 执行层报错，不是劝说——符合"限制静默走执行层"哲学） |
| **A3 长命令前置后台化** | `tools/bash_tool/timeout_map.py` | 通用能力 | 对已知长命令族（apt/pip/conda/make/采样/OCR/编译）在收尾窗口内一律走后台，结果就绪后继续；避免单条命令吃光收尾窗口 |
| **A4 中间产物不强制** | — | 不做 | 引擎不能命令"先落盘"；靠 A2①的事实 + A2②的窗口让模型自己完成 |
| **A5 档位不匹配题单列** | 评测协议层 | 装配 | 专家估时 >> 档位的题（make-doom-for-mips 480min、gpt2-codegolf 2400min）属**任务强度与预算不匹配**，应调 `timeout_multiplier` 或标注后不计入引擎能力评估——不要用引擎机制硬凑 |

**A 类预期**：10 题里"路径正确只差时间/落盘"约 4~5 题（其中 rstan 已按 R3-SAVE 计入 v1 模型，避免双算）→ **新增 +1~2 题**。
