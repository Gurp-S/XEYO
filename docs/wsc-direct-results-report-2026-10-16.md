# 366：正文文件与直接入口的对照

## 结论与交付状态

本轮没有准入新的生产机制。按唯一调用关联发布正文文件、再在热层直接给出正文目录，两项试验都没有带来稳定的任务质量收益。候选源代码、测试、运行器已封存并从生产目录移除；`wsc_semantic_evidence.py`与366之前的备份逐字节相同。先前已准入的修复保留，没有回退其他工作。

这里验证的是有效冷恢复，未重新生成语义交接，也没有完成独立A1、多代或整个Goal验收。四项GUI任务来自同一真实历史，另两项为旧解释纠正/迟到身份的受控任务，不是六个真实会话。

## 三轮审查与候选

审查记录：[实施前及入口复审](wsc-direct-results-plan-2026-10-16.md)。结构性假设是目录行号、原始封套行号和调用参数offset的多重转换使恢复复杂；搜索与Read指向同一文件应减少转换。

候选复用现有内容寻址发布与清单，以原始封套为依据，按唯一assistant调用与后续tool/user结果关联生成文本文件。每文件含调用信息、来源身份、`[tool_result_text]`分界和原始字符串。重复/孤立/过早/非文本结果不猜测配对，仍由原始封套和媒体恢复。不加入Source工具、语义Guard、重排状态或新的摘要提示。

23项定向检查通过，覆盖字符串逐字保真、角色与关联、迟到回执、来源绑定、发布失败、冻结和重启、对象损坏拒绝。这个结果只证明上述机械边界，不代表模型会使用文件。

## 第一轮：增加冷正文文件，但入口仍在旧目录

同历史、同交接、同尾部、原生Read/Grep/Write；每臂7次请求、2048输出额度。真实工作区包含公开证据，私有转录与评分在工作区外且Read被拒。工作区及密封地址不同，不能称请求字节相同。

| 指标 | 原实现 | 增加正文文件 |
| --- | ---: | ---: |
| 完整完成任务 | 4/6 | 4/6 |
| 正确产物 | 5/6 | 5/6 |
| 模型请求 | 30 | 30 |
| Read/Grep调用 | 27 | 28 |
| 新正文文件Read/Grep | 0 | 0 |

任务明细：原实现runs未产出；候选runs完成，但excerpt错误；versions两臂均写出正确产物，耗尽请求额度而未最终回复。current、interpretation、late_identity均完成。不把正确产物与完整结束混记，不给额度失败补记成功。

新增正文文件无人使用：模型仍先读旧目录，部分任务一次读完整目录触发25K工具返回额度，然后回到JSONL。候选excerpt把JSON包装抄进正文。这一轮没有有效验证直接正文阅读收益，不能根据runs改善归因于新文件。

GUI每份存档新增77个文件，约302KB（总公开对象字节约+17%），对象5→82；本机单次发布样本约0.06–0.11秒→0.33–0.48秒。各臂热输入约5643–5646估算tokens，差异主要为地址。这里不是正式性能基准，但额外磁盘和校验成本真实存在。

证据：`_wsc_out/wsc-direct-results-366-scoped/`。60次API，input739525、output13154、hit560256、miss179269，估计¥0.48618024。

## 第二轮：同文件、同产物，只改变发现入口

第一轮之后撤回生产接线。三轮复审后，第二轮复用同一批after冷文件、同一工作区、交接、尾部和工具，只比较原目录入口与直接列出正文目录＋原始消息/身份目录的事实入口。没有新增文件、工具、提示性劝导或目标答案定位器。无文本回执的会话维持原入口；不是所有历史都有新正文文件。

| 指标 | 原目录入口 | 正文目录直接呈现 |
| --- | ---: | ---: |
| 完整完成任务 | 4/6 | 4/6 |
| 正确产物 | 4/6 | 4/6 |
| 模型请求 | 30 | 28 |
| Read/Grep调用 | 27 | 29 |
| 新正文文件Read/Grep | 0 | 7 |

直接入口让runs用5次请求完成，原目录需7次；但整体任务成功率未提升。两边excerpt和versions失败，其他四项通过。直接入口versions没有取得完整目标证据，原目录取得目标证据但未产出。不能拿第一轮最好版本成绩和第二轮最少调用数拼接成胜利。

直接excerpt实际读到了正确文件和完整前三行，却把新增的`[tool_result_text]`也当作正文首行，挤掉第三行。原文没有丢失；新增包装又产生了需要模型解释的边界。给文件加身份和标记，仍然不是“纯正文直接读取”。versions仍选择旧目录，11次检索后耗尽额度，未使用新正文文件。它说明直接列出路径不足以保证有效发现，不证明文本文件无法做成有效恢复。

证据：`_wsc_out/wsc-direct-entry-366/`，`comparison-summary.json`含两轮分开统计。58次API，input657985、output13185、hit546432、miss111553，估计¥0.35044328。

## 归因与根本问题

| 层次 | 本轮证据 | 结论边界 |
| --- | --- | --- |
| 引擎/接口 | 冷目录隐藏新入口；同一任务有JSONL、可读视图、身份目录和正文文件等多条路径；正文又带机器包装 | 引擎增加了发现与解释成本。源文件完整不能认证模型输入便利或续接有效。新增副本没有替换原复杂路径，难以证明净收益。 |
| 模型 | 正确原文已送达，excerpt仍把包装标记当正文；versions未采用直接正文目录 | 存在提取和检索选择失败。接口诱因与模型错误分开，不归为存储丢失，也不只靠提示纠偏。 |
| 评测 | 统一请求上限使正确产物可能缺最终回复；第一轮新能力从未被使用 | 保留artifact/完整结束两个分数；按实际路径确认暴露。第二轮只改入口，不能把它与第一轮混排。 |

下一项讨论应聚焦：恢复表示是否把原始正文和解释性包装真正分开，以及一个任务是否被迫在重复表示之间判断路线。先核对现有索引、原始封套与正文的必要职责，再做最小对照；不继续给目录加字段、给分界加提示、引入Judge或增加语义状态。纯正文、关联信息按需是否更好仍待验证，不宣称已证明。

362–366连续低收益历史不清零。停止修改这组候选、讨论方向；Goal保持active。后续需要独立行为收益和非退化，才能恢复生产实现。
