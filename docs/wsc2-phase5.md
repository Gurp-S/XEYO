# WSC Phase 5 —— 目标定义与编号清单（2026-09-23）

## 1. 用户裁定（原话要点）

- 下一轮**唯一主指标 = 去噪 / 在场信息密度**；信息保留、压缩率降为**硬约束**（不得退化）。
- 去噪**两条臂都测**：① 只标注 + 段内合并（不删）；② 相关性寿命（真删）。用数裁，不靠哲学。
- 压缩率**必须看**，但它是"去噪率 × 信息保留率的合集"，定位成**信息密度**；
  并且"压缩率 = 压缩后未命中的价格 ⇒ 尽量低"。

## 2. 基率复核：折叠到底值多少（`_wsc_out/_fold_pricing.py`，只读厂商账本，零 API）

单位用 **token·枪**（少发的 tok × 后续枪数），不碰价格表就能比：

| 量 | 值 |
|---|---:|
| 可比折叠次数 | **40**（3,373 次折叠事件里，2,254 次"prompt 没变小"被跳过、10 次会话太短） |
| 移出量中位 | 2,643 tok |
| 折叠后本会话剩余枪数中位 | 13.5 |
| 单次收益中位 | **26,973 token·枪**（p25 7,420 / p75 105,146） |
| 单次代价中位（该枪比本会话基线多出的未命中） | 4,573 tok |
| **收益 / 代价（同单位）** | **5.99×**；净为负的折叠占 12.5% |

**但换成钱方向就反了**：被移出的那段本来就**已缓存**，省下的是**命中价**；而代价付的是**未命中价**。
DeepSeek 两档都是 30× 价差（flash 0.05/1.5，pro 0.15/4.5），于是：

`5.99 × (1/30) ≈ 0.20` ⇒ **按可测样本，折叠在钱上是净亏的**（收益只有代价的 ~1/5）。

同向的独立证据（既有 p8 vs attempt2 两臂，厂商实付）：多折的那臂 **45 次折叠、每请求 ¥0.0284、
命中 43.7%**；少折的那臂 **5 次、每请求 ¥0.0104、命中 84.1%** ⇒ 折得越多，每请求越贵。

两条偏差必须写清，别让这数被当成判决书：
- 代价被**高估**：4,573 tok 里含该枪本来就要发的新内容；
- 收益被**低估**：不折的话那段还会继续长大，且**不折就会溢出窗口**（这才是折叠存在的理由）。

⇒ 结论不是"折叠没用"，而是：**折叠买的是窗口，不是省钱。** 所以你的裁定自洽——
压缩率是**代价项**，越低越好、够用就折；真正要挣的是"同样的在场里塞进更多有效信息"。

样本量只有 40，且这 40 次来自能观测到净缩小的少数场景 ⇒ 要坐实钱，需要一次**配对 A/B**
（同一任务、同种子、WSC on/off 两臂，收厂商实付）。属付费项，未授权。

## 3. 主指标的定义（防"各说各话"，先钉公式）

**有效信息密度 D = 事后被复用的行数 / 热层千 tok**（分子分母同点同尺，零成本可算）。
- 分子：该行含的事实在 `t` 之后确实再被引用（沿用 §14 的事后复用金标，含 basename 匹配）；
- 分母：整段投影的 tok（生产尺 `memory.token.token_len`，探针启动自检 `prod == wsc2`）。
一个数同时惩罚"占地方"和"重复"，抓得住 V1 那个 53.6%（同一文件出现在 ≥2 段）。

硬约束两条：① 四路事后召回 **不得 < 现值 1.000**（V2）/ 0.751（V1 file）；② 热层不得超名义预算、
长会话不得溢出（压缩率当约束看，不当目标看）。

## 5. 四条跑完的实测（`_wsc_out/_wsc2_phase5.py`，126 点，零 API，未改库）

### 5.1 P5-前置：ACTIVE 的 WORKING SET 行"闲了几枪"，闲久了还会不会被复用

| 空闲枪数 | 行数 | 事后仍会被复用 | 复用率 |
|---|---:|---:|---:|
| 0（本枪刚碰） | 56 | 42 | 0.750 |
| 1 | 42 | 21 | 0.500 |
| 2–3 | 73 | 48 | 0.658 |
| 4–7 | 112 | 47 | 0.420 |
| 8–15 | 175 | 68 | 0.389 |
| 16–31 | 293 | 88 | 0.300 |
| **32+** | **959** | 123 | **0.128** |

噪音主体就是这 959 行（占在场文件行 **56%**）。但即使闲够 32 枪仍有 **12.8%** 事后会被用
⇒ **"闲够久 ⇒ 可安全删"被数据否掉**，寿命规则不存在零误删的阈值。
（第一版这里全是 0：行号→枪号只查了回执行，而触碰事件都在调用行上，查不到就当 0 枪 —— 已修，
分布才第一次有意义。）

### 5.2 P5-2 臂②（真删，扫 N）：**判死**

| N | D | tok 省 | 误删次数 | 误删率 |
|---:|---:|---:|---:|---:|
| 基线（不删） | **4.132** | 0 | 0 | 0 |
| 1 | 1.945 | 39.2% | 374 | 17.6% |
| 4 | 2.607 | 37.1% | 316 | 14.2% |
| 8 | 3.133 | 34.8% | 265 | 11.3% |
| 16 | 3.692 | 31.7% | 204 | 8.2% |
| 32 | 4.294 | 25.3% | 117 | 4.2% |

没有任何 N 同时满足"D 不降"和"误删=0"：D 只在最松的 N=32 微升 0.162（+3.9%），却要付 117 次误删；
**越积极越亏** ⇒ 按 P5-4 判死，不写退场规则、不加寿命字段，保守 KEEP 保住。

### 5.3 P5-1 臂①（不删）：钱在 V1 的**重复**，不在 V2 的**寿命**

| | 在场 tok | D |
|---|---:|---:|
| V1 现状 | 1,815,938 | 3.684 |
| V1 段内合并·上限版 | −48.4% | 7.136 |
| V1 段内合并·**安全版**（不丢带句柄的行） | **−16.8%** | **4.426** |

上限版不可实施——被丢的行里含 PATHS/PRUNED 的**句柄行**，丢了等于把"被剪节点必可拉回"丢掉，
只能当上限引用。安全版是 V1 侧真能落的一刀（−16.8% 在场、D +20%）。
V2 侧的"只标注"（#31 已交 STALE/hash/read_ranges）**不改尺寸也不删 ⇒ D 不变**，
其注意力收益离线测不到 ⇒ 不能拿标注冒充去噪收益。

### 5.4 我自定的主指标有缺陷（先自曝）

D = 复用行/千 tok **偏袒"塞得多"的臂**：V1 每点约 14.4k tok、V2 每点约 1.0k tok，
跨一个量级比 D 无意义（合并后的 V1 甚至"赢"了 V2）。⇒ 补一条 **P5-3b：同 tok 预算对照**——
两臂都裁到同一在场预算（1,000 tok/点，按各自的优先级），再比谁装的有效行多。
这才是"V2 的头能不能替 V1"的正面答案，仍然零成本。

### 5.5 四条的净结论

1. 去噪**不该靠删**（寿命阈值无一能达零误删，积极删反而拉低主指标）；
2. 去噪该靠**去重复**，而且那笔钱在 **V1 侧**（安全合并 −16.8% tok / D +20%）；
3. 主指标必须配尺寸硬帽才有意义 ⇒ 下一步 P5-3b 同预算对照；
4. V2 基线：**D 4.132 @ 1,006 tok/点**（V1：3.684 @ ~14.4k tok/点）。
