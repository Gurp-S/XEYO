# D 优化：根因方案及三轮复审

本计划记录用户最新要求：进展必须转向明显、稳定的工作质量收益；未来实施前完整考虑最合理的治本方案，至少三轮实质复审。本轮仅静态阅读、制定并复审计划，未修改引擎/Prompt/schema/工具行为，未调用付费API，未运行测试。

三轮由当前代理直接完成，不使用子代理。它们是静态复审，不是实验通过证明；不能据此宣称方案全局最优或Goal已经完成。当前是证据支持下的首选方案，仍需被对照结果检验。

## 固定目标与问题判断

目标与六轴合同不变：D达到A1或更好，保持原228约束18/18、具体值21/21、来源36/36及旧事实复活不增加。机械正确性、语义质量、长期稳定性、恢复、去噪、效率按原优先级执行，质量优先于成本。

慢的主要原因是推进单位选错：逐项修接口、验证静态字段和积累局部正例，却未形成通过实际任务的完整链。已经得到的根因证据和失败应复用，不能重新跑一遍或以更多合同数冒充优化。

## 第一轮：根因、职责和最小方案

阅读依据：native生成/反馈循环、ReplayModel、task_checkpoint投影、已有observations以及263实际单变化协议。

**否决v0：** 同时开启思考、加语义句、默认物化结果包、附加元数据、缩目录，以组合结果证明“D优化”。这样既无法归因，也可能把热层重新扩成旧C。

**修订为v1：** 单一语义声明 → 既有机械校验/事务 → 薄投影 → 完整精确冷层。先恢复协议与实验可信度，然后优化同一份交接的继续工作覆盖，最后测恢复与长期任务成功。

唯一职责：

- 模型声明当前目标、范围、步骤、决定、约束、必要工作证据和不确定性。
- Runtime提供原执行身份、可用/已发送状态、文件版本及真实结果，不能由编号或关键词发明语义关联。
- Guard验证来源、结构和转换依据，不再理解一遍取消/覆盖含义。
- 投影表达已经声明的适用状态；复用applicable等既有函数，不能另起语义选择器。
- 冷层提供精确目录、正文和原回执事实；查询决策仍属于模型。

字段先复用现有objective/todos/decisions/constraints/observations。若现有字段确实无法表达某项必需状态，先给出不能表达的具体来源证据再评审schema；不能直接新建平行WorkState/摘要。

## 第二轮：反例、时间轴与恢复

阅读依据：handoff_transaction的captured/fingerprint/validate/publish/persist，冻结头复用条件，事实退休校验与覆盖证明。

**再次否决：**

1. 在旧状态旁新增一份自由语义摘要。两份内容冲突时没有唯一权威，且增加注意力和持久化。
2. 一概删除compaction_handoff回执或旧验证绑定。回执可证明声明提交，不能直接证明任务产物验收；历史绑定还有恢复和连续性用途。
3. 新建提交/恢复协调器。已有事务和持久化需先复用；仅有被证实的缺口才改。
4. 将267“原typed帧一致”等同于完整厂商wire一致。真实argument序列、思考/签名顺序、截断和usage都须单列核验，不能伪造占位思考补协议。

**修订为v2：** 保留现有单一声明与原事务；协议适配只服务专用生成帧。声明回执、任务执行回执、产物证据按原身份与marker区分用途，来源不删除；不能靠工具名称或文本做分类推断。

实施时必须守住时间轴：捕获来源 → 模型生成 → 来源一致性/Guard检查 → 真实TodoWrite提交 → 持久化回执 → 发布新投影。任一步失败，旧合法状态、后续原文与未消费结果继续有效。晚到事件使来源变化时，不能发布基于旧捕获的状态；原fingerprint合同保留。

重启只恢复通过seal/cursor/publication检查的版本；折叠之间旧头字节不变。不修改普通压缩模型自决、80%一次事实通知、85%完整请求强压边界。

## 第三轮：效果、公平性、成本及淘汰

阅读依据：228原指标/方法边界，255/257/260/263请求额度与旧结果复用，264–266明确/未知关联，faithful热渲染与实际投影代码。

**再次否决：**

1. 静态字段答对或格式合法即可过Goal。实际任务必须产生并验收正确产物，重启/压缩后还能继续。
2. 拿D开启思考、A1关闭思考作方法排名。模式、输入、工具、额度、来源真值与任务验收必须相同；不同原生条件另列。
3. 把旧已付费结果复用的筛查当同期重复，或把无最终答案记成所有语义字段错误。
4. 用report_version=execution.revision、数字相同或新旧名称作隐含gold。新任务明确产物绑定、版本轴、授权与未知；旧结果原样保留。
5. 合同检查和一例改善自动准入默认结果包/索引。热层增加必须有稳定行为收益，不能因能恢复而长期展开全部证据。

**最终v3：** 以任务产物/continuation为主验收，用静态字段定位失败；方法、模型能力、投影、协议、恢复工具分开对照。每项无稳定收益的机制退出当前付费支线，保留原证据，不反复找正例。

## 通过三轮后的实施顺序

### P0：冻结基线与验收定义，免费先做

明确A1是已固定源码prompt加Flash的方法对照，D是已有原生交接与薄层方法，均不是Codex/Claude模型能力排名。固定源码、来源、请求格式、模型模式、工具与评分真值；分别标记候选渲染和生产链路，禁止试验驱动私自换一种热头却仍称原D。

预登记任务产物标准：当前目标/请求、约束和授权、版本/执行关联、明确未知、冷信息需要与不需要、验收文件/结果。原228仍独立复测，不能用新分数替代。开发样本与保留样本分开。

P0交付是一个完整可执行协议和首次请求审核材料，不再创建多个小候选去跑旧QA。未证明来源足以决定答案的题暂不用于排名。

### P1：只修专用交接的协议保真

复用现有消息构造/原生块校验与267旁路；补实provider帧、argument表示、子客户端及实际usage的合同，不改Prompt、schema、选择规则或默认mode。只用少量真实专用读取/拒绝续接确认无协议错误和原帧丢失，不重送历史失败请求。

协议正确是P2前置条件，不算交接语义质量提升。补缺口的具体代码计划仍需各自三轮，267总计划不能豁免它。

### P2：优化同一份语义交接

先在可信链路下比较D/A1，取得实际任务失败归因。再选择**一个**最能解释主要失败的修改：交接内容合同或同一声明schema的表达方式；不能同时改Prompt、mode和默认证据展开。

目标是交接本体表达继续工作需要的当前状态、结果与原因，并在不知道时保留未知；重要证据的选择仍由模型完成。已有observations首先作为可复用表达，是否要求显式字段、如何改善语义覆盖，要按具体三轮计划与消融决定，不预先宣布有效。

不沿用已无稳定收益的253句子、254ID形式、260metadata作为新的热层优化前提。不强制填“有用结果”来掩盖未知，不为947等测试值加规则。

### P3：在质量合格产物上做长期任务与按需恢复

每臂使用自身产物，逐代加入真实进展/范围改变/产物版本/迟到结果，验证1/3/5/10代、重启、stale、完成重开、取消、截断/非法/网络/余额失败。失败原文回退单列，不算成功压缩。

任务中既有直接可继续的步骤，也有必须读取冷证据才能做对的步骤；模型自行决定检索。验收实际Locate/Read/Use以及产物，不能只问历史摘录。媒体的精确存档与模型使用分列，能力不足不能冒充引擎恢复失败或媒体通过。

若恢复成为主要失败，才评审通用接口调整；259/256等已有候选可复用，不再重复实现。方法效果未稳定前不扩大热层、不做缓存命中率竞赛。

### P4：原底线、泛化与并入

原228约束18/18、值21/21、来源36/36、复活不增加全部保住；D在新任务成功与续接上达到A1或更好；保留任务和异常矩阵通过，才比较热头、完整请求、调用/输出、成本、延迟与复杂度。

增加开销仅凭测得的任务/恢复收益准入。无稳定增益保持不参与主链或删除。最后再决定接入实际WSC路径，给出现场真实重建对照、并入清单及全部未完成TODO；Goal完成需要全范围证据。

## 每次后续修改的硬门槛

以下门槛对代码、Prompt、schema、工具行为、投影/默认配置及实验行为变更逐项适用：

1. 给出结构性根因、事实/状态所有者、现有机制不能解决的证据；比较复用/修改/新增/不做四种选择。
2. 三轮有不同审查焦点，并记录实际问题、否决意见、v1→v2→v3变化及剩余风险，不能仅写三次“通过”。
3. 列明改动边界、正常/失败/并发/恢复时间轴、旧不变量、对照与可证伪假设、成功/退出条件、注意力与维护代价。
4. 实质改变方案或关键假设被推翻后，重新完成三轮；总架构复审不能代替具体修改的复审。
5. 三轮完成前只允许必要阅读、离线分析和计划材料；不实施行为变更、不调用付费API试错。
6. 完成三轮后，在用户既有授权范围内继续实施；不再添加无来源的确认流程。没有收益不并入，质量不退化，预算/未知费用/冻结前缀仍按原合同。

当前完成的是这份总体方案三轮静态复审。P0–P4及Goal仍未完成；本轮没有新的行为改动或付费请求。
