# 批次98：写入确认不越过完整损坏来源（仅静态）

根因：批次97收紧执行恢复，但_load_written_ids仍替换坏编码、跳坏行/读失败；reconcile_retry也跳完整损坏行后继续append/fsync。读侧严格、写侧宽容会把“不完整可恢复来源”留到下一次启动才发现，而同步确认可能已让交接进入后续折叠。

不变量：失败重试不能通过忽略完整来源损坏来确认日志写入。复用load_transcript(strict=True)读取已写身份，删除独立的宽容解析循环及OSError吞错。reconcile_retry以UTF-8读取并核对对象行，完整坏行报错；仅当前文件未换行的坏尾append可沿原机制截去，旧归档不修写。空行仍忽略，合法未换行字典仍沿原补换行路径处理。

静态核对：重试异常由后台writer保留到_failed，flush返回失败，同步持久化抛错；交接失败不进入fold。新写行仍由现有序列化和提交队列负责，未新增扫描器或状态组件。

边界：已缓存身份路径并不每次全量扫描，不能因此宣称检测所有外部磁盘篡改；整归档缺失、并发初始扫描、重复inline身份内容、断电仍未证明。current未完成尾修复是已有授权机制，不改完整旧行/旧归档或冻结头。历史源有损坏会显式停止而非继续恢复，旧UI宽容路径不代表执行完整性。
