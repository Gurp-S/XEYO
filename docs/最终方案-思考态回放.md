## 问题 1｜思考态被丢弃：花了钱、内容丢了、模型每轮重推

**症状**
- 【码】`msgtypes/message.py:28,64,81` — `Message` 结构**没有 reasoning 字段** → 思考内容不落盘、不进历史、不回传；
- 【码】`model/_openai_common.py:104` 客户端**解析过**它（→ `reasoning_delta`）；`engine/query_loop.py:800/1162` 按轮收集进 `turn_reasoning_parts`；默认开关关 → **收集完即丢**；
- 【测】实测输出 token 里**约 94% 不可见**（可见正文 P50 仅 155 token）→ 花钱的主体正是思考。

**影响**
- 不可审计（花了钱的内容没留档）；
- 模型**下一轮看不到自己上一轮的思考** → 从零重推 → 输出 token 重复燃烧（输出占成本 **83%**）。

### 解决方法
1. **S1 数据模型**：`Message` 增加不透明容器 `provider_state`（引擎从不解读其内部语义），随会话 JSONL 持久化。老会话无该字段 = 现行为，**零迁移**。
2. **S2 采集**：按各厂商形态**原样**收下，不做任何清洗（DeepSeek `reasoning_content` 原文；Anthropic `thinking`/`redacted_thinking` 块含 signature 且顺序不变；Gemini `thought_signature` 字节）。
3. **S3 回放**：组装请求时按原形态贴回**产生它的那条 assistant 消息**；是否回放由 per-provider 策略表决定。
4. **验收**：字节等价测试（采集值与原始响应逐字节相等）+ 顺序保持测试。

### 注意风险
- **风险：清洗/截断会破坏签名**。【官】Anthropic 官方错误页 + 社区实测（openclaw#24612）：**仅因剥离未配对 Unicode 字符**就导致签名失效 400。
  → **缓解**：契约测试锁死"任何代码不得对 `provider_state` 做 truncate/sanitize/re-serialize"（grep 型 + 运行时断言）。
- **风险：回放会增加输入 token**（进入历史后走缓存，首轮为 miss）。【推】净账需在收益 A/B 中一并测，预期输入侧便宜、输出侧省。

## 问题 2｜补偿机制方向错：必须删除，不是改良

**症状**
- 【码】`permissions/policy.py:375` 开关默认关；`engine/query_loop.py:1279-1284` 开启时只取**末尾 600 字符**，塞进 **T_now（指令区）**；
- 关闭理由写在注释里：*"弱模型存在旧结论指令化的锚定/续写压力"*。

**影响**：这套机制**永远无法修成正确**——
- **lossy**（截断 600 字符）→ 违反"逐字节原样"，对需要回放的厂商是**非法输入**；
- **位置错**（指令区）→ 读起来像命令，这才是它被关掉的真正原因。

### 解决方法
- **S4**：在 S3 落地并验证通过**之后**，删除这 600 字符构造与 T_now 注入路径；保留开关位以免破坏 GUI 设置契约（语义改为"回放开关"或废弃，实现时定）。

### 注意风险
- **风险：顺序颠倒**。先删旧机制再建新机制 → 中间态既没有历史保真、也没有兜底注入。
  → **缓解**：先建后删（S3 → 验证 → S4）。
- **风险：GUI 设置契约**（`/reasoning-tail`、`set_reasoning_tail_enabled`）。删除时需同步处理 `server/routers/chat.py:863` 的调用点，避免设置项失效引发前端异常。

## 问题 3｜协议合规哑弹：工具轮不回传思考态 = HTTP 400

**症状（三方规则对照，均【官】已核）**

| 厂商 | 载体 | 工具调用时的硬要求 | 违规后果 |
|---|---|---|---|
| DeepSeek | `reasoning_content` | 两轮 user 之间**有 tool call** → **必须**参与拼接且后续**所有轮原样回传**；**无** tool call → 不需要（传了被忽略） | **400** `must be passed back to the API`；**截断/摘要同样被拒** |
| Anthropic | `thinking` / `redacted_thinking`（带 **signature**） | **必须原样回传**（含 thinking 为空的块）；**不能重排/编辑/部分丢弃**；连续块**顺序须与原始响应一致** | **400** `cannot be modified` |
| Gemini（2.5/3） | `thought_signature`（挂 functionCall 上，加密字节） | Gemini 3 **强制**原样回传（含 MINIMAL 档）；并行调用时第一个 part 带签名也必须带回 | **400** `missing a thought_signature` |
| OpenAI | Chat Completions 不暴露；Responses API 有 reasoning item + encrypted_content | 【推】store=false 时需 include 才能跨轮携带 | 【推】不硬失败 |

**当前状态**：【测】89 条评测轨迹 `reasoning_content` **零命中、无 400**——因为请求里从未显式声明 thinking，**恰好没进强制校验区**。**现在没有正在流血，但这是"一动就炸"的耦合点。**

### 解决方法
- **S3** 与 **S5 必须成对**：S3 先落地（能原样回放），S5 才敢显式声明 thinking；
- **★4.1 双调用验证（¥≈0.01）**：造一个"必须用工具"的两轮对话——
  - **A 臂**（不回放）→ 期望 **400**，留存原始报错作为对照证据；
  - **B 臂**（回放）→ 期望 **200** 并正常完成第二轮。
  这一步把"我推断"变成"你确定"，成本可忽略。**这是分水岭：跑通之前不宣称任何收益。**

### 注意风险
- **风险：A 臂可能不报 400**（若该模型/档位不强制）。此时不能据此认为"不用做"——需按文档要求做保守实现（原样回放），仅把"强制校验"的结论降级。
- **风险：不同 provider 路径行为不同**（适配器传 `provider="openai"` 走通用分支）。验证时需覆盖**实际生产用的那个入口**，不能只测 `provider="deepseek"` 分支。

## 问题 4｜思考档位从未声明、从未记录（83% 的成本处于厂商默认档）

**症状**
- 【码】`model/openai_compat.py:135` 客户端默认 `thinking="disabled"`，但 `:184` **只在 `provider == "deepseek"` 时才发送该字段**；
- 【码】`engine/query_engine.py:1202` `build_default_engine()` **不接受 `thinking` 参数**；
- 【码】评测适配器传 `provider="openai"` → **该字段从未发出** → 实际生效的是**厂商默认**；
- 【官】DeepSeek 文档：**thinking 默认开启，默认 effort = high**（flash 映射 `low→low` / `high→high`）。

**影响**
- 占总成本 **83%** 的那一项，引擎既不能声明也不能上报；
- **分数不可复现**：厂商改默认值，分数会变而代码无变化，我们不知道变量是什么；
- 同一引擎两个入口参数不一致（GUI 侧 `server/routers/chat.py:666/777/813` 能传 `reasoning_effort`，引擎自有入口不能）。

### 解决方法
- **S5**：`build_default_engine` 接受并透传 `thinking` / `reasoning_effort`，不再依赖 provider 字符串走不同分支；**把实际生效值写进 run 配置与日志**。

### 注意风险
- **风险：S5 单独上线 = 满屏 400**（显式声明即进强制校验区）。
  → **缓解**：**S3 必须先上线并验证通过**。
- **风险：顺手把 effort 调低"省钱"** → 这是**引擎替模型决定想多少**，且【测】有反证（同题 134k token 失败 vs 1.44M token 解出）。
  → **缓解**：引擎只**声明与记录**，不自动降档；要降只能是用户显式配置 + A/B 验证。

## 总执行顺序

```
S1 数据模型(零风险) → S2 原样采集 → S3 原样回放
   → ★4.1 双调用验证(¥0.01，分水岭)
   → S4 删除旧的 600 字符机制 → 4.2 回归
   → S5 显式化 thinking + 记录生效值
   → 4.3 收益 A/B(¥6，比 Σoutput)
```

**总验收标准**
1. 4.1：B 臂 200（协议正确性）；
2. 4.2：字节等价 + 顺序保持 + **连续 3 轮前缀哈希不变**（证明不破 KV 缓存）；
3. 4.3：Σoutput 是否下降 ——【推】**项目原注释自认"强模型收益≈0"，flash 上是否有收益必须实测；无收益则只保留协议修复，不宣称省钱**。

## 本轮明确不做

| 不做 | 理由 |
|---|---|
| 把思考塞进 assistant 的 `content` | 伪造模型自己的历史；可能诱发风格模仿、话更多（与省钱相反） |
| 继续用"末尾 600 字符"塞 T_now | lossy + 位置错，对需回放的厂商是非法输入 |
| 对思考做摘要/清洗后回放 | 三家官方均明确拒绝 |
| 默认开启"输出精简"注入 | 纯导演（`pre_llm_inject.py:109` 内容即"思考：精简完整推理"），注意力漂移 |
| 引擎自动调低 `reasoning_effort` | 引擎替模型决定想多少；有反证；只能用户显式配置 |
