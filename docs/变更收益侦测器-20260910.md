# 变更收益侦测器（changedetect）

> **入口**：`python -m evals.changedetect <subcmd>`
> **代码**：`python/evals/changedetect/`  · **golden**：`goldens/{surface,trace}/`
> **设计核心**：把"完美侦测"拆成两层语义，分别给出能达到什么、做不到什么。

## 一句话总结

> **L0 + L1 = 真正的完美侦测（1 字节 / 1 分支、零假红、零成本）。**
> **L2 = 统计 + MDE 报价，永远诚实，告诉你"再花多少样本才能测出来"。**

## 为什么不能"一处工具侦测一切"

真模型是随机的。同一份代码、同一组任务重跑两次，通过率会差 4.1~4.5pp（XEYO
在 TerminalBench 上自测的复现律）。在这种噪声地板上：

- 想"完美测出 1pp 改动"在数学上不可能——配对设计也要 **7,800+ 对**样本才
  能达到 80% 功率（见 `power` 子命令）。如果小样本就"判"你稳定，那它
  一定在骗你。
- 但**确定性的层面**根本不需要统计：把模型可见文本面、注入载荷、工具
  schema、决策轨迹**字节级钉死**，任何改动——1 个字、1 个分支、1 个参数名
  ——必然让 hash 变，且能立刻指出在哪个文件第几行。

所以正确的形态是**分层**：

```
┌─────────────────────────────────────────────────────────────────────┐
│ L2 配对 A/B + McNemar  ──→  "模型是不是真的变好了？"                │
│      · 有噪声，灵敏度 = 预算的函数                                    │
│      · 永远给出 MDE 报价（最小可侦测效应）                           │
│      · 低于 MDE 的差异一律标 inconclusive                             │
├─────────────────────────────────────────────────────────────────────┤
│ L1 引擎决策轨迹  ──→  "在 FakeModel 下，引擎在同样输入               │
│                      下决定做什么（注入哪些块、工具调用序列）？"       │
│      · 零噪声、零成本、< 1 秒                                        │
│      · 1 个分支条件变化 / 1 行块文本修改 必被检出                     │
├─────────────────────────────────────────────────────────────────────┤
│ L0 模型可见文本  ──→  "模型到底能看到哪些文本？"                      │
│      · 字节级：system prompt / 工具 schema / T_now 块 / slash manifest│
│      · 零噪声、零成本、< 1 秒，1 字符灵敏度                           │
└─────────────────────────────────────────────────────────────────────┘
```

## 子命令

| 子命令                              | 用途                                                                  | 成本 |
| ----------------------------------- | --------------------------------------------------------------------- | ---- |
| `surface list`                      | 列出当前渲染的全部模型可见文本（45 个 artifact, 5 组）                | 0    |
| `surface check`                     | 跟 golden 比对；任何变化都报 `modified`/`added`/`removed`             | 0    |
| `surface update`                    | 重新写 golden（**你必须清楚你在把什么钉成新基线**）                    | 0    |
| `surface selftest`                  | 对每个 artifact 注入 1 字符变异，断言 100% 被检出（"完美"的证明）       | 0    |
| `trace check` / `trace update`      | 同上，对 L1 决策轨迹（24 个 inject + loop 场景）                      | 0    |
| `trace selftest`                    | 跑两次断言 hash 稳定（确定性）                                        | 0    |
| `power`                             | 打印 MDE / 样本预算法                                                | 0    |
| `ab plan --repeats N`               | 跑前报价（不发请求）                                                  | 0    |
| `ab dry-run --repeats N`            | 干跑（FakeModel）—— 验管道，出统计                                    | 0    |
| `ab live --repeats N --budget ¥X`   | 实跑，**必须给预算上限**（超预算直接拒绝，不烧钱）                     | 真钱 |
| `compliance`                        | 扫 git diff 的新增行，命中 R2/R4 立即报警                            | 0    |
| `check`                             | 提交门：L0 selftest + L1 selftest + L0 check + L1 check + compliance  | 0    |
| `verdict`                           | 合并确定性 + 统计 + 应试性 → 单张判决书                              | 0    |

## L0 模型可见文本面

按组分类的 45 个 artifact：

- `system/*`（5 个）：`identity` / `env` / `fence` 三段原文 + 装配结果 + 加
  custom 后的去重结果。
- `tools/*`（24 + 3 = 27 个）：每个工具的 schema 单独一个文件
  （`tools/Read.json` ...）；外加 `_index` 工具名清单、`_count` 总数、
  `_bench_minimal_names`（XEYO_BENCH_MINIMAL=1 时的工具集——单独钉住，
  是 TB 评测口径的红线）。
- `tnow/*`（6 + 块数）：`registry`（klass/why 表） + `hard_cap` + `block_count` +
  7 个静态块渲染文本（`wrap_up` / `output_compact` / `code_compact` /
  `compact` / `browser_preview` / `pending_jobs` / `runtime_mode_snapshot`）。
- `slash/*`（2 个）：GUI 和 TUI 的 `slashManifest.ts` 生成物。改注册表
  但忘跑 `export_manifest` 时这里会立刻红。
- `meta/power_table`（1 个）：侦测器自己的 MDE 算表。表本身变了就当 meta 检。

**灵敏度证明**（不只是声明）：

```
$ python -m evals.changedetect surface selftest
{
  "probed": 39,
  "detected": 39,
  "missed": [],
  "sensitivity": "1 字符",
  "perfect": true
}
```

这意味着改任何 artifact 里的 1 个字符，**保证**被检出。同样的进
`commit` 门也是秒级。

## L1 引擎决策轨迹

两个电池，**全部确定性**（FakeModelClient + 纯函数 `run_pre_llm_inject`，
无网络、无随机）：

### inject 电池（20 个场景）

合成投影 × 多种注入上下文 → 跑 `run_pre_llm_inject` → 把输出（含
环境声道伪造的 assistant/tool_result 对）**整个**规范化后哈希。覆盖：

- 基础形态：`plain` / `after_tools`（续写块触发）/ `after_failed_tool`
- 触发条件：`wrap_up` / `runtime_notice` / `multi_agent` / `goal` /
  `approved_plan` / `approved_plan_pointer` / `subagent`
- 声道策略：`channel_legacy` vs `channel_env`（**两种输出必然不同**，
  否则 injection 层的判别力作废，已在测试里硬性 assert）
- 记忆开关：`no_instructions` / `instructions_on`（真实子目录 XEYO.md
  触发 nested）/ `instructions_off`
- 模式：`plan_mode` / `ask_mode`
- 预算镜像：`budget_mirror`（传 BudgetTracker 触发死线会话的预算块）

### loop 电池（4 个场景）

FakeModelClient 跑 `query_loop` → 收集事件流，**压缩**为

`[ToolCall:echo, ToolResult, Final]`

这种结构化形态而不是逐字流（避免字符数把轨迹淹掉，但保留轮次/分支信息）。

### 灵敏度自证

```
$ python -m evals.changedetect trace selftest
{ "deterministic": true, "scenarios": 24 }
```

## L2 配对 A/B + 统计

### 设计选择

- **配对**（同任务同时刻在 A 和 B 上各跑一次）→ McNemar 精确检验
  （n≤500 走精确，>500 走带连续性校正的正态近似）
- **连续量**（成本 / 字符 / 耗时）→ 配对 bootstrap CI，固定 seed
  跨进程稳定
- **MDE 自报**：每次实验结尾都明确说"本次只能测出 ≥X pp 的差异"，
  而不是含糊地"未发现显著差异"
- **预算门**：`--live` 必须配 `--budget ¥X`，否则直接拒跑

### 预算法（`power` 子命令的输出节选）

| 不一致率 ψ | 想测出的效应 | 配对所需样本 |
| ---------: | ----------: | -----------: |
| 2%         | 1%          | 1,570        |
| 10%        | 1%          | 7,849        |
| 10%        | 5%          | 314          |
| 10%        | 10%         | 79           |

非配对，p=0.7，δ=1pp → **每臂 32,966**。非配对，p=0.7，δ=4.5pp（你
们自己测的噪声地板）→ **每臂 1,628**。

### 用法

```bash
# 1) 跑前报价
$ py -3.11 -m evals.changedetect ab plan --repeats 3
{
  "n_tasks": 10,
  "repeats": 3,
  "arms": 2,
  "total_runs": 60,
  "cost_per_task_run_cny": 0.2975,
  "estimated_total_cny": 17.85,
  "price_preset": "2026-09-10 官方新价"
}

# 2) 干跑验管道
$ py -3.11 -m evals.changedetect ab dry-run --repeats 1 \
    --variant-env XEYO_T_NOW_SKIP=wrap_up

# 3) 实跑
$ py -3.11 -m evals.changedetect ab live --repeats 5 \
    --variant-env XEYO_T_NOW_SKIP=wrap_up \
    --budget 50
```

## 应试性自动扫描

对应用户红线 R1–R4（见 `docs/应试性审查-副作用修复与53号.md`），
本模块只做**纯文本可判定**的 R2 + 部分 R3/R4：

- R2 评测分支：`XEYO_BENCH_MINIMAL` / 容器路由 / `terminal_bench` / 按任务名分支
- R4 兑现：`read|open|load|...` 加 `/tests` 路径
- R3 导演型措辞：`你应该` / `请务必` / `建议你` / `优先` / `必须`

每一行命中都会带 where 信息，**但 scanner 是报警器不是判官**——命
中不等于违规，但每条命中必须能在 PR 里解释。

## 提交门（已挂进 `scripts/check.ps1`）

```
== Python ==
...
py -3.11 -m evals.changedetect check
```

这条门：

- **L0 + L1 selftest**：防 golden 漂移（39 个 L0 文本 + 24 个 L1 轨迹）
- **L0 + L1 check**：当前代码 vs golden
- **compliance 扫描**：未提交的 `git diff` 必须无 R2/R4 命中

不挂 L2：每次 commit 都跑真模型既慢又烧钱，**不实用**。L2 单独手动跑。

## 何时应该 `surface update` / `trace update`

**必须**满足两个条件再动 golden：

1. 改动**不是**一时手抖——有 commit/PR 记录在
2. 改动**有合法理由**——要么是 L2 验证过的收益，要么是必需的 bug fix
   / 重构 / 文档

`update` 不是"清错误"，是"重新钉基线"——`docs/应试性审查-副作用修复与
53号.md` 的精神同样适用。**光跑绿不叫收益**。

## 已知边界

- L2 dry-run 用 FakeModelClient，所有 task 都会 FAIL——这是预期，因为它
  不会"在"任务里说对的话。dry-run 的价值是**管道**而非能力数字。
- L1 inject 电池的 `pending_jobs` 等少数块依赖引擎全局队列，可能因
  其他测试/进程的全局状态产生不稳定；以 `trace selftest` 为准（跨进
  程两次跑结果一致即视为稳定；如不稳定请报 issue 并附场景输出）。
- T_now 块硬顶 `T_NOW_BLOCK_HARD_CAP=21` 与登记数都进 L0，加块必须
  改两处（已有机器执法）。
- `usage/pricing.py` 截至 2026-09-10 仍带旧价 + peak×2；本模块用
  `official-new` 预设（2026-09-10 新价）作为默认，**不**依赖 pricing.py。

## 维护铁律（写新功能前必读）

1. 任何会让 L0 / L1 输出变化的代码改动，**必须**自己跑一次
   `surface check` / `trace check`，然后**解释每一处变化**才能 update。
2. 任何会进入 L2 影响分支的代码改动，**必须**在 update 之前有 L2 验
   过的收益数据；纯"清红" = 应试。
3. 加新检测点时先**问 L0 已经够不够**——L0 是零成本零噪声的，加不进
   L0 的再考虑 L1，L1 都不行的才上 L2。
4. 写新工具时**严守观测域一致性**：侦测器走与模型动作**同一执行通道**，
   否则注入"模型看不到的事实"——这是老 R3 题。
